# 02 記録を壊さない

## この章で読むこと

記録は本人の PC に残る素の文字のファイルで、AI が無くても読め、AI が替わっても残ります（基本計画 §4）。足した機能が、
この記録を読めない形にしたり、本人の言葉を消したりしない事。記録の形、seed が読まない物、本人の言葉、
写真と座標、新しい記録のファイルを足す時。

## 記録の形は `docs/記録の形.md`

- 仕様はこのページで、コード（`src/seed/records.py`）はこれに合わせて書いてあります。形を変える時は、**先にこのページへ
  日付付きで書く**決まりです（記録の形の頭）。フォークした seed で形を変える時は、コードより先にここを直します
- 一行の形は一つです: `- <key>: <text> [<confidence>]  → farmer: right | wrong (<reason>)`（記録の形 §2）
  - `key` は小文字の ASCII（`[a-z][a-z0-9_]*`）。違えば `Line` が `ValueError` を出します
  - あなたの行（AI の行）は確からしさ `[0.00]`〜`[1.00]` で終わります。本人の行には付けません
  - `→ farmer: …` は本人だけが付けます。あなたは書きません
- 見出しは英語の ASCII で四つ、この順です: `## Reading (<model>)`、`## Earlier reading`、`## Data`、`## Record`
- ファイルの中の決まった語（key、見出し、`farmer: right|wrong`、`(none)`）は英語のままで、本人の言葉だけが本人の言語です
  （記録の形 §2「国際対応」）。画面に出す時に訳すのは `lang.t` と `strings.key_label` の仕事です

## 欄を足さない

- 観察の前書きの欄は決まっています（date、time、photos、location、lookup、model、language、kind、ask）
- `## Record` の key は五つです: `did`（したこと）、`saw`（見たこと）、`said`（言ったこと）、`note`（そのほか）、`ask`
  （知りたいこと）。`Observation.say` はこれ以外の key を断ります（`RECORD_KEYS`）
- 品種名も被覆も、本人の一言に書きます（設計書 §3）。足したい記録は、まずこの五つの key のどれかで書けるかを見ます
- `## Record` の行には日付の欄がありません。行の日は、その観察の `date`（`obs.date`。写真の撮った日）です
- アプリの「話す」で本人が送った言葉は `said` の行になります（写真と一緒の時も、言葉だけの時も。問いが残っていれば、問いを
  添えた `said`。`talk.py`、`highlights.answer_line`）。key を選んで書けるのは `seed say` と `seed observe --say "did: …"` です

## seed が読まない物

`Observation.parse` は、知らない見出し、見出しの下の行の形でない文、前書きの知らない鍵、前書きと最初の見出しの間の文を
読み飛ばし、`kept_sections`、`kept_text`、`kept_front`、`kept_preface` に取っておきます。`Observation.render` は、それを
消さずに書き戻します（記録の形 §2。本人が書き足した言葉は、年を重ねて読み返す記録の一部だから）。置く所は決まっていて、
行の形でない文はその見出しの行の後、知らない見出しは `## Record` の後に元の順で並びます。`## Reading` の下の行の形でない
文は、読みを書き直す時（`reread`）に `## Earlier reading` へ移ります。

消えはしませんが、読まれもしません。`kept_*` を使うのは `records.py` の中だけです。だから、

- 観察のファイルに自分の見出し（`## Water` など）を足して行を書くと、その行は `obs.record` にも読みにも入らないので、
  seed の画面と命令はその行を使いません
- 自由な文の段落は、書き戻すたびに見出しの行の後へ寄ります。書いた所に留まりません
- 足したい物は、決まった key の行として足すか、別のファイルに置きます（下の「新しい記録のファイル」）

`plan.md` も同じ作りです（`Plan.parse`、`Plan.render`）。

## 記録を書く時は seed の関数を通す

手で文字を組み立てずに、`records.py` と各モジュールの関数を使います。形が一つの所で守られます。

| したい事 | 使う物 |
|---|---|
| 観察を読む | `Folder.list_observations()`（古い順の道）、`Observation.read(path)`。日と時は `obs.date`、`obs.time`、本人の行は `obs.record`（一行は `Line`。`line.key`、`line.text`）。形の崩れた観察（`date` が `YYYY-MM-DD` でないなど）は `Observation.read` が `ValueError` を出します。`weather.place_center` は `ValueError` と `OSError` を受けて、その観察を飛ばします |
| 本人の行を足す | `obs.say(key, text)` の後に `obs.write(path)`（`seed say` と同じ道） |
| 読みの行に判定を付ける | 本人がする事です。命令は `seed mark` |
| あなたの行を置き換える | `obs.reread(lines, model)`。判定の付いた行は残り、文が変わった物は `## Earlier reading` へ移る |
| 場所の資料を読む | `Folder.place_data()`、`Folder.place_record()` |
| 一行ずつの記録のファイルに足す | `lots.append_to_section(path, heading, line)`（`lots.md` と `ledger.md` が使う形） |
| 気象の記録を読む | `weather.recorded(folder.root, start, end)`（`start`、`end` は `datetime.date`）→ 日付の文字 → `Day`（`rain` は降水 mm） |

読むだけの画面なら、記録は変わりません。画面から書く物は、`procedure.toggle` のように書く関数を一つ作り、命令と画面の
両方からそれを呼ぶ形にします（01 の `procedure.py`）。

## 本人の言葉を直さない

- `record` の行は、本人が言った事をそのまま写します（`skill/SKILL.md` の「守ること」）。言い換え、まとめ、誤字の直しを
  しません。一行に収めるために改行を空白にするだけは、seed もしています（`talk.py` の `note_words`）
- 本人の行に確からしさを付けません。本人の行を消しません
- 判定の付いた行は、読み直しても残ります（`JudgedLines.reread`）。この仕組みを通らずに `## Reading` を書き換えると、
  判定が消えます

## 写真と座標

- `photos/` の写真は EXIF の座標を含めて本人の物で、記録のフォルダーの中に残ります（利用マニュアル §9）
- 観察が指している写真（観察の前書きの `photos:` に在る物）は動かしません。外すのはアプリの「写真」で、外した写真は消さずに
  `photos/removed/` へ移ります（`album.py`）
- 画面に細かい座標を出しません。「この土地」の画面も出していません（設計書 §5.11）
- 公開に出る座標は小数 2 桁（約 1 km）です（`records.coarse_coord`）。公開の文の中の細かい座標らしい数の対は
  `records.fine_coords` が見つけます
- 外へ送る写真は縮めて EXIF を外します（`photos.shrink`、`photos.for_public`、`photos.strip_exif`）。外へ送る時の決まりは 04

## 新しい記録のファイルを足す時（フォークした seed で）

一言の行で書けない物（一行に決まった列が並ぶ物）は、`lots.md`（種のロット）、`ledger.md`（帳簿）、`weather/<YYYY-MM>.md`
（気象）と同じく、別のファイルにします。やる事は次の四つです。

1. `docs/記録の形.md` に、日付付きの節を足す（ファイルの名、見出し、一行の形、命令、公開に出すか）。§15〜18 が見本
2. 読み書きのモジュールを `src/seed/` に一つ（`lots.py` が短い見本。一行の欄に改行と `|` を入れない `plain`、誤りを
   `strings.py` の語で返す `LotError`）
3. 畑を分ける時（`seed field new`）に根から畑へ移す物の並び `cli.py` の `ROOT_RECORDS` に足す。足さないと、そのファイルは
   根に残ります
4. 公開に出すかを記録の形に書く。`lots.md`、`ledger.md`、`weather/` は公開ファイルに出しません（記録の形 §15〜17）

記録のフォルダーのプラグインから自分のファイルを書く事もできます。その時も、記録の形と同じ一行の文法と、英語の見出しに
揃えると、ほかの読み手（人、表計算、別の AI）がこのコード無しで読めます（記録の形 §1）。
