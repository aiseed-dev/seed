# 03 テストと確かめ

## この章で読むこと

書いた物が動くかを、機械で確かめる所と、目で確かめる所。フォークした seed では `pytest` と `ruff`、記録のフォルダーの
プラグインでは読み込みの一行、どちらもアプリを開いて画面を見るまで。

seed は書き直しやすいアプリで、その理由の一つはテストです（基本計画 §4）。同じ入力で同じ答えが出るかを機械で比べられる
所は、AI が書き、機械が確かめ、人は結果を見るだけで済みます。

## フォークした seed で

道はリポジトリの根からです。README の「使ってみる」の入れ方なら、Python は `.venv/bin/python` です。テストの道具は
`pip install -e ".[dev]"` で入ります（`pyproject.toml` の `dev`）。

```bash
.venv/bin/python -m pytest -q
```

```bash
.venv/bin/python -m pytest -q tests/test_plugins.py
```

```bash
.venv/bin/ruff check src tests
```

- 一行の長さは 110 字までです（`pyproject.toml` の `[tool.ruff]`）
- 全部のテストを回してから、本人に「済んだ」と返します。足した物のテストだけが通っても、ほかを壊していないとは限りません

### テストが本人の物に触れない仕組み

`tests/conftest.py` の、毎回自動で効く物です。新しいテストもこの上で動きます。

| 名 | 何をするか |
|---|---|
| `credentials_in_tmp` | 秘密の置き場（`credentials.toml`）を一時のフォルダーへ向ける（`SEED_CREDENTIALS`） |
| `fields_in_tmp` | 畑の一覧（`fields.toml`）を一時のフォルダーへ向ける（`SEED_FIELDS`） |
| `no_local_claude` | 手元の `claude` を見つけない |
| `no_home_server` | 家のサーバーを聞きに網へ出ない |
| `no_weather_fill` | 気象の記録の穴埋め（網に出る）をしない |

`seedfolder` は、まだ無い記録のフォルダーの道を返します（言語は ja）。

### プラグインのテストの見本 `tests/test_plugins.py`

- `put(folder, name, body)` が `plugins/<名>.py` を書き、`App(FakePage(), str(seedfolder))` でアプリを作ります
  （`FakePage` と、画面の文を全部集める `texts`、部品をたどる `walk` は `tests/test_app.py`）
- `app.route_change(path="/p/<名>")` の後に `texts(app.page.views[-1])` で、画面に出た文を確かめます
- 網に出る所は `monkeypatch` で差し替えます（例 `monkeypatch.setattr(W, "fetch_week", …)`）。後ろで動く仕事は、`FakePage` の
  `tasks` に溜まるので、テストの `run_tasks(app)` で回します
- 壊れたプラグインが飛ばされる事、`build` の例外で一行が出る事、動いている間に書いたプラグインを拾う事も、ここにテストが
  あります。同じ形で足します
- 同梱のプラグインを足したら、`test_shipped_land_is_found` などの、同梱の並びを見ているテストの並びも直します

### 文を足した時

`strings.py` の `ja` と `en` に同じ語が揃っている事を `tests/test_cli.py` が見ています。片方だけに足すと落ちます。

## 記録のフォルダーのプラグインで

記録のフォルダーにはテストの置き場がありません。seed を入れた Python で、読み込めるかを一行で確かめます。

```bash
python -c "import logging; logging.basicConfig(); from seed.records import Folder; from seed.app import plugins; print([p.route for p in plugins.own(Folder('~/seed'))])"
```

- 読めた物は `/p/<名>` で並び、読めない物は `プラグイン <名> を飛ばす: …` の警告が出ます
- `Folder('~/seed')` の所は、本人の記録のフォルダー（プロジェクトなら根）の道にします
- これは読み込みまでで、`build` の中は確かめません。中はアプリで画面を開いて見ます
- seed のリポジトリが手元に在れば、`build` の中も上のプラグインのテストと同じ形で確かめられます。`tests/` にテストを一つ
  置き、`put(seedfolder, "<名>", <plugins/<名>.py の中身>)` で置いて、`route_change` と `texts` で画面の文を見ます。
  `tests/conftest.py` の自動で効く物は、`tests/` の下のテストにだけ効きます

## アプリで画面を見る

```bash
seed app
```

```bash
seed app --web
```

- `seed app` は PC の窓、`seed app --web` はこの PC のブラウザで開きます（画面の確かめ用の一人用。`--port` で口を決められる）。
  フォークした seed では `.venv/bin/flet run` でも開きます（README）
- 開く記録のフォルダーは `--folder <道>` で選べます（既定は `~/seed`）。試しの記録のフォルダーは `seed --folder <道> init` で
  作れます
- 上の端に印が増えている事、押して画面が出る事、文が本人の言語で出る事を見ます
- 「このプラグインは動きません（<名>: <例外の名>）。」が出たら、例外の全文は `seed.app` のログに書かれています
  （`main.py` の `_plugin_builder` の `log.exception`）
- 窓の幅を狭くして見ます。スマートフォンの幅でも読めるかは、ここで分かります。幅が足りない時、入らない画面の印は右の端の
  「…」の一覧に回ります（`main.py` の `nav_fit`）。本人のプラグインは並びの最後なので、狭い幅では「…」の中に在ります
- 畑が幾つもあるプロジェクトなら、上の端のフォルダーの印で「プロジェクト全体」を選んでも開くかを見ます（`app.whole`）
- 見た画面を本人にも見てもらいます。本人の畑の記録で見るのが、一番の確かめです
