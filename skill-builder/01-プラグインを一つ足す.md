# 01 プラグインを一つ足す

## この章で読むこと

一つの Python ファイルが一つの画面になる仕組み（設計書 §5.11、`src/seed/app/plugins.py`）。置き場、三つの名、`app` に
在る物、同梱の三つの形。最後に、プラグインでない足し方（命令、「こういう事ができます」の例）の入口。

## 置き場

| 置き場 | 誰の物 | 出る端末 |
|---|---|---|
| `src/seed/plugins/<名>.py` | パッケージに同梱（配る物） | PC とスマートフォン |
| 記録のフォルダーの `plugins/<名>.py` | 本人の物 | PC だけ |

- 畑が幾つもあるプロジェクトでは、畑のフォルダーに `plugins/` が在ればそれ、無ければプロジェクトの根の `plugins/` です
  （`plugins.plugins_dir`、`Folder.shared`）。二つは合わさりません。畑に `plugins/` が一つでも在ると、その畑を開いている間、
  根の `plugins/` のプラグインは出ません
- 名が `_` で始まるファイルは読みません。同梱と同じ名の本人の物は、同梱の方が出ます（`plugins.load`）
- 道は `/p/<ファイルの名の幹>` です。上の端の印は、話す、写真、同梱の物（名の順）、本人の物（名の順）の並びです

## 三つの名

```python
# SPDX-License-Identifier: AGPL-3.0-or-later
"""一行で、何の画面か。"""

from __future__ import annotations

import flet as ft

TITLE = {"ja": "収穫", "en": "Harvest"}   # 言語 → 画面の名。無い言語は en
ICON = "AGRICULTURE"                      # ft.Icons の名（文字で）


def build(app) -> list[ft.Control]:      # 画面の中身。枠（上の端の名と印）はアプリが付ける
    return [ft.Text("収穫の画面です")]
```

- `TITLE` が空でない dict、`ICON` が `ft.Icons` に在る名、`build` が呼べる物、の三つが揃わないと、印は出ず、ログに一行
  出ます（`plugins.make`）。読み込みで例外が出た物も同じです
- `build` が例外を投げると、その画面に「このプラグインは動きません（<名>: <例外の名>）。」の一行が出ます。アプリは落ちません
  （`main.py` の `_plugin_builder`）
- `ICON` の名は `python -c "import flet as ft; print(hasattr(ft.Icons, 'WATER_DROP_OUTLINED'))"` で確かめられます

## いつ読まれるか

- アプリの起動時と、別のフォルダーや畑を開いた時（`App.open_folder` → `plugins.load`）
- 画面を切り替えるたびに、`plugins/` の `.py` の名と更新の時を見て、変わっていれば読み直します（`App.reload_plugins`、
  `plugins.stamp`）。「話す」の間に Claude Code が書いたプラグインは、次に画面を切り替えた時に印が出ます
- `build(app)` は、その画面を描くたびに呼ばれます（`App.route_change`、`app.refresh()`）。重い事や網に出る事を `build` の中で
  そのまましないのは、そのためです。天気の形（下）を使います

## `app` に在る物

`app` は `seed.app.main.App` です。

| 名 | 何か |
|---|---|
| `app.folder` | 今の畑の記録のフォルダー（`seed.records.Folder`）。プロジェクト全体の時は根で、`app.folder.list_observations()` は空。観察は `app.fields` の畑ごとに読む（下の `land.py` の形） |
| `app.lang` | 言語（`ja`、`en` …） |
| `app.t(word, **kw)` | `strings.py` の文を引く |
| `app.state` | この窓の間だけ残す dict。畑が替わると空になる。アプリの芯と共有（下） |
| `app.refresh()` | 今の画面を描き直す |
| `app.page` | Flet の page。`app.page.run_task(関数)` で後ろで動かす |
| `app.toast(text)` | 下に一行の知らせ |
| `app.whole`、`app.fields`、`app.for_field(f)` | プロジェクト全体を見ているか、畑の並び（`Folder` の並び）、畑一つ分の `app`（設計書 §5.12） |
| `app.settings` | 設定。秘密の欄も在るが、プラグインからは触れない（04） |

`app.state` は、アプリの芯も同じ dict を使います。芯が使う鍵は `await_invite`、`await_key`、`await_server`、`capture`、
`capture_parts`、`capture_text`、`claude_session`、`confirm`、`direct_messages`、`home_asked`、`index_error`、
`index_loading`、`invite_digits`、`kind`、`pending`、`photo_tag`、`public_cache`、`remote`、`remote_name`、`talk`、
`talk_open`、`talk_stop`、`talk_to`、`videos_sending` で、同梱の天気は `weather_forecast`、`weather_forecast_failed`、`weather_forecast_loading`、
`weather_filled` を使います。本人のプラグインは、鍵の頭に `<プラグインの名>_` を付けます（`harvest_rows` など）。
芯の鍵を書くと芯の動きが変わるからです。たとえば `kind` は設定の札の「自分の畑／候補地」の切り替えが書き
（`cards.py` の `flip_kind`）、写真から観察を作る時にその値が前書きの `kind`（own か candidate）になります（`talk.py` の
`send_photos`）。

見た目の部品は `seed.app.theme` にあります（`subheading`、`body`、`muted`、`error`、`note`、`line_text`、`BODY_SIZE`）。

## 同梱の三つ

### `land.py`（この土地）— 一番短い形

`build` は `landview.controls(app)` を返すだけです。プロジェクト全体の時（`app.whole`）は、`app.fields` の畑ごとに
`theme.subheading(畑の名)` と `landview.controls(app.for_field(f))` を並べます。畑の物を見せる画面は、この形で全体にも
対応します。AI を使わず、細かい座標を出しません。

### `procedure.py`（手続き）— 記録を読み、押して書く形

手引き 13 章の段を読み（本人の `skill/` に在ればそれ、無ければパッケージの物）、`procedures/nochi-3jo/` の三つのファイルを
読んで出します。印を押すと `procedure.toggle(folder, slug, key, done)` が `checklist.md` の `[x]` を書き換えます。下書きが
無い時の「下書きを作る」は、`asyncio.to_thread(procedure.PROCEDURES[slug], folder)` で後ろで作り、`app.toast` と
`app.refresh()` で知らせます。ファイルを書く所は、画面のコードではなく `seed.procedure` の関数が持っています。命令
（`seed procedure`）と画面が同じ関数を使うので、書く形が一つで済みます。

### `weather.py`（天気）— 外と話す形

1. 座標を `centre(app)` で取る。畑一つなら `land.center(app.folder)`、プロジェクト全体なら `app.fields` を回して座標の在る
   最初の畑の `land.center(f)`。無ければ「位置の入った写真が一枚あると…」の一行で終わる
2. `app.state["weather_forecast"]` に `(座標と今日の日付, 取った物)` が在れば、それで描く。同じ日の開き直しでは取り直さない
3. 無ければ、`app.state["weather_forecast_loading"]` に印を置き、`app.page.run_task(load)` で後ろへ。`load` の中で
   `await asyncio.to_thread(weather.fetch_week, *c)`、取れたら `app.state` に置いて `app.refresh()`
4. 取れなかった時は `app.state["weather_forecast_failed"]` に理由を置き、`theme.error` の一行と「取り直す」の釦を出す
5. 画面の一番下に、出典の link と計算の仕方の二行（`credits`）

座標を丸める事と、網に出る所の形は 04 にあります。

## 文

- 同梱のプラグインの文は `src/seed/app/strings.py` に置き、`app.t("<語>")` で引きます。`STRINGS["ja"]` と `STRINGS["en"]` の
  両方に同じ語を足します。両方の語の組が同じ事を `tests/test_cli.py` が見ています
- 本人のプラグインは `strings.py` に足せないので、`TITLE` と同じく `{"ja": …, "en": …}` の dict を持ち、`app.lang` で引きます
- 文は来た人に向く文です。です・ますで短く書きます。設計書の固い文を写しません

## スマートフォンにも出す時（同梱にする時）

- スマートフォンの包みに入るのは `[tool.flet.ios]` と `[tool.flet.android]` の `dependencies` に在る物だけです（`pyproject.toml`。
  flet、flet-camera、flet-geolocator、pillow、httpx、pyyaml）。それ以外の包みを使うプラグインは、スマートフォンでは読めず、
  印が出ません
- `seed/server` は包みから外してあります（`[tool.flet.app]` の `exclude`）。プラグインから `seed.server` を読みません

## プラグインでない足し方の入口（フォークした seed で）

### 命令を一つ足す（`src/seed/cli.py`）

- 関数 `cmd_<名>(st, args) -> int`。`st.records` が記録のフォルダー、`st.language` が言語。出力は `_out(s("<語>", lg))`、
  誤りは `_err(...)`。終わりの値は、済んだら 0、誤りは 1 か 2
- `parser()` の中で `sub.add_parser("<名>", parents=[common], help=...)`。読むだけの命令は `set_defaults(readonly=True)`
  （フォルダーを作らない）
- `COMMANDS` に足す。畑ごとの記録を使う命令は `FIELD_ONLY` にも足す（プロジェクト全体では断る）
- 同じ仕事をアプリの「話す」の手元の Claude Code にもさせるなら、`local.py` の `TALK_COMMANDS`（許す命令の並び）と、
  `claude_md.py` の命令の一覧に足す
- 見本は `cmd_lot`、`cmd_ledger`（記録のファイルに一行ずつ足す命令）

### 「こういう事ができます」の例を一つ足す（`src/seed/app/talk.py`、`cards.py`）

画面を作らずに、できる事を本人に見せる所です。

- `EXAMPLES` に `Example("<鍵>")`（Claude が要る物は `needs_claude=True`）、`examples()` の並びに鍵を足す
- 文は `strings.py` の `ex_<鍵>`（ja と en）
- 押した時の動きは `run_example`。Claude が要る物は、その言葉を Claude に送ります。札を出す物は `CARD_OF` と、`cards.py` の
  `card()` の dict と `card_<鍵>` の文に足します
