# 00 始める前

## この章で読むこと

本人の「こういう事をしたい」を一文にする事と、言葉・画面・コードの三つのどれで足すかを見る事。
画面や欄を増やす前に、Claude との対話で済まないかを先に見る理由。

## 何を足したいかを言葉にする

本人の最初の言葉は、たいてい形が決まっていません（「水やりを記録したい」「収穫を見たい」）。足す物を決める前に、
次の四つを本人と話して、一文にします。

| 聞く事 | なぜ聞くか |
|---|---|
| どの場面で使うか（畑で撮る時か、家で見返す時か） | 畑ではスマートフォンで撮るだけにする作り（基本計画 §4）なので、畑で使う物と家で使う物は足す所が違う |
| 何を残したいか（言葉、写真、数） | 残す物が本人の一言で書けるなら、記録の形を変えずに済む（02） |
| 何を見たいか（一覧、並び、図） | 見る物が Claude に頼めば出る物なら、画面は要らない |
| 外の資料が要るか（天気、地図、識別） | 外と話す物は、送る物と鍵の扱いが要る（04） |

一文の例:「水をやった日を残し、後で日付順に、雨の日と並べて見たい」。

## 三つの足し方

利用マニュアル §11「機能は自分で足す」の三つです。上から順に見ます。

| 足し方 | 何をするか | 何ができるか | どこで |
|---|---|---|---|
| 言葉で足す | 本人の手引き（記録のフォルダーの `skill/`）に書き足す | 記録の種類、読む順、見せ方、頼み方。次の読みと「話す」から効く | 記録のフォルダー。アプリの「話す」でも、手元の Claude Code が使える PC なら |
| 画面を足す | 記録のフォルダーの `plugins/<名>.py` を一つ置く | 上の端に印が一つ増え、自分の畑の画面（表、図、一覧）が出る | 記録のフォルダー。フォークは要らない（01） |
| コードで足す | フォークした seed の `src/seed/` を直す | 撮る、位置、話すと写真の画面、命令、記録の形 | フォークした seed（01、02） |

決め手になる事実:

- スマートフォンでは、記録のフォルダーがアプリの入れ物の中にあるので、本人のプラグインは置けません。スマートフォンに出る
  画面は、パッケージに同梱した物（`src/seed/plugins/`）だけです（設計書 §5.11）
- アプリの「話す」で手引きとプラグインを書けるのは、PC の手元の Claude Code の運び方だけです。自分の鍵とサーバーの運び方は、
  本人の言葉を一番新しい観察に `note` として残し、PC で足せると案内します（`prompts.py` の `TALK_RULES`）
- 撮る、位置、話すと写真の二つの画面は、アプリの芯で、プラグインでは変えられません（`claude_md.py`、設計書 §5.11）

## 画面を増やす前に、対話で済まないかを見る理由

基本計画 §4「画面も同じ」に、作者の考えがあります。まとめると次の三つです。

1. **欄を決めると、欄に合わない物が落ちる。** 土の種類、洪水の区域、昔の空中写真、目の前の草むら、かぼちゃを見つけた日。
   自然農法の畑は、種類も形もばらばらで、畑ごとに在る物が違います。決まった欄に入れる数字が無かった事が、自然農法の
   アプリが作りづらかった理由で、写真と一言を読める AI がそれを変えました
2. **分担がある。** 文字の細かい作業は本人の Claude Code、写真（撮る、見渡す、選ぶ、外す）はアプリです。機能ごとに画面を
   作らず、入力の上に「こういう事ができます」の例を出します（`talk.py` の `EXAMPLES`）
3. **畑ではやる事が多い。** 畑では撮るだけにし、記録と観察を楽しくする事が先です

だから、本人の頼みが「見たい」なら、まず「話す」で頼む言葉を一緒に作ります（例「水をやった日を並べて」）。
手元の Claude Code は記録のフォルダーを Read と Grep で読めるので、一度の頼みならこれで出ます。
同じ物を毎日見る、図にしたい、押して記録を変えたい、の時に画面を考えます。

## 言葉で足す時

- 書き足す先は、記録のフォルダーの `skill/` の章です（無ければ `SKILL.md` の末尾。`local.py` の `talk_rules`）。どこに何を
  書いたかを本人に返します
- 手引きの決まりは `skill/SKILL.md` の「守ること」のままです。判定の行（〜すべき）は書きません。出典の無い事を足しません
- 本人の手引きは、パッケージが新しくなっても上書きされません（利用マニュアル §11「手引きは本人の物」）。書き足した物は
  本人の写しにだけ在ります

## 例: 「水をやった日を記録して、見たい」

- 残す物: 水をやった事は、本人の一言で書けます。欄は要りません。写真を撮って「水をやった」と送れば、その写真の観察の
  `## Record` に入ります。写真を撮る、Claude と話す、記録を活かす、の三つの芯の中で済みます
- 気を付ける事実が三つあります
  - アプリで写真と一緒に送った言葉と、言葉だけで送った言葉は、key が `said`（言ったこと）の行になります（`talk.py`）。
    `did`（したこと）の行にするのは、`seed say <観察> did "…"`、`seed observe --say "did: …"`、手元の Claude Code に頼む時です
  - `## Record` の行には日付の欄が無く、行の日はその観察の `date`（写真の撮った日）です。写真を撮らずに言葉だけを送ると、
    一番新しい観察に足されます（`talk.py` の `note_words`）。その日に観察が無ければ、行の日は前の観察の日になります
  - 同梱の画面と同じく AI を使わない画面にすると、行は文字で拾います。本人の言葉は直さないので（02）、画面の側が拾う言葉を
    幾つか持つ形にします（「水やり」「水をやった」など。本人がいつも使う言い方を聞いて決める）。文字で拾うので、
    「水やりはしなかった」のような打ち消しの文も拾います
- 本人と話す材料: 水をやる時に一枚撮る（その日の観察ができる）、言葉に日付を入れる、別の記録のファイルを足す（コードで足す。
  02 の「新しい記録のファイル」）。一枚撮る形は、記録の形を変えずに済みます
- 見る物: 一度なら「話す」で「水をやった日を並べて」。毎日見るなら、観察の `said` と `did` の行から、拾う言葉の入った物を
  日付順に並べ、`weather/<YYYY-MM>.md` の降水と並べるプラグイン（01、02 の表）。読むだけの画面で、記録は変えません。
  `weather/` は、`seed weather fill`、観察の終わり、天気の画面を開いた時に埋まります（記録の形 §17）。三つとも
  `weather.fill_missing` で、畑の座標（`place.md` の `center` の行か、位置の入った写真の観察。`weather.place_center`）が
  無ければ何も書きません。読む側は `weather.recorded` で、網には出ません
