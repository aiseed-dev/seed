# 08 ビルダーの訓練

## この章で読むこと

観察 → 読み → 判定 → 手引きを直す、の一周。この一周が、自分の場所で AI を使い、確かめ、直す、ビルダーの
最初の仕事です。ソフトウェア開発者はビルダーになろう、が作者の立ち位置で、ビルダーは自分の場所で実際に使い、確かめ、直すことで
育ちます（01 立ち位置）。自給農は、土地が一反あれば相手が現実（畑）なので、自分で訓練できます。

## 読み方

### 一周

1. **観察。** 本人が畑を観察し、写真を撮る
2. **読み。** あなた(AI)が、この手引きに従って読みを書く
3. **判定。** 本人が、読みの行に合う／違うを付け、違うには理由を書く（あなたは付けない）
4. **手引きを直す。** 違うの理由が溜まったら、手引きの章を直す。直した手引きで、次の観察を読む

三までは、毎回の仕事です。四は、理由が溜まってからです。一回の違いで章を直さず、同じ違いが
繰り返されたときに直します。

### 手引きは本人の物

`seed init` が、パッケージの `skill/` を `~/seed/skill/` に写します。自分の Claude（Claude Code、
Claude.ai）に読ませるのは、こちらです。本人が直してかまいません。パッケージが新しくなっても、本人の
手引きは上書きされません。違いは、本人が見て取り込みます（`docs/記録の形.md` §9）。

### 違うの理由から、章を直す手順

1. 違うを集める。`observations/` の `farmer: wrong` の行を、理由と一緒に一覧にする
2. 当たる章を探す。読みの行の `basis` に、拠った章や資料が書いてある。違うと付けた行の `basis` と key から、
   どの章のどの文に当たるかを、本人の AI と探す。`basis` が無い行は、key（`plants` なら 06 畑を読む）から探す
3. 同じ違いが複数あるかを見る。一回なら、直さず、次の観察を待つ。複数あれば、直す案を考える
4. 案を出すのはあなたで、直すかどうか、どう直すかを決めるのは本人です。直す前と後の文を並べて見せます
5. 根拠を足すときは、本人が自分で読んだ一次資料を `sources.md` に番号を付けて足します。足していない資料を
   根拠にした文は、書きません。知らないことは、知らないままにします
6. 直したら、同じ場所の次の観察を、直した手引きで読みます。`change`（前の観察からの変化）と本人の `did` を
   並べて、直しが効いたかを、本人が畑で確かめます

### 記録を、スクリプトで並べる・比べる・数える

記録は素の文字のファイルなので、本人の AI と小さなスクリプトで読めます。コードは書かず、何を頼むかの文
だけを置きます。一例です。

> `~/seed/observations/` のファイルをすべて読んで、`farmer: wrong` の付いた行を、key ごとに数え、
> 理由と観察の日を並べた表を作る小さなスクリプトを書いて。結果は表で見せて

出てきた数や表は、仮説の材料です。どの key で違うが多いか、どの理由が繰り返されているかを、本人が読んで、
章を直すかどうかを決めます。同じ頼み方で、観察の日ごとに `change` の行だけを並べたり、`did` と
読みの `plants` を日付で並べたりもできます。

### 直した手引きを、人に渡す

直した手引きは、GitHub の自分のリポジトリに置いて渡せます。公開ファイル（`public/<id>.md`）とは別です。
公開ファイルは、観察から選んだ行を渡す物で、手引きは、読み方を渡す物です。

- 置くのは `~/seed/skill/` の中身だけです。`observations/`、`place.md`、`photos/` は置きません
- 手引きの文に、本名、住所、電話、メール、土地の所有者の名前を書いていないか、置く前に本人が確かめます
- どこを直したか、何が違ったから直したかを、リポジトリに文で残すと、渡された人が読めます
