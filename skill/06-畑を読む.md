# 06 畑を読む

## この章で読むこと

座標の入った写真を、何を見て、どの行に、どう書くか。読みの行は仮説で、書くのはあなた(AI)、
合う／違うを付けるのは本人、決めるのは畑です。

## 読み方

### 写真から見る物

写真に写っていることから始めます。写っていないことは、写っていないと書きます。

- **草。** 種類(分かる範囲で。分からなければ「イネ科らしい」のように上の括りで)、高さ(人、棒、
  道具など写っている物と比べた目安)、優占(どの草が面を占めているか)、まだらか一様か
- **勢い。** 同じ種類の草が、周りの畑や道端や畦の物と比べて大きいか小さいか、密か疎か、茎が太いか。草の勢いは、
  土の状態を知る人が最初に見る物です。勢いが土の何を語るかは、下の「本人が書く」所が埋まるまで、あなたは仮説として
  低い確からしさで書きます。本人が勢いから土を読んだら、それは本人の `record` で、次の観察で合うかを見ます
- **裸地。** 土が見えている所があるか。無いか。広さの目安
- **地表の色と湿り。** 見えるときだけ。草に隠れて見えないときは、見えないと書く
- **水。** 溜まり、流れ、乾いた跡。畝や溝の向き
- **作物。** あれば、何が、どの段階か。無ければ無いと書く(草だけの畑は、その読みを書く)
- **まわり。** 隣の畑、畦、法面、川、林が写っていれば。写っていることだけ

一枚から言えることと、歩いた全体から言えることを分けます。一枚しかないときは、`uncertain` に書きます。

### 写真の組を読むときに

- **写真は、前書きの `photos` の名で指します。** `photos/2026-11-02/153402.jpg` なら `153402`。行の中で「どの写真に
  写っているか」を書くと、本人が合う／違うを付けるときに、その写真を開いて確かめられます。ある写真に基づく行には、
  その写真の名を書きます。アプリは、行が名で指す写真をその行の横に出します
- **決まった書き出しの行を三つ入れます。** 行はただの文のままで、key は下の表の順のままです
  - `overall` の最初の行を「今日の一枚: <写真の名>。<なぜその一枚か、何が写っているかを一言>」にします。本人に一番見せたい一枚を選びます。アプリはこの写真を大きく出します
  - 本人への問いを一つ、`uncertain` の行で「問い: …」と書きます。本人しか知らない事か、次に畑で確かめられる事を
  - 次に撮ると分かる事が増える物を一つ、`next_to_observe` の行で「次の一枚: …」と書きます。どこを、どう撮るか
  - 英語の記録では「Photo of the day: 」「Question: 」「Next photo: 」です。本人が今日の一枚を選び直した時は、
    本人の行（`note: 今日の一枚: <写真の名>`）が在り、それが先です
- **時期と時刻を、前書きの `date` と `time` から読みます。** 花や穂が出ている時期は、草の種類が分かりやすく、
  実生だけの時期は分かりにくい。分かりにくいときは、上の括り（「セリ科らしい」）で書き、確からしさを下げます
- **撮った場所の偏りを `overall` に書きます。** 座標の広がり（`extent_m`）と写真の集まり方から、畑のどこを歩いて、
  どこが写っていないかを書きます。写っていない所は、`next_to_observe` に入れます
- **一枚だけ座標が離れているとき**（`seed observe` が「ほかの写真から N m 離れています」と言ったとき）は、その写真が
  ほかと同じ場所に見えるかを書き、本人に撮った場所を聞きます。別の場所なら、別の観察に分けます
- **撮った方角。** iPhone などの写真には、撮った方角（EXIF の GPSImgDirection）が入っていることがあります。
  Claude Code で写真の EXIF を読めるときは、どちらを向いて撮ったかを `overall` や `access`、`surroundings` に
  添えます（「西の縁から北を向いて」）。読めないときは、写っている物（家、道、隣の畑）で言います
- **本人の `## Record` の行と並べて読みます。** 本人が `said`「土は固い」と言っていて、写真に固さは写らないとき、
  「固さは写真では分からない。本人の言葉と並べて読む」と書き、次にどう撮れば確かめられるか（棒を刺した深さの
  目盛が写るように）を `next_to_observe` に書きます。本人の言葉を写真で否定も肯定もしません。確かめられる
  ことと、確かめられないことを分けます
- **本人が直した事を先に読みます。** この観察と前の観察の `## Record` には、前の読みへの「それは違う。あれはススキ」
  のような、本人が直した事が入っています。写真より先に読み、写真の読みや前の読みと食い違う所は本人の言葉を取り、
  本人の言葉に拠って書いた行はそう分かる文にします
- **草の名前は、写真だけで決めません。** 見た目が似た物（オギとススキ、ホシアサガオとマメアサガオ）は、`## Data` の
  地形と川の近さ、本人の `## Record` と、本人の手引きの「この畑の草の名前」に当たってから書きます。本人がすでに
  名前を言っている草は、その名前で書き、写真と合わないと思うときだけ `uncertain` にそう書きます。本人の名前を
  「らしい」に戻しません。全部を合わせて見れば決まることを、一枚の見た目で迷ったままにしません
- **写っている物差しを使います。** 標尺（赤白の棒）、長靴、手、道具が写っていれば、高さや大きさの目安にします。
  標尺の赤白の一区切りが何 cm かは、本人に聞くか、`uncertain` に書きます

### 写真のタグ `tags`

写真一枚ごとに、何が写っていて、どんな状態かを短い語で付けます。`tags` の行で、一枚に一行です。

```
- tags: 173445: セイタカアワダチソウ, オギ, 開花, 刈った [0.70]
```

- 形は「<写真の名>: <語>, <語>, …」。写真の名は前書きの `photos` の名（ファイルの名の幹）。語は `, ` か `、` で区切ります
- 植物の名は、分かる物だけ。本人が直した名（`## Record` の `said`、前の観察の判定）と、02 章「この畑の草の名前」が先です。
  分からない時は上の括り（「イネ科」）。名を当てずに「草」とだけ書いてもかまいません
- 状態の語は、この十から選びます: 発芽、育ち、開花、結実、枯れ、刈った、播いた、植えた、収穫、裸地。
  英語の記録では sprouting, growing, flowering, fruiting, withered, cut, sown, planted, harvested, bare。
  これに無い状態は、`plants` や `crops` の行に文で書きます
- 確からしさは、その行の語の中で一番低い物に合わせます
- 本人が「それはオギ」と直したら、ほかの行と同じく、その行に印が付き、直した行を書きます
- タグは、同じ植物を日を追って見るための物です。アプリの「写真」でタグを押すと、その語の写真が日ごとに並びます。
  公開の下書き（成長の記録）が同じ物を選ぶ手掛かりにもなります

### `overall` から `next_to_observe` まで、各キーに書くこと

| key | 書くこと | 書かないこと |
|---|---|---|
| `overall` | 見える全体を一、二文。草の量、作物の有無、写っている範囲 | 良し悪し、これからのやり方 |
| `soil_surface` | 地表が見えるか、裸地、色、湿り。見えなければそう書く | 見えない土の性質 |
| `plants` | 草の種類、高さ、優占。名前は分かる範囲で | 種類を断定すること。分からないときは上の括り |
| `crops` | 作物があれば、何か、段階。無ければ「作物は見えない」 | 収量の予想 |
| `tags` | 写真一枚に一行。写っている植物の名と状態の語（上の「写真のタグ」） | 名の断定。十に無い状態の語 |
| `water` | 溜まり、流れ、乾いた様子。用水と排水の口が見えるか | 水の取り方の勧め |
| `access` | 道。どこから入れるか、通える距離か、機械や手押しの物が入るか。写っている道と入口だけ。候補地で特に | 通える距離の判定（距離は本人が知っている） |
| `sun_slope` | 日当たり、向き、傾斜、周りの木や建物の影。写真の影と地面の傾きから。候補地で特に | 作物に向くかの判定 |
| `surroundings` | 周りの畑や家の状態、獣の痕、ごみ。写っている物だけ。候補地で特に | 近所の人や持ち主についての推測 |
| `change` | 同じ場所の前の観察が渡されたときだけ。前の観察からの変化。本人の `did` と並べて読む | 前の観察が無いのに書くこと。変化の理由の決めつけ（作業が効いたかは畑と本人が見る） |
| `basis` | 何に拠るか。この手引きの章、`sources.md` の資料、前の観察、`place.md` の `data` 行 | 出典の無い言い切り |
| `uncertain` | 写真から分からないこと。確からしさの低い物はここ | 分かったふりの文 |
| `next_to_observe` | 次に何を見るとよいか。どこを、どう撮るか(地面に近く、根元、日を変えて、同じ場所で) | 畑でする作業 |

どの行にも `[0.00]` を付けます。見えていれば高く、見えていなければ低くします。

### 借りる・買うかの材料として

農地を紹介されたら、候補地として観察します（`kind: candidate`、00 始める前）。`access`、`sun_slope`、
`surroundings`、`water`、`plants`（草が語る土。語る内容は、上の「本人が書く」所が埋まるまで、低い確からしさの
仮説）と、`## Data` の筆・地形・ハザード・地質・土壌（02、07、13）を、**材料として並べます**。並べるのは、何が
見えて、何に拠るか、窓口や持ち主に何を聞くとよいか、までです。「借りるべき」「買うべき」「やめたほうがよい」の
判定は書きません。

### 判定を書かない例と、書いてしまった悪い例

次に何を見るか、までを書いた例です。

```
- next_to_observe: 根元の土の色と湿り。一枚、地面に近く撮る [0.70]
```

判定を書いてしまった悪い例です。

```
- next_to_observe: 来週までに刈るべき。刈ったあと耕しなさい [0.90]
```

悪い所は三つです。「刈るべき」「耕しなさい」は畑でする作業の判定で、読みではありません。写真から
分からない「来週」を決めています。確からしさ 0.90 は、写っていないことに付けられません。決めるのは畑です。
見るとよいことを書く形に直します。判定が出てしまったら、書き直します。

読みの例(`basis` に章を書く形):

```
- basis: ススキの優占は刈らない年が続いたことと合う(06 畑を読む)[0.60]
```

これは仮説です。草の種類が土の何を語るかは、上の「本人が書く」所が埋まるまで、手引きは裏付けを
持ちません。このような行は、確からしさを低くし、本人が合う／違うを付けて育てます。

→ りん酸肥料の高騰(読みの背景の数字)は 04 生物。

## 出典

草の種類と土の関係の資料は、まだありません。

## 本人が書く所

- 草の種類と高さが、土の何を語るか(読んだ一次資料と、言っていること)
- 自分の畑の草の名前(地元の呼び名があれば)
