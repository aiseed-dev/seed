# 11 売る

## この章で読むこと

販売を、農協と市場から、記録を見せて繋がって売る側に戻す、という読み方。本人が公開ファイルを作るときに、
どの行をどう見せるか。始める人への支援、農業の保険、申告で読む資料の名と窓口。野菜をそのまま売る時の表示（生鮮食品）。

## 最低限の貨幣

自給農だけでは生活できません。生活には最低限の貨幣が要り、それも本人が自分で稼げるようになる必要が
あります。これは福岡の価格無用論とは同じではありません(01 立ち位置)。隠しません。

貨幣に届く道は三つで、どれも**記録が元手**です。

| 道 | 何を売るか | 記録がどう働くか |
|---|---|---|
| 記録を見せて売る | 畑の物 | 一反の作物は量も形も揃わず、市場には乗りません。買う人に届くのは、どう作ったかの記録です。公開ファイルが説明、一言が店先 |
| 加工して記録ごと売る | 加工した物 | 藍がこの土地でそうだった形です(12 加工)。畑の記録と加工の記録を一緒に渡します |
| 手伝って稼ぐ | 手間と読み | 近所の畑や手続きの書類を、本人が自分の Claude と一緒に読んで手伝います。`next` の札「手伝う」がその入口で、本人の観察と手引きの直し(08)の記録が、そのまま実績になります |

**最初の貨幣は手伝うことです。** 作物が採れる前にできて、ビルダーの訓練(08)がここで貨幣に繋がります。
seed は決済を持ちません。繋がるまでで、その先は本人と相手の話です。

売った、掛かった、手伝って得た貨幣は、本人が記録のフォルダーの `ledger.md` に一行ずつ残します(`seed ledger add`、
月の合計は `seed ledger sum`。`docs/記録の形.md` §16)。公開ファイルには出ません。税の計算は seed にありません。

### 支援、保険、申告で読む資料

本人が「始める人への支援はあるか」「保険は」「申告は」と聞いたときに、制度の名と窓口までを出典付きで答える所です。
どれも、農業を経営として営む人を前提にした制度です。受けられるか、入れるかの判定は書きません。要件（年齢、計画、
面積、申告の形）と、その人の暮らしで決まり、それを見るのは窓口だからです。

| 読むこと | 資料（`sources.md`） | 引く所 |
|---|---|---|
| 始める人への支援 | 30 | 就農準備資金・経営開始資金、青年等就農資金、認定新規就農者制度、雇用就農資金、農業インターンシップなどの名 |
| 相談の窓口 | 31 | 全国新規就農相談センター（全国農業会議所）の、相談の窓口の一覧、研修先、地域の支援情報 |
| 農業の保険 | 32、33 | 農業保険法 1 条の目的。収入保険（青色申告をする人。窓口は各地の NOSAI）と農業共済（NOSAI） |
| 申告 | 34 | 令和 7 年分の青色申告決算書（農業所得用）の書き方。家で食べた分（家事消費）は、収穫した時の生産者販売価額で書く |

- 記録の行: 制度の名と窓口は、`## Data` の `support` の行か返事に、出典と確認日を付けて。窓口で言われたことは本人の `said`、受けた・入った
  ことは `did`、お金は `ledger.md`
- 年ごとに変わる物（34 は令和 7 年分）は、確認日と何年分かを書き、古い年の物を引きません
- 写真と記録から読める所は、ありません。制度に当たるかは記録に出ないからです。`ledger.md` の行（売った、掛かった）は、
  本人が申告の書き方と並べて読む材料です

### 野菜をそのまま売る時の表示（生鮮食品）

採った野菜を加工せずに売る時に、何を表示するかを読む所です。読むのは食品表示基準の生鮮食品の条と、消費者庁の
Q&A 第 3 章です（`sources.md` 55、42）。本人の売り方が表示の要る形に当たるかは書きません。売る場所、袋に入れるか、
誰が売るかで変わり、それを答えるのは表示の窓口だからです。加工した物を売る時は 12 加工。

- 18 条 1 項: 食品関連事業者が一般用の生鮮食品を売る時は、名称（その内容を表す一般的な名称）と原産地を表示する。農産物の
  原産地は、国産品は都道府県名で、市町村名その他一般に知られている地名に代えてよい。除かれるのは、設備を設けて飲食
  させる場合と、容器包装に入れないで、生産した場所で売る場合か、不特定または多数の人に売らずに譲る場合
- 20 条: 容器包装に入れて生産した場所で売る時も、名称（りんご、もも、ばれいしょなど条に挙がる物を除く）と原産地は要しない。
  容器包装に入れないで売る時は、内容量と事業者の名と住所などは要しない
- 22 条 1 項: 容器包装に入れた物は容器包装の見やすい所に（農産物の名称と原産地は、製品に近い掲示でもよい）。容器包装に
  入れない物は、製品に近い掲示その他の見やすい所に
- Q&A 生鮮－1: 「生産した場所で販売する場合」は、生産者が生産した生鮮食品を、自らその場で消費者に売る場合。生鮮－3:
  生産農家でも、消費者向けに直接出荷するなど「業として」売る場合は表示が要る。農協と合意して農協が表示を含めた販売に
  責任を持つなら、農協から出る段階で表示されていればよい。生鮮－14: 「一般に知られている地名」の例（郡名、島名、
  旧国名など）。生鮮－46: 立札などの掲示でよく、壁やボードに全商品の原産地をまとめて書くのも、分かりやすければよい
- 直売所や対面で売る時を名指しした問いは、Q&A 第 3 章にありません。直売所が「生産した場所」に当たるかは、上の生鮮－1 の
  言葉と並べて、表示の窓口で本人が聞きます
- 記録の行: 条文は `## Data` に `law` の行で、条番号と確認日を付けて。窓口で言われたことは本人の `said`、立てた札や貼った表示は `did`
- 写真から読める所: 売り場の札、袋、貼った表示の写り（`overall`、`surroundings`）
- 写真から読めない所: その売り方が 18 条の除かれる場合に当たるか。`uncertain` に、表示の窓口で確かめると添えて書きます

## 読み方

- 売る相手に見せるのは、畑の記録です。何を見て、何をして、AI の読みに本人がどう合う／違うを付けたか。
  合う／違うが付いた行は、付いていない行より、相手に渡せる物です
- 公開は、本人が「この観察を公開したい」と頼んだ時に、次の順でします。公開すると本人の畑と言葉が人に見えるので、
  本人が全文を読んでから送ります
  1. 行の候補(判定の付いた行が先)と、場所の粗さ、一言を本人と決め、下書きを作ります
     (`seed publish <観察> --id … --place … --word … --local`。`public/<id>.md` に書かれ、送られません)。
     公開は成長の記録です。写真は、同じ場所を日を追って撮った物が、日ごとに一枚 `- photo: <名>` の行で入ります。本人が別の写真を頼んだら
     `--photo <写真の名>` で作り直します(何度でも。一日 3 枚、全部で 12 枚まで)
  2. 下書きの写真と全文を本人に見せます。直す所があれば直し、直したらもう一度見せます
  3. 本人が「出す」と言ったら、その下書きをそのまま送ります(`seed publish --file public/<id>.md`)。
     「出す」の前に送りません。本人が読んだ文と、送る文が同じであるためです。写真は縮めて、
     撮った場所などの情報(EXIF)を外して一緒に送られます
- スマートフォンのアプリからも、同じ順で公開できます
- 公開ファイル `public/<id>.md` は、観察ファイルの行をそのまま写します(判定も付いたまま)。
  前書きの鍵は、`id`、`place`、`coord`、`since`、`what`、`next`、`name`、`contact`、`word`、`language`、
  `observations` だけです。ほかの鍵は書きません
- `next` の札は、売る、加工、宿や教室、手続き、貸す、借りる、手伝う、です。土地の持ち主が土地の記録を
  公開して「貸す」を付け、始めたい人が探して一言を送る、という使い方もあります。seed は権利も契約も
  扱いません。繋がった先の会話は Discord です
- 他人の個人情報(土地の所有者の名前・住所など)の入った `said`、`note` の行は、公開ファイルに写しません（13）
- `place` は本人が選んだ粗さ(都道府県、市町村、大字)です。既定は市町村、座標は無しです。座標を付けるなら
  小数二桁(約 1 km)までです
- **公開ファイルに書かない物。** 本名、住所、電話番号、メールアドレス、HTML。`name` は呼び名です。
  写真は `photo` の行で入れます
- `word`(一言)は 200 字までで、入口に並びます。本人の言葉で書いてもらいます。あなたが下書きをするなら、
  本人の言葉を使い、本人が直します
- 値段、売り先、売り方の判定(「この値段で売るべき」)は書きません。値段の根拠になる資料を本人が読んで
  いれば、その資料を出典に付けて話します

売る話は、福岡の価格無用論とは同じではありません(01 立ち位置)。「繋がって売る」は、記録を見せて
人と繋がることです。

### 成長の記録を作る（作者 2026-11-07「ほしいのは成長の記録」）

公開の中心は、成長の記録です。同じ物を、日を追って撮った写真を、古い日から並べます。作物の育ちだけでなく、
畑の移り変わり(草むらに通路ができる、畝ができる、作業の前と後)も成長の記録です。写真を見て選ぶのは
あなたです。手間が掛かっても、写真は全部見ます。

1. `seed photos --by-place` で、撮った場所ごと、日ごとの写真の並びを出します
2. 写真を、Read で一枚ずつ、全部見ます。一日しか撮っていない場所も見ます。場所の組は当てにならない事が
   あります(位置がずれて別の組に入る、同じ組でも寄りと引きや向きが違う)。同じ物かどうかは、写真の中身
   (家、山、電柱、同じ株)で比べます
3. 追う物を一つか二つに絞ります(同じ株、同じ畝、同じ向きの眺め、通路)。その物の移り変わりが分かる写真を、
   日ごとに一枚選びます(多くて一日 3 枚、全部で 12 枚まで)
4. 同じ物が写った写真が無い日は、近い眺めで代えて、そう書きます(下の `change` の行に)。途中でできた物
   (通路など)は、できる前の日の近い眺めを最初に置きます。本人には、どの日を代えたかと、次に撮る時に
   同じ所から同じ向きで撮ると続きが繋がる事を伝えます
5. 下書きを作ります(`seed publish <観察…> --id … --place … --word … --local --photo <名> --photo <名> …`)。
   渡す観察は、選んだ写真が入っている観察です。`what` と `next` は、本人が言わなければ空のままにします。
   `since` は公開する日が入ります
6. 下書き `public/<id>.md` を開いて、整えます
   - 二日目からは、日ごとに、前の日から何が変わって見えるかを一行足します(`- change: <文> [確からしさ]`)。
     写真で見えた事だけを書きます。見えていない事(根、土の中、これからの事)は書きません。最初の日には書きません
   - 言葉の無い日(写真だけの日)は、`## <日>` の見出しと `- photo: <名>` の行を足します。公開の写真の名は、
     手元の道の `photos/` を取り、`/` を `_` に替えた物です(`photos/2026-11-05/142107.jpg` → `2026-11-05_142107.jpg`)
   - 残す行は、写真(`photo`)、変わった事(`change`)、その日にした事(`did`)です。ほかの行(`said`、`note`、
     `data`、草の名の読みなど)は、成長の記録には入れない案として本人に一覧で見せ、本人が残すと言った行だけを
     残します。黙って外しません
7. 写真と全文を本人に見せ、「出す」と言われたら送ります(上の 2、3 と同じ)

### 記録を見せる形: 動画と Web（作者 2026-11-05「販売用のビデオは、Claude がつくれますよね」「販売用の Web も」。11-08 の後の案）

記録を見せて売るとき、見せる形は二つ考えられます。どちらも、**台本と文はあなた（Claude）が公開ファイルから書き、組み立ては seed のコードがし、
絵は本人の写真と出典付きの行**です。あなたが動画や Web を一人で作るのではありません。

- **動画。** `seed origin`（地図と空中写真の一分）と同じ作りで、公開ファイル（本人が了解した行だけ）から場面と字幕を書き、本人の写真、
  `data` の行、計画の絵を並べて一分ほどにします。声は付けず字幕にします（声は本人の物でないから）。動く映像の生成は seed の外（本人が撮った物か、
  本人の機械に置いた画像のモデル）です
- **Web。** 公開ファイルから書き出す静的サイト（記録のページ）に、「今あるもの（作物、種のロット、加工品）、渡せる時期と量、受け取り方」の欄と
  「一言を送る」を足した物です。決済と注文の仕組みは seed に無く、支払いと受け渡しは本人が選ぶ場所（対面、既にある販売の場）で、ページには
  その案内だけ書きます
- どちらも、**記録に無いことは書きません。** 「無農薬」「安全」「おいしい」のような売り文句は、記録の行（本人の `did`、`saw`、合う／違う）と
  出典に無ければ書きません。買い手が見るのは記録で、動画と Web はその入口です。公開は、本人が全文を読んで「出す」と言った物だけを送ります
