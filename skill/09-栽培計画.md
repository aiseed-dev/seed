# 09 栽培計画

## この章で読むこと

借りる・買うことができた畑で、写真を撮ってから、栽培計画 `plan.md` を立てること。seed の立ち位置は、
菌根菌を活かす自然農法から始めることです。立ち位置と、その畑の案は別の物です。立ち位置はどの畑にも同じで、案は、その畑の土と水と本人の暮らしで変わるからです。

計画の数字（収量、単価、経費、労働時間）は、この章では書きません。作者の別の手引き aiai の
`nouka-keikaku`（`nougyou/keikaku/` の `SKILL.md` と `keikaku.py`）が、本人から根拠を聞いて表にして計算します。

## 最初に伝えること

計画を始める前に、次の二つを本人に伝えます。どちらも `sources.md` の物です。

**一、seed の立ち位置**（りん酸肥料の高騰と、菌根菌を活かす自然農法から始める理由、その出典）→ 04 生物

自給農では、川口由一の自然農（草を刈って、その場に敷く）を選ぶのもあり、と作者は言います（2026-11-03。01 の
「福岡と川口」）。刈って敷く手にも効果があります。`ground` と `cover` では、福岡の形と川口の形を、並ぶ選択肢として
出します。どちらを選ぶかは本人で、あなたは順位を付けません。

**二、難しいこと。** 立ち位置を勧めるときは、難しいことを同じ重さで伝えます。aiai の
`nougyou/keikaku/README.md`（`sources.md` 8）の「分かっていることと、分かっていないこと」「いいこと」
「難しいこと」を読んで、その順に伝えます。難しいことを軽く言いません。その README に無いことは、言いません。

## 守ること

- **立ち位置は出発点で、前提ではありません。** 「耕さない、肥料をやらない」を、その畑の計画の前提として
  黙って置きません。畑の現実（元田んぼの硬盤層、排水、土性）が先で、立ち位置がそれにどう会うかを、本人と
  議論できる形で書きます。本人が「それは前提でない」と言ったら、前提を外して案を並べ直します
- **移行は一度には起きません。** 工業的農業（耕起、施肥、単作、農薬）から、菌根菌を活かす自然農法へは、すぐに
  移れる物ではありません。何年もかけた段階です。一年目に機械で硬盤層を一度壊すこと、始めの年に何かを入れることは、
  立ち位置に背くことではなく、移行の段階として `ground` と `no_input` に書きます。「今年はここまで、来年はここから」を
  本人が決められるよう、段階を分けて案を書きます。始めたばかりの畑は収量が低く不安定です（`sources.md` 8 の
  「難しいこと」）。それを隠して、一年目から立ち位置の全部を求めません
- **立ち位置と判定を分けます。** 立ち位置は手引きが書きます。あなたは、畑ごとの判定を書きません。
  `plan.md` の行は、案として書き、確からしさを付けます。「〜すべき」「〜しなさい」にしません
- **本人の作り方を聞きます。** 「自然農法」の中身は人によって違います。耕すか、何を土に入れるかを、
  本人の言葉で聞きます。あなたの知っている定義を当てはめません。本人が別の作り方を選んだら、その作り方で
  書き、立ち位置と違うと責めません
- **数字を書きません。** 収量、単価、経費、労働時間は、aiai の `nouka-keikaku` に任せます。seed の
  `plan.md` に数字を書くなら、本人が言った数字を `## Record` に写すだけです
- **日本の公の研究データは、前提を添えて読みます。** 農研機構、農水省、都道府県の指針などのデータは、
  工業的農業（施肥、耕起、単作、農薬）を前提に取られています。無施肥・不耕起・混植の畑に、そのまま当てはまる
  とは限りません。`## Data` の行に使うときは、その前提を一行添えます。**施肥基準や目安の値を、その畑の
  目標にしません**
- 混植の案を作らないこと → 04 生物
- **入れない物の理由は、出典を付けます。** `no_input` に書く物（りん酸肥料、家畜ふん堆肥、油かすなど）の
  理由は、`sources.md` 8 の README が引く出典に拠ります。出典を言えないことは、書きません
- 土の状態は、観察と、本人が渡した土壌診断の値だけを根拠にします。診断の値は `## Data` に、診断した
  機関の名前と日を出典に付けて写します

→ 元田んぼの硬盤層（`ground` の案を並べる所）は 02 地質と土。

## 手順

1. **本人の作り方を聞く。** どこで、誰から、何年学んだか。これから、耕すか、何を土に入れるか
2. **写真を撮ってもらう。** 借りる・買うことができた畑を、観察する（06 畑を読む）。栽培計画は、その
   観察の後に立てます。観察が無いときは、先に観察をしようと伝えます
3. **立ち位置と難しいことを伝える。** 上の「最初に伝えること」の一（04 生物）と二
4. **`plan.md` の案を書く。** 形は下。観察の `basis` と、`## Data`、前の観察の `change` を材料にします
5. **本人が決める。** 本人が決めたことは、本人が `## Record` の `decided` に書く。あなたは、決めた事を
   写すだけで、決めません
6. **作業して、観察を続ける。** したことは `did`。同じ場所を撮り続け、`change` と並べて、計画が合って
   いたかを、本人が畑で確かめる（13、08）。計画を直すときは、同じ形で、新しい `plan.md` の行を書く

## `plan.md` の形

```yaml
---
since: '2026-11-20'              # 計画を書き始めた日
season: '2026-27 冬'             # 本人の言葉で
language: ja
model: claude-code
---
## Plan (claude-code)
- ground: 地面の支度。硬盤層、排水、耕すかどうか。案と、それに要る物（機械、人、貨幣）と、確かめること。一行に一案 [0.50]
- sow: 何を、どこに、いつ。一行に一つ [0.70]
- host: 菌根菌の宿主になる作物や緑肥 [0.60]
- cover: 地面を覆う物。刈った草をそのまま、など。刈って敷くことは、畑の中の物で養分を補給すること（01 の川口） [0.70]
- no_input: 入れない物と、その理由の出典 [0.80]
- basis: 何に拠るか。観察の日、資料の番号、手引きの章 [0.60]
- uncertain: 分からないこと。混植の案は、資料が無いので書いていない [0.40]
- next_to_observe: 計画を確かめるために、次に何を見るか [0.60]

## Data
(none)

## Record
- decided: 本人が決めたこと
- did: 実際にしたこと
```

- `## Plan` のキーの順は `ground`、`sow`、`host`、`mix`、`cover`、`no_input`、`basis`、`uncertain`、`next_to_observe`。
  `ground` は、播く前の地面の話（02 地質と土 の「元田んぼの硬盤層」）。案を並べ、要る物を添える。決めない。
  `mix` は、混植の資料が `sources.md` に入るまで書きません（04 生物）
- 行の形、確からしさ、`(none)`、本人の言葉は、観察ファイルと同じです（`SKILL.md`）。`## Data` は出典付きの行、
  `## Record` は本人の言葉で、確からしさは付けません
- `host`、`cover` に書く作物や緑肥の名前は、aiai の README（`sources.md` 8）にある物だけです。README を
  読めないときは、名前を挙げず、本人に調べてもらいます
- `season` と `since` は、本人の言葉と日です。`decided`、`did` は、本人が言ったことをそのまま写します。
  `plan.md` の `## Record` の key は `decided` と `did` の二つです（`docs/記録の形.md` §10）。まだ決めていない希望は、
  観察の `## Record` の `said` に写します
- `## Plan` の行は、`uncertain` と `next_to_observe` も含めて、すべて確からしさで終わります
- 観察が無いときは、先に観察をしようと伝え、案は最小限にして確からしさを低くします。案を書かず、
  `uncertain` に理由を書くだけでもかまいません

## 計画の絵（仮説）`grow/`

本人が頼んだら、`plan.md` の `## Plan` の行から、この畑が季節ごとにどう見えるはずかの場面を書きます。
あなたが書くのはシナリオ（JSON）だけで、図は seed が決まった語彙で線に描きます（`seed grow`）。
絵は仮説です。本人の写真でも判定でもありません。`seed publish` では送りません。時期が来たら、本人が同じ所を撮って並べ、合う／違うを付けます。

**どこに書くか。** `grow/<今日の日>/scenario.json`。書いたら、本人に `seed grow --render grow/<日>/scenario.json` を走らせてもらいます
（あなたが走らせてもかまいません）。seed が検証して、`grow/<日>/` に場面ごとの図（SVG）と `captions.md` を書きます。

**形。**

```json
{
  "language": "ja",
  "scenes": [
    {
      "when": "2026-12",
      "title": "刈った筋に播いて一か月",
      "from": [
        {"key": "sow", "text": "地面の支度を決めてから。刈った筋に、冬は ライムギかエンバク"},
        {"key": "cover", "text": "刈って敷くことは、畑の中の物で養分を補給すること"}
      ],
      "see": ["刈った筋に二列の芽。高さ 5 cm ほど", "筋の間は刈った草の茎がそのまま", "刈っていない所はオギが立ったまま"],
      "unsure": "芽が出るかは、播く時期と霜で変わる",
      "confidence": 0.45,
      "top": {
        "strips": [
          {"state": "uncut", "label": "刈っていない", "grass": {"name": "オギ", "height_cm": 200}, "width": 2},
          {"state": "sown", "label": "刈った筋", "crop": "ライムギ", "rows": 2, "width": 1},
          {"state": "cut", "label": "刈った筋（播かない半分）", "width": 1}
        ],
        "marks": [{"kind": "pool", "label": "雨の後に水が溜まるか"}, {"kind": "hole", "label": "穴 30 cm"}]
      },
      "side": {
        "hard_layer_cm": [20, null],
        "mulch": {"label": "刈った草を敷く", "thickness_cm": 5},
        "ridge_cm": null,
        "roots": [{"name": "ライムギ", "depth_cm": 15}, {"name": "オギ", "depth_cm": 18}],
        "holes_cm": 30
      },
      "prompt": "Soft watercolor illustration on textured paper, muted colors, a small field in early winter seen from a low angle above. Follow the left-to-right layout of the strips in the reference diagram. On the left half, a wide strip of tall standing reed-like grass, uncut. Right of it, one strip of cut ground with two straight rows of young rye seedlings, and at the far right one strip of cut ground with nothing sown. Cut grass stems lie flat between the rows. Nothing else in the field. No text, no labels, no people, no buildings, no fences, no tools, no machinery.",
      "negative": "photograph, photorealistic, text, letters, people, buildings, fence, tractor"
    }
  ]
}
```

- `when` は年-月。場面は最大 6 で、時期の順に並べます
- `from` に、元になる `## Plan` の行を挙げます。`key` はその行の key、`text` は行の先頭をそのまま 30 字以上写します（空白の違いは
  seed が詰めて比べます）。どの行にも対応しない場面は、seed が落とします
- `top` は上から見た図です。畑を一つの長方形とし、左から右へ筋（`strips`）を並べます。`state` は `uncut`（刈っていない）、`cut`（刈った）、
  `sown`（播いた。`rows` は列の数）、`ridge`（畝）、`bare`（裸地）の五つだけです。`width` は筋の幅の比です。`marks` の `kind` は
  `pool`（水が溜まる所）、`hole`（穴）、`probe`（棒を押す所）の三つだけです
- `side` は横から見た土の断面です。`hard_layer_cm` は固い層の上端と下端で、下端が分からなければ `null`。深さは、計画の行と本人の
  Record にある数字だけを使います（棒が入った深さ、掘った穴）。推測の深さを書きません。分からなければ `hard_layer_cm` を `null` にします
- `crop`、`grass.name`、`roots[].name` の語は、`from` に挙げた行の文に出てくる語をそのまま使います。**計画に無い作物、肥料、構造物を
  出しません。** 行に無い語は、seed がその要素だけ落とします
- `see` は見えるはずの物を、本人の言葉で 3〜5 行。草の高さ、芽、刈り跡、畝、水。`unsure` は分からないことを一行
- `confidence` は、`from` の行の確からしさの最小値を超えません（超えていれば seed が下げます）
- **実在の地名・座標・人の名を書きません。** seed はこれを確かめられません。あなたが書かないことだけが頼りです
- 判定の行（〜すべき、〜しなさい）は書きません。本人が「違う」を付けた行は、場面にしません（seed も確かめ、そういう行から書いた場面を落とします）

seed が落とした場面と要素、下げた確からしさは、`captions.md` の「省いた場面・省いた要素」と「直した所」に理由と一緒に出ます。
それを読んで、シナリオを直して描き直してかまいません。

### 絵の指示 `prompt`（`seed grow --draw`）

本人が、画像を作るモデルを置いた自分の機械で絵にしたいときのために、場面ごとに `prompt` を書きます。seed は文から prompt を作りません。`prompt` の無い場面は描かれず、
`captions.md` に理由が出ます。絵を描くのは、`seed.toml` の `[grow]` の `server` に書いた画像生成のサーバーで、seed の図（SVG を PNG にした物）と、本人が選べば本人の写真が参照に付きます。

- 英語の一段落。最初に様式を書きます（`Soft watercolor illustration on textured paper`、`pen and ink line drawing with light wash` など）。**写真に見せません**
- 中身は、その場面の `see`、`top`、`side` にある物だけ。上から見た筋の**左右の並び**を文でも言います（「On the left half, …; on the right, …」）。図の左から右の順と同じにします
- **計画に無い作物、構造物（柵、小屋、ハウス、道具、機械）を書きません。** 見えるはずの物に無い季節の姿（穂、花、実）も書きません
- 最後に `Nothing else in the field. No text, no labels, no people, no buildings, no fences, no tools, no machinery.` を入れます
- 実在の地名・座標・人を入れません。seed は座標らしい数（小数 4 桁以上）のある prompt を落とします
- `negative`（任意、英語）は、絵のサーバーの設定によっては効きません。書くなら `photograph, photorealistic, text, letters, people, buildings`

### 絵をシナリオと照らす（「Claude の照らし」）

`seed grow --draw` の後、描かれた絵を一枚ずつ見て、場面に無い物が入っていないかを `grow/<日>/captions.md` の節「Claude の照らし」に書きます。
この PC の claude があれば seed が聞いて書きます。無ければ、Claude Code で開いたあなたが Read で絵を見て書きます。

- 一場面一行: `- 01 2026-12（誰が）: none`。入っていれば、計画に無い作物、構造物、人、文字を挙げます（`crop: …; structure: …`）
- 「誰が」には、あなたが何か（例「Claude（Opus、Claude Code）」）を書きます
- 場面と合わない所（列の数、穴の位置、畝の形、季節の姿）も、見えたら同じ行に書きます。上と下の白い帯（印、時期、題、何で描いたか）は seed が焼いた物で、挙げません
- 合わない物が多ければ、本人に伝えて、prompt を直して描き直すか、その絵を使わないかを本人が選びます
