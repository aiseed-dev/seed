## 3. プロジェクト概要

このプロジェクトは、耕作放棄地で自然農法をはじめる人の「教えてくれる人が少ない」という課題を、写真を撮って Claude と話しながら畑を読み、畑そのものから学べるように変える試みです。

AI で人の仕事は無くなるのか。その答えを、徳島の耕作放棄地で Claude と一緒に確かめています。

今までの IT は、決まった欄に入る物だけを記録にしてきました。土も草も水も一枚ずつ違う畑は、欄に入りません。システムは業者に任せ、畑も肥料と種を買って言われた通りに作りました。そうすると経験と知識は、残りません。

福岡正信は、麦は話を聞こうとする人にだけ語る、と書きました（『無 III』p.426）。seed には入力欄がなく、写真と言葉で畑に聞きます。Claude が「ススキらしい」と読んだ白い穂を、私は「オギ」と直しました。その直しも記録に残ります。

畑の知識は地質から農地の手続きまで広いので、画面の代わりに手引き（Skill）を育てました。一週間で 11 組、引く資料は 470 余りです。機能も手引きも自分で話して足すので、経験は手元に残ります。一週間で全部は出来ません。

## 7. 開発中に一番詰まった場面

**何を作ろうとしていましたか？**
Claude が、畑の記録のアプリで、記録の一部を人に見せる「公開」の画面と、サーバーの管理画面を作っていました（11-06 の夜）。

**Claude にどのように指示しましたか？**
指示はしませんでした。画面をどんな形にするかは何も言わず、Claude に任せていました。

**何が起きましたか？期待していた結果と何が違いましたか？**
Claude は、機能を足すたびに、欄とチェックとボタンの並ぶ画面を作っていきました。公開の画面は、観察を選ぶ、行にチェックを付ける、粗さを選ぶ、一言を書く、送る、の五つの操作になりました。期待していたのは逆の向きです。畑の物は形がばらばらで欄に入りません。Claude に話せば済む事なら、画面は要りません。私が見て「全部の画面がこれまでの作り方」と言いました。

**どのように対処しましたか？**
私が形を言葉で言い直しました。フォームは全部なくす、Claude Code のようにチャットの形にする、です。Claude はその夜のうちに、アプリを全部作り直しました。画面は「話す」と「写真」の二つで、文字を打つ所は下の一行だけです。公開は、Claude が下書きして、本人が「出す」と言った物だけを送る形にしました。Claude はこの決まりを基本計画と自分の記憶に書き、新しい機能を頼まれたら、先に「Claude に頼めば済むか」を考える順にしました。翌日、機能を足す手引き（skill-builder）の最初の歩にも入れました。

## 10. Claude を使った感想と改善してほしい点

**日本語や日本の業務で使う立場から気づいた欠点と利点**
欠点: Claude は、来た人に向ける文に、設計書の固い言い回しをそのまま写します。自分で作った縮めた言い方（「出る向きの手」など）で私に問い返し、何の事か分からない事がありました。端末のスマートフォンを「電話」と書きます。
利点: 決まりを手引き（Skill）と記憶に一度書くと、Claude は次の会話からはその通りに書きます。法令や国の地図・土壌図のような日本語の一次資料を読み、出典と日付を付けて書けます。コミットの題と本文、設計書、手引きを、一週間すべて日本語で通せました。

**一つだけ直せるとしたら何を直してほしいか、その改善で何が作れるようになるか**
動画を直接読めるようにしてほしいです。今の seed は、スマートフォンで撮った動画を PC に送って残すだけで、読みには使えません。動画が読めれば、畑を歩きながら撮った一本（風に揺れる草、虫や鳥の動き、水の流れ）がそのまま記録になります。「写真や動画を撮って Claude と話す」が、そのまま成り立ちます。
