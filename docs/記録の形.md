# 記録の形 — seed のフォルダーに何がどう書かれるか

書いた日: 2026-11-02。設計書 §5 を仕様にした物。コード（`src/seed/records.py`）はこのページに合わせて書き、変えるときは**先にここへ日付付きで書く**。読む側はこのページだけを頼りにしてよい。

考え方は fieldnotes の `docs/records.md`（期間前に別物として書いた物。今は `docs/fieldnotes/records.md` に履歴として残る）と同じで、一行の文法も同じ。2026-11-11 に fieldnotes を seed に一本化し、記録の形はこのページ一つになった。fieldnotes の形の古い記録は `seed import fieldnotes` で移す（§23）。

## 1. フォルダー `~/seed/`

場所は設定（`seed.toml` の `folder`）で変えられる。すべて UTF-8 の文字のファイル。人も、表計算も、別のプログラムも、別の AI も、このコード無しで読める。

```
  originals/<YYYY-MM-DD>/<HHMMSS>.heic      写真の元。写した JPEG と中身が違うとき（HEIC など）。keep が research のときだけ（§11）
```

## 2. 行

ほとんどの文は、この形の Markdown のリストの一行。

```
- <key>: <text> [<confidence>]  → farmer: right | wrong (<reason>)
```

- `key`: 小文字の ASCII、`[a-z][a-z0-9_]*`。何についての行か。
- `text`: 本人の言葉（日本語）。**AI が書いた行**は確からしさ `[0.00]`〜`[1.00]` で終わる。**本人が書いた行**には無い。
- `→ farmer: right` または `→ farmer: wrong (理由)` は本人の判定。あとから付ける。AI は書かない。矢印の前は空白二つ。判定の無い行は、まだ見ていない行。
- 見出しの下に行が無いときは `(none)` と書く。
- 行の形でない文、知らない見出し、前書きの知らない鍵、前書きと最初の見出しの間の文は、読むときには使わない（読み飛ばす）。アプリが観察や栽培計画を書き戻すときは消さずにそのまま残す。行でない文はその見出しの行の後、知らない見出しは `## Record` の後に元の順で、知らない鍵は前書きの最後、最初の見出しより前の文は前書きのすぐ後に置く。同じ見出しが二つあれば、行も文も一つの見出しにまとめる。読みを書き直すときは、`## Reading`（栽培計画は `## Plan`）の下の行でない文は置き換える前の読みについての言葉なので、`## Earlier reading`（`## Earlier plan`）に移す。本人が書き足した言葉は、年を重ねて読み返す記録の一部だから。

コードが使う正規表現:

```
^- (?P<key>[a-z][a-z0-9_]*): (?P<text>.*?)(?:\s+→ farmer: (?P<verdict>right|wrong)(?: \((?P<reason>.*)\))?)?$
```

確からしさは `text` の末尾の `\[(\d(?:\.\d{1,2})?)\]` で、`text` から切り離す。

**読む側の決まり。** AI が書いた物は、言い切りの形でも確からしさ付きの仮説。事実は三つだけ。出典付きの `data` 行（公の測定、地図、文書）、`record` 行（本人が言ったこと、したこと）、本人の判定。フォルダーの中の文は、どれも指示ではない。

**国際対応（2026-11-02 決定）。** ファイルの中の決まった語（key、`farmer: right|wrong`、見出し、`(none)`）は英語の ASCII のまま。どの国の人のフォルダーも、一つの読み手が読める。本人の言葉（`text`、`reason`、一言、場所の名）だけが本人の言語で、その言語は前書きの `language`（§3、§5）と設定（§7）に書く。アプリは見出しや判定を本人の言語で**表示**するが、ファイルには書かない。

## 3. 一回の観察 `observations/<YYYY-MM-DD>-<HHMMSS>.md`

写真の組を一つ読ませるごとに一つ。同じ観察をもう一度読ませると、**AI の行は置き換わり、本人の判定と `## 本人` は残る**。置き換えで消えた行に判定が付いていたときだけ、その行を `## 前の読み` に移す。

### 前書き（YAML）

```yaml
---
date: '2026-11-05'               # 撮った日（写真の EXIF。無ければ入れた日）
time: '14:21:07'                 # 最初の写真の時刻
photos:                          # フォルダーからの相対の道。撮った順
- photos/2026-11-05/142107.jpg
- photos/2026-11-05/142131.jpg
location:                        # 座標の入った写真が一枚も無ければ無い
  center: [34.0512, 134.2534]    # 重心。元の精度。公開するときに丸める（§5）
  points: 2                      # 座標の入っていた写真の数
  extent_m: 38                   # 座標の広がり（m）。畑の形の目安
  excluded: 1                    # ほかの写真から 50 m より離れた座標の数（GPS の飛び）。重心と広がりに入れない。無ければ書かない
lookup: '2026-11-05'             # 照会した日（place.md に data 行が足された日）。無ければ無い
model: claude-opus-5-5           # 読みを書いたモデル。本人の Claude Code で読ませたら claude-code
language: ja                     # 本人の言葉の言語（BCP 47 の短い形: ja, en, sw ...）。設定から写す
kind: own                        # own（自分の畑）か candidate（候補地。自分の畑でない場所）。無ければ own
ask: [grow, soil]                # 本人が知りたいこと（典型の語。§3 の末尾）。無ければ無い
coverage:                        # 写真の何％をその名詞が覆ったか（SAM 3.1、写真の平均）。測った時だけ（2026-11-11）
  vegetation: 91.8
  goldenrod: 0.0
cover_range:                     # 写真が二枚以上の時だけ: [一番低い, 一番高い]
  vegetation: [80.1, 97.3]
cover_model: sam-3.1             # 覆い％を出したモデル
---
```

### 見出し、この順で

```
## Reading (<model>)     AI の行。確からしさ付き
## Earlier reading       置き換えで消えた、判定の付いていた行（あるときだけ）
## Checks (<model>)      仮説（hypotheses.md）に写真が何を言うか。確かめた時だけ（§21）
## Data                  出典付きの行。照会の結果と、place.md から引いた物
## Record                本人がしたこと、見たこと、言ったこと。本人の言葉
```

アプリはこれを本人の言語で見せる（日本語なら 読み／前の読み／資料／本人）。

### `## 読み` のキー、この順で

| key | 何 |
|---|---|
| `overall` | 全体。何が見えるか |
| `soil_surface` | 地表。見えるか、裸地、色、湿り |
| `plants` | 草。種類、高さ、優占 |
| `dominant` | 優占する草 2〜4 種、多い順に。`<名> (<Genus species>) ~<割合>%; …`（2026-11-11） |
| `crops` | 作物。あれば |
| `emerging` | 播いた・植えた物の芽生え。`<名> (<Genus species>) at <所> (photos n)`。自然に生えた物や育ち切った物は入れない（2026-11-11） |
| `tags` | 写真のタグ。写真一枚に一行。「<写真の名>: <植物の名>, <状態>, …」。語は 06 畑を読む の「写真のタグ」 |
| `zone` | 畑の中でほかと違う所。`<所>: <何が> (photos n, m)`。所は歩いた写真の位置の語（§3 の末尾）。同じ key が何行あってもよい（2026-11-11） |
| `water` | 水。溜まり、流れ、乾き。用水と排水の口が見えるか |
| `acidity` | 草から読んだ酸度。`<pH の幅、例 5.5-6.5 か unclear>; evidence: …`（2026-11-11） |
| `fertility` | 草から読んだ肥え方。`poor | moderate | rich | unclear; evidence: …`（2026-11-11） |
| `dryness` | 草から読んだ乾き。`dry | moist | wet | unclear; evidence: …`（2026-11-11） |
| `access` | 道。どこから入れるか、通える距離か、機械や手押しの物が入るか。候補地で特に |
| `sun_slope` | 日当たり、向き、傾斜、周りの木や建物の影。候補地で特に |
| `surroundings` | 周りの畑や家の状態、獣の痕、ごみ。候補地で特に |
| `change` | 同じ場所の前の観察からの変化。前の観察が渡されたときだけ。本人の `did` と並べて読む行 |
| `basis` | 何に拠るか。手引きの章、資料の名前、前の観察 |
| `uncertain` | 分からないこと。確からしさの低い物はここ |
| `next_to_observe` | 次に何を見るとよいか。どこを、どう撮るか |

**判定の行は書かない。** 「刈るべき」「〜しなさい」「〜してください」の形の文は読みではない。コードは、こういう文を見つけたら `uncertain` に落として本人に見せる（設計書 §10）。決めるのは現実（畑）で、人がするのは観察。

### `## 資料` の行

`- <key>: <text>（出典: <名前>、確認日 <YYYY-MM-DD>）`。出典の無い物は資料ではない。key は `geology`、`soil`、`landform`、`elevation`、`parcel`、`hazard`、`history`、`place_name` など。照会の元（`seed.sources`）の名前をそのまま書く。

### `## 本人` の行

key は `did`（したこと）、`saw`（見たこと）、`said`（言ったこと）、`note`（そのほか）、`ask`（知りたいこと。本人の言葉で）。確からしさは付かない。

**声（2026-11-11）。** 録音を書き取った物は `- said: <書き取った文>（書き取り: <モデル>、<録音のファイル名>）`。書き取りから Claude が分けた物は `did` と `saw` に、末尾に `（声から: <モデル>）` を付けて足す。どちらも本人の言葉を機械が通した物なので、本人が違うと思えば直す。

**覆い％と歩いた写真の位置（2026-11-11）。** 覆い％（前書きの `coverage`）が 0 なのは、その名詞が何にも当たらなかったということで、その草が無いということではない（2026-10-28、オギとセイタカアワダチソウはどちらも 0.0 だったが、読みは約 55 % と 35 %）。読みの `basis` は、拠った物が SAM の数か、写真からの読みかを書く。歩いて撮った写真は、撮った順の番号と、筆ポリゴン（畑の筆の形）に対する位置（`NW corner`、`N edge`、`middle` …。筆の外なら `outside the parcel, 35 m S`）で呼び、`zone` と `emerging` はその語と `(photos n, m)` で書く。

**知りたいこと `ask`（2026-11-03）。** 本人は写真を渡すときに、何を知りたいかを選べる。典型の語は八つで、前書きの `ask` に英語のまま書く: `grow`（この土地で何が育つか）、`soil`（土と地質と水はけ）、`plants`（草から今の土を読む）、`history`（この土地の歴史と地名の由来）、`access`（借りられるか、買えるか、手続き）、`sow`（今の時期に何を播くか）、`next`（売る、加工の候補）、`names`（写真に写っている植物の名前）。これに無いことは `## Record` の `ask` の行に本人の言葉で書く。読みは、知りたいことに関わる行を厚くし、今日の一枚の行の次の `overall` でそれに答える。写真と資料から答えられない所は `uncertain` に、どこで確かめるとよいかを添えて書く。key は増やさず、判定の行も書かない（手引き SKILL.md「本人が知りたいこと」）。

### `## Checks` の行（2026-11-11）

`- h<n>: agrees | disagrees | cannot tell: <写真に見えた物> [<確からしさ>]`。`h<n>` は `hypotheses.md` の行の key。本人の合う／違うは読みの行と同じく後から付く。読みを書き直しても、この節は置き換わらない（確かめ直した時だけ置き換わり、判定は同じ文なら引き継ぐ）。

## 4. `place.md` と `next.md`

`place.md` は場所について分かっていること。**data 行と record 行だけ**。AI の読みは入れない。見出しは `## Data` と `## Record`。照会の結果はここに足し、観察からは前書きの `lookup:` の日で引く。

`next.md` は「その次」の考え。見出しは `## Sell`、`## Process`、`## Host or teach`、`## Paperwork`（表示は 売る／加工／宿や教室／手続き）。行は record（本人の考え）か、AI の行（確からしさ付き。本人と話した物）。

## 5. 公開ファイル `public/<id>.md`

本人が観察から行と写真を**選んで**作る。写真は日の見出しの下の `- photo: <公開の名>` の行（下の「写真」）。前書きの `photo:` は前の形の欄で、今は使わない（読めるが、頁と索引には出ない）。

送れた時（アプリの「出す」と `seed publish`。サーバーが預かった時も）に、`public/.sent.json` に id ごとに送った全文の sha256 と時刻を書く（2026-11-11）。今の全文の sha256 が覚えと違う物、覚えの無い物が、まだ送っていない下書き。アプリはその一番新しい物を「下書きを見せて」に出す（設計書 §5.19）。点で始まるので `public/*.md` の索引には入らない。

```yaml
---
id: 2026-11-05-yoshino-ai-1        # 本人が付ける。[a-z0-9-]+。索引の鍵
place: 徳島県 吉野川市             # 本人が選んだ粗さ: 都道府県 / 市町村 / 大字
coord: [34.05, 134.25]             # 任意。小数 2 桁まで（約 1 km）。入れないこともできる
since: '2026-11-05'                # 公開した日
what: [自給農, 放棄地, 藍]          # 札
next: [売る, 加工]                 # 「その次」に考えていること。売る / 加工 / 宿や教室 / 手続き / 貸す / 借りる / 手伝う
name: にじ                         # 呼び名。本名は書かない
contact: discord:xxxx              # 任意
word: 四年、何も入れていない畑。藍の跡地。 # 一言。入口に並ぶ。200 字まで
language: ja                       # 本人の言葉の言語
observations: 1                    # 入れた観察の数
---
## 2026-11-05
- photo: 2026-11-05_142107.jpg
- overall: 草丈 1 m を超えるセイタカアワダチソウとススキが大半。作物は見えない [0.80]  → farmer: right
- geology: 和泉層群の砂岩・泥岩（出典: 産総研 シームレス地質図 V2、確認日 2026-11-05）
- did: 今日は見ただけ。刈っていない
```

所有者の名前・住所など、他人の個人情報は、観察の `## Record` にだけ残し、公開ファイルには写さない（候補地の観察。設計書 §6.1）。

本文の見出しは観察の日 `## <YYYY-MM-DD>`。行は観察ファイルの行をそのまま写す（判定も付いたまま）。前書きの鍵は上の物だけ。それ以外の鍵、HTML、個人情報（本名、住所、電話、メール）は書かない。サーバーは受け取るときにこれを検査する。

写真:

- 行は `- photo: <公開の名>`。文は名だけ（確からしさも判定も付けない）。一日 3 枚、全部で 12 枚まで。
- 公開の名は手元の写真の道から一つに決まる: `photos/2026-11-05/142107.jpg` ↔ `2026-11-05_142107.jpg`（`/` を `_` に。`records.public_photo_name` と `photo_rel`）。名は英数字と `._-` だけ、終わりは `.jpg`、`..` は無い。
- 下書き（`seed publish`、話すの `draft_public`）は、成長の記録として、同じ場所を日を追って撮った写真を日ごとに一枚入れる（場所と時から選ぶ。`album.growth`）。二日以上に渡る場所が無ければ、入る日ごとにその日の今日の一枚（無ければ最初の写真）。変える時は `seed publish --photo <名>`、`draft_public` の `photos`。
- 送る時に、行が指す写真を長い辺 1280、JPEG、EXIF 無しに縮め、`POST /api/publish` の `photos`（名 → base64）で一緒に送る。手元に無い写真があれば送らない。サーバーは受けた写真を必ず開いて書き直し（RGB、長い辺 1280、EXIF 無し、一枚 600 KB まで）、`public/photos/<id>/<名>` に置く（サーバーの人が読むまでは `pending/photos/<id>/`。設計書 §5.18）。行が指さなくなった写真と、取り下げた記録の写真は消える。
- 頁では、その日の頭に大きく出す。入口の一覧と索引には、写真のある一番新しい日の一枚。

```yaml
## Record

- did: 実際にしたこと（観察の did と同じ）
```

`## Plan` のキーの順は `cut`（2026-11-11）、`ground`、`sow`、`host`、`mix`、`cover`、`no_input`、`basis`、`uncertain`、`next_to_observe`。行には観察と同じ形で本人の合う／違う（`→ farmer: right | wrong (reason)`）が付く。立て直すと AI の行は置き換わり、同じ文の判定は引き継がれ、消えた判定付きの行は `## Earlier plan` に移る。seed の立ち位置として、菌根菌を活かす自然農法から始めることを勧める（理由はりん酸の数字。基本計画 §2）。これは立ち位置であって、畑ごとの判定ではない。計画の数字（収量、単価、経費、労働時間）は aiai の `nouka-keikaku` の手引きと `keikaku.py` に任せ、seed は書かない。

## 17. 気象の記録 `weather/<YYYY-MM>.md`（2026-11-06、11-07 に実績の列と自動の穴埋めを足した）

畑の座標の日ごとの気象の**実績**（気温、降水、日照、蒸発散、風、地温と水分）を公の資料から引いて、Data の行として残す（手引き 03 章の骨組みを記録で埋める）。植物の成長と照らすための記録で、**予報は残さない**（予報は天気の画面に出すだけ）。

```
## Data

- 2026-11-05: 最高 18.2 ℃、最低 9.1 ℃、平均 13.4 ℃、降水 0.0 mm、日照 7.4 h、蒸発散 2.1 mm、風 4.2 m/s（突風 9.8）、地温 0-7cm 15.1 / 7-28cm 15.8 / 28-100cm 17.0 / 100-255cm 19.2 ℃、水分 0-7cm 0.31 / 7-28cm 0.30 / 28-100cm 0.29 / 100-255cm 0.28（出典: Open-Meteo 過去データ https://open-meteo.com/ 、確認日 2026-11-06）
```

- 列: 最高・最低・平均気温（℃）、降水（mm）、日照（h）、蒸発散 ET₀（mm、FAO 式）、風の日最大と突風（m/s）、地温と水分は層ごとの日平均（0-7、7-28、28-100、100-255 cm。水分は m³/m³）。足した列（平均、蒸発散、風、地温、水分）が無い値は、その部分を書かない。11-06 までの行（最高、最低、降水、日照だけ）もそのまま読める。英語の行も同じ並び（`max … °C, min … °C, mean …`）。
- 出所は二つ。一つは Open-Meteo の過去データの API（`archive-api.open-meteo.com`。鍵無し、無料、座標を送る。ERA5 系の再解析で、日の値は `daily` の変数、土は `soil_temperature_0_to_7cm_mean` などの日平均）。もう一つは、過去データがまだ来ていない直近の日を埋める予報の API の過去の値（`api.open-meteo.com` に `past_days=7`）。後者の行は出典が「Open-Meteo 予報の過去の値」で、過去データが来たら同じ日の行を置き換える。気象庁の観測は一次資料だが API が無いので、月に一度、気象庁の過去の気象データの頁の url を同じファイルの頭に添える（人が見比べられるように）。座標は `place.md` の center を小数 2 桁に丸めて送る（1 km の格子で足りる）。
- 命令: `seed weather fetch --from YYYY-MM-DD --to YYYY-MM-DD`（取って追記。同じ日は置き換え）、`seed weather show --month YYYY-MM`、`seed weather fill`（最初の観察の日から昨日まで、記録の無い日と予報の過去の値の日を過去データで埋める。直近は予報の過去の値）。`fill` は `seed observe` の終わりと、アプリの天気の画面を開いた時（一日に一度）にも自動で走る。網に繋げなくても観察や画面は止まらず、警告を一行だけ残す。観察の読みには混ぜない（読みに使う時は Data の行として観察に引く。key は `weather` にし、日付を文の頭に置く: `- weather: 2026-11-02 の日の値。最高 …`。日付の key `- 2026-11-02: …` は行の形の key（小文字の英字で始まる）に合わず、観察の中では読み飛ばされるため）。
- 公開ファイルには出さない（座標の精度が上がるため）。
- 実装（11-06）: 座標の出所の順は `--lat --lon` → `place.md` の `- center:` の行 → 座標のある一番新しい観察。値は 2 桁に丸めて送り、ファイルには書かない。値の無い日（過去データは数日遅れる）は書かず、数だけ言う。
- 実装（11-07）: `weather.py` の `parse_line`（新旧の形を読む）、`fill_missing`（最初の観察の日〜昨日。過去データを一回で、残りを `past_days=7` で）。昨日までの実績だけを書き、今日以降（予報）は書かない。

## 18. 手続きの下書き `procedures/<slug>/`（2026-11-06）

```
  draft.md         申請の下書き。place.md と records から埋められる欄（住所の市区町村、面積の概算、現況、栽培の計画 plan.md の decided）は埋め、分からない欄は `（本人が書く）`
  sources.md       引いた条文の url と確認日
```

- 命令: `seed procedure nochi-3jo`（下書きを作る。既にあれば本人の [x] と手書きの行は残す）。他の手続きは slug を足す（`chimoku`、`hojokin` は 11-08 の後）。

## 19. 畑とプロジェクトの一覧（2026-11-06、11-07 に分けた。作者「記録は、畑ごとに選択できないと」「一つのプロジェクトフォルダーで、複数の畑を管理できるようにして」）

**プロジェクトの中の畑。** プロジェクトフォルダーの中に `fields/<畑の名>/` があれば、その一つ一つが畑（§1 の記録の中身）。
今の畑は `seed.toml` の `field`（§7）。空ならプロジェクト全体。`fields/` が無いプロジェクトは、根そのものが一つの畑（11-07 までの形）。
手引き（`skill/`）、`CLAUDE.md`、`plugins/` は、畑の中に在ればそれ、無ければ根の物を使う。

- 命令: `seed field new NAME`（`fields/NAME/` を作り、`field` をそれにする。畑がまだ無く根に observations/ か photos/ があれば、根の記録（observations、photos、originals、videos、place.md、plan.md、next.md、connections.md、public、lots.md、ledger.md、weather、procedures、origin、grow。bulk の originals も）をこの畑へ移す）、`seed field use NAME`（`all` でプロジェクト全体）、`seed field list`（今の物に `*`）。他の命令の `--field NAME` は、プロジェクトに `fields/NAME/` があればその畑。
- `--folder <プロジェクト>/fields/<名>` と、その中で開いた Claude Code は、そのプロジェクトのその畑（`seed.toml` は根の物）。
- 記録を作る・読む命令（observe、say、plan、publish など）は、プロジェクト全体では使えない。畑を選ぶ。

**プロジェクトの一覧 `~/.config/seed/fields.toml`。** 別のフォルダー（自分の畑、候補地、知人の田を別のフォルダーにしている時）に名を付けて切り替える。記録の中身は変えない。

```toml
current = "自分の畑"

[[field]]
name = "自分の畑"
folder = "~/seed"

[[field]]
name = "知人の田"
folder = "~/知人の田"
```

- 場所は `~/.config/seed/fields.toml`（秘密ではないので 644 でよい。`SEED_FIELDS` で変えられる）。無ければ、今まで通り `--folder` か `SEED_FOLDER` か既定の `~/seed`。
- 命令: `seed project add NAME FOLDER`、`seed project list`、`seed project use NAME`（`current` を変える）。前の名の `seed field add` は `seed project add` と同じ。`seed field use` に、このプロジェクトの畑に無く一覧に在る名を渡すと `seed project use` と同じ。`--field NAME` は、このプロジェクトの畑に無ければ一覧の名。フォルダーを決める順は `--folder` → 今いるフォルダー（`seed.toml` がある時）→ `--field` → `current` → `SEED_FOLDER` → `~/seed`。
- アプリ: 上の端にプロジェクトフォルダーの名（畑を選んでいれば「プロジェクト / 畑」）とフォルダーの印。下の板の上に「プロジェクト全体」と畑の並び、細い線の下に一覧のプロジェクト、PC では「別のフォルダーを開く」。選んだフォルダーがフォルダー名で一覧に足され `current` になる（同じフォルダーなら今の名を使う）。候補地（`kind: candidate`）の印を行の頭に付ける。

## 20. 動画 `videos/` と、zip から入れた物（2026-11-07）

動画は読まず、観察にも入らない。撮った時と所は、同じ名の `.json` に書く（動画の中には書き足さないため）。

```
videos/<YYYY-MM-DD>/<HHMMSS>.mp4       動画（PC のアプリで選んだ物は元の拡張子を小文字で: .mov、.m4v）
videos/<YYYY-MM-DD>/<HHMMSS>.json      撮った時と所
videos/<YYYY-MM-DD>/<HHMMSS>-2.mp4     同じ秒の二本目（-3 …）と、その .json
```

- 日と時刻は撮った時。アプリのカメラは撮り始めの時刻。家のサーバーはスマートフォンが付けた `taken`（無ければ受けた時）。PC のアプリで選んだ物は動画の中の `moov/mvhd`（UTC をこの PC の時刻に直す）、無ければファイルの時刻（zip の中の物は zip に書かれた時刻）。
- `.json` の鍵は、置いた道で違う。

| 置いた道 | どこの記録 | 鍵 |
|---|---|---|
| スマートフォンのアプリのカメラ（`capture.keep_video`） | スマートフォン | `taken`、取れていれば `lat`、`lon`、`accuracy`、`heading`。PC へ送れたら `sent`（PC の上の道。畑からの相対）、PC が断ったら `refused`（断りの語） |
| 家のサーバーが受けた物（`server/home.keep_video`） | PC | `taken`、スマートフォンが付けた物のうち `lat`、`lon`、`accuracy`、`heading`（ほかの鍵は捨てる） |
| PC のアプリで選んだ物、zip の中の物（`bundle.place_video`） | PC | `taken`、動画の中に所（`moov/udta/©xyz`）があれば `lat`、`lon`、`from`（元のファイルの名） |

- `sent` と `refused` はスマートフォンの側だけの印で、まだ送っていない動画（どちらも無い物）を古い順に選ぶために使う。PC の `.json` には書かない。
- 同じ名で同じ大きさの物が在れば同じ動画とみなし、二本目を作らない（送り直した時、同じ物を二度選んだ時）。大きさが違えば `-2` を付ける。上書きはしない。
- `.json` の `lat`、`lon` は細かい座標（丸めない）。Claude が動画の `.json` を読んで同じ日の観察と並べる時も、公開ファイルと返事には写さない（公開は §5 の通り市区町村まで。手引き SKILL.md の動画の段）。mp4 の中身は読みに使わない。
- スマートフォン（Android）では、撮った写真と動画の写しが共有の `Pictures/seed/<YYYY-MM-DD>/` にも残る（`photos.keep_on_device`）。記録の外の物で、seed は消さない（撮る画面で「消す」を押した物だけ、カメラを出る時に消える）。
- **zip から入れた物。** zip の中の写真と動画だけを取り出し、写真は `photos/` へ（§1、§3。撮った日ごとに 6 枚までを一つの観察にする）、動画は上の `videos/` へ置く。zip の中のフォルダーの形は残さない。zip そのものと、写真でも動画でもない物は記録に入れない。
- **一時の物（名が `.` で始まる。終われば消え、落ちた時だけ残る）。** `.unzip-*/`（zip の取り出し。一時間より古い物は次に入れる時に消す）、`.video-*.part`（家のサーバーが受けている途中の動画。一日より古い物は次に受ける時に消す）、`.home-*/`（家のサーバーが受けた写真の一時の置き場）、`.seed-trash/`（撮る画面で消した物。元のファイルの横に置き、カメラを出る時に消す）。

## 11. どれだけ残すか `keep`

PC の性能で効くのはほぼディスクの空きなので、`seed init` が空きを測って見せ、本人が三つから選ぶ（`seed init --keep research`、
後から `seed keep research`）。案と理由は `使い方とデータの置き方.md` §4。

| keep | 残す物 |
|---|---|
| `text` | 観察、読み、判定、手引き。写真は読み用の大きさ（長辺 2,000 px。EXIF の座標・時刻・向きは残す） |
| `photos`（既定） | 写真を元の大きさの JPEG で（JPEG はそのまま、HEIC などは JPEG に直す） |
| `research` | 上に加えて、写真の元 `originals/`（写した JPEG と中身が違うときだけ）と、読みの生の出力 `observations/<id>.raw/` |

**別の盤 `bulk`。** 写真の元は重いので、`seed.toml` の `bulk`（`seed init --bulk <道>`、`seed keep --bulk <道>`、`--bulk ""` で外す）に
別の盤の道を書くと、`originals/` はそこに置かれる（`<bulk>/originals/<日>/…`。畑が在るプロジェクトでは `<bulk>/fields/<畑の名>/originals/<日>/…`。`settings.py` の `Settings.records`）。観察と読みと raw は記録のフォルダーに残る（文字で、小さい）。
`seed keep` はその盤の空きも出し、`seed prune` はそこの `originals/` も消す対象に入れる。作者は `/mnt/hdd2/lab/fields/<畑>`（`docs/研究室.md`）。

`observations/<id>.raw/` の中身: `system.md`（そのとき渡した手引き。本人の `skill/SKILL.md` と 06 章）、`prompt.md`（依頼。写真の道、
前書き、Data、Record、前の観察）、`answer.json`（`claude -p` の答えそのまま。失敗の答えも）、`meta.json`（いつ、何で、モデル、usage、
手引きの版 `skill_hash`（`skill/` の .md 全部のハッシュ）、写真）。後で別の手引き・別のモデルで読み直して比べるための物。

**上げるのは自由。下げても seed は何も消さない。** 消すのは `seed prune` で、今の keep では残さない物（`originals/`、`*.raw/`）を
何 MB か見せてから、本人が y と答えたときだけ消す（`--yes` で聞かない）。`photos/` は prune でも縮めない。`seed keep` が今の大きさを出す。

```markdown
---

model: claude-opus-5-5            # Expect を書いたモデル
---

- h1: 吉野川の平野の南側の微高地（出典: 本人、2026-10-28）  → farmer: right

- h2: visible: no [0.80]

## Record
- note: h1 は 1 m の標高で確かめた
```

- `## Hypotheses` の行の key は `h<n>`（`h1` から順に、消しても番号は詰めない）。本人や資料の物は確からしさ無しで、出典を括弧に書く。AI の物は確からしさ付き。本人の `→ farmer: right` は「確かめられた」、`wrong (理由)` は「違った」。

fieldnotes の農場のフォルダー（`records/` と `photos/` のある所）を、一度だけ seed の形にする。元のフォルダーは変えない。移す先はプロジェクトの `fields/<畑の名>/`（畑の名は fieldnotes の field の名のまま）。

| fieldnotes | seed |
|---|---|
| `records/<field>/<date>.md` | `fields/<field>/observations/<date>-<最初の写真の時刻>.md`。`## AI observation` → `## Reading`（`leaf_colour`、`weed_height`、`soil`、`animal`、`other` は `change` に、元の key を文の頭に）、`## Earlier AI lines` → `## Earlier reading`、`## Checks` → `## Checks`、`## From the farmer's voice` の `work`/`seen` → `## Record` の `did`/`saw`（声から）、`## Farmer note` → `## Record` の `said`（`HH:MM 文 (ファイル)` の行）と `note`。前書きの `coverage`、`cover_range` はそのまま、`weather` は捨てる（seed が weather/ に引き直す）。本人の判定と理由はそのまま |
| `photos/<field>/<date>/<HHMMSS>-<name>.jpg` | `fields/<field>/photos/<date>/<HHMMSS>.jpg`（同じ時刻が二枚なら `-2`）。`index.json` の座標から観察の `location` |
| `photos/.../<HHMMSS>-voice.<ext>` | `fields/<field>/photos/<date>/<HHMMSS>-voice.<ext>` |
| `records/<field>/<date>-overlay-<n>.jpg` | `fields/<field>/observations/<観察>.sam/<n>.jpg` |
| `records/site.md` の `data`、`record` | 各畑の `place.md` の `## Data`、`## Record`（`lat`、`lon` は `- center:` の行） |
| `records/site.md` の `hypothesis`、`supported`、`refuted`、`records/surroundings.md` の行 | 各畑の `hypotheses.md`（`supported` は `→ farmer: right`、`refuted` は `→ farmer: wrong (理由)`） |
| `records/_checks/<field>/expect.md` | その畑の `hypotheses.md` の `## Expect` |
| `records/lookup.md` | 各畑の `place.md` の `## Data`（照会の行の形に） |
| `records/lookup/parcel_jp.json` の筆の形 | 各畑の `parcel.geojson` |
| `records/_concepts/<field>.md` | `fields/<field>/concepts.md` |
| `records/_plants/*.md` | `fields/<field>/plants/`（どの畑にも同じ物） |

| それ以外（`documents/`、`_compare/`、`surroundings/` の絵、`lookup/*.json`） | プロジェクトの `notes/fieldnotes/` にそのまま写す（捨てない） |

### 移す先に同じ物が既にある時（2026-11-11）

二度目の取り込みと、fieldnotes と seed の両方で同じ日を記録していた畑（同じ写真を seed でも読んだ畑）の時。seed で付けた物は消さず、古い側の物も落とさない。

- **写真と録音。** 元の日のフォルダーを名前の順に見て、同じ時刻の n 枚目は、移す先の同じ時刻の n 番目の名（`<HHMMSS>.jpg`、`<HHMMSS>-2.jpg`、…）に当てる。その名が既にあれば写さず、在る物を使う。中身では比べない。fieldnotes の写真は縮めて書き直した物で、seed に在る元の写真とバイトが合わないため。名は写真の撮った時刻（秒まで）から付くので、同じ日の同じ時刻の同じ番目は同じ一枚と読む。
- **観察。** 移す先に同じ名の観察（`<date>-<最初の写真の時刻>.md`）が既にあれば、書き換えずに、足りない物だけを足す。
  - 古い `## AI observation` と `## Earlier AI lines` の行は、在る観察の `## Earlier reading` へ。その見出しの下に「fieldnotes の読み（<model>、<date> の一日分）」の一文を置く（行でない文は書き戻しても残る。上の「読むときには使わない」の段）。同じ行が既にあれば足さない。
  - `## Checks` は、在る観察に Checks が無い時だけ入れる（`checks_model` も）。
  - `coverage`、`cover_range`、`cover_model` は、在る観察に `coverage` が無い時だけ入れる。
  - 覆いの絵（overlay）は、在る観察の `.sam/` に同じ番号の絵が無い物だけ写す。
  - `## Record` に行く行（声からの `did`、`saw`、`said`、`note`）は、同じ行が無い物だけ足す。
  - 在る観察の `photos`、`location`、`## Reading`、`model` は変えない。
  - 入れられなかった物（在る観察に Checks や `coverage` が既にあった時、同じ番号の絵が既にあった時）がある日は、元の `<date>.md` と、その日の覆いの絵を、プロジェクトの `notes/fieldnotes/records/<field>/` にそのまま写す。
- **数。** 取り込みの後の一行は、新しく書いた観察と写真の数に続けて、在る観察に足した数と、既に在って写さなかった写真の数を言う。
- 同じ取り込みを繰り返しても、二度目からは何も増えない。
