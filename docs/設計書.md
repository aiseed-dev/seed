## 1. 形

一つのリポジトリに二つの側がある。畑の側（seed）と業務の側（kagi）。どちらも Python、素の文字のファイル、鍵は repo の外。

```
本人の PC                                      deb2（Cloudflare の後ろ、Caddy）
  seed アプリ（Flet 1.1、PC 版とスマートフォン）／seed 命令  seed.aiseed.dev  静的サイト site/（入口、p/<id>.html、index.json）
  ~/seed/ 本人の記録（素の文字）  ──写真+座標+招待──▶  /api/*（招待コード必須、:8010）── read、talk ──▶ Claude API（作る人の鍵、上限）
  ~/.config/seed/credentials.toml（600）◀──読みの行──   lookup ──▶ seed.sources（地理院ほか。seed-farm[lookup]）  identify ──▶ Pl@ntNet（鍵があれば）
  SAM 3.1 の覆い％・声の書き取り ──▶ Meta の Model API（本人の meta_key があれば。§5.20）  seed mcp ──▶ 本人の AI
  (A) claude -p ──▶ Anthropic（本人のサブスク）     Web は使い方の説明を置く所（アプリの Web 版はやめた）
  (B') 本人の鍵 ──▶ Claude API（費用は本人）       鍵は /etc/credstore/seed.*（root 600）、ImportCredential= で seed.service（利用者 seed）にだけ
  (C) Claude Code で ~/seed/ を開いて手で頼む
  seed home（家の網の :8800。PC を探す口 UDP 8801）◀── 写真（元のまま）・動画・言葉 ── スマートフォンのアプリ（§5.13）
  kagi（在庫表、口の表、記録。鍵の値は読まない）
halo（作者の家。公開しない）  sd-server :11435（門 :11445、Bearer）。Glimmer :11434 は fieldnotes の読みに使っていた（11-11 から使わない）。deploy/halo/
```

- **読みの道は三つ、手引きと行の形は一つ。** (A) 本人の PC の `claude -p`（`local.py`）。(B) Claude の API: サーバー経由（`server/read.py`。作る人の鍵と一日の上限）か、本人の鍵で端末から直に（`direct.py`）。読みの指示はどちらも `prompts.py` の同じ物。(C) Claude Code に `skill/SKILL.md` を読ませて手で頼む。
- **話す（言葉で頼む細かい作業）の運び方は三つ、道具は一つ。** 手元の Claude Code（`local.talk`）、本人の Anthropic の API の鍵で端末から直に、seed のサーバー（`/api/talk`）経由。後の二つは Claude Code と同じやり方をアプリの中に持つ: Claude に道具（`prompts.TOOLS`）を渡し、Claude が呼んだ道具をアプリが端末の中で動かして結果を返す、を答えが出るまで（上限 12 回、途中で止められる。`direct.py`）。道具は記録のフォルダーの中だけに効く物（観察の一覧と全文、縮めた写真、場所ごとの並び、合っている・違うの印、本人の言葉、読みの書き直し、計画を読む・書く、土地の成り立ち、草の名、公開の下書き）。公開を送る道具と命令を走らせる道具は無い。手元の Claude Code の運び方だけは、記録のフォルダーの中でフォルダーを作る・ファイルや写真を移す事（`mkdir`、`mv`）もできる。消す事はせず、本人が打つ命令を返す（観察が指す写真は動かさない）。サーバーの運び方（`direct.py`）にこの道具は無い。順は、PC が手元の Claude Code → 本人の鍵 → サーバー、スマートフォンが本人の鍵 → サーバー（歯車のフォームの「読む所」か、設定の札の一行で変えられる）。どれも使えない時（招待コードも鍵も無い、上限、止めている）は本人の言葉として書き留め、理由を返す。間違いの指摘はどの運び方でも、印を付け、本人の言葉を残し、直した行を先に返す。 返事の中の `![一言](photos/…)` は写真として出し、一言（草の名など）を写真の下の見出しにする（名で指しただけの写真は付いたタグ）。
- **記録は本人の手元**（`~/seed/`）。サーバーは読み取りの写真も座標も残さず、答えを返したら捨てる（残るのは token のハッシュ、日時、回数）。サーバーに残る写真は、本人が公開で出すと決めた物だけで、サーバーが開いて書き直した物（長い辺 1280、EXIF 無し。位置の情報は無い）。アプリは PC 版とスマートフォンで、どちらも記録は本人の端末に置く。スマートフォンが家のサーバー（`seed home`）に繋いでいれば、写真の元と動画は PC のプロジェクトフォルダーに入り、スマートフォンには読み用の小さな写しが残る（§5.13）。
- **公開は人が了解した行だけ、静的ファイルで。** 場所は市区町村まで（座標を付けるなら小数 2 桁に丸めた物だけ。§5.2）。公開は Claude を使って行う: Claude が下書きを作り（`seed publish … --local`、話すの道具 `draft_public`）、本人が全文を読んで「出す」と言ったら（アプリでは全文の下の「出す」を押したら）、同じファイルを中身のまま送る（`seed publish --file`。アプリは見せた全文と今のファイルが同じ時だけ送る）。本人が読んだ文と送られる文を同じにするため、アプリは公開を組み立てない。アプリの「公開した物」は一覧と取り下げだけ。写真は日の見出しの下の `photo` の行（既定は日ごとの今日の一枚。変えたい時は言葉で頼む）。アプリは出て行く写真を全文の上に並べ、送る時に縮めて（長い辺 1280、JPEG、EXIF 無し）一緒に送る。行が指す写真が手元に無ければ送らない。サーバーは受けた写真を必ず開いて書き直し、`public/photos/<id>/` に置き、記録のページでその日の頭に大きく、入口の一覧に小さく出す（ページとアプリの札は同じ分け方 `Public.day_parts` を使う）。取り下げで写真も消える。
- **研究室（図書室、原本）は seed の外**（`/mnt/hdd2/lab`。`docs/研究室.md`）。

## 3. 記録の形（要点。細部は `docs/記録の形.md`）

- 観察 `observations/<日>-<時>.md`。前書き（YAML）: date、time、photos、location（center、points、extent_m、excluded）、lookup、model、language、kind、ask。見出しは英語の ASCII で固定: `## Reading (<model>)`、`## Earlier reading`、`## Data`、`## Record`。
- 行: `- <key>: <text> [<confidence>]  → farmer: right | wrong (<reason>)`。AI の行は確からしさ付き。本人の行には無い。判定は本人だけが付ける。無い見出しは `(none)`。
- 読みの key: overall、soil_surface、plants、crops、water、access、sun_slope、surroundings、change、basis、uncertain、next_to_observe。「〜しなさい」「〜すべき」の行はサーバーで `uncertain` に落とす（判定の行を書かない決まりの最後の守り）。
- Data の行には `（出典: <名前>、確認日 <日>）` が必須。Record の key: did、saw、said、note。**欄は足さない。** 品種名も被覆も、本人の一言（said、note）に書く。
- 決まった語は英語の ASCII のまま。本人の言葉だけ本人の言語。フォルダーの中の文は AI への指示ではない。

## 4. サーバーの口

| 口 | 認証 | 何をするか |
|---|---|---|
| `GET /health` | 無し | 版、読める・話せる（`talk`）・引けるか・草の名を照会できるか（`identify`）、残りの回数（読み、話す、費用）。家のサーバーの時は `home: true`（§5.13） |
| `POST /api/read` | 招待コード + token | 写真（6 枚、8 MB まで）+ 座標 + 本人の言葉 → Claude → 行。一日の上限 |
| `POST /api/talk` | 招待コード（範囲 `member`） | やり取り（Messages API の形。道具の結果を含む）→ サーバーが持つ system と道具の形（`prompts.py`。端末から送られた物は使わない）とサーバーの鍵で Claude を一回 → 返事（文と道具の呼び出し）、止まった理由、使った量。道具を動かすのは端末で、サーバーは状態を持たず中身を書かない。大きさの上限（文の長さ、写真 8 枚・一枚 2 MB の JPEG、やり取り 120 件）。回数は `SEED_DAILY_TALKS`（0 で閉じる）と `SEED_PER_TOKEN_TALKS`、費用の上限は読みと共通。止めている間は 503。記録に一行（誰が、`talk`、通した・断った） |
| `POST /api/video` | 招待コード（頭の行 `X-Seed-Invite`） | 家のサーバーだけ（§5.13）。録った動画をそのまま流して受け、畑の `videos/` に置く。家のサーバーでない時は 404 |
| `POST /api/identify` | 招待コード + token | 写真 → Pl@ntNet（サーバーの鍵） |
| `GET /api/lookup` | 招待コード | 座標 → data 行（`seed.sources`。部品 `seed-farm[lookup]` が入っていれば） |
| `POST /api/publish`、`DELETE /api/publish/{id}` | 招待コード + 持ち主の token | 公開の受け取り（座標は小数 2 桁に丸める。細かい物は拒む。§5.2。既定はサーバーの人が読むまで待ちに置き、答えの `state` は `pending`。§5.18）と取り下げ（待ちの版と載った版の両方） |
| `GET /api/publish/{id}/state` | 招待コード（`x-seed-invite`）+ 持ち主の token（`x-seed-token`）。秘密は URL にも本文にも載せない | 載ったか: `pending`、`returned`（`reason` 付き）、`public`、`none` |
| `POST /api/connect` | 招待コード（+ token） | 一言を置き、site を書き直す。200 字、同じ相手に 1 日 1 回 |
| `GET /api/whoami`、`/api/admin/*` | 招待コードか token（管理の口は範囲 `admin`） | 範囲を尋ねる口と管理の口（§5.10） |
| `GET /`、`/p/{id}`、`/index.json`、`/public/{name}`、`/photos/{id}/{name}`、`/robots.txt` | 無し | 静的サイト |
| `GET /manual`、`/static/{name}` | 無し | 使い方の頁（`docs/利用マニュアル.md` を `markdown` の包みで HTML に。`site/manual.html` と `site/manual/index.html`。包みかマニュアルが無ければ書かず、ログに一行）と入口の写真（`src/seed/server/static/` を `site/static/` に写す）。マニュアルは clone の `docs/` から読む（deb2 は `/opt/seed` の clone から動く）。相対リンクは GitHub の頁に替え、文の中の生の HTML は字のまま出す |

サービスは専用の利用者 `seed` で動く（`dev` は AI が動くアカウントで、sudo も鍵も持たない）。Claude と Pl@ntNet の鍵は鍵ごとに root だけが読めるファイル（`/etc/credstore/seed.anthropic`、`/etc/credstore/seed.plantnet`。600 root）に置き、systemd の `ImportCredential=`（254 から。Debian 13 は 257）が `seed.service` にだけ渡す。`ImportCredential=` は無いファイルを飛ばすので、鍵が無くてもサービスは起きる（`LoadCredential=` は無いと `status=243/CREDENTIALS` で起きない。11-08 の deb2 で起きた）。鍵の要る口は 503 で、`error` の語（`read_unavailable`、`talk_unavailable`、`identify_unavailable`）はそのまま、`detail` は来た人向けの「Claude の読み取りは準備中です」「Claude と話すのは準備中です」「草の名の照会は準備中です」。アプリはその語を受けて「このサーバーでは、…は準備中です」と出す。入口の頁は、無い鍵があれば「Claude の読み取りと話すは準備中です。公開された記録は読めます。」の一行を出す（`pages.not_ready_line`。鍵を置いて restart すると、起きた時の書き出しで消える）。記録の署名の鍵 `/etc/seed/log-key` は `LoadCredential=` のまま（配備の 0-1 で必ず作る）。サーバーは `$CREDENTIALS_DIRECTORY` に鍵が在ればそれを、無ければ環境変数を読む（手元とテスト）。`/etc/seed/env` は秘密でない設定だけ、招待コードの一覧は root:seed 640。鍵の値は repo、会話、ログ、例外の文、`/health`、管理の画面（kagi の「人の出入り」）に入れない（在るか無いかだけ）。手順は `docs/deb2 の配備.md`。

### 5.11 プラグインの画面（作者 11-07「『この土地の成り立ちを教えて』というのは、Claude とのチャットにする。今表示している内容は、Python プラグインとして別画面で動作するようにしたらどうですか」）

話すと写真の二つの画面は変えず、三つ目からはプラグイン。一つの Python ファイルが一つの画面。

- **置き場は二つ。** 配る物はパッケージの `src/seed/plugins/*.py`。本人の物は記録のフォルダーの `plugins/*.py`（フォルダーが畑なので、畑ごと。手引きと同じで本人が置き、本人の PC で本人の権限で動く。スマートフォンでは記録のフォルダーがアプリの入れ物の中なので、置けるのは配る物だけ）。
- **形は三つだけ。** モジュールの変数 `TITLE: dict[str, str]`（言語 → 画面の名。無い言語は en）、`ICON: str`（`ft.Icons` の名。例 `"MAP_OUTLINED"`）、関数 `build(app) -> list[ft.Control]`。`app` は `seed.app.main.App`（`app.folder`、`app.lang`、`app.t`、`app.state`、`app.refresh()`、`app.page`）。枠（上の端の名と印）はアプリが付ける（`app.view`）。
- **道は `/p/<ファイルの名の幹>`。** 上の端の印は、話す、写真の後ろに、配る物 → 本人の物、名の順。
- **読み込みは起動時と、別のフォルダーを開いた時**（`plugins.load(folder)`）。話す間に Claude Code が `plugins/` に書いた物は、画面を切り替える時に `plugins/` のファイルの名と更新の時（`plugins.stamp`）を見て、変わっていれば読み直す（`App.reload_plugins`。開き直さずに拾うため）。読めない物（ImportError、読み込み時の例外、三つが揃っていない）は印を出さず、一行ログ。`build` が例外を投げたら、その画面に「このプラグインは動きません（<例外の名>）」の一行。アプリは落ちない。
- **一つ目は `land.py`（この土地の成り立ち）。** `place.md` の data 行の四つのまとめ（土地と地形、土、水と災害の区域、歴史）と、昔の地図と空中写真（`seed origin` の絵。無ければその場で作る）。AI 無し。話すのやり取りの一番上に出していた土地の札と、「この土地の成り立ちを教えて」「土はどんな土？」の決め打ちの答えは外し、この二つの言葉は Claude に渡す（Claude は `place.md` の出典付きの行から答える。サーバーの道は `read_land`、手元の Claude Code は Read）。「昔はどんな土地だった？」の札は、この画面を開く。
- 二つ目は `weather.py`（天気。Open-Meteo の二週間（16 日）の予報、座標は 2 桁）。上から、土の段（今の地表面と地温の一行、地温と土の水分の深さごとの図）、今日と明日の一時間ごとの図（降水量、降水確率、気温、湿度）、二週間の図（最高・最低気温、降水量）、作業の目安の図（日照、蒸発散、風の最大と突風）、出典の link と計算の仕方の二行、「取り直す」（図は SVG、`chart.py`。取るのは `fetch_week`、`parse_soil`。地表面温度は ECMWF の `fetch_surface`、二つ目の問い合わせで、取れなくても他は出す）。開いた日に一度、気象の実績の記録の穴を埋める（`weather.fill_missing`。記録の形 §17）。畑の座標は `land.center`（全体の時は座標のある最初の畑）。取った物は `app.state["forecast"]` に日付つきで置き、同じ日の開き直しでは取り直さない（「取り直す」で消す）。AI 無し。
- **プラグインが触れてよいのは本人のフォルダーの中だけ**、という決まりは手引きと同じで、コードでは縛らない（本人が自分の PC に置く物）。鍵の値には触れない。
- **三つ目は `procedure.py`（手続き）。** 手引き 13 章の道のり（〇 貸し農園から始める → 一〜七）と、`seed procedure nochi-3jo` の下書き（必要な物の一覧は押せる印でファイルの `[x]` に、申請の下書き、引いた条文へ行ける link）。無ければ「下書きを作る」。作者 11-07「手続きも見せましょう。初心者が最初にやらないといけないこと」「農地を見つけるまでは、貸し農園」。

### 5.12 一つのプロジェクトに畑を幾つも（作者 11-07「一つのプロジェクトフォルダーで、複数の畑を管理できるようにして、それを Claude Code のように選択できるようにして」「プロジェクトフォルダー全体もできるように」）

- **形。** プロジェクトフォルダーの中に `fields/<畑の名>/` を置くと、その一つ一つが畑（今までの記録のフォルダーと同じ中身: observations、photos、place.md、plan.md、public …）。共有の物（`seed.toml`、`CLAUDE.md`、`skill/`、`plugins/`、鍵の置き場）はプロジェクトの根に一つ。`fields/` が無いプロジェクトは、今まで通り根そのものが一つの畑（11-07 までの形はそのまま動く）。
- **今の畑は `seed.toml` の `field`。** 畑の名（`fields/` の下のフォルダーの名）か、空（プロジェクト全体）。`seed field new <名>` が `fields/<名>/` を作って init する。`seed field use <名>`、`seed field list` はこの中の畑。プロジェクトの一覧（別のフォルダー）は `~/.config/seed/fields.toml` のまま（`seed project add/use/list`。`seed field add/use` は前の名で同じ事をする）。
- **選ぶのは上の端のフォルダーの印。** 板の上に「プロジェクト全体」と畑の並び（今の物に印）、下に別のプロジェクト。Claude Code の仕事場の選び方と同じ。選ぶと `seed.toml` の `field` が変わり、上の端の名は「<プロジェクト> / <畑> — 話す」、全体なら「<プロジェクト> — 話す」。
- **畑を選んでいる時**は今まで通り（`app.folder` がその畑の Folder。手引きとプラグインと CLAUDE.md は畑 → プロジェクトの根の順に探す）。
- **プロジェクト全体の時**は、見る・話す。写真は畑ごとの見出しで全部、話すは畑ごとの見出しでやり取りを並べ、言葉は Claude に「プロジェクトの根」で渡す（手元の Claude Code は根で動き、決まりに「畑は fields/ の下、それぞれに観察がある」と足す。サーバーと鍵の道の道具は畑を一つ指す引数 `field` を持つ）。撮る・写真を選んで送るは、畑を選んでからにする（押すと畑を選ぶ板が出る）。公開は畑ごと。
- **プラグイン**は `build(app)` で `app.folder`（選んだ畑。全体の時は根）と `app.fields`（畑の並び）を見る。land は畑の物なので、全体の時は畑ごとに並べる。

### 5.13 スマートフォンから PC へ、一方通行（作者 11-07「ローカルネット又はインターネットで繋いで、PC 側とやり取りができるようにしないといけない」「『両方に記録を持ち、同期する』ではなくて、一方通行にしろ」）

- **向きは一つ。スマートフォン → PC。** PC のプロジェクトフォルダーが本物の記録。スマートフォンは撮って送り、PC の Claude Code が読み、答えだけがその場でスマートフォンに返る。PC からスマートフォンへ記録を送る事も、両方を突き合わせる事もしない。
- **PC で `seed home` を打つ。** 今の seed のサーバー（`seed.server.main`）を、プロジェクトフォルダーを家にして家の網に立てる（既定 `0.0.0.0:8800`。`--host`、`--port`）。渡す環境変数は `SEED_HOME=<プロジェクト>`、`SEED_INVITES=<プロジェクト>/home.toml`、`SEED_PUBLIC_DIR=<プロジェクト>/public-home`、プロジェクトに `skill/SKILL.md` があれば `SEED_SKILL_DIR`、`SEED_PUBLISH_REVIEW=0`（家では作者がサーバーの人なので待たない）（`cli.home_env`）。招待コードは手で打てる 6 桁を一つ、`<プロジェクト>/home.toml`（600）に作って持ち（在ればそのまま使う。消せば次の `seed home` で作り直す。値はログに出さない）、端末に URL と招待コードを出す。間違えた招待コードか token を 10 分に 10 回送った番地は、10 分のあいだ正しいコードでも 429 で断り、端末に一行出す（記録があれば記録にも。コードの値は書かない。`limits.Tries`。門の全部に効く。数は `SEED_GATE_TRIES`、`SEED_GATE_WINDOW`、`SEED_GATE_BLOCK`）。一日の上限は、使うのが本人だけなので緩い（読みと話すは全体で各 1000、招待コードごとに各 500、番地ごとの読み 500。環境変数があればそれ。`cli.HOME_LIMITS`）。外（インターネット）からは、同じ物を自分のサーバーに置くか、家の網に入る道（VPN など）で届く。seed は口を開けない。
- **PC を探す（作者 11-07「つなげない。コピペも出来ないから、簡単には繋がらない」）。** スマートフォンでは長い URL を打つのも貼るのも難しいので、同じ Wi-Fi の中で見つける。`seed home` は、待つ番地が `0.0.0.0` の時、UDP 8801 で `seed?` に `seed-home <URL>` と答える（`home.answer_discovery`）。スマートフォンの「PC を探す」は、網の全体と自分の /24 に `seed?` を放送し、1.2 秒で答えが無ければ同じ /24 の番地に一つずつ送り、3.5 秒まで待つ（放送を通さない網のため。`discover.find_home`）。見つかれば URL を保存し、読む所を「サーバー」にして、6 桁の招待コードを待つ（歯車のフォームの招待コードの欄に打って保存する）。同じ網の外へは何も出さない。

- **家のサーバーがする事（`SEED_HOME` がある時だけ）。**
  - `/api/read`: 受けた写真（アプリは家のサーバーには縮めず、座標の入った元のまま送る。一枚 12 MB、全体 60 MB まで）を `seed observe` と同じ道で `<プロジェクト>/fields/<畑>/`（`field` の欄。無ければ今の畑か根）に写真と観察として置き、PC の Claude Code（無ければサーバーの鍵）で読み、読みを観察に書き、答えを返す。

  - `/api/video`（作者 11-07「動画のほうがアップできていません」）: 録った動画を、そのままの本体で流して受け（メモリに貯めず、畑の中の一時のファイル `.video-*.part` に書く。一本 2 GB まで。頭が MP4／MOV（4 バイト目から `ftyp`）でなければ 415）、`<畑>/videos/<日>/<時刻>.mp4` と同じ名の `.json`（`taken`、`lat`、`lon`、`accuracy`、`heading`。知らない鍵は捨てる）に置く。名は撮った時（無ければ受けた時）。同じ名は上書きせず `-2` を付ける。同じ名で同じ大きさなら送り直し（前の答えが届かなかった）とみなし、在る物の道を返す。落ちた時の残り（一日より古い `.video-*.part`）は次に受ける時に消す。招待コードと時と所は要求の頭の行（`X-Seed-Invite`、`X-Seed-Where`）で受け、URL には載せない。読みはしない（観察には入らない）。家のサーバーでない時は 404、受け付けを止めている時は 503。

- **スマートフォンの側。**

### 5.14 撮る画面（作者 11-07「カメラアプリは使いづらいので設計をやり直して」「できるだけ標準のカメラアプリに近いものにして」）

前の形は、題と説明の文と上の帯が場所を取り（特に横にした時）、横では倍率を変えにくく、戻り方が分かりにくく、失敗した写真や動画をすぐ消せなかった。標準のカメラの形に寄せると、覚える事が増えない。

- **どこで出るか。** スマートフォンのアプリ（と画面の確かめ用のブラウザ）で、話すの左下の「撮る」を押すと開く（`capture.available`: flet-camera と flet-geolocator が入っていて、iOS か Android かブラウザ）。PC の窓はカメラの部品が動かないので出さず、写真・動画・zip を選ぶ（§5.15）。プロジェクト全体の時は、先に畑を選ぶ板が出る（§5.12）。
- **形。** 画面いっぱいがカメラで、開くとすぐ点く（後ろのカメラ、一番大きい解像度、JPEG。音は録らない）。題や説明の文や上の帯は置かない。上の端は「← 戻る」と位置の印（誤差の m。押すと取り直す）、録画中は赤い印と経過の時間。縦の時は下の帯に、上から倍率の印、写真と動画の切り替え、左に最後に撮った物の丸・真ん中に丸いシャッター・右に ✓（観察にする。撮った枚数）。横の時は右の端の板に ✓・シャッター・最後に撮った物を縦に並べ、その左に写真と動画の切り替えと倍率の印を縦に置く（上の端の印は板の手前まで）。シャッターは写真で白、動画で赤、録画中は赤い四角。
- **倍率。** 1× から始める。二本の指でつまむか、印を押す。印は 0.5× 1× 2× 5× 10× のうちその機種の最小〜最大に入る物で、最小が 1 より小さければ最小も（`zoom_steps`）。上の限りは 10×。倍率を送っている間に変わった分は、送り終わってから最新を送り直す（印と映りが食い違わないように）。倍率を持たない機種は印を出さない。
- **写真。** 位置が取れるまでシャッターは切れない（座標はこの作業に必須）。撮った時は最後に取れた位置ですぐ書き（`photos.stamp`。座標・時刻・向き・誤差）、位置の取り直しは後ろで。一度に 6 枚まで（一つの観察で読める数）。一時の場所に置き、✓ で観察にする時に記録のフォルダーへ写す。Android では共有の `Pictures/seed/<日>/` にも写しを書く（`photos.keep_on_device`）。
- **動画。** 位置が無くても録れる（取れていれば書く）。止めると、記録の `videos/<日>/<撮り始めの時刻>.mp4` と同じ名の `.json`（`taken`、`lat`、`lon`、`accuracy`、`heading`）に置く（`capture.keep_video`）。同じ秒に始めた二本目は `-2`。Android では `Pictures/seed/<日>/` にも。写真の 6 枚には数えず、観察には入らない。
- **見返す・消す。** 最後に撮った物の丸を押すと見返し（前後に送れる）。「消す」で、写真は Pictures/seed の写しごと、動画は記録の `.mp4` と `.json` と写しごと、それぞれのファイルの横の `.seed-trash/` へ名を変えて移す（同じ円盤の中なので大きな動画も写さない）。下の帯の「元に戻す」（6 秒で消える）で、元の所と撮った順に戻る（写真が 6 枚に達していれば戻さず一行）。カメラを出る時に `.seed-trash/` を本当に消す。消した動画は PC へ送らない。
- **出る。** 「← 戻る」と端末の戻る操作（アプリは閉じない）。写真があれば観察にするかを聞く（「<n> 枚で観察にする」か「観察にせずに戻る」）。撮っている・残している途中は受けない（途中の一枚を失わない）。録画中なら止めてから出る。出た時に、家のサーバーに繋いでいれば、まだ送っていない動画を送る（§5.13）。
- 確かめ: `tests/test_capture.py`（位置の値、一枚ずつの座標と後始末、出る端末、Pictures/seed への写し、動画の置き方と同じ秒の名、動画を送る時の時と所と畑、送っていない動画を一度だけ送る、消した動画は `.json` と写しごと消えて送らない、動画は 6 枚に数えない、倍率の印、横と経過の時間、元に戻すは 6 枚を越えない、ごみ箱はファイルの横で出る時に消える、断られた動画の印と後ろの動画）。

### 5.15 PC のアプリで写真・動画・zip を入れる（作者 11-07「zipでまとめていれたいので、zipにも対応させて」「動画は単独でいれることもあるので、mp4に対応して」）

PC にはカメラが無いので、スマートフォンや標準のカメラで撮った物を PC に移して入れる。まとめて移すには zip が楽で、動画だけを入れる事もある。

- **入口。** PC のアプリの話すの左下「写真・動画・zip を選ぶ」で、写真（jpg、jpeg、png、heic、heif）、動画（mp4、mov、m4v）、zip を、数を絞らずに選ぶ（`app.main.PICK_EXTENSIONS`、`bundle.py`、`talk.add_picked`）。プロジェクト全体の時は、先に畑を選ぶ。
- **zip。** 記録のフォルダーの中の一時の場所 `.unzip-*/` に、中の写真と動画だけを取り出す。zip の中のフォルダーの道は使わず名だけで書く（`../` や `/` で外に書かないため）。名が `.` で始まる物と `__MACOSX` の中は飛ばす。同じ名は `-2`。上限は、中の一つ 4 GB、取り出す全体 16 GB、中の数 2000（`MEMBER_MAX`、`TOTAL_MAX`、`MEMBERS_MAX`）。書かれた大きさより実際が大きい物も、読んだ量で止める。上限を越えたら取り出しを止め、理由を一行で見せる。鍵の掛かった物、開けない縮め方、壊れた物は、その一つだけを外して残りを入れる。zip の中の時刻をファイルに写す（EXIF の無い写真の撮った時に使う。0 月 0 日のような時刻は写さない）。終われば一時の場所を消し、前に落ちた時の残り（一時間より古い `.unzip-*`）も次に消す。
- **写真。** 撮った時（EXIF、無ければファイルの時刻）の順に並べ、日ごとに 6 枚までを一つの観察にして（`photo_groups`）、順に送って読む。取り込みは今まで通り `photos.import_photos`（同じ中身は二枚にしない）。本人の言葉は最初の観察にだけ付ける。
- **動画。** 記録の `videos/<日>/<時刻>.<拡張子>`（拡張子は小文字にしてそのまま）に置き、同じ名の `.json` に撮った時と所と元の名（`taken`、`lat`、`lon`、`from`）を書く（`place_video`）。時は動画の中の `moov/mvhd`（1904 年からの秒、UTC。この PC の時刻に直す）、所は `moov/udta/©xyz`（標準のカメラが書く ISO 6709 の文字。緯度経度の範囲の外は捨てる。`mp4_where`）。時が無ければファイルの時刻で、所が無ければ書かない。同じ名で同じ大きさの物が在れば同じ動画とみなし二本にしない。違えば `-2`、`-3`。選んだ元は写して残し、zip から取り出した物は動かす。動画は読まず、観察には入らない。
- **見せる事。** 置いた動画の道（三つまで）、写真でも動画でもなく外した物の名（五つまで）、写真が幾つの観察に分かれたか、何も入らなかった事を、話すに一行ずつ。
- 確かめ: `tests/test_bundle.py`（mvhd と ©xyz の読み、名の付け方と `.json`、中の時刻が無い時と mov、zip から外に書かない、大きすぎる zip で止める、日ごとに 6 枚、zip と mp4 を一度に入れる、0 月 0 日と鍵の掛かった物があっても残りを入れる、残りの掃除、壊れた zip の一行）。

### 5.18 公開の時に、名前を見る。サーバーの人が読んでから載る（作者 11-08「記録では本名がやりやすい」「サーバーに公開するときには、人も確認するようにしませんか？」「個人用のデータで、秘匿をしていたらやってられないでしょう。公開する時にチェックするのが一番簡単でしょう」）

## 6. 安全（守りの六つがどこにあるか）

1. 記録は本人の手元に素の文字で。`~/seed/`。— 動いている
2. 外に出るのは人が了解した行だけ。Claude の下書き → 本人が全文を読んで「出す」→ そのファイルを送る → 静的ファイル。座標は 2 桁まで（§5.2）。— 動いている
3. 鍵は repo の外。サーバーは鍵ごとに root だけが読めるファイルを `LoadCredential=` でサービス（利用者 seed）にだけ渡す（§4）。本人は `~/.config/seed/credentials.toml`（§5.1。本人の Anthropic の鍵もここで、送り先は Anthropic の API だけ）。門は招待コードと、相手ごとの token（範囲、期限、取り消し。台帳はハッシュだけ。§5.9）。誰が何をしたかは追記だけの記録に。— 動いている（5.1 と 5.9 の後。deb2 にはまだ置いていない）
4. 外れを同じ Claude が見つけて直す。座標の見本が本物だった → 見本に置き換え、走査（設計書 backup-11-06 §12）。— 済み
5. 攻撃に使われる AI で自分の機械の口を読む。halo の口の表 → 門（`deploy/halo/`）。— 設定は書いた。当てるのは作者
6. 控えと三層の認証（人はパスキー、AI は token、機械は鍵の対）。— 紙（`docs/鍵の管理の仕組み.md`）。アプリ間の token の形は `docs/研究室.md` §5b の 11-06 の追記（fieldnotes は 11-11 に seed に一本化したので、揃える相手は無くなった）

効かない所: PC とスマートフォンそのものへの侵入（本人の鍵は端末の秘密のファイルに在る）。deb2 でサービスの利用者 seed として動ける者（渡された鍵はサービスが動いている間そのサービスに見える）。控えの運用は未決。Web はアプリを置かず、使い方の説明を置く所。家のサーバー（`seed home`）の招待コードは手で打てる 6 桁（百万通り）。門は間違えた番地を 10 分に 10 回で 10 分止めるので、一つの番地から試せるのは一時間に 60 回ほど、一日に 1440 回（10 回 × 6 × 24）で、半分の 50 万通りを試すのに一つの番地で 347 日ほどかかる。番地をいくつも使える機械（IPv6 で番地を替える等）には、その数だけ速くなる（家の網の中だけに立てる形で、外へ口を開けない。§5.13）。
