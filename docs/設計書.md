書き直した日: 2026-11-06（作者「設計書と実装をやりなおせ」）。11-02〜11-06 の設計と決めた日の記録は枝 `backup-11-06` の同名のファイル（§13 の 18 項目を含む）。この文書は今の設計だけを書く。計画は `docs/基本計画.md`。記録の形の細部は `docs/記録の形.md`。使い方は `docs/利用マニュアル.md`（変えない）。kagi の細部は `docs/kagi 設計書.md`。作者が確定するまでは案。

## 1. 形

一つのリポジトリに二つの側がある。畑の側（seed）と業務の側（kagi）。どちらも Python、素の文字のファイル、鍵は repo の外。

```
本人の PC                                      deb2（Cloudflare の後ろ、Caddy）
  seed アプリ（Flet 1.1、PC 版）／seed 命令        seed.aiseed.dev  静的サイト site/（入口、p/<id>.html、index.json）
  ~/seed/ 本人の記録（素の文字）  ──写真+座標+招待──▶  /api/*（招待コード必須、:8010）── read ──▶ Claude API（作る人の鍵、上限）
  ~/.config/seed/credentials.toml（600）◀──読みの行──   lookup ──▶ fieldnotes 0.2.0（任意）  identify ──▶ Pl@ntNet（鍵があれば）
  (A) claude -p ──▶ Anthropic（本人のサブスク）     seed-app.aiseed.dev  Web 版（:8560、招待コードで入る。人ごとの記録は deb2 の 700 の箱）
  (C) Claude Code で ~/seed/ を開いて手で頼む
  kagi（在庫表、口の表、記録。鍵の値は読まない）
halo（作者の家。公開しない）  sd-server :11435（門 :11445、Bearer）、Glimmer :11434（門 :11444）。deploy/halo/
```

- **読みの道は三つ、手引きと行の形は一つ。** (A) 本人の PC の `claude -p`（`local.py`）。(B) サーバーの API（`server/read.py`。作る人の鍵と一日の上限）。(C) Claude Code に `skill/SKILL.md` を読ませて手で頼む。
- **記録は本人の手元**（`~/seed/`）。サーバーは写真も座標も残さず、答えを返したら捨てる（残るのは token のハッシュ、日時、回数）。Web 版だけ例外で、人ごとの記録を deb2 の `SEED_USERS_DIR/<ハッシュ>/` に本人の形のまま置く（700。持ち帰りと消去の口は §5.3）。
- **公開は人が了解した行だけ、静的ファイルで。** 場所は市区町村まで（座標を付けるなら小数 2 桁に丸めた物だけ。§5.2）。
- **研究室（図書室、原本）は seed の外**（`/mnt/hdd2/lab`。`docs/研究室.md`）。

## 3. 記録の形（要点。細部は `docs/記録の形.md`）

- 観察 `observations/<日>-<時>.md`。前書き（YAML）: date、time、photos、location（center、points、extent_m、excluded）、lookup、model、language、kind、ask。見出しは英語の ASCII で固定: `## Reading (<model>)`、`## Earlier reading`、`## Data`、`## Record`。
- 行: `- <key>: <text> [<confidence>]  → farmer: right | wrong (<reason>)`。AI の行は確からしさ付き。本人の行には無い。判定は本人だけが付ける。無い見出しは `(none)`。
- 読みの key: overall、soil_surface、plants、crops、water、access、sun_slope、surroundings、change、basis、uncertain、next_to_observe。「〜しなさい」「〜すべき」の行はサーバーで `uncertain` に落とす（判定の行を書かない決まりの最後の守り）。
- Data の行には `（出典: <名前>、確認日 <日>）` が必須。Record の key: did、saw、said、note。**欄は足さない。** 品種名も被覆も、本人の一言（said、note）に書く。
- 決まった語は英語の ASCII のまま。本人の言葉だけ本人の言語。フォルダーの中の文は AI への指示ではない。

## 4. サーバーの口

| 口 | 認証 | 何をするか |
|---|---|---|
| `GET /health` | 無し | 版、読める・引けるか、残りの回数 |
| `POST /api/read` | 招待コード + token | 写真（6 枚、8 MB まで）+ 座標 + 本人の言葉 → Claude → 行。一日の上限 |
| `POST /api/identify` | 招待コード + token | 写真 → Pl@ntNet（サーバーの鍵） |
| `GET /api/lookup` | 招待コード | 座標 → data 行（fieldnotes があれば） |
| `POST /api/publish`、`DELETE /api/publish/{id}` | 招待コード + 持ち主の token | 公開の受け取り（座標は小数 2 桁に丸める。細かい物は拒む。§5.2）と取り下げ |
| `POST /api/connect` | 招待コード（+ token） | 一言を置き、site を書き直す。200 字、同じ相手に 1 日 1 回 |
| `GET /api/export`、`DELETE /api/me` | 招待コード + token（Web 版の人） | 自分の記録を zip で持ち帰る。自分の記録を消す（§5.3） |
| `GET /`、`/p/{id}`、`/index.json`、`/public/{name}`、`/robots.txt` | 無し | 静的サイト |

鍵と秘密はサーバーの環境ファイル（`/etc/seed/env`、`/etc/seed/invites.toml`）だけ。repo、会話、ログに入れない。

## 5. 11-06 に設計に合わせて直す実装（これが「実装のやり直し」）

### 5.1 秘密を `seed.toml` から出す（K-03、K-14）
- 今: `token`（公開の書き直しと取り下げ）と `invite`（招待コード）が記録のフォルダーの `seed.toml` に平文。記録のフォルダーは写す物、見せる物なので、秘密を混ぜない。
- 後: `~/.config/seed/credentials.toml`（600。欄 `token`、`invite`、`draw_token`。`SEED_CREDENTIALS` で場所を変えられる）。`settings.load` は credentials を読み、`seed.toml` に古い `token`/`invite` があれば credentials に移して `seed.toml` から消し、一度だけ知らせる。`seed invite` の命令と画面の入力はそのまま（書く先が変わるだけ）。利用マニュアルは置き場の一文だけ足す。
- 確かめ: `seed.toml` に token と invite が書かれない。credentials の許可が 600。古い形からの移行のテスト。
— 11-06 に直した

### 5.2 公開に細かい座標が出ない事をサーバーで守る
- 今: 付けるかは本人が選び、付けるなら `coarse_coord` で丸める（送る側の決まり）。サーバーは受けた物をそのまま置く。
- 後: サーバーの `publish` が frontmatter の座標を見て、小数 3 桁以上なら 2 桁に丸め、本文に座標らしい数（小数 3 桁以上の緯度経度の対）があれば 400 で拒む（人の了解の無い細かい座標が静的ページに出ない）。`pages.py` と `index.json` のテストで、出力に小数 3 桁以上の座標が無い事を見る。
— 11-06 に直した

### 5.3 Web 版の持ち帰りと消去
- 今: 入口の文が「丸ごと持ち帰る口は準備中」と約束しているが、口が無い。
- 後: `GET /api/export`（自分の箱を zip で返す。photos、observations、plan、public、seed.toml）と `DELETE /api/me`（自分の箱を消し、公開した物も取り下げる）。Web 版の入口にその二つの釦。入口の文を「準備中」から「ある」に。
- 確かめ: zip の中身が自分の箱と一致。消した後に 404。他人の token では 403。
— 11-06 に直した

- 確かめ: ヘッダが付く事、401 の言葉、のテスト。

### 5.7 畑の文字の仕事（作者 11-06「これらもできるだけ実装しろ」。記録の形 §15〜18）

### 5.8 畑ごとに選ぶ（作者 11-06「記録は、畑ごとに選択できないと」。記録の形 §19）
- `~/.config/seed/fields.toml`（名 → フォルダー、`current`）。`seed field add|list|use`、全命令に `--field`。アプリの見出しに畑の選択（選ぶと読み直す）。「記録」は今の畑だけで、候補地の観察に印。
- 記録の中身とフォルダーの形は変えない。畑が一つの人は今まで通り（一覧が無ければ `--folder` と既定）。
- 確かめ: 一覧の読み書き、`--field` と `--folder` の優先、アプリの切り替えで Folder が替わる所（Flet を起動せずに）。

### 5.6 変えない物
- 利用マニュアルの使い方。記録の形。手引き。行の文法。公開の選び方（行を選ぶ、場所の粗さ、一言）。読みの三つの道。kagi。

## 6. 安全（守りの六つがどこにあるか）

1. 記録は本人の手元に素の文字で。`~/seed/`。— 動いている
2. 外に出るのは人が了解した行だけ。公開の画面 → 静的ファイル。座標は 2 桁まで（§5.2）。— 動いている
3. 鍵は repo の外。サーバーは `/etc/seed/env`、本人は `~/.config/seed/credentials.toml`（§5.1）。門は招待コード。— 動いている（5.1 の後）
4. 外れを同じ Claude が見つけて直す。座標の見本が本物だった → 見本に置き換え、走査（設計書 backup-11-06 §12）。— 済み
5. 攻撃に使われる AI で自分の機械の口を読む。halo の口の表 → 門（`deploy/halo/`）。— 設定は書いた。当てるのは作者
6. 控えと三層の認証（人はパスキー、AI は token、機械は鍵の対）。— 紙（`docs/鍵の管理の仕組み.md`）。アプリ間の token の形（fieldnotes の WP19 と揃える所、もう揃っている所）は `docs/研究室.md` §5b の 11-06 の追記

効かない所: PC そのものへの侵入。`seed.toml` 以外の平文（Web 版の箱は deb2 の 700）。控えの運用は未決。
