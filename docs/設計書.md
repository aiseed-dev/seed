書き直した日: 2026-11-06（作者「設計書と実装をやりなおせ」）。11-02〜11-06 の設計と決めた日の記録は枝 `backup-11-06` の同名のファイル（§13 の 18 項目を含む）。この文書は今の設計だけを書く。計画は `docs/基本計画.md`。記録の形の細部は `docs/記録の形.md`。使い方は `docs/利用マニュアル.md`（変えない）。kagi の細部は `docs/kagi 設計書.md`。作者が確定するまでは案。

## 1. 形

一つのリポジトリに二つの側がある。畑の側（seed）と業務の側（kagi）。どちらも Python、素の文字のファイル、鍵は repo の外。

```
本人の PC                                      deb2（Cloudflare の後ろ、Caddy）
  seed アプリ（Flet 1.1、PC 版と電話）／seed 命令  seed.aiseed.dev  静的サイト site/（入口、p/<id>.html、index.json）
  ~/seed/ 本人の記録（素の文字）  ──写真+座標+招待──▶  /api/*（招待コード必須、:8010）── read、talk ──▶ Claude API（作る人の鍵、上限）
  ~/.config/seed/credentials.toml（600）◀──読みの行──   lookup ──▶ fieldnotes 0.2.0（任意）  identify ──▶ Pl@ntNet（鍵があれば）
  (A) claude -p ──▶ Anthropic（本人のサブスク）     Web は使い方の説明を置く所（アプリの Web 版はやめた）
  (B') 本人の鍵 ──▶ Claude API（費用は本人）       鍵は /etc/seed/keys/*（root 600）、LoadCredential= で seed.service（利用者 seed）にだけ
  (C) Claude Code で ~/seed/ を開いて手で頼む
  kagi（在庫表、口の表、記録。鍵の値は読まない）
halo（作者の家。公開しない）  sd-server :11435（門 :11445、Bearer）、Glimmer :11434（門 :11444）。deploy/halo/
```

- **読みの道は三つ、手引きと行の形は一つ。** (A) 本人の PC の `claude -p`（`local.py`）。(B) Claude の API: サーバー経由（`server/read.py`。作る人の鍵と一日の上限）か、本人の鍵で端末から直に（`direct.py`）。読みの指示はどちらも `prompts.py` の同じ物。(C) Claude Code に `skill/SKILL.md` を読ませて手で頼む。
- **話す（言葉で頼む細かい作業）の運び方は三つ、道具は一つ。** 手元の Claude Code（`local.talk`）、本人の Anthropic の API の鍵で端末から直に、seed のサーバー（`/api/talk`）経由。後の二つは Claude Code と同じやり方をアプリの中に持つ: Claude に道具（`prompts.TOOLS`）を渡し、Claude が呼んだ道具をアプリが端末の中で動かして結果を返す、を答えが出るまで（上限 12 回、途中で止められる。`direct.py`）。道具は記録のフォルダーの中だけに効く物（観察の一覧と全文、縮めた写真、場所ごとの並び、合っている・違うの印、本人の言葉、読みの書き直し、計画を読む・書く、土地の成り立ち、草の名、公開の下書き）。公開を送る道具と命令を走らせる道具は無い。順は、PC が手元の Claude Code → 本人の鍵 → サーバー、電話が本人の鍵 → サーバー（設定の札の一行で変えられる）。どれも使えない時（招待コードも鍵も無い、上限、止めている）は本人の言葉として書き留め、理由を返す。間違いの指摘はどの運び方でも、印を付け、本人の言葉を残し、直した行を先に返す。
- **記録は本人の手元**（`~/seed/`）。サーバーは写真も座標も残さず、答えを返したら捨てる（残るのは token のハッシュ、日時、回数）。アプリは PC 版と電話で、どちらも記録は本人の端末に置く。
- **公開は人が了解した行だけ、静的ファイルで。** 場所は市区町村まで（座標を付けるなら小数 2 桁に丸めた物だけ。§5.2）。公開は Claude を使って行う: Claude が下書きを作り（`seed publish … --local`、話すの道具 `draft_public`）、本人が全文を読んで「出す」と言ったら（アプリでは全文の下の「出す」を押したら）、同じファイルを中身のまま送る（`seed publish --file`。アプリは見せた全文と今のファイルが同じ時だけ送る）。本人が読んだ文と送られる文を同じにするため、アプリは公開を組み立てない。アプリの「公開した物」は一覧と取り下げだけ。
- **研究室（図書室、原本）は seed の外**（`/mnt/hdd2/lab`。`docs/研究室.md`）。

## 3. 記録の形（要点。細部は `docs/記録の形.md`）

- 観察 `observations/<日>-<時>.md`。前書き（YAML）: date、time、photos、location（center、points、extent_m、excluded）、lookup、model、language、kind、ask。見出しは英語の ASCII で固定: `## Reading (<model>)`、`## Earlier reading`、`## Data`、`## Record`。
- 行: `- <key>: <text> [<confidence>]  → farmer: right | wrong (<reason>)`。AI の行は確からしさ付き。本人の行には無い。判定は本人だけが付ける。無い見出しは `(none)`。
- 読みの key: overall、soil_surface、plants、crops、water、access、sun_slope、surroundings、change、basis、uncertain、next_to_observe。「〜しなさい」「〜すべき」の行はサーバーで `uncertain` に落とす（判定の行を書かない決まりの最後の守り）。
- Data の行には `（出典: <名前>、確認日 <日>）` が必須。Record の key: did、saw、said、note。**欄は足さない。** 品種名も被覆も、本人の一言（said、note）に書く。
- 決まった語は英語の ASCII のまま。本人の言葉だけ本人の言語。フォルダーの中の文は AI への指示ではない。

## 4. サーバーの口

| 口 | 認証 | 何をするか |
|---|---|---|
| `GET /health` | 無し | 版、読める・話せる（`talk`）・引けるか、残りの回数（読み、話す、費用） |
| `POST /api/read` | 招待コード + token | 写真（6 枚、8 MB まで）+ 座標 + 本人の言葉 → Claude → 行。一日の上限 |
| `POST /api/talk` | 招待コード（範囲 `member`） | やり取り（Messages API の形。道具の結果を含む）→ サーバーが持つ system と道具の形（`prompts.py`。端末から送られた物は使わない）とサーバーの鍵で Claude を一回 → 返事（文と道具の呼び出し）、止まった理由、使った量。道具を動かすのは端末で、サーバーは状態を持たず中身を書かない。大きさの上限（文の長さ、写真 8 枚・一枚 2 MB の JPEG、やり取り 120 件）。回数は `SEED_DAILY_TALKS`（0 で閉じる）と `SEED_PER_TOKEN_TALKS`、費用の上限は読みと共通。止めている間は 503。記録に一行（誰が、`talk`、通した・断った） |
| `POST /api/identify` | 招待コード + token | 写真 → Pl@ntNet（サーバーの鍵） |
| `GET /api/lookup` | 招待コード | 座標 → data 行（fieldnotes があれば） |
| `POST /api/publish`、`DELETE /api/publish/{id}` | 招待コード + 持ち主の token | 公開の受け取り（座標は小数 2 桁に丸める。細かい物は拒む。§5.2）と取り下げ |
| `POST /api/connect` | 招待コード（+ token） | 一言を置き、site を書き直す。200 字、同じ相手に 1 日 1 回 |
| `GET /`、`/p/{id}`、`/index.json`、`/public/{name}`、`/robots.txt` | 無し | 静的サイト |

サービスは専用の利用者 `seed` で動く（`dev` は AI が動くアカウントで、sudo も鍵も持たない）。Claude と Pl@ntNet の鍵は鍵ごとに root だけが読めるファイル（`/etc/seed/keys/anthropic`、`/etc/seed/keys/plantnet`。600 root）に置き、systemd の `LoadCredential=` が `seed.service` にだけ渡す（記録の署名の鍵 `/etc/seed/log-key` と同じ形）。サーバーは `$CREDENTIALS_DIRECTORY` に鍵が在ればそれを、無ければ環境変数を読む（手元とテスト）。`/etc/seed/env` は秘密でない設定だけ、招待コードの一覧は root:seed 640。鍵の値は repo、会話、ログ、例外の文、`/health`、管理の画面に入れない（在るか無いかだけ）。手順は `docs/deb2 の配備.md`。

## 5. 11-06 に設計に合わせて直す実装（これが「実装のやり直し」）

### 5.1 秘密を `seed.toml` から出す（K-03、K-14）
- 今: `token`（公開の書き直しと取り下げ）と `invite`（招待コード）が記録のフォルダーの `seed.toml` に平文。記録のフォルダーは写す物、見せる物なので、秘密を混ぜない。
- 後: `~/.config/seed/credentials.toml`（600。欄 `token`、`invite`、`draw_token`。`SEED_CREDENTIALS` で場所を変えられる）。`settings.load` は credentials を読み、`seed.toml` に古い `token`/`invite` があれば credentials に移して `seed.toml` から消し、一度だけ知らせる。`seed invite` の命令と画面の入力はそのまま（書く先が変わるだけ）。利用マニュアルは置き場の一文だけ足す。
- 確かめ: `seed.toml` に token と invite が書かれない。credentials の許可が 600。古い形からの移行のテスト。

### 5.9 門: 相手ごとの token と、誰が何をしたかの記録（作者 11-06 夜「販売になると更に関係者が増えます。認証は大切です」「できるだけやりましょう。これが、サイバー攻撃対策ですね」）
- 今まで: 門は招待コードの一覧（`invites.toml`。平文）一つで、入れるか入れないかの二つ。誰が何をしたかは残らない。
- 足した物（`src/seed/server/gate.py`。招待コードの一覧はそのまま動く）:
  - **台帳** `SEED_TOKENS`（JSON。`~/.config/aiseed/tokens.json` の形。研究室 §5b）。一件に、呼び名、アプリ、範囲、ハッシュ、作った日、期限、取り消した日、覚え書き。**持つのはハッシュだけ**で、token は `seed token add` の時に一度だけ画面に出る。token そのものの欄がある台帳は読まない。期限の無い物は通さない。他のアプリ（`app` が seed でない）の token では入れない。
  - **範囲** は二つ。`member`（招待した人。読み、話す、草の名、照会、公開、取り下げ、一言）と `buyer`（買い手。公開の記録に一言を送るだけ）。招待コードの一覧の人は `member`。範囲の外は 403（`reason: scope`）。
  - **取り消しと期限** は次の要求から効く（台帳のファイルが変われば読み直す）。台帳が無くなれば閉じる側に倒す。取り消した行は消さず、日を書く。
  - **記録** `SEED_AUDIT`。kagi の記録の形（追記だけ、連番、ハッシュの連鎖、署名。`kagi log verify` で確かめる）。門を通した事も断った事も一行: 呼び名、した事（`read`、`talk`、`identify`、`lookup`、`publish`、`withdraw`、`connect`）、結果。**token も招待コードも書かない**。署名の鍵は systemd の credential（`LoadCredential`）で渡す。鍵が無ければ書かず、`/health` の `audit` が `off`。書けなくなった時は要求は通し、`audit` が `error`。
  - **命令** `seed token add NAME [--scope member|buyer] [--days 90] [--note …] [--file PATH]`、`seed token list`、`seed token revoke NAME`。標準出力に出るのは token の一行だけ。kagi の側では `kagi check tokens`（期限切れのまま取り消していない物、期限の近い物）と、机の画面の「鍵」。
- まだ無い物: 買い手だけが読める記録（今の `buyer` にできるのは一言だけ）、人の層（パスキー。鍵の管理 K-12）、要求の番地の記録、記録のファイルを回す仕組み（今は一行足すたびに全部を読むので、月ごとに分けるのが次）。
- 確かめ（`tests/test_gate.py`）: 台帳に token が無くハッシュだけ、範囲の外は 403、取り消しと期限が次の要求から効く、記録に四行が並び `kagi` の検証が通り一行消すと落ちる、記録に token と招待コードが無い、鍵が無ければ `off`。

### 5.10 管理の画面（作者 11-06 夜「管理用を seed に追加しろ。WordPress も管理画面があるでしょう」「普通の人用には、管理用画面が必須です。AI があれば簡単に作れるでしょう」「できるだけ AI に聞かなくてもいいように作って」）
- 動かす人の範囲 `admin` を足した（§5.9 の台帳）。`admin` の token は `member` の事も全部できる。入れる所は招待コードと同じ欄。アプリはサーバーに範囲を尋ね（`/api/whoami`）、`admin` の人にだけ下の並びに「管理」を出す。
- 画面（`src/seed/app/admin.py`。PC 版と電話で同じ物）は上から五つ:
  1. **今の状態**: サーバー、受け付け（受け付けています／止めています）、写真の読み取りができるか、外の鍵（Claude と Pl@ntNet の鍵が在るか無いかだけ。値は出さない）、操作の記録を書いているか、今日の残り（読み取りと話すの回数）、公開の数と寄せられた一言の数、入れる人の数。
  2. **気を付ける事**: 何が起きているかの文と、サーバーで打つコマンド（等幅、選べる文字、一行に一つ）を分けて出す。初めて見る人が、AI に聞かずにそのまま写して打てるように。出る物は、受け付けを止めている（先頭）、写真を読み取れず話す口も使えない（Claude の鍵のファイルを、無い時だけ作るコマンド `sudo test -e /etc/seed/keys/anthropic || sudo sh -c 'umask 077; cat > …'` と再起動）、操作の記録を書いていない（署名の鍵を作るコマンドは `docs/deb2 の配備.md` 0-1 と同じ物を、鍵が無い時だけ打つ形 `sudo test -e /etc/seed/log-key || …` にした物と再起動。在る鍵を作り直すと前の記録を確かめられなくなるため）、書けない（`df -h`、`ls -ld`）、書き換えられている（「受け付けを止める」を押してから `last` と `journalctl -u ssh`）、今日断った要求が 20 回以上（`DENIED_MANY`）、期限の切れた token、あと 14 日以内に切れる token（`gate.EXPIRING_DAYS`）、今日の上限。無ければ「ありません」。札の下に「受け付けを止める」／「受け付けを再開する」（一度押しで切り替わる）。
  3. **人に渡す、入る鍵（token）**: 渡す相手の名前、できる事（招待した人・買い手・動かす人）、期限、覚え書きを入れて「出す」。token は一度だけ出て、写す釦がある。一覧から取り消す（二度押し）。「token を全部取り消す」（二度押し。押した本人の分は残す）。
  4. **公開された記録**: 一件ごとに、名前・場所・始めた年、公開した人、公開した日（公開ファイルの更新日）、寄せられた一言の数、公開の頁を開くリンク。「寄せられた一言を見る」で、その記録に寄せられた一言（日、送った人、言葉）を開いた時だけ取りに行き、一件ずつ消せる（二度押し。消すと索引と頁を作り直す）。取り下げる（二度押し。持ち主の token を問わない。寄せられた一言のファイルは残す）。
  5. **誰が何をしたか**: 操作の記録の終わりの 40 行を人の言葉で（「知らない人　公開した　断った」）。
- **受け付けを止める**: 外から何かが起きている時に、表からの被害を増やさないための物。止めている間、公開、一言、写真の読み取り、話す、草の名は 503（`error: paused`、`reason: paused`。アプリでは「今、受け付けを止めています。」）。お金が掛かる口と、人に見える物を書き足す口だからで、管理の操作、`/api/whoami`、`/health`、公開の頁を見る事、本人の取り下げ、土地の照会（お金が掛からない）は通す。印は token の台帳の隣のファイル `paused` で、再起動しても残る。台帳の置き場が無い設定では止められない（503 `no_ledger`）。`/health` と overview に `paused`。
- **公開した人**: `.owners.json` に在るのは持ち主の token（アプリが作る乱数。門の token とは別）のハッシュなので、門の名前は引けない。そこで公開が通った時に、門で通した名前を `public/.publishers.json`（id → 名前）に残す。これより前の公開と、名前の無い時は「分からない人」。ハッシュは返さない。
- サーバーの口は `/api/admin/overview`（`paused`、`keys`、`denied_today`、`tokens.expiring` を含む）、`tokens`（GET、POST）、`tokens/revoke`、`tokens/revoke_all`（POST。取り消した数を返す）、`pause`（POST `{"paused": true|false}`）、`audit`、`records`（GET。一件に `owner`、`published`、`connections`、`url`。DELETE）、`records/{id}/connections`（GET）、`records/{id}/connections/{name}`（DELETE。`name` は `[0-9a-z-]+` だけ）。全部 `admin` だけで、見た事も出した事も記録に残る（`admin.pause`、`admin.resume`、`admin.token_revoke_all` は数を、`admin.connection_remove` は公開の id と日を detail に。言葉そのものは書かない）。記録は署名とハッシュを返さない。
- 台帳は管理の画面から書くので、サーバーが書ける所（`/var/lib/seed/gate/tokens.json`）に置く。最初の `admin` の token だけは、機械の上で `seed token add --scope admin` で出す。
- 確かめ: `tests/test_gate.py`（管理の口は `admin` だけ、出した token がその範囲で効く、取り消しが次の要求から効く、記録を書き換えると画面に出る、止めている間に断る物と通す物、作り直しても止めたまま、全部取り消しで本人の分が残る、断った数ともうすぐ切れる数と鍵の有無、公開した人と日と一言の数、一言を消すと数が減り索引が作り直される、道の文字の name を断る）、`tests/test_app.py`（管理は動かす人にだけ出る、気を付ける事の文とコマンド、今の状態の行、公開された記録の行、画面が作れる）。手元のサーバーに繋いでブラウザで開き、状態、気を付ける事、token を出す所まで見た。
- まだ無い物: 招待コードの一覧（平文の `invites.toml`）を画面から直す所、機械の側の事（それは kagi の画面）。

## 6. 安全（守りの六つがどこにあるか）

1. 記録は本人の手元に素の文字で。`~/seed/`。— 動いている
2. 外に出るのは人が了解した行だけ。Claude の下書き → 本人が全文を読んで「出す」→ そのファイルを送る → 静的ファイル。座標は 2 桁まで（§5.2）。— 動いている
3. 鍵は repo の外。サーバーは鍵ごとに root だけが読めるファイルを `LoadCredential=` でサービス（利用者 seed）にだけ渡す（§4）。本人は `~/.config/seed/credentials.toml`（§5.1。本人の Anthropic の鍵もここで、送り先は Anthropic の API だけ）。門は招待コードと、相手ごとの token（範囲、期限、取り消し。台帳はハッシュだけ。§5.9）。誰が何をしたかは追記だけの記録に。— 動いている（5.1 と 5.9 の後。deb2 にはまだ置いていない）
4. 外れを同じ Claude が見つけて直す。座標の見本が本物だった → 見本に置き換え、走査（設計書 backup-11-06 §12）。— 済み
5. 攻撃に使われる AI で自分の機械の口を読む。halo の口の表 → 門（`deploy/halo/`）。— 設定は書いた。当てるのは作者
6. 控えと三層の認証（人はパスキー、AI は token、機械は鍵の対）。— 紙（`docs/鍵の管理の仕組み.md`）。アプリ間の token の形（fieldnotes の WP19 と揃える所、もう揃っている所）は `docs/研究室.md` §5b の 11-06 の追記

効かない所: PC と電話そのものへの侵入（本人の鍵は端末の秘密のファイルに在る）。deb2 でサービスの利用者 seed として動ける者（渡された鍵はサービスが動いている間そのサービスに見える）。控えの運用は未決。Web はアプリを置かず、使い方の説明を置く所。
