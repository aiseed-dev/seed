# 基本計画 — seed（Built with Claude: Japan 2026）

書き直した日: 2026-11-06（作者「計画をきちんと作り直せ」）。11-02〜11-06 の計画と言葉の記録は枝 `backup-11-06` の同名のファイルにある。この文書は、今の計画だけを Fable の言葉で書く。作者が確定するまでは案。

## 1. 一行と主題

**seed — Claude と一緒に種を播く。** 畑の写真と場所を自分の Claude に渡して、畑を読むための手引きとアプリ。持ち込む物は、生物学・気象・地質の読み（出典付き）で、農業のやり方ではない。

**主題（テーマ 1「あなたにしかない深さを」）: AI との付き合い方 — 業務システムと自然農法を比べてみた。** 作者は、会社のシステムを IT 業者に預ける側に居て、今は徳島の元田んぼで四年間肥料を入れずに自然農法を試している。二つの世界に身を置いてきたから見えた事が一つある。AI との付き合い方は分野で分かれるのではなく、二つの問いで分かれる。

1. **世界が文字で書かれているか。** サーバーは構成も口も鍵の置き場も全部読める。畑は、この土で今何が起きているかを誰も書いていない。
2. **結果を機械が確かめられるか。** サーバーはテストと動作で機械が確かめる。畑の結果は季節が返し、見るのは人。

**主題がはっきりした（作者 11-06 夜）。** 比べていた二つは、一つの物の表と裏だった。

- 表: 畑を始める人のアプリ。「seed は、自然農法を始める人のためのアプリ」。
- 裏: それを安全に動かす仕事。「でも、これを安全に動かすためには、裏で多くのことをしないといけない。こちらもできるだけ AI にさせないと回らない」。機械を入れて動かす、認証、鍵の管理、管理の画面、スマートフォンのアプリ。
- 裏は、普通の人にはできず、業者に預けてきた所。「Linux マシンのインストールや運用は難しかったけど、AI 時代には逆に簡単になる」「普通の人用には、管理用画面が必須です。AI があれば簡単に作れるでしょう」。
- 作る事と守る事は別。作者（11-06 夜、主催の Applied AI Architect チームのセッションを受けて）: 「コンピュータサイエンスの知識がなくてもできる。でも、それだけでは守れない」「ビルダーになるためには、守りのスキルが必要だということですね」。裏付けは作者の三台で測った事: 三台とも出る向きの防火壁が開いていた、入口の機械の ssh はパスワードの入口が開いていた、どの機械にも表に無い鍵が一本入っていた、ルーターの管理の口に入口の機械から届いた。作って動かしている本人の機械でも、見るまで分からなかった。
- 普通の人の手に届く形は二つ。スキル（自分の Claude が毎回同じに進める。「スキルを作るのが重要」）と、画面（「できるだけ AI に聞かなくてもいいように作って」）。

動画の最初の字幕は作者の三文のまま使う。「AI で雇用は減少する。でも、人間のやることは増える。守るためには人がいる。」

**一週間の成果（作者 11-08「多くのスキルを作って、仕事がなくならないことがわかった」）。** 作ったのは手引き（Skill）11 組（`skill/` 14 章、`skill-keeper/`、`skill-builder/`、`skill-kagi/`、`skill-folder/`、`.claude/skills/` 6 つ）、引く資料 470 余り。11-08 に始める人に要る分野を足すほど（作業の安全、片付けと燃やすこと、水と土地改良区、集落の共同作業、加工と表示の法令、井戸、竹、蜂、残った果樹）、まだ足りない分野が見えた（設計書 §5.16）。一週間で全部は出来ない（作者 11-08「これだけは理解しておいて」）。だから、AI で人の仕事は無くならない。手引きを書く、Claude が読んだ物を畑で確かめる、読んだ資料を出典付きで足す、の形に変わる。この事を書く場所は、README の頭、ここ、動画の結び、提出の概要の結び。

## 2. 誰のために

二人いて、どちらも AI が助けるが、助け方が反対。

| | 畑を始めたい一人 | 業務システムを守る係 |
|---|---|---|
| 困っている事 | 本当に育つのかの不安、自分の土地を知らない、聞ける人がいない。肥料の供給が不安定になり（りん安の 7 割は中国、2026 年に輸出がほぼ止まった）、攻撃で水や電気や肥料が止まりうる | ランサムウェアの被害 116 件のうち中小企業 77 件、侵入は VPN とリモートデスクトップの機器からが 8 割以上、原因は安易な ID・パスワードと不要なアカウント（警察庁 令和 7 年上半期） |
| AI がやる事 | 人が見て撮った写真と一言を読み、出典を並べる | 現状を調べ、対策を書き、確かめ、直す。守りは終わらない |
| 人に残る事 | 見る。減らす。何を残すか決める | 何を守るか決める。これでよいと決める。できたかを確かめる |
| 道具 | seed（§4） | 鍵の管理の仕組みと kagi（§5） |
| 使い続ける人 | 作者。記録は年を重ねて初めて意味を持つ | 作者。自分のサーバーと扉で |

**11-06 夜にはっきりした事。** 右の列の人は、遠くの会社の係ではなく、仲間のために入口を動かすビルダー。畑を始めたい人が記録を人と並べるには、誰かが入口を持たないといけない（§5 の表）。

人の仕事は同じ三つ（決める、決める、確かめる）で、その前に「調べる」がある。サーバーの調べは AI が一日でできる。畑の調べは人が見るしかない。違いは AI の取り分の大きさだけで、畑では記録が無ければ AI は何もできない。だから畑では記録を残す事が一番大事になる。

この二つを選んだ理由（作者 11-06）: どちらも普通の人の経験が使えず、改善の案が出ない所で、経験でなく論理（何の事実で決まるかを並べて決める）でやる問題。AI の効果は「AI 無しでできた事」との差で決まり、アプリを作る・データを分析するは人を雇えばできたが、守りと無肥料の畑は止まっていた。0 から動く所の方が効果は大きい。

## 3. 常識と、ここでの決め（この計画の背骨）

この計画は、今までの常識と反対の決めを十三並べた物で、それぞれ何の事実で決めたかを付ける（作者 11-06「計画は常識的になるな」「過去の常識にとらわれるな」）。常識の側が間違いだったのではなく、AI が無く、肥料も輸入も安かった時代には合理的だった。変わったのは、AI が文字で書かれた仕事を一日でやる事と、輸入と委託が止まりうる事。

| 常識 | ここでの決め | 決めた事実 |
|---|---|---|
| システムは IT 業者に委託する | 委託先に残る物は無い。現場に居て責任を負い設計を確定する一人を社内で雇い、仕事は AI がやる | 書く・調べる・確かめる・直す・待つは全部文字の仕事で、AI が一日でやった（kagi、§5）。事故の損は委託していても会社が負っていた（中小 77/116） |
| 認証は Entra ID に一律に預ける | Microsoft からは Office のアプリだけ買う。ID と鍵と記録は自分の側（パスキー、仕事ごとの門、kagi、係） | §5c の会社は Entra の機能をほぼ使わない。相手の鍵が盗まれると全部偽造される（Storm-0558、2023） |
| 社外からは VPN で社内に入る | VPN は無い。仕事ごとの口にスマートフォンのパスキーで入る。古いシステムには前に門を置く | 侵入の 8 割以上が VPN と RDP の機器から。VPN は網に入る口で、一台の感染で社内の全部に届く |
| 業務には Windows の PC が要る | スマートフォンが業務の端末。Windows はそこでしか動くアプリのためだけ | 日常生活はスマートフォンで足りている。鍵はスマートフォンに二つ（Wallet の社員証とパスキー） |
| AD には Windows Server を買う | Samba を AD にする。今の AD に相乗りで入れて役を移す | ライセンス 0。業者の作業（数十万〜数百万円）は文字の仕事で AI がやる |
| 農業は肥料と農薬と種子を買い、業者の言う通りに作る | 無肥料で、自分の畑を見て、記録を残す。やり方は教えない | りん安の 7 割は中国で 2026 年に輸出がほぼ止まった。無施肥の田は 10 年で落ち着いて 2〜4 t/ha。畑は見えるから分かる |
| 記録は決まった欄に数字を入れる | 記録は写真と本人の一言だけ。欄を足さない。測る・区を作る・数える手を勧めない | 自然農法にソフトウェアが使えなかったのは欄に入れる数字が無かったから。AI は写真と言葉を読める |
| AI の読みを答えとして使う | AI の行は確からしさ付きの仮説。事実は出典付きの行と本人の言葉と本人の判定だけ。判定の行は書かない | 草の名を二度外した。固さは写真に写らない。決めるのは畑を知っている人 |
| AI が AI の仕事を確かめれば足りる | 人が確かめる列を残す | 同じ系統が同じ系統に強く配慮する（Anthropic 2026-11-05、差 75 ポイント）。Fable が Opus を確かめた形にそのまま乗る |
| Web アプリで公開し、サーバーに記録を集める | 主は PC 版。記録は本人の手元。公開は了解した行だけで座標は 2 桁まで。Web 版は従 | PC 版はサーバーも口も鍵の置き場も要らない。全員の記録を集めるサーバーが無ければ一度に抜かれる物が無い |
| git の履歴は残し、書き換えない | 今の版だけ。コミットは区切りだけ一行で | AI が積む履歴は読まれず、消したい物を抱え込む。決めた日と理由は文書にある |
| 専門家の経験が要る | 経験は使えない。論理（何の事実で決まるかを並べて決める）と、自分の所でやってみせる事 | 守りと無肥料の畑は普通の人に案が出ず止まっていた所。AI の効果は 0 から動く所で一番大きい |
| 「普通はこうする」で始める | 作法を物ごとに、ここで誰が読むか・何が困るかで見る。全部疑うのも極端 | テスト・出典・控え・鍵の許可は今も役に立つ。細かいコミットと長い履歴は AI の量で意味を失う |

見直さない物は一つだけ。何を守るか決め、これでよいと決め、できたかを確かめる人。その人の中身は変わる（書く人から出して確かめる人へ、預ける人から持つ人へ、教わる人から見て書く人へ）。AI も変わる（量を出す側から、読まれる物だけを出す側へ）。

## 4. 畑の側 — seed

**何をする。** 写真（一度に 6 枚まで）と場所を自分の Claude に渡すと、手引き（Skill）を読んだ Claude が、座標から公開の地図（地形、地質、土壌、筆の形、史跡）を出典付きで引き、写真に写る草と地面を一行ずつ確からしさ付きで読む。本人が「合う」「違う」を付ける。選んだ行だけ公開し、場所は市区町村まで。計画（`plan.md`）には無肥料（`no_input`）の案を出典付きで並べる。

**何をしない。** やり方を教えない（畑は見えるから分かる）。判定の行を書かない。欄を足さない（記録は写真と本人の一言。品種名も被覆も、本文に書けばよい）。測る・区を作る・数える手を勧めない（作者「分析的なことはやらない」）。

**記録の形**（`docs/記録の形.md`）: 素の文字のファイルが本人の PC に残る。AI が無くても読め、AI が替わっても残る。今まで自然農法にソフトウェアが使えなかったのは、決まった欄に入れる数字が無かったから。写真と一言を読める AI がそれを変えた。

**画面も同じ（作者 11-06 夜）。** 「全部の画面がこれまでの作り方。AI 時代の作り方にかえて」「Form 形式はすべてなくせ」「Claude Code のようにチャット形式にすればいい」「フォームにはできないでしょう」「自然農法のアプリが今まで作りづらかった理由です」。土の種類、洪水の区域、昔の空中写真、目の前の草むら、かぼちゃを見つけた日。種類も形もばらばらで、畑ごとに在る物が違う。欄を決めると、欄に合わない物が落ちる。だから画面は、文と写真と、Claude とのやり取りにする。分担は、文字の細かい作業は本人の Claude Code、写真（撮る、見渡す、選ぶ、外す）はアプリ（「細かい作業は、Claude Code でやればいい」「Claude Code でやりづらいのが、写真の管理」）。機能ごとに画面を作らず、「こういうことが出来ますと出せばいい」。記録と観察は楽しく（「記録と観察をできるだけ楽しくできるソフトでないとダメでしょう」）。自然農法はやる事が多いので、畑では撮るだけにする。フォームにするのは、決まった物を決まった形で扱う側だけ（「認証管理アプリ…こちらは、フォーム形式にして厳格に管理する。自然農法のアプリはそういうアプリでないから、もっと自由にやる」）。アプリは PC とスマートフォン（iPhone、Android）。Web は使い方の説明だけ（「Web 版だと何もできないでしょう」）。サーバーの Claude を使う分は作者の鍵の費用になるので、使うのは写真の読み取りだけ。

**畑の仕事にも、全部文字で書かれている部分がある**（作者 11-06）。農地の手続き（農地法の許可、農業委員会、契約）、補助金と届出、法令、土壌図と地質図と気象の記録、売る時の帳簿と請求、種のロットの記録。これらは欄のある世界で、サーバーの仕事と同じく AI が調べ、書き、確かめられる。手引きの 13 章（手続きと農地）、11 章（売る）、12 章（加工）がその側。畑そのもの（この土で何が起きているか）だけが人の目で、そこは記録を残す。畑の人が AI と一緒にやるべき仕事は、畑の外の文字の仕事で、それは今まで一人で抱えて止まっていた所。

**読みの道は三つ**（手引きと行の形は一つ）: 本人の PC の `claude -p`、サーバーの API、Claude Code に直接。Claude が使えなくなっても記録は読める（向かう先。今すぐでなくてよい）。

**畑も面で見る（作者 11-06 夜）。** 「画像や音声データはすぐに大きな容量が必要になりますよね」「気象データも大きくなります」「ポイントだけでは情報が少なすぎでしょう」「畑も同じでしょう。自分の畑だけを見ていたのではよくわかりません。協力してデータを集める必要があります」。気象が一地点の値だけでは読めないのと同じで、畑も一枚だけでは、その草や土がその土地の事か、どこでも同じ事かが分からない。だから記録を人と並べる。§3 の「記録は本人の手元。公開は了解した行だけ」は変えない: 本籍は本人の PC で、集まるのは本人が了解した物だけ。今ある物は、了解した行の公開、公開の索引、一言の繋がり。まだ無い物は、同じ地質・土・標高の畑を並べる所と、写真の元を了解付きで預かる置き場（重いので halo。kagi 計画書 §10 の機械ごとの役）。公開の座標は 2 桁までなので、畑は座標でなく土地の行（地質、土、地形、気候）で並べる。

**売ると関係者が増える（作者 11-06 夜）。** 「販売になると更に関係者が増えます。認証は大切です」。自給の間は本人と、招待した数人。売ると、買い手、加工する人、運ぶ人、決済、宿や教室の客、届け出の先が加わり、相手ごとに見せてよい物が違う（買い手には公開した行とロットの記録。座標、写真の元、帳簿、他の買い手の事は見せない）。今の seed の門は招待コード一つで、入れるか入れないかの二つしか無い。要る物は、相手ごとの範囲（fieldnotes の WP19 の `buyer` の形。研究室 §5b）、相手ごとに出して取り消せる token と期限、誰が何を見たかの記録（kagi の記録の形）、買い手の個人情報の置き場（公開の機械と分ける。kagi 計画書 §10）。作者「できるだけやりましょう。これが、サイバー攻撃対策ですね」→ 同じ夜に入れた物: 相手ごとの token の台帳（ハッシュだけ、範囲 `member`／`buyer`、期限、取り消し）と、誰が何をしたかの記録（設計書 §5.9）。まだ無い物: 買い手だけが読める記録、人の層（パスキー）、買い手の個人情報の機械。deb2 にはまだ置いていない。

**アプリ**: Flet 1.1（Python だけで PC の窓・Web・スマートフォンに同じコードで出る。作者は Flet を広めたい側で、seed はその実例）。 流れの中に置くと言いやすい。Discord は 2026-11-04 に、十年使った Electron と React Native を捨て、デスクトップもモバイルも Rust（画面は GPUI）で書き直していると CTO が確かめた（公開の日は未発表）。書き直す費用が下がったから、動いている物を作り直す方が安くなった。向きは、Web のブラウザを丸ごと抱えるアプリから、機械の性能を直に使う物へ。Flet は同じ側に居る。Flutter が GPU で描き、Python は中身だけを書き、三つの端末で一つのコード。Discord が Rust でやる事を、Python の人がやる道が Flet。 書き直せる理由の大きな一つはテストの作りやすさ（作者 11-06）。古い物と同じ入力で同じ答えが出るかを機械で比べられる所では、AI が書き直し、機械が確かめ、人は結果を見るだけで済む。Rust は型と検査が強く、Discord が「見た目と動きは同じ」と言えるのはそれを機械で確かめているから。seed も同じで、312 のテストがあるから Opus に書き直させ、Fable が数分で確かめられた。畑にもテストはある。種を播いて季節を待てば答えが返る。ただし一回に一年かかり、一年に一回しか回せない（作者 11-06「テストが無いのではない。時間がかかる」）。二つ目の問いの中身は、確かめられるかではなく、一回の確かめに何秒かかるか。サーバーは秒、畑は年。 もう一つは条件の多さ（作者 11-06）。サーバーは条件を固定できるので、同じ入力なら同じ答えが返り、一回で一つの事が分かる。畑は天気も土も品種も年も固定できず、一回の結果がどの条件によるかを分けられない。だから試験場の 49 年の試験でも、りん酸と微生物と水と品種のどれがどれだけ効くか分けられなかった（`docs/りん酸と無肥料の現状.md` §2c）。一回が長く、条件が多い。この二つで、畑では記録を年を重ねて残す事しか手が無い。画面は入口、観察、記録、計画、公開、探す。Web 版は招待コードで入る。使い方は `docs/利用マニュアル.md`（変えない）。 **主は PC 版、Web 版は従**（作者 11-06「やはり Web よりも楽」）。PC 版は、サーバーも口も招待コードも鍵の置き場も要らず、記録は手元、読みは `claude -p`、動画も GitHub の main と同じ版をそのまま撮れる。Web 版はスマートフォンの人とテスターのための物で、deb2 と Caddy と人ごとの箱と門が要る（配備 §0）。業務の側も同じで、kagi の係の机の画面は PC 版だけ（Web 版は作らない。口を開けない）。

**守りの六つ**: (1) 記録は人の手元に素の文字で、(2) 外に出るのは人が了解した行だけ、(3) 鍵は repo の外・門は招待コード、(4) 外れを同じ Claude が見つけて直す、(5) 攻撃に使われる AI で自分の機械の口を読む、(6) 控えと三層の認証（紙の物）。

**この畑**: 徳島、吉野川沿いの藍のふるさと、三波川帯の片岩が川で運ばれた氾濫平野の元田んぼ。福岡正信の一反百姓（『無』3 第 5 章）を読んで立てた計画で、seed はその続きを自分の Claude と一緒にやってみる物。成り立ちの出典は README と手引き 02。

**守りのスキル（これから。作者「スキルを作るのが重要」）。** 今あるスキルは畑の側だけ（`skill/`、14 章）。裏の側は道具と文書になったが、動かす人の Claude が読んで同じに進められる形になっていない。裏の仕事は順が決まっていて、間違えると入れなくなる・止まる。だからスキルにする。

- 形: `skill-keeper/SKILL.md` と章。畑のスキルと同じ作り（読む順、してはいけない事、章、出典）。
- 章: 何を守るか（機械の役と置く物）、機械を入れる、入口と鍵、守りの基本、今の形を見る（kagi）、門と token と管理の画面、控え、網、週の定例、出典。
- 決まり: AI は鍵と token の値を見ない。機械を変える手は文で出し、打つのは人。届く・届かないは測ってから書く。理由は現場の事実から書く。
- 材料: kagi 設計書 §3.4b（連載の章との対応表）、手引き、配線図、deb2 の配備、設計書 §5.9・§5.10、作者の連載（ https://aiseed.dev/debian-server/ ）。
- 確かめ: 作者の三台で、スキルだけを読んだ Claude が、写しを取り、差を読み、直す手を出す所まで行くか。

**連載の担当との議論（11-06 夜。作者「website の opus と議論して」）。** 論点は「ビルダーになるためには、守りのスキルが要る」。

| | 中身 |
|---|---|
| 合う | 守りは、連載のビルダーの四つの手順の「確かめる」の中にあり、深く学ぶ物（連載 1-04、1-02）。鍵の値は人が置き、AI には置き場の名だけ（2-02）。AI と話すのはビルダー一人で、仲間は道具を使う（2-02）= 使う側と動かす側 |
| 合わない | 実行の手。公開されている連載 2-02（2026-09-20、見直し 10-05）は、AI に root を渡す。壊れても初期化して始め直せるからで、人が持つのは初期化で戻らない三つ（鍵と認証、外でやる操作、データの写し）。AI がやる前に言う操作は六つ（DNS を変える、防火壁に新しい口を開ける、メールを外へ送る、外のサービスのデータを消す、OS を初期化する、機械の外の写しを消す）。担当は議論で、これを重要な八つ（下）に広げ、それ以外は一つずつ確認せず結果を検証する、と言った。守りのスキルは、機械を変える手を全部人が打つ。担当の懸念: 守りになるのは打つ事ではなく、読んで分かる事 |
| 決まった事（作者 11-06 夜「渡さない」） | AI が動くアカウントに sudo を渡さない。人のデータを預かる機械では、初期化で戻るのは OS だけで、預かった記録と写真は控えから人が戻すしかない。だから変える力を AI の側に置かない（連載 2-02 より厳しい所）。連載の八つに当たる手は、人が読んで確かめてから打つ。それ以外の sudo の手は、人が通し、もう一度写しを取って結果で確かめる |

| 連載の側で直す物（担当が作者に出す） | 1-04 に、動かしている間の確かめを足す（今夜の四つは、作った時の確かめでは見つからなかった）。2-17 と 2-02 の「一つずつ」を揃える。2-02 の八つの 1 の範囲をはっきりさせる |

担当が挙げた八つ（スキルはこの八つで分ける。公開の 2-02 の六つは、八つの「外でやる操作」「外への口を開ける」「取り消せない操作」に入る）: 秘密のある機械への反映、鍵の作り直し、外でやる操作、取り消せない操作、権限を渡す・取り消す、外への口を開ける、新しいソフトや外のサービスを入れる、控えと記録の設定を変える。

**機械の持ち方の想定（作者 11-06 夜「PC をどうするかは、いろいろ想定したほうがいいですよね」）。** 今のスキルと道具が試してあるのは、作者の形（机、入口、データの三台）だけ。使う人の持ち方は違うので、形ごとに、役（机、入口、データ、個人情報）がどこに乗るかと、その形で守れない物を並べる。

| 形 | 役の乗り方 | データを人と共有するには | この形で守れない物 | 試したか |
|---|---|---|---|---|
| スマートフォンだけ | 机も入口も無い | 人が動かす入口が要る。記録の置き場もその人のサーバー | その人が止めると止まる | 試していない |
| PC 一台 | 机だけ。入口を持たない | 人が動かす入口が要る。手元だけでは、観察も読みも記録もできるが、公開も、探すも、一言も動かない | 守る物は PC そのもの（盤、控え、更新） | 机の PC で写しと突き合わせまで |
| PC と、借りた機械 | 机は家、入口は借りた機械 | 自分の入口で共有できる | 入口の機械の盤は貸す側の物。雛形の設定が先に効く事がある | 試していない |
| PC と、家の一台 | 入口とデータが同じ機械 | 自分の入口で共有できる | 入口が破られると、同じ機械のデータに届く | 試していない |
| PC と、家の二台 | 入口とデータを分ける | 自分の入口で共有できる。重いデータも置ける | 同じ網に居る間は、番地を名乗る手が残る（配線図） | 作者の今の形。写し、突き合わせ、届くかを測った |
| 上に、もう一台 | 個人情報を分ける。盤を暗号化 | 相手の情報を、入口とデータから離して持てる | 再起動のたびに、人が合言葉を打つ | 入れていない |

**共有には、誰かの入口が要る（作者 11-06 夜「seed の PC 版はこの形で全部動きます。でも、これではデータを共有できない」）。** PC 一台とスマートフォンだけの人は、使う側。畑を面で見る（§4）には、仲間のうち誰かが入口とデータの機械を動かす側になる。動かすのはビルダー（作者「共有には、誰かの入口が要る。ビルダーがやらないといけないでしょう」）。裏の仕事（機械、認証、鍵、管理の画面、守りのスキル）は、そのビルダーのための物で、畑のスキルの 08 章（ビルダーの訓練）の続きになる。今は、動かす側は作者の deb2 だけで、まだ置いていない。今共有できるのは、了解した行（文字）だけで、写真の元を預かる置き場は無い。

形が変わっても、する事の順は同じ（表を書く、写しを取る、差を読む、直す手を打つ）。変わるのは、表に書く機械の数と、入口の章と網の章を読むかどうか。スキルの 00 章に、この表と、形ごとにどの章から入るかを足す。

**例**: Windows/Samba のファイル共有の会社（同 §5c）。スマートフォンを業務の端末にする（Wallet の社員証とパスキー。同 §5d）。ノート PC に VPN を入れない。古いシステムには前に門を置く。ERP（aiai-tools の Tryton）は仕事ごとの口の例（kagi 計画書 §9）。

**委託先に残る物は無い。** 書く・調べる・確かめる・直す・待つは AI。現場に居て、責任を負い、設計を確定する一人は、社内で雇う。それが「人を育てる事が移る先になる」の中身。守りの仕事は終わらない（相手が人で、学び、変わる）。

**パスキーは、deb2 に置いた後に作る（作者 11-06 夜「置いた後に作る」）。** パスキーは名前（ドメイン）に結び付き、https が要る。スマートフォンの実機で確かめられるのは、本物の名で動く deb2 が在ってから。置く前に確かめられたのは、この PC の Chrome と仮の認証器まで（登録、ログイン、同じ返事の送り直しを断る。入口に残るのは番号、公開鍵、数えの三つ。サーバーの部品は `webauthn` 3.0.1）。Flet にパスキーの部品は無いので、画面は普通の Web の頁で出し、Flet はそこへ出て戻る（`page.login` と `OAuthProvider`）。スマートフォンのアプリへ戻る口と、iPhone・Android の実機は確かめていない。
