# 使い方とデータの置き方（案、2026-11-03）

作者の「seed アプリの使い方を考えて。自然農法をするために必要な知識を持たないといけない。研究したいので、
できるだけデータを保存する。~/farm にはその農場について分析した結果を置く。どれだけ置くかは PC の性能で
選べるように」から。Claude の案で、まだ決めていない。決まったら設計書 §4・§5 と記録の形に移す。

## 1. 一言で

seed は、**知識**（自然農法をするための手引きと資料。共通で、GitHub にある）と、**その農場のデータ**（写真、観察、
読み、照会、分析。本人の PC の `~/farm` にだけある）を、本人の Claude で結ぶ道具。データはできるだけ残す。
残す量は、PC の空きを見て本人が選ぶ。消すのは本人だけ。

## 2. 二つの置き場

| 置き場 | 中身 | 誰の物 | 増え方 |
|---|---|---|---|
| `~/dev/seed`（GitHub、公開） | **知識。** 手引きの章（00〜09）、資料の一覧（`sources*.md`）、植物ごとの資料 `plants/<学名>/`（README、sources、図、座標を除いた写真）、コード、設計 | みんなの物。植物一般のこと、畑を離れても言えることだけ | 人が手引きを直して戻すたびに。文字が主で、今 4.8 MB |
| `~/farm`（公開しない） | **その農場について分析した結果。** 畑ごとのフォルダーに、写真、観察、読み、判定、照会、計画、地図、本人の手引きの写し、資料の全文 | 本人の物。座標、持ち主、本人の畑でのこと | 観察のたびに。写真が主で、今 750 MB |

2026-11-03: 置き場は三つになった。他人の著作物と重い物は別の盤の研究室へ（`docs/研究室.md`）。`~/farm` の記録から研究室へは `seed.toml` の `bulk`。

知識と農場のデータの境は、**「この畑で」と書いてあるかどうか**。「オギの地下茎は 20 cm より浅い」は知識、
「この畑のオギは硬盤層の上で生きている」は農場のデータ（本人の手引きの 06 章「資料から立てた仮説」）。

### 畑ごとのフォルダー

```
~/farm/
  <畑の名前>/                seed の記録のフォルダー。seed --folder ~/farm/<畑の名前>
    seed.toml                設定。keep（§4）もここ
    photos/<日>/<時刻>.jpg   取り込んだ写真（座標は残す）
    originals/<日>/…         写真の元（HEIC など。keep が「研究」のとき）
    observations/<id>.md     観察（写真の組、読み、Data、Record、判定）
    observations/<id>.raw/   読みの生の出力（prompt、JSON、usage、使った手引きの版。keep が「研究」のとき）
    place.md plan.md next.md
    lookup/                  照会の応答（地質、土壌、筆、ハザード）。取った日付きでそのまま
    maps/                    地図（タイルの写しと描いた図）
    weather/<年>.csv          気象庁の日ごとの値（候補。観測所名と取った日を付ける）
    skill/                   本人の手引き（共通の写し + 本人の 06 章、plants/ の本人の畑の写真）
    sources/                 資料の全文の写し（PDF、txt。公開しない）
    notes/                   覚え書き、手で頼んだ読みの写し
  uploads/<日>/              スマートフォンから落とした物を最初に置く所（取り込む前）
```

今の `~/farm/seed/` は一つの畑の記録なので、畑の名前に変える（名前は本人が付ける。公開しないので地名でよい）。
畑が二つなら二つのフォルダー。共通の手引きは一つで、畑ごとに `skill/` の写しが分かれる。

## 3. 使い方（一周）

1. **始める。** `seed --folder ~/farm/<畑> init`。PC の空きを見せ、keep（§4）を選ぶ。共通の手引きを `skill/` に写す。
2. **撮る。** 畑を歩いて、スマートフォンで撮る（座標と向きが入る）。`uploads/<日>/` に落とす。
3. **取り込む。** `seed observe uploads/<日>/`。写真を `photos/` に入れ、観察を一つ作る。離れた一枚と偏りを警告。
4. **読む。** 手元の `claude -p` が、本人の手引き + 写真 + Data + Record + 前の観察 を読み、確からしさ付きの行を書く。
   keep が「研究」なら、渡した物と返った物をそのまま `observations/<id>.raw/` に残す（後で別の手引き・別のモデルで読み直して比べるため）。
5. **本人が書く。** `did`（したこと）、`saw`、`said`。棒の入る深さ、土の硬さ、刈った日。
6. **判定する。** 読みの行に 合う／違う と理由を付ける。「ススキではなくてオギ」。
7. **手引きを直す。** 理由が溜まったら、本人の `skill/` を直す。畑を離れても言えることは共通の手引きに戻す（GitHub）。
8. **資料を集める。** 畑の草が決まったら `plants/<学名>/` を作る。資料の一覧は共通に、全文の写しは `sources/` に。
   本人が読んだ物だけ、確からしさを上げる。
9. **計画を立てる。** `plan.md`。地面の支度（硬盤層、排水）から。立ち位置は前提ではなく、選択肢として並べる。
10. **公開する。** 本人が行を選んで `public/` に。座標と持ち主は入れない。
11. **研究する。** 記録は素の文字なので、本人のスクリプトで読む。`change` の行と `did` を並べて、何が効いたかを見る。
    古い観察を今の手引きで読み直し、読みの行がどう変わったかを見る（`seed reread`、候補）。

## 4. どれだけ置くか — `keep`

PC の性能で効くのは、ほぼ**ディスクの空き**（メモリと CPU が効くのは写真の変換と手元の claude の間だけ）。
`seed init` が空きを測って見せ（`shutil.disk_usage`）、本人が三つから選ぶ。後から `seed.toml` の `keep` で変えられる。
**上げるのは自由、下げても seed は消さない。** 消すのは `seed prune` で、何を何 MB 消すかを見せてから、本人が頷いたときだけ。

| keep | 残す物 | 一回の観察（写真 10 枚）の目安 |
|---|---|---|
| `text`（最小） | 観察、読み、判定、照会の行、本人の手引き、資料の一覧。写真は**読み用の縮小 JPEG**（長辺 2,000 px、座標は残す。約 0.5 MB/枚） | 約 5 MB |
| `photos`（既定） | 上に加えて、取り込んだ写真を**元の大きさの JPEG** で（今の作り。約 7.5 MB/枚）、地図（タイルの写しと図）、資料の全文の写し | 約 80 MB |
| `research`（研究） | 上に加えて、写真の**元**（HEIC 約 3.7 MB/枚）、読みの生の出力（prompt、JSON、usage、手引きの版。約 1 MB/回）、照会の生の応答、気象の日ごとの値、手引きの写しを観察のたびに固める（`skill/` を git にして観察の id でタグを打つ） | 約 120 MB |

今の数字（作者の畑、2026-11-02 の 32 枚）: HEIC の元 3.7 MB/枚、変換した JPEG 7.5 MB/枚、地図の PNG 0.5 MB、資料の全文 47 本で 30 MB、
観察の md は 10 KB。**変換した JPEG が元の 2 倍**なので、`research` は元を残して JPEG を読み用の大きさにしてもよい
（読みの精度が落ちないかは、同じ写真で両方読んで確かめてから）。

### 何を残すと研究になるか

読みを後からやり直せる物を残す。つまり、渡した物（写真、Data、Record、前の観察、**そのときの手引き**）と、返った物
（行、モデル、usage）と、本人の判定。手引きは直していくので、**観察のときの手引きの版**が無いと、読みの違いが手引きのせいか
モデルのせいか分からなくなる。`research` で `skill/` を git にするのはそのため。

残さなくてよい物: サーバーには何も残らない（設計書 §9。変えない）。共通の手引きには農場のデータを置かない（§2）。

## 5. 知識の側 — seed が持つべき自然農法の知識

今あるのは、手引きの章（立ち位置、畑の読み方、種、計画）と、資料の一覧（福岡、川口、リジェネラティブ、りん酸）と、
植物二つ（オギ、セイタカアワダチソウ）。足りないのは:

- **植物。** 畑に出る草と作物を一つずつ `plants/<学名>/` に。草は「土の何を語るか」、作物は「何と一緒に、いつ」。混植の資料が特に足りない（基本計画 §6）
- **土。** 土性の手での見分け（握る、紐にする）、硬盤層の測り方（棒、スコップの断面）、排水の見方。元田んぼの支度の選択肢（02 章の表）を資料で裏付ける
- **季節と天気。** 刈る時期で応えが変わる（オギの記録）。日ごとの気象を記録に並べられるように
- **読みの精度。** 草の名前を写真だけで決めない（06 章）。本人の名前付けが溜まったら、見分けの資料（穂、株元）を `plants/` の図と写真で増やす

知識は共通の手引きに溜まり、一人の畑で確かめたことが、出所を添えて戻る。それが「Claude も人と一緒に育つ」の形。

## 7. コードで変える所（決まったら）

2026-11-03: 先頭の四つを入れた（`keep`、`originals/`、`observations/<id>.raw/`、`seed keep` と `seed prune`。記録の形 §11）。
`seed reread`、`lookup/`、`maps/`、`weather/` は残り。

- `settings.py`: `keep`（text / photos / research）。`init` で空きを測って見せる
- `photos.py`: `originals/` に元を残す、読み用の縮小 JPEG を作る（keep で分ける）
- `local.py`、`cli.py`: `research` で `observations/<id>.raw/` に prompt・JSON・usage・手引きの版を書く
- `cli.py`: `seed prune`（見せてから消す）、`seed reread`（候補）
- `lookup`: 照会の応答を `lookup/` に日付きで残す（サーバーは 24 時間で消す。本人の側で残す）
- 記録の形 §: `originals/`、`observations/<id>.raw/`、`lookup/`、`maps/`、`weather/`、`sources/` を足す
