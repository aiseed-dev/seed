# 利用マニュアル — seed

書いた日: 2026-11-02。使う人（自給したい人、テスター）のための手引き。作っている最中で、11-08 まで画面と手順は変わる。変えたら末尾の「変更の記録」に日付付きで書く。仕組みの側は [設計書.md](設計書.md)、ファイルの中身は [記録の形.md](記録の形.md)。

## 1. seed は何をする物か

すべては畑の写真を撮ることから始まる。記録を置くフォルダーを、このマニュアルではプロジェクトフォルダー（記録のフォルダー）と呼ぶ。アプリの上の端に、その名と、変えるためのフォルダーの印が出る。自分の畑が無くてもよい（§5）。畑の写真（座標入り）を自分の Claude に渡すと、**読み**が戻る。あなたは読みに**合う／違う**を付ける。選んだ行を**公開**でき、公開された記録で人と**繋がる**。座標から引く地形・土壌・筆の**資料の行**（`data`）は、サーバーで読んだときだけ付く。この PC の Claude で読んだときは付かない（§5、§6.1）。

seed が持ち込む物は、生物学・気象・地質の読み（出典付き）で、農業のやり方ではない。ただし気象の章（手引き 03）はまだ骨組みだけで、記録に天気の行も無い。

**事実は三つだけ。** 出典付きの `data` 行、あなたの言葉の `record` 行、あなたの判定（合う／違う）。AI の行は、言い切りの形でも仮説で、確からしさ `[0.00〜1.00]` が付く。

しないこと:
- 「こうしなさい」とは言わない。読みは、何が見えて、何に拠るか、次に何を見るとよいか、まで。判定の形の文（〜すべき）は `uncertain` に落とされる。決めるのは畑。
- 記録を預からない。記録（写真と座標を含む）はあなたの PC の `~/seed/` に残る。座標はこの作業に必須で、記録から外さない。人に見える所に出るのは、あなたが了解した行だけ（§9）。
- 売買と伝言の仕組みは持たない。繋がった後の会話は Discord で。

## 2. 要るもの

| 使い方 | 要るもの |
|---|---|
| 畑を観察する | Python 3.11 以上と `git` の入った PC（Windows / macOS / Linux）。読みは、この PC の Claude Code（`claude` コマンド。入れ方は https://claude.com/claude-code 。Pro 以上のサブスクでログイン。API キーは不要）か、自分の Claude に手で頼む（§6）。サーバーで読む道もあるが、まだ開いていない（§4）。地形・土壌・筆の資料の行はサーバーの道でだけ付き、この PC の Claude の道では付かない |
| 写真 | 位置情報（GPS）の入った写真。一枚でも、歩きながら何枚でも |
| 畑 | 無くてよい。気になる耕作放棄地を道から撮れば、候補地として観察できる（§5） |
| 公開・一言・サーバーで読む | 招待コード（Discord「AI と一緒に自給農」で渡す）。この PC の Claude で読むだけなら要らない |

作者以外の人が入れて観察まで一周した記録は、まだ無い（11-05）。詰まった所は Discord か Issues へ（§12）。

## 3. 入れ方（自分の PC）

配布は GitHub だけ（作者 2026-11-07「アプリとして配布するのではなくて、GitHub で配布するアプリにするのが一番いい」）。PyPI にもアプリのストアにも出さない。GitHub から取ってきて入れ、自分の物にするにはフォークする（§11「機能は自分で足す」）。動かし方（`seed app`、`flet run`、スマートフォンで試す `flet run --android`）と、アプリにする手順（`flet build apk` など。Flutter が要る）は README の「使ってみる」にある。

```bash
git clone https://github.com/aiseed-dev/seed.git
```

```bash
cd seed && python -m venv .venv && .venv/bin/pip install -e ".[app]"
```

venv を有効にする（ターミナルを開くたびに一度）。macOS / Linux:

```bash
source .venv/bin/activate
```

Windows:

```
.venv\Scripts\activate
```

有効にした後は、コマンドは `seed` でよい（以下もそう書く）。有効にしないなら `.venv/bin/seed`（Windows では `.venv\Scripts\seed`）。足す物（extra）は使うときだけ:

| extra | 中身 | 何に |
|---|---|---|
| `[app]` | Flet 1.0.5、Pillow、httpx、pillow-heif | アプリと写真。ふつうはこれ。iPhone の HEIC も読める |
| `[origin]` | Pillow、httpx、imageio-ffmpeg | `seed origin` の mp4。無ければ GIF になる |
| `[grow]` | Pillow、httpx、resvg-py | `seed grow --draw`（図を PNG にして絵に） |
| `[heic]` | pillow-heif | HEIC だけ要るとき |
| `[server]`、`[lookup]` | FastAPI など、fieldnotes-farm 0.2.0 | サーバーを動かす人の物。使う人は要らない |

```bash
seed init
```

`seed init` は `~/seed/` と設定 `~/seed/seed.toml` を作り、公開のための乱数（token）を決め、手引きを `~/seed/skill/` に写す。場所を変えるなら `--folder <道>`（環境変数 `SEED_FOLDER` でも）。招待コードがあれば `--invite CODE`、後からでも `seed invite CODE`。サーバーを置く人は、渡したコードの一覧を `seed invite --list --invites /etc/seed/invites.toml` で見る（呼び名とコードの先頭 4 桁だけ）。失効は `invites.toml` からその行を消すだけで、再起動しなくても次の要求から効く。

`seed init` はディスクの空きを測って見せ、**どれだけ残すか**（`keep`）を出す。観察一回（写真 10 枚）の目安は、`text`（写真は読み用の長辺 2,000 px。座標は残る）約 5 MB、`photos`（既定。写真を元の大きさの JPEG で）約 80 MB、`research`（さらに写真の元 `originals/` と読みの生の出力 `observations/<id>.raw/`）約 120 MB。`seed init --keep research` か、後から `seed keep research`。写真の元を別の盤に置くなら `--bulk <道>`（`--bulk ""` で外す）。上げるのは自由、下げても何も消えない。消すのは `seed prune`（何を何 MB 消すかを見せ、y と答えたときだけ。`--yes` で聞かない）。詳しくは [記録の形.md](記録の形.md) §11。

## 4. Web で見る（seed.aiseed.dev）— まだ開いていない

**11-05 の時点で、seed.aiseed.dev はまだ開いていない**（配備は作者がする）。開いたら Discord で知らせる。コードにある形では、入口に何をする物か、公開された記録の一覧、公開の件数と繋がりの数が並ぶ。記録を開くと、その人が選んで公開した行（読み、資料、本人の言葉、判定）が読める。写真は無い。静的なページに一言の欄は無く、一言はアプリ（PC 版とスマートフォン）の「話す」から招待コード付きで送る（§8）。Web は使い方の説明を置く所で、アプリの Web 版は作らない。

サーバーが開くまで、アプリでサーバーを使う所（写真をサーバーで読む、ほかの人の畑、一言、取り下げ）は「サーバーに届きません」で止まる。

## 5. 自分の PC で

```bash
seed app
```

アプリは PC 版とスマートフォン（iPhone、Android）。画面は二つで、上の端の小さな印で切り替える。**話す**（Claude とのやり取り）と **写真**（この畑の写真を全部）。サーバーの管理は、このアプリではなく kagi の机の画面「人の出入り」から（§11c）。

「話す」は、Claude Code の画面のように、上から下へやり取りが並ぶ（新しい物が下）。一番下に、写真を足すボタン（スマートフォンは「撮る」、PC は「写真を選ぶ」）、一行の欄、送るボタン。文字を打つ所はここだけで、選ぶ欄や印を付ける欄は無い。やり取りの一番上（一番古い所）には、**この土地の成り立ち**が出る。座標から引いた土地の資料の行（`place.md` の `## Data`）を、土地と地形・土・水と災害の区域・歴史の四つにまとめ、出典を小さく添える（頭の一行ずつ。「続きを読む」で全部）。`seed origin` の昔の地図と空中写真が在れば、地図を先に、空中写真を古い順に並べる（押すと大きく）。その下に自分の観察が続くので、昔 → 今 → 自分の観察が一本の時の流れになる。細かい座標は出さない。写真を読む時は、土と歴史をいつも聞く（`ask` の `soil`、`history`）。読みの中で土や歴史に触れた行は「土地の資料から分かる事」として分けて出る。

何ができるかは、入力の上に「こういう事ができます」の例で出る（「この土地の成り立ちを教えて」「土はどんな土？」「昔はどんな土地だった？」（無ければその場で地図を取って来る）「写真を場所ごとに、時の順に並べて」「この草の名前は？」「それは違う。あれはススキ」「来年の春の計画を立てたい」「この観察を公開したい」「設定を見せて」など）。押すか、同じ言葉を書いて送る。

一周は、写真を撮る → 読み → 違う所を言葉で言う → 計画 → 公開 → 繋がる、の順。撮るから違う所までは下の「畑を観察する」、計画は「借りる・買うことができたら — 栽培計画」、公開は §7、繋がるは §8。畑が無い人、紹介された農地を見る人は「農地が無いとき」「農地を紹介されたら」も読む。

### 畑を観察する

1. 「話す」で写真を送る（一言を添えてもよい。例「北の角。土が固い」）。アプリは一度に 6 枚まで。PC にはカメラが無いので、スマートフォンで撮った写真を PC に移し、下の左のボタンで選ぶ（HEIC でもよい）。写真は `~/seed/photos/<日>/<時刻>.jpg` に写され、座標と時刻は EXIF から読む。ほかの写真から 50 m より離れた写真は知らせる。
2. 送った写真が大きく出て「読んでいます…」。読み方は設定の「読み取りと話す」の通り。既定は在る物を順に: この PC の Claude Code（§6.1）、自分の Claude の鍵（§6）、サーバー（招待コード）。スマートフォンは自分の鍵かサーバー。どれも無ければ「招待コードを貼ってください」と出るので、下の欄に貼る（その一行はやり取りに残らない）。
3. Claude の側に、今日の一枚（一番見せたい写真）とその一言、見つけた事（行が指す写真が左に小さく出る）、Claude からの問い、次の一枚（次に撮るとよい物）が出る。長い読みは頭の数行だけで、「続きを読む」で開く。読みは `~/seed/observations/<日>-<時刻>.md` に残る。
4. 問いへの答えや、読みの違う所は、下の欄に言葉で書いて送る（例「3 行目は違う。あれはススキ」「水が溜まるのは雨の後だけ」）。Claude が使える時（この PC の Claude Code、自分の Claude の鍵、招待コードでサーバー）は、Claude が違う行に印を付け（`seed mark` と同じ）、あなたの言葉を残し、読み直して、直した行を先に見せる。どれも使えない時は、あなたの言葉として一番新しい観察に残り（「書き留めました」と、Claude と話すには何を入れるか）、次に写真を送った時の読み取りが「あなたが直した事」として先に読む。
5. 「写真」の画面で、写真を日ごと・観察ごとに見る。押すと大きく開き（左右で前後へ、つまんで拡大。位置の入っていない写真には「位置なし」）、「この草の名前は？」「今日の一枚にする」「この写真を外す」ができる。外した写真は消えず、`~/seed/photos/removed/` に移る（すぐ後なら「戻す」）。

   Claude は読みの中で、写真一枚ごとに「タグ」の行を付けます（植物の名と、発芽・育ち・開花・結実・枯れ・刈った・播いた・植えた・収穫・裸地の十語のうちの状態）。「写真」の画面の上に、タグが札（語と枚数）で並び、押すとその語の写真だけが日ごとに出ます（もう一度押すと全部に戻ります）。大きく開いた写真の下にも出ます。直したい時は、ほかの行と同じに「話す」で言葉で言います（例「この写真の開花は違う」）。
6. `place.md`（場所について分かっていること）、`next.md`（その次の考え）、観察のファイルは、どれも文字のファイルなので、エディターで直してよい。細かい作業（並べ替え、比べる、まとめる）は Claude Code に頼む。写真を場所ごとに時の順に並べるのは `seed photos --by-place`（AI を使わない）。

### コマンドで

```bash
seed observe ~/Pictures/IMG_0012.jpg ~/Pictures/IMG_0013.jpg
```

Windows では写真の道を `C:\Users\<名前>\Pictures\IMG_0012.jpg` のように書く。

```bash
seed observe --ask grow,soil --say "ask: 果樹は向くか" ~/Pictures/IMG_0012.jpg
```

`--ask` の語は `grow, soil, plants, history, access, sow, next, names`。`--say` は `did:`、`saw:`、`said:`、`note:`、`ask:` の形で何度でも。読む先は `--local`（この PC の claude。あれば既定）、`--server`（claude が無いときの既定）、`--claude-code`（読まずに手順を出す）。CLI の写真の数に上限は無いが、サーバーの道は 6 枚まで。サーバーは 11-05 の時点で開いていないので、Claude Code が無い PC では、今は既定のままでは読みが戻らない（`--claude-code` で手順を出し、§6.2 で頼む）。Claude Code がある PC では既定（この PC の claude）でよい。

```bash
seed mark 2026-11-05-142107 soil_surface wrong --reason "北側は見える"
```

同じ key の行がいくつもあるとき（`plants` など）は `--text "行の文"` でどの行かを指す。本人の行は `seed say 2026-11-05-142107 did "今日は見ただけ"`。

### 借りる・買うことができたら — 栽培計画

1. 自分の畑として撮る（「自分の畑」、`kind: own`）。
2. 「話す」で「来年の春の計画を立てたい」のように言う（季節もその言葉で）。Claude（この PC の Claude Code、自分の鍵、サーバーのどれか）が、手引き、観察、`place.md` を読んで、`~/seed/plan.md` の `## Plan` の行を書く。
3. どれも使えない端末では「これは PC の Claude Code でできます」と、鍵か招待コードを入れればここでも頼める事が返る。手で頼む手順は `seed plan --claude-code` が出す。立てた計画は「計画を見せて」で見える。
4. 違う行は「話す」で言葉で言う（Claude が印を付ける）。決めたことは「決めたこと」（`decided`）、したことは「したこと」（`did`）として、「話す」で言うか `seed say plan …` で書く。立て直しても、判定と自分の行は残る。
5. 立ち位置（菌根菌を活かす自然農法から。理由はりん酸肥料の高騰）は出発点で、前提ではない。数字と混植は書かない（手引き 09 章、04 章）。収量や経費の数字は、作者の別の手引き aiai（就農の手続きと自然農法の経営計画）に任せる。

```bash
seed plan --season "2026-27 冬" --decided "南側は草のまま"
```

`seed say plan did "北側を刈った"`、`seed mark plan sow wrong --reason "種が無い"` のように、`plan` を観察の名の代わりに使う。

同じ場所（100 m 以内）をまた撮ると、読みに `change`（前の観察からの変化）が付く。「したこと」を残しておけば、何が効いたかが並んで読める。同じ写真をもう一度読ませると AI の行は置き換わり、判定と自分の言葉は残る。判定の付いていた行の文が変わると、古い行は「前の読み」に移る。

### 一周の実例（作者の畑、2026-11-02）

1. 徳島の元田んぼ（自分の畑）で写真を 24 枚撮った（CLI で渡した。アプリなら一度に 6 枚まで）。
2. この PC の Claude Code が読み、読みの行が 17 行戻った。地形（氾濫平野）と土壌図（水田化褐色低地土）の行は Claude の読みではなく、fieldnotes の座標からの照会で付いた資料の行。今の seed では、この行はサーバーの道でだけ付く。
3. 白い穂の草を Claude は「ススキらしい」と読み、作者が「違う」を付けた（理由: ススキではなくてオギ）。土の固さは写真に写らない、と読みの側にも書かれた。
4. 栽培計画 `plan.md` の元になったのは、作者が記録に書いた言葉（元田んぼ、硬盤層、おそらくシルト質埴土、サブソイラにはトラクターが要る）で、Claude はそれを案に並べた。固い層の厚さは分からないので、次に見ることとして計画に残った。
5. 公開と繋がるは、サーバーが開いていないので、まだ通していない。

### 農地が無いとき — ここから始める

1. 気になる耕作放棄地を、道から撮る（人の土地に入らない）。
2. 「話す」で「設定を見せて」と送り、「今見ている畑」を「候補地に変える」にしてから撮る（CLI は `seed observe --candidate`）。
3. 筆と所有者を調べるのは、あなた。手引き 13 章に、地番は法務局の地図（公図）で、所有者は登記事項証明書か近所で、とある。分かったことは「言ったこと」「そのほか」に自分の言葉で残す。**所有者の名前や住所は公開しない。** アプリが止められるのは電話・メール・郵便番号の形だけ。
4. 持ち主と話せたら、その人にも seed を渡す。公開の「その次」に「貸す」「借りる」「手伝う」の札がある。

### 農地を紹介されたら — 借りる・買うかの材料

1. その農地を候補地として観察する（道、水の口、周りの畑、傾斜が分かるように）。
2. 読みに、道（`access`）、日当たりと傾斜（`sun_slope`）、周り（`surroundings`）、水（`water`）、草（`plants`）が並ぶ。
3. 筆・地形・ハザード・地質・土壌の**資料の行（`data`）は、サーバーで読んだときだけ付く**（座標からの照会はサーバーがする）。この PC の Claude で読んだときは付かない。サーバーはまだ開いていない（§4）。
4. これは材料で、借りる・買うの判定は出ない。決めるのはあなた。手続きは手引き 13 章と 00 章。

### 「違う」を集める `seed marks`

付けた判定を key ごとに集め、手引き 06 章（`~/seed/skill/06-畑を読む.md`、無ければパッケージの物）の当たる行と並べて出す。章を直す材料（§11）。

```bash
seed marks
```

`--all` で「合う」も、`--key plants` で一つの key だけ、`--json` で JSON。

### 畑の成り立ちの動画 `seed origin`

座標から、公開の地図と空中写真を順に並べた一分ほどの動画を組む。AI は使わない。場面は、標準地図（引いた所から寄る）、色別標高図、地形分類、洪水浸水想定区域、土砂災害警戒区域、土壌図、年代別の空中写真（その場所にある年代だけ）、近くの史跡、あなたの写真。字幕は `place.md` の照会の行（出典付き）だけで、各場面の下に地図の出典が出る。照会の行が無いと字幕は付かず、史跡の場面は省く。

```bash
seed origin
```

- 中心は、座標のある一番新しい観察か、`--lat` と `--lon`。ほかに `--seconds`（一場面、既定 3）、`--fps`（既定 24）、`--size`（既定 1280x720）、`--font`、`--out`（記録のフォルダーの中だけ）。
- 出力は `~/seed/origin/<日>/`（`origin.mp4`、`frames/`、字幕と出典の表 `captions.md`）。タイルは `~/seed/origin/tiles/` に置き、次からは取らない。一回に取るタイルは 200 枚まで。
- mp4 には `pip install -e ".[origin]"`。無ければ `origin.gif`。日本語のフォント（Noto Sans CJK など）が無ければ `--font` で渡す。
- **動画には畑の場所が写る。公開するかはあなたが選ぶ。** `seed publish` は動画を送らない。地図の利用の条件は `captions.md` の最後（Claude が確認）。タイルのキャッシュは人に渡さない。

### 計画の絵（仮説）`seed grow`

`plan.md` の `## Plan` の行から、畑が季節ごとにどう見えるはずかを、線と色と字の図にする（場面は 6 まで）。上から見た図、横から見た土の断面、見えるはずの物が一枚に並ぶ。**仮説の図で、あなたの写真でも判定でもない。** 時期が来たら同じ所を撮って並べ、合う／違うを付けるための物。

Claude が場面を書き、seed がそれを計画の行と照らして描く。計画の行に無い場面と作物は描かず、省いた理由を `captions.md` に書く。確からしさは元の行より高くならない。先に `seed plan` で計画の行が要る。

```bash
seed grow
```

- 道は二つ。この PC の claude（既定。`--scenes 3` で場面の数を絞る）か、`seed grow --claude-code` で手順を出し、Claude Code に手引き 09 章の「計画の絵（仮説）」に従って `grow/<日>/scenario.json` を書かせ、`seed grow --render grow/<日>/scenario.json` で描く。
- 出力は `~/seed/grow/<今日>/`（`scenario.json`、`01-2026-12.svg` のような図、`captions.md`）。図はブラウザで開ける。
- **公開しない。** `seed publish` は `grow/` を送らない。図に実在の地名が入っていないかは seed には確かめられないので、人に見せる前に読む。

**自分の機械で絵にする（`--draw`）。**（上級者向け。GPU のある機械と画像生成サーバーが要る）場面の図を、あなたが用意した画像生成の機械（stable-diffusion.cpp の sd-server、FLUX.2 klein 4B）でイラストにする。要るのは `[grow]` と、その機械。絵の指示（英語の `prompt`）は Claude がシナリオに書く物で、`prompt` の無い場面は描かない。

```bash
seed grow --draw --server http://<あなたの機械>:11445   # 門（deploy/halo）の口。token は credentials.toml の draw_token
```

- 機械の場所は `--server` > 環境変数 `SEED_DRAW_URL` > `seed.toml` の `[grow]` の `server`。無いか応えなければ止まる（図の SVG は残る）。日は `--day`（既定は `grow/` の一番新しい日）。参照の写真は `--photo <道>`（3 枚まで）、`--size` の既定は 1280x720。
- **送るのは、場面の `prompt`、図の PNG、`--photo` の写真（EXIF を落とした写し）だけ。座標は送らない。** 機械が家の中（192.168.*、10.*、localhost）なら `captions.md` に「写真は家の外に出ていない」と出る。
- 出力: `grow/<日>/raw/`（戻ったまま）と、「計画の絵（仮説）」の印を焼いた `grow/<日>/01-2026-12.png`。`captions.md` に「絵の作り方」と「Claude の照らし」。
- 描いた後、この PC の claude があれば、絵にシナリオに無い物（計画に無い作物、構造物、人、文字）が入っていないかを照らす。無ければ Claude Code で見る手順が出る。**生成の絵は計画に無い物を描く**（11-04 の作者の畑では、穂の出たライムギ、畝の形の筋）。人に見せる前に照らしを読む。
- 機械の支度の例は `scripts/setup-draw-server.sh`（読んでから、その機械で走らせる）。

### 畑を分ける `seed field`

畑が二つ以上ある時は、一つのプロジェクトフォルダーの中に `fields/<畑の名>/` を作って分けます。
畑のフォルダーの中身は、今までの記録のフォルダーと同じです（写真、観察、`place.md`、`plan.md`、公開の控え）。
設定（`seed.toml`）、手引き（`skill/`）、`CLAUDE.md`、本人の画面（`plugins/`）は、プロジェクトフォルダーに一つだけ置き、どの畑でも使います。
`fields/` が無いプロジェクトは、今まで通り、プロジェクトフォルダーそのものが一つの畑です。

- `seed field new 北の畑` で `fields/北の畑/` を作り、今の畑にします。プロジェクトフォルダーにもう記録（観察や写真）があれば、初めての畑を作る時に、その記録をこの畑へ移します（設定、手引き、`CLAUDE.md`、`plugins/` は移しません）。
- `seed field use 北の畑` で今の畑を選びます（`seed.toml` の `field` に書きます）。`seed field use all` でプロジェクト全体にします。
- `seed field list` で畑の並びを見ます（今の物に `*`）。
- どの命令も `--field 北の畑` で、その回だけその畑を使えます。観察を作る、読む、公開するなどの命令は、畑を選んでから使います。

アプリでは、上の端のフォルダーの印を押すと、下に板が出ます。上に「プロジェクト全体」と畑の並び（今の物に印）、細い線の下に別のプロジェクトが並びます。
畑を選ぶと、上の端の名は「プロジェクトの名 / 畑の名 — 話す」になります。
「プロジェクト全体」では、写真は畑ごとの見出しで全部を並べ、話すは畑ごとの見出しでやり取りを並べます。言葉は、この PC の Claude Code にプロジェクトフォルダーで渡します。
写真は畑ごと、月ごと、日ごとに並びます（新しい月、新しい日が上）。話すのやり取りには、月が替わる所に小さく月が出ます。
写真を撮る、選んで送る、公開するは、畑を選んでからです（全体の時に写真のボタンを押すと、畑を選ぶ板が出ます）。

別のフォルダー（別のプロジェクト）は、プロジェクトの一覧（`~/.config/seed/fields.toml`）で切り替えます。
`seed project add 知人の田 ~/farm/知人の田` で一覧に足し、`seed project use 知人の田` で替え、`seed project list` で見ます。前の名の `seed field add` も同じ事をします。
**どのフォルダーを使うか**は、この順で決まります: `--folder` → 今いるフォルダー（`seed.toml` がある時。Claude Code と同じ）→ `--field`（このプロジェクトに無い名なら一覧の名）→ 今のプロジェクト → `SEED_FOLDER` → `~/seed`。
PC のアプリでは、板の「別のフォルダーを開く」で選んだフォルダーが、フォルダーの名で一覧に足されて、今のプロジェクトになります。

## 6. 自分の Claude で読む

**自分の Claude の鍵（Anthropic の API の鍵）で。** Claude Code が無い PC とスマートフォンでも、自分の鍵を入れると、写真の読み取りと「話す」の細かい作業（違う所を直す、計画、公開の下書き）がその端末から直にできる。費用はあなたの鍵に掛かる。鍵は [console.anthropic.com](https://console.anthropic.com/) で作る。入れ方: 「話す」で「設定を見せて」→「自分の Claude の鍵」の「入れる」→ 下の欄が「Anthropic の API の鍵を貼る」（伏せ字）になるので貼って送る。「入りました」とだけ返り、鍵はやり取りにも記録にも残らない。置き場はこの端末の `~/.config/seed/credentials.toml`（600）だけで、送り先は Anthropic の API だけ。外すのは同じ所の「鍵を外す」（二度押し）。モデルは `seed.toml` の `claude_model`（既定 `claude-opus-5-5`。安くするなら `claude-sonnet-5-5` か `claude-haiku-5-5`）。Claude は記録のフォルダーの中だけに効く道具を使い、アプリがそれを端末の中で動かす（公開を送る事と、命令を走らせる事はできない）。待つ間も画面は動き、「止める」で止まる。

**サーバー経由で。** 招待コードを入れると、写真の読み取りと「話す」がサーバー（作る人の鍵）を通る。一日の回数に上限があり、使い切った時と受け付けを止めている時は、あなたの言葉を書き留めて理由を返す。

どれを使うかは「設定を見せて」の「読み取りと話す」に出て、押すと次の物に変わる。既定は、PC がこの PC の Claude Code → 自分の鍵 → サーバー、スマートフォンが自分の鍵 → サーバー。

### 6.1 この PC の Claude Code に読ませる（自動）

Claude Code が入っていてログインしている PC では、`seed observe` は何も付けなくてもこの PC の `claude -p` で読む。アプリでは、写真を送った時に、設定の「読み取りと話す」が「手元の Claude（Claude Code）で」（PC の既定）ならこの道で読む。API キーは要らない。費用はあなたのサブスクの分。

- 渡す手引きは、`SKILL.md` と、06 畑を読む、02 地質と土、04 生物（栽培計画と `seed grow` では 06 の代わりに 09）。03 気象と時期は骨組みなので渡さない。
- `SKILL.md` は、あなたの写し `~/seed/skill/` にあればそれ、無ければパッケージの物を一つ選ぶ。章（06 か 09、02、04）は一つずつ、写し → パッケージの順で探す。写しに無い章はパッケージの物で補われるので、11-05 より前の写し（古い章の名）でも章は付く。ただし、あなたが古い名の章に書き足した物は名が合わないので読まれない（写し直し方は §11）。
- 「話す」では、記録のフォルダーの中でなら、言葉でフォルダーを作ったり写真を移したりできます（例: 「島根の写真。フォルダーを作って保管して」）。観察が指している写真は動かしません（外すのは「写真」で）。消すのは Claude はしません。頼むと、自分で打つ命令を返事に書くので、中身を確かめて自分で走らせてください。
- 写真はこの PC から Anthropic に送られ、seed のサーバーは通らない。照会の資料の行（`data`）はこの道では付かない（§5）。
- 写真の数だけ時間がかかる（11-03 の別の観察で、23 枚に約 2 分の実例がある。§5 の実例の 24 枚とは別）。モデルは `--model opus` か `--model sonnet`。別の場所の claude を使うなら環境変数 `SEED_CLAUDE`。
- `keep = research` なら、渡した物と戻った物が `observations/<id>.raw/` に残る。

### 6.2 手で頼む

1. Claude Code で `~/seed/` を開く。
2. `~/seed/skill/SKILL.md`（`seed skill-path` が道を出す）を読ませる。Claude.ai なら、プロジェクトの知識に `~/seed/skill/` の中身を入れる。
3. 「`observations/<日>-<時刻>.md` の写真を読んで、観察を書いて」と頼む（`seed observe --claude-code` が、この手順を道付きで出す。同じ場所の前の観察があれば、それも読ませるように出る）。
4. 書けたら、アプリの「話す」で同じように見える。費用はあなたの Claude の分。seed のサーバーは通らない。

フォルダーには `CLAUDE.md`（`seed init` が書く）があるので、Claude Code をここで開けば（PC の端末でも、スマートフォンから使う時も）、アプリの「話す」と同じ決まりで動きます。

## 7. 公開する

11-05 時点で seed.aiseed.dev は開いていないので、この節の手順は最後まで通らない。開いたら README に書く。

公開は、Claude を使って行う。本人が読んだ文と、送られる文を同じにするためで、アプリは公開を組み立てない。「話す」で「この観察を公開したい」と送ると、Claude（この PC の Claude Code、自分の鍵、サーバーのどれか）が下の 1〜2 をする。自分の鍵とサーバーの時は、Claude は下書きを作るだけで送れない。アプリが下書きの写真と全文と「出す」を出し、あなたが写真と全文を見て「出す」を押すと、その中身のまま送る（見せた後に下書きが変わっていたら送らず、新しい全文を出す）。どれも使えない端末では「これは PC の Claude Code でできます」と返る。

1. Claude に「この観察を公開したい」と頼む。Claude が、行の候補（判定の付いた行が先）、場所の粗さ（都道府県／市町村／大字。座標を付けるなら小数 2 桁、約 1 km まで）、呼び名、札、その次、一言（200 字まで。入口に並ぶ）をあなたと決め、下書きを作る（`seed publish … --local`。`~/seed/public/<id>.md` に書かれ、送られない）。公開は成長の記録で、写真は、同じ場所を日を追って撮った物が日ごとに一枚 `photo` の行で入る（二日以上に渡る場所が無ければ、その日の今日の一枚）。別の写真にしたい時は、Claude にそう言う。
2. 下書きの全文を読む。直したい所は Claude に言う。直したら、Claude はもう一度全文を見せる。
3. 「出す」と言うと（自分の鍵とサーバーの時は「出す」を押すと）、その下書きがそのまま送られる（`seed publish --file ~/seed/public/<id>.md`）。「出す」の前には送らない。写真は長い辺 1280 に縮め、撮った場所などの情報（EXIF）を外して一緒に送る。サーバーも受けた写真を開いて書き直し、位置の情報を残さない。行が指す写真が手元に無い時は送らない。
4. 取り下げ・書き直しは同じ PC（同じ token）から。アプリの「話す」で「公開した物を見せて」と送り、「取り下げる」を二度押す。取り下げると、出した写真もサーバーから消える。
5. HTML、電話・メール・郵便番号の形の文があると止まる（「直す所」が出る）。候補地の観察を含むと、所有者のことを書かないよう注意が出る。

```bash
seed publish 2026-11-05-142107 --id my-field --place "徳島県 吉野川市" --word "元田んぼを草ごと読んでいます" --local
seed publish --file ~/seed/public/my-field.md
```

一つ目は、判定の付いた読みの行と、`data`、`record` を全部入れた下書きを作る。`--coord`、`--what`、`--next`、`--name`（既定は `seed.toml` の `name`。空なら止まる）、`--contact`、`--photo`（出す写真の名。何度でも。一日 3 枚、全部で 12 枚まで。付けなければ日ごとに今日の一枚）、`--local`（送らずに `public/` に書くだけ。付けなければ作ってすぐ送る）。二つ目は、在る下書きを中身のまま送る（観察や `--id` などは要らない。形が合わなければ送らずに止まる）。

1. 「話す」で「ほかの人の畑を見たい」と送ると、公開された記録の一覧が出る（一覧はサーバーから取る）。「開く」で中身が読める。

## 9. 写真と座標、個人情報

- 座標は記録に必須で、あなたの記録には残る。`~/seed/photos/` の写真は位置情報も含めてあなたの物。
- 外に出る物は道ごとに違う。この PC の Claude（§6.1）: 写真を Anthropic へ。自分の鍵（§6）: 縮めた写真（EXIF 無し）と、Claude が道具で読んだ記録の文（観察の細かい座標は渡さない）を Anthropic へ。サーバーで読む・話す: 縮めた写真（EXIF 無し）と座標、話すのやり取りを seed のサーバーへ（サーバーはやり取りの中身を書き残さない）。今の実装は答えを返したら捨て、残すのは回数の上限のための token のハッシュと日時と使った量。Pl@ntNet（§11a）: 縮めた写真だけ、座標は送らない。`--draw`（§5）: prompt と図と選んだ写真（EXIF 無し）だけ。
- これは今の実装で、約束の中心ではない。**約束は、公開はあなたが了解した物だけ**ということ。場所の粗さもあなたが選ぶ。
- 公開ファイルに本名、住所、電話、メールを書かない。アプリが止められるのは電話・メール・郵便番号の形と HTML だけで、住所や名前は止められない。

## 10. 設定 `~/seed/seed.toml`

```toml
folder = "~/seed"
server_url = "https://seed.aiseed.dev"
name = ""                 # 呼び名。公開の既定
language = "ja"           # 本人の言葉の言語。無ければ OS の言語。画面の文と、AI が書く言葉
place_level = "city"      # prefecture / city / oaza。公開の場所の粗さの既定
keep = "photos"           # text / photos / research（seed keep で変える）
bulk = ""                 # 写真の元 originals/ を置く別の盤の道（seed keep --bulk で変える）
read = ""                 # local / key / server。Claude を呼ぶ所（読み取りと話す）。空なら在る物を順に（「話す」の設定で変える）
claude_model = ""         # 自分の鍵で呼ぶモデル。空なら claude-opus-5-5（費用はあなたに掛かる）
# token、invite、自分の Claude の鍵（秘密）は seed.toml ではなく ~/.config/seed/credentials.toml（600）にある

[grow]
server = "http://<あなたの機械>:11445"   # seed grow --draw の描く機械（任意。門の口。token は credentials.toml）
```

秘密（`token`、`invite`、halo の門の `draw_token`、自分の Claude の鍵 `anthropic_key`）は `seed.toml` ではなく `~/.config/seed/credentials.toml`（許可 600。環境変数 `SEED_CREDENTIALS` で場所を変えられる）に置かれ、`seed.toml` に古く書かれていた物は次に開いた時にそこへ移る。

知らない鍵と表は消さずに書き戻す。ファイルの中の決まった語（`overall`、`farmer: right`、`## Reading`）は英語のまま。どの国の人のフォルダーも同じ読み手で読めるようにするため。画面では日本語で見える。

コマンドの共通の引数と環境変数: `--folder`（`SEED_FOLDER`）、`--server-url` はこの回だけのサーバー（`SEED_SERVER_URL`。ファイルには書かない）、`SEED_CLAUDE`（§6.1）、`PLANTNET_API_KEY`（§11a）、`SEED_DRAW_URL`（§5）。

## 11. ビルダーの訓練

観察して、読みに合う／違うを付け、「違う」の理由が溜まったら `~/seed/skill/` の手引きの章を直す（`seed marks` が材料を並べる）。この一周が、自分の場所で AI を使い、確かめ、直す、ビルダーの最初の仕事。記録は素の文字のファイルなので、自分の Claude と小さなスクリプトで並べたり比べたりもできる。手順は手引き 08 章。

### 機能は自分で足す

seed は、使う人が自分で機能を足していくアプリです（作者 2026-11-07）。畑は一枚ずつ違うので、何を記録するか、何をどう読むか、どう見せるかは、人ごとに違います。足し方は二つです。

- **言葉で足す。** 「話す」で「これからは収穫の量も記録して」「写真はまず植物の名で分けて見せて」と言うと、Claude が `~/seed/skill/` の手引きに書き足し、次からそうします。欄も画面も増えません。記録の種類、読む順、売り方、見せ方は、だいたいこれで足ります。
- **画面を足す。** 自分の畑の画面（収穫の表、気象の絵など）は、記録のフォルダーの `plugins/` に Python のファイルを一つ置くと、アプリの上の端に印が増えます。ファイルには `TITLE`（画面の名）、`ICON`（印）、`build(app)`（画面の中身）の三つを書きます。見本は seed の `src/seed/plugins/land.py`（この土地の成り立ち）。自分の Claude Code に「plugins/ に〜の画面を作って」と頼めます。フォークは要りません。
- **コードで足す。** 端末でしかできない事（撮る、位置、画面の形）は、コードです。GitHub の seed を自分のアカウントにフォークし、自分の PC に取ってきて、自分の Claude Code に「写真を撮る画面に〜を足して」と頼みます。`pip install -e ".[app]"` で、その写しが自分の seed になります。ライセンス（AGPL）は、そうやって自分の物にする事を許しています。

フォークした seed は、その人の物で、その人の Claude が動かします。元の seed の Claude があなたのアプリのコードを書き換える事はありません。

### 手引きは本人の物

`seed init`（とアプリ、`seed observe`、`seed plan` の始まり）は、手引きを `~/seed/skill/` に写す。これはあなたの手引きで、直してよい。直した手引きが効くのは、この PC の Claude と自分の鍵で読むとき（§6）。サーバーは共通の手引きを読む。

章は 2026-11-05 に組み替えた: 00 始める前、01 立ち位置、02 地質と土、03 気象と時期（骨組み）、04 生物（菌根菌・草・混植）、05 鳥獣害、06 畑を読む、07 周りの物（筆・史跡・地名）、08 ビルダーの訓練、09 栽培計画、10 種、11 売る、12 加工、13 手続きと農地。

**11-05 より前に写した手引きは、古い章の名のまま**（`02-畑を読む.md`、`06-手続きと農地.md` など）。`seed init` は、もうある `~/seed/skill/` を上書きしない（「上書きしません」と出る）。古い写しのままでも章は付く（§6.1 を見てください）。自分の直しを効かせるには写し直す。写し直すコマンドは無い。手で次のようにする。

```bash
mv ~/seed/skill ~/seed/skill-old
```

```bash

```

新しい写しができたら、`skill-old/` で自分が直した所を見て、新しい章に移す（`seed marks` の 06 章は、古い写しのあいだはパッケージの物を使っている）。

数字は aiai（作者の別の手引き）に任せ、seed は書かない。混植は、読んだ資料が `~/seed/skill/sources.md` に入るまで書かない。

資料の候補は五つ（`seed init` が `~/seed/skill/` に写す。写した後にリポジトリの `skill/` に足された物は写しに無いので、リポジトリの方を見る。どれも資料の候補で、手引きの本文に引いていない。根拠にはしない）: `sources-regenerative.md`（リジェネラティブ農業と混植と菌根菌、59 件）、`sources-wildlife.md`（鳥獣害）、`sources-law.md`（法令の本文と解説）、`sources-defense.md`（植物の防御機構の論文 178 件）、`sources-security.md`（サイバー攻撃への守り 59 件）。

## 11a. 草の名を確かめる — Pl@ntNet

はじめて作物を作ると、雑草か作物かが分からない。seed は写真を一枚ずつ Pl@ntNet（植物の識別器）に送り、種の候補を `plants` の行に「Pl@ntNet（写真の名）: 名 0.62、…」の形で足す。Claude の読みとは別の行（モデルの読み）なので、合うか食い違うかが分かる。決めるのはあなた。

**今の状態（11-05）:** コードは入っているが、本物の鍵で通したことはまだ無い。整えるのは 11-08 の後。

- 名を知りたい草は、花か穂か葉を近くで一枚。歩き撮りの全景では当たらない。
- 鍵: 自分の鍵を [my.plantnet.org](https://my.plantnet.org/) で取り、環境変数 `PLANTNET_API_KEY` に置く。鍵がなく招待コードがあれば、サーバーの鍵で送る（`--server`）。11-05 時点で seed.aiseed.dev は開いていないので、このサーバーの鍵の道は最後まで通らない。開いたら README に書く。
- 送るのは縮めた写真だけ。座標（EXIF）は送らない。一つの観察で 10 枚まで。
- アプリ: 「写真」で写真を大きく開き「この草の名前は？」。「話す」の例「この草の名前は？」は、一番新しい観察の今日の一枚を確かめる。見つけた草は「この畑で見つけた草を見せて」で写真と並ぶ。
- CLI: 写真の名を省けば全部。`seed observe --ask names` なら観察のときに送る（`--no-identify` で止める）。

```bash
seed identify 2026-11-05-142107 092817 092733
```

`keep = research` なら、答えが `observations/<id>.raw/plantnet-<写真>.json` に残る。

## 11b. スマートフォンだけの人 — スマートフォンのアプリ

アプリは PC 版とスマートフォン（iPhone、Android）。人ごとに記録をサーバーに置く Web 版は作らない。Web は使い方の説明を置く所。iPhone 版の作り方と入れ方は [iPhone 版.md](iPhone%20版.md)。

1. 「話す」の「撮る」で撮る。撮った所と時刻が写真に書き込まれる（位置が取れるまでシャッターは切れない）。
2. 写真の読み取りと「話す」は、自分の Claude の鍵でスマートフォンから直に（§6。費用はあなた）か、サーバーで（作る人の API キーで、一日の回数に上限がある。招待コードは、初めに「招待コードを貼ってください」と出た時に下の欄に貼る）。
3. 計画を立てる、公開の下書き、読みをその場で直す、も鍵かサーバーで「話す」から頼める。公開は、全文を読んで「出す」を押した時だけ送られる。
4. 撮った写真は、Android ではスマートフォンの Pictures/seed（日付ごとのフォルダー）にも残る。アプリを消しても残り、ギャラリーに出て、PC へ写せる。外した写真の分は消さない。iPhone は後で（写真ライブラリーへの保存は部品が要る）。
5. 鍵も招待コードも無い時に言葉だけを送ると、一番新しい観察にあなたの言葉として残る（AI は呼ばない）。次に読み取れた時に、それを先に読む。記録はスマートフォンの中のあなたのフォルダーに残る。

スマートフォンから、PC の Claude Code と話すこともできます。PC のアプリの「設定を見せて」にある「スマートフォンから使う」の「始める」を押すと、その畑のフォルダーで Claude Code のリモートコントロールが立ちます。スマートフォンの Claude アプリの Code に畑の名のセッションが出るので、開けば、その PC の Claude（seed の手引きと `seed` の命令つき）と話せます。要る物は、Pro 以上の Claude のアカウントと、点けたままの PC です。初めて立てる時は、Claude Code が「Remote Control を使ってよいか」と聞くので、アプリの「はい」を押します。そのフォルダーは、一度端末で `claude` を開いて、信頼すると答えておきます。立ったあとに出る URL か QR コードからも開けます。スマートフォンから写真を送ると PC に保存されます（座標が残るかは、まだ確かめていません）。

### スマートフォンから PC へ（一方通行）

PC のプロジェクトフォルダーを本物の記録にして、スマートフォンで撮った写真をそこへ送れます。

1. PC で、プロジェクトフォルダーの中で `seed home` を打ちます（`--folder` でも選べます）。家の網にサーバーが立ち、端末にサーバーの URL（`http://<PC の番地>:8800`）と招待コードが出ます。招待コードはプロジェクトフォルダーの `home.toml` に一つ作られ、次からも同じ物が出ます。
2. スマートフォンのアプリの設定で、サーバーの URL と招待コードをその二つにします。設定の札に「PC に送っています: <URL>」と出ます。
3. スマートフォンで撮ると、写真（座標の入った元のまま）と観察が PC のプロジェクトフォルダー（今の畑）に入り、PC の Claude Code が読んで、答えがスマートフォンに返ります。「話す」の言葉も、PC の Claude Code がその畑のフォルダーで受けます。
4. スマートフォンには小さな写しだけが残り、元の写真は PC にあります。

PC からスマートフォンへ記録を送る事はしません。使えるのは家の網の中だけです（外から使うには、家の網に入る道、VPN などが要ります）。止めるには、PC の端末で Ctrl+C を押します。

## 11c. サーバーを動かす人 — 相手ごとの token

seed のサーバーを自分で動かす人のための節（使うだけの人は読まなくてよい）。招待コードの一覧に加えて、相手ごとに token を出せる。

```bash
seed token add "買い手の呼び名" --scope buyer --days 30
```

出た一行が token。**出るのはこの一度だけ**で、台帳（`~/.config/aiseed/tokens.json`。サーバーでは `--file /var/lib/seed/gate/tokens.json`）に残るのはハッシュだけ。その人にだけ渡す。相手は招待コードと同じ所（「話す」の設定の「招待コード」か `seed invite`）に入れる。

- `--scope member`（既定）: 招待した人。読み、公開、一言。
- `--scope buyer`: 買い手。公開の記録に一言を送るだけ。読みも公開もできない。
- `seed token list` で、誰に、範囲、期限、今の状態。`seed token revoke "呼び名"` で取り消す（次の要求から効かない）。

管理は、kagi の机の画面（`kagi app --dir <作業の場所>`）の「人の出入り」から。サーバーの URL と、動かす人の token（`--scope admin`）を「繋ぐ先」に入れると、今の状態、気を付ける事、人に渡す token、公開された記録、操作の記録をそこで見て、出す・取り消す・取り下げるができる（`docs/kagi 手引き.md`）。動かす人の token を seed のアプリに入れても、ほかの人と同じ様に使えるだけ。

- 「気を付ける事」には、何が起きているかの文の下に、サーバーで打つコマンドが一行ずつ出る。そのまま写して、サーバーの端末で打つ。
- 「受け付けを止める」を押す（二度押し）と、公開、一言、写真の読み取り、話す、草の名を断る（使う人には「今、受け付けを止めています。」と出る）。管理の操作、公開の頁を見る事、本人の取り下げ、土地の照会は通る。「受け付けを再開する」（二度押し）で戻る。サーバーを再起動しても止めたまま。操作の記録が書き換えられた時や、断った要求が多い時に使う。
- 「token を全部取り消す」（二度押し）は、押した本人の token だけを残して全部取り消す。token が漏れたかもしれない時に使い、要る人に出し直す。
- 「公開された記録」には、公開した人、公開した日、寄せられた一言の数と、公開の頁を開くリンクが出る。「寄せられた一言を見る」で中身を見て、一件ずつ消せる（二度押し）。

誰が何をしたか（通した、断った）は、サーバーの記録に一行ずつ残る。token も招待コードも書かれない。確かめは `kagi log verify`、期限は `kagi check tokens`（`docs/kagi 手引き.md`）。
