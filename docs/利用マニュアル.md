# 利用マニュアル — seed

書いた日: 2026-11-02。使う人（自給したい人、テスター）のための手引き。画面や手順を変えたら、末尾の「変更の記録」に日付付きで書く。仕組みの側は [設計書.md](設計書.md)、ファイルの中身は [記録の形.md](記録の形.md)。

## 1. seed は何をする物か

すべては畑の写真を撮ることから始まる。記録を置くフォルダーを、このマニュアルではプロジェクトフォルダー（記録のフォルダー）と呼ぶ。アプリの上の端に、その名と、変えるためのフォルダーの印が出る。自分の畑が無くてもよい（§5）。畑の写真（座標入り）を自分の Claude に渡すと、**読み**が戻る。あなたは読みに**合う／違う**を付ける。選んだ行を**公開**でき、公開された記録で人と**繋がる**。座標から引く地形・土壌・筆の**資料の行**（`data`）は、照会の部品（`[lookup]`）を入れた PC か、サーバーで引く（§3、§5「この土地」）。この PC の Claude Code は写真を読むだけで、照会はしない（§6.1）。

seed が持ち込む物は、生物学・気象・地質の読み（出典付き）で、農業のやり方ではない。気象の章（手引き 03）は、気象庁の平年値と天気の害の資料の入口と、記録の気象の行の読み方です。気象の実績は `weather/<月>.md` に残る（§5「気象の記録」）。

**事実は三つだけ。** 出典付きの `data` 行、あなたの言葉の `record` 行、あなたの判定（合う／違う）。AI の行は、言い切りの形でも仮説で、確からしさ `[0.00〜1.00]` が付く。

しないこと:
- 「こうしなさい」とは言わない。読みは、何が見えて、何に拠るか、次に何を見るとよいか、まで。判定の形の文（〜すべき）は `uncertain` に落とされる。Claude の行は仮説で、合っていたかは次の季節の畑に出ます。
- 記録を預からない。記録（写真と座標を含む）はあなたの PC の `~/seed/` に残る。座標はこの作業に必須で、記録から外さない。人に見える所に出るのは、あなたが了解した行だけ（§9）。
- 売買と伝言の仕組みは持たない。繋がった後の会話は Discord で。

## 2. 要るもの

| 使い方 | 要るもの |
|---|---|
| 畑を観察する | Python 3.11 以上と `git` の入った PC（Windows / macOS / Linux）。読みは、この PC の Claude Code（`claude` コマンド。入れ方は https://claude.com/claude-code 。Pro 以上のサブスクでログイン。API キーは不要）か、自分の Claude に手で頼む（§6）。外のサーバーで読む道もあるが、今は準備中（§4）。地形・土壌・筆の資料の行は、照会の部品 `[lookup]` を入れるとこの PC で引ける（§3） |

| スマートフォン | Android か iPhone。seed のアプリはストアに無く、PC で作って入れる（README「スマートフォンで試す」、[iPhone 版.md](iPhone%20版.md)）。撮る画面には、カメラと位置を使う許しが要る（§11b） |
| スマートフォンから PC へ送る | PC とスマートフォンが同じ Wi-Fi にあること。PC に `[server]` の部品と Claude Code（§11b） |
| 畑 | 無くてよい。気になる耕作放棄地を道から撮れば、候補地として観察できる（§5） |
| 公開・一言・サーバーで読む | 招待コード（Discord「AI と一緒に自給農」で渡す）。この PC の Claude で読むだけなら要らない。家の PC に送る時の 6 桁の招待コードは、これとは別の物で、PC の `seed home` が出す（§11b） |

詰まった所は Discord か Issues へ（§12）。

## 3. 入れ方（自分の PC）

**命令を打たずに入れる。** GitHub の頁の緑の「Code」から「Download ZIP」で取り、解いたフォルダーの中の一つを二度押しします（Windows は `open-seed.bat`、macOS は `open-seed.command`、Linux は `open-seed.sh`）。初めての時は、要る部品を入れてからアプリが開きます（数分かかります）。二度目からはすぐ開きます。Claude Code が入っていない時やログインしていない時は、最初に「準備」の画面が出て、「入れる」「ログインする」のボタンで済みます。この画面は、上の端の歯車の「準備を見直す」でいつでも開けます。確かめたのは Linux です。Windows と macOS でうまく開かない時は、下の命令で入れてください。

新しい版にするのは、歯車の「新しくする」です（`git clone` で取った写しの時。ZIP で取った写しは、GitHub の頁が開くので、新しい ZIP を取り直します）。自分で直した所がある時は、入れ替えずに知らせます。

**命令で入れる。** GitHub から取って入れます。PyPI には今は出していません。いいアプリが出来たら上げます（例: 同じ作者の fieldnotes-farm https://pypi.org/project/fieldnotes-farm/ ）。アプリのストアには出しません。自分の物にするにはフォークします（§11「機能は自分で足す」）。動かし方（`seed app`、`flet run`）は README の「使ってみる」にある。スマートフォンで試すのは、USB で繋いだ Android に `flet devices` で出る番号を渡す `flet debug android --device-id <番号> --arch arm64-v8a`。アプリにして入れるなら `flet build apk --arch arm64-v8a` で出来る `build/apk/seed-farm.apk` を入れる（どちらも PC に Flutter と Android Studio が要る。README の「スマートフォンで試す」）。iPhone は Mac で作る（[iPhone 版.md](iPhone%20版.md)）。

```bash
git clone https://github.com/aiseed-dev/seed.git
```

```bash
cd seed && python -m venv .venv && .venv/bin/pip install -e ".[app]"
```

venv を有効にする（ターミナルを開くたびに一度）。macOS / Linux:

```bash
source .venv/bin/activate
```

Windows:

```
.venv\Scripts\activate
```

有効にした後は、コマンドは `seed` でよい（以下もそう書く）。有効にしないなら `.venv/bin/seed`（Windows では `.venv\Scripts\seed`）。足す物（extra）は使うときだけ:

| extra | 中身 | 何に |
|---|---|---|
| `[app]` | Flet 1.1.0、Pillow、httpx、pillow-heif ほか | アプリと写真。ふつうはこれ。iPhone の HEIC も読める |
| `[origin]` | Pillow、httpx、imageio-ffmpeg | `seed origin` の mp4。無ければ GIF になる |
| `[grow]` | Pillow、httpx、resvg-py | `seed grow --draw`（図を PNG にして絵に） |
| `[heic]` | pillow-heif | HEIC だけ要るとき |
| `[server]` | FastAPI、uvicorn など | `seed home`（スマートフォンから PC へ送る。§11b）。サーバーを動かす人も |
| `[lookup]` | numpy、Pillow、httpx | 座標から土地の資料の行（地名、筆、標高、地形、地質、災害の区域、土、史跡）を、この PC で引く（§5「この土地」） |
| `[sam]` | meta-sam-parser、numpy、openai | `seed sam`（写真の覆い％。Meta の SAM 3.1。Meta の鍵が要る） |
| `[voice]` | httpx、av | `seed voice`（録音の書き取り。Meta の Muse Voice Transcribe。Meta の鍵が要る） |
| `[mcp]` | mcp | `seed mcp`（本人の AI から記録を読む） |

```bash
seed init
```

`seed init` は `~/seed/` と設定 `~/seed/seed.toml` を作り、公開のための乱数（token）を決め、手引きを `~/seed/skill/` に写す。場所を変えるなら `--folder <道>`（環境変数 `SEED_FOLDER` でも）。招待コードがあれば `--invite CODE`、後からでも `seed invite CODE`。サーバーを置く人は、渡したコードの一覧を `seed invite --list --invites /etc/seed/invites.toml` で見る（呼び名とコードの先頭 4 桁だけ）。失効は `invites.toml` からその行を消すだけで、再起動しなくても次の要求から効く。

`seed init` はディスクの空きを測って見せ、**どれだけ残すか**（`keep`）を出す。観察一回（写真 10 枚）の目安は、`text`（写真は読み用の長辺 2,000 px。座標は残る）約 5 MB、`photos`（既定。写真を元の大きさの JPEG で）約 80 MB、`research`（さらに写真の元 `originals/` と読みの生の出力 `observations/<id>.raw/`）約 120 MB。`seed init --keep research` か、後から `seed keep research`。写真の元を別の盤に置くなら `--bulk <道>`（`--bulk ""` で外す）。アプリでは「どれだけ残しているか見せて」の答えの下のボタンで変えられる。上げるのは自由、下げても何も消えない。消すのは `seed prune`（何を何 MB 消すかを見せ、y と答えたときだけ。`--yes` で聞かない）。アプリでは「残さない物を消したい」から、「消す」を二度押した時だけ。詳しくは [記録の形.md](記録の形.md) §11。

## 4. Web で見る（seed.aiseed.dev）

seed.aiseed.dev は開いています。Claude の読み取りと話すは準備中で、公開された記録は読めます。入口に公開された記録の一覧と件数が並び、記録を開くと、その人が選んで公開した行と写真（位置の情報を外した物）が読めます。一言はアプリの「話す」から送ります（§8）。Web は説明と公開された記録を置く所で、アプリの Web 版はありません（`seed app --web` は、この PC のブラウザで画面を確かめるための物です）。使い方は https://seed.aiseed.dev/manual でも読めます（このマニュアルと同じ物です）。

外のサーバーが開くまで、それを使う所（サーバーで読む、ほかの人の畑、一言、取り下げ）は「サーバーに届きません」で止まります。家の PC の `seed home`（§11b）は外のサーバーとは別の物で、今も使えます。

## 5. 自分の PC で

```bash
seed app
```

アプリは PC 版とスマートフォン（iPhone、Android）。上の端に、プロジェクトの名と小さな印が並ぶ。左から、歯車（**設定**のフォーム。PC と繋ぐ、読む所、自分の鍵。§6、§11b）、フォルダー（プロジェクトフォルダーと畑を変える）、**話す**（Claude とのやり取り）、**写真**（この畑の写真を全部）、同梱の画面 **この土地**、**手続き**、**天気**、自分で足した画面（§11）。サーバーの管理は、このアプリではなく kagi の机の画面「人の出入り」から（§11c）。

「話す」は、Claude Code の画面のように、上から下へやり取りが並ぶ（新しい物が下）。一番下に、写真を足すボタン（スマートフォンはカメラの印で「撮る」、PC は「写真・動画・zip を選ぶ」）、一行の欄、送るボタン。文字を打つ所は、ここと歯車の設定のフォームだけ。写真を読む時は、土と歴史をいつも聞く（`ask` の `soil`、`history`）。読みの中で土や歴史に触れた行は「土地の資料から分かる事」として分けて出る。

「この土地」の画面には、座標から引いた土地の資料の行（`place.md` の `## Data`）が、土地と地形・土・水と災害の区域・歴史の四つにまとまって、出典と一緒に出る。資料がまだ無ければ「この場所の資料を調べる」、昔の地図と空中写真がまだ無ければ「昔の地図と空中写真を取って来る」を押す（AI は使わない。地図を先に、空中写真は古い順。押すと大きく）。資料は、位置の入った写真を初めて送った時にも引きに行く（照会の部品 `[lookup]` があればこの PC で、無ければ招待コードでサーバーで）。「この土地の成り立ちを教えて」と話すと、Claude がこの資料を読んで答える。

何ができるかは、入力の上に「こういう事ができます」の例で出る（「この土地の成り立ちを教えて」「土はどんな土？」「昔はどんな土地だった？」（無ければその場で地図を取って来る）「写真を場所ごとに、時の順に並べて」「この草の名前は？」「それは違う。あれはススキ」「来年の春の計画を立てたい」「この観察を公開したい」「設定を見せて」など）。押すか、同じ言葉を書いて送る。

一周は、写真を撮る → 読み → 違う所を言葉で言う → 計画 → 公開 → 繋がる、の順。撮るから違う所までは下の「畑を観察する」、計画は「借りる・買うことができたら — 栽培計画」、公開は §7、繋がるは §8。畑が無い人、紹介された農地を見る人は「農地が無いとき」「農地を紹介されたら」も読む。

### 畑を観察する

1. 「話す」の左下のボタンで写真を足す（一言を添えてもよい。先に下の欄に書いてからボタンを押す。例「北の角。土が固い」）。スマートフォンはカメラが開く（§11b）。PC にはカメラが無いので、スマートフォンで撮った写真を PC に移し、「写真・動画・zip を選ぶ」で選ぶ（HEIC でもよい。動画と zip も。下の「PC で写真・動画・zip を入れる」）。家の PC で `seed home` を動かせば、スマートフォンで撮った物がそのまま PC に届く（§11b）。一つの観察は写真 6 枚まで。写真は `~/seed/photos/<日>/<時刻>.jpg` に写され、座標と時刻は EXIF から読む。ほかの写真から 50 m より離れた写真は知らせる。
2. 送った写真が大きく出て「読んでいます…」。読み方は設定の「読み取りと話す」の通り。既定は在る物を順に: この PC の Claude Code（§6.1）、自分の Claude の鍵（§6）、サーバー（招待コード）。スマートフォンは自分の鍵かサーバー（家の PC の `seed home` もサーバーの一つ）。どれも無ければ「招待コードを貼ってください」と出るので、下の欄に貼る（その一行はやり取りに残らない）。
3. Claude の側に、今日の一枚（一番見せたい写真）とその一言、見つけた事（行が指す写真が左に小さく出る）、Claude からの問い、次の一枚（次に撮るとよい物）が出る。長い読みは頭の数行だけで、「続きを読む」で開く。読みは `~/seed/observations/<日>-<時刻>.md` に残る。
4. 問いへの答えや、読みの違う所は、下の欄に言葉で書いて送る（例「3 行目は違う。あれはススキ」「水が溜まるのは雨の後だけ」）。Claude が使える時（この PC の Claude Code、自分の Claude の鍵、招待コードでサーバー）は、Claude が違う行に印を付け（`seed mark` と同じ）、あなたの言葉を残し、読み直して、直した行を先に見せる。どれも使えない時は、あなたの言葉として一番新しい観察に残り（「書き留めました」と、Claude と話すには何を入れるか）、次に写真を送った時の読み取りが「あなたが直した事」として先に読む。
5. 「写真」の画面で、写真を日ごと・観察ごとに見る。押すと大きく開き（左右で前後へ、つまんで拡大。位置の入っていない写真には「位置なし」）、「この草の名前は？」「今日の一枚にする」「この写真を外す」ができる。外した写真は消えず、`~/seed/photos/removed/` に移る（すぐ後なら「戻す」）。

   Claude は読みの中で、写真一枚ごとに「タグ」の行を付けます（植物の名と、発芽・育ち・開花・結実・枯れ・刈った・播いた・植えた・収穫・裸地の十語のうちの状態）。「写真」の画面の上に、タグが札（語と枚数）で並び、押すとその語の写真だけが日ごとに出ます（もう一度押すと全部に戻ります）。大きく開いた写真の下にも出ます。直したい時は、ほかの行と同じに「話す」で言葉で言います（例「この写真の開花は違う」）。
6. `place.md`（場所について分かっていること）、`next.md`（その次の考え）、観察のファイルは、どれも文字のファイルなので、エディターで直してよい。細かい作業（並べ替え、比べる、まとめる）は Claude Code に頼む。写真を場所ごとに時の順に並べるのは `seed photos --by-place`（AI を使わない）。

### 入力欄の上の例

「話す」の入力欄の上に、次に言えそうな言葉が三つまで出ます。押すと、その言葉が自分の言葉として送られます。並ぶ物は、その時の場面で変わります。

- 準備が足りない時は「準備を見る」（スマートフォンは「PC を探す」）。
- 読みの中に Claude の問いが残っている時は「問いに答える」。押すと入力欄が「問いへの答えを書く」に変わり、次に書いた一行が、その問いへの答えとして観察に残ります。
- 写真を送って読みが返った後は「それは違う。あれはススキ」「この草の名前は？」。
- 前の観察から 7 日以上空いた時は「今日の一枚を撮る」「同じ場所を前と比べて」。
- Claude が返事の終わりに付けた、次の一言。

最後の「ほかに何ができますか」を押すと、できる事が全部並びます。「今月の帳簿を見せて」「種のロットを見せて」「今月の気象の記録を見せて」「違うと言った所を集めて」「どれだけ残しているか見せて」は、Claude が使えない時でもそのまま答えます。「残さない物を消したい」は、何を何 MB 消すかを見せ、「消す」「本当に消す」と二度押した時だけ消します。

### PC で写真・動画・zip を入れる

「話す」の左下のボタン（「写真・動画・zip を選ぶ」）を押すと、ファイルを選ぶ窓が出ます。いくつでも選べます。プロジェクト全体を見ている時は、先に畑を選ぶ板が出ます。

| 選んだ物 | どうなるか |
|---|---|
| 写真（jpg、jpeg、png、heic、heif） | 撮った時（EXIF。無ければファイルの時刻）の順に並べ、撮った日ごとに 6 枚ずつの観察にして、順に読みます。二回以上に分かれる時は「写真 N 枚を、撮った日ごとに M 回に分けて読みます。」と出ます |
| 動画（mp4、mov、m4v） | 読みには入りません。`videos/<撮った日>/<時刻>.<元の拡張子>` に写し、撮った時と所を同じ名の `.json` に書きます。撮った時は動画の中の時刻、無ければファイルの時刻。所は、動画の中に位置が書かれている時だけ入ります（スマートフォンの標準のカメラで、位置を付けて撮った物）。選んだ元のファイルはそのまま残ります。撮った時と大きさが同じ動画がもうあれば、同じ物として二度は置きません。「動画 N 本を置きました: …」と出ます |
| zip | 中の写真と動画だけを取り出して、上の二つと同じに入れます。zip の中のフォルダーは見ず、ファイルの名だけで取り出します。写真の撮った時が無ければ、zip に書かれた時刻を使います。取り出した物は記録のフォルダーの中の一時の場所に置き、終われば消します |
| そのほか | 入れません。「写真でも動画でもない物 N 個は入れませんでした: …」と名が出ます（zip の中の、写真でも動画でもない物、鍵の掛かった物、壊れた物、zip の中の zip も） |

- zip の大きさの上限は、中の一つが 4 GB、取り出す全体が 16 GB、ファイルの数が 2,000 です。超えると「zip を開けませんでした（…）。」と出て、その回に選んだ物は何も入りません。
- zip の中の、名が「.」で始まる物と、Mac が付ける `__MACOSX` の中の物は、黙って飛ばします。
- 写真も動画も無ければ「写真も動画も見つかりませんでした。」と出ます。
- 動画は、アプリの「写真」の画面には出ません。`videos/` のフォルダーを開いて見ます。

### 畑に入っていない写真

記録のフォルダー（`~/seed`）に、どの畑にも入っていない写真があると、アプリを開いた時に「話す」で知らせます。前のアプリから移した写真や、手でフォルダーに置いた写真です。

- 写真ごとに、どの畑の観察から何 m 離れているかが出ます。撮った場所が書かれていない写真は「撮った場所が分かりません」と出ます。小さな絵も付きます。
- どの畑に入れるかは、下の欄に言葉で書きます。例「島根のは知人の田」「IMG_5663 は rokuse」。フォルダーの名か写真の名と、畑の名を一つ書きます。写真を選んで入れた時と同じに、撮った日ごとの観察になって読まれます。
- 元の写真は、そのまま残ります。フォルダーの写真が全部畑に入ると、そのフォルダーを消す命令が出ます。消すのはご自身です。アプリは消しません。
- もう畑に入っている写真は数だけが出ます。中身が同じ物か、撮った時刻の同じ物があれば、入っていると見ます。

### コマンドで

```bash
seed observe ~/Pictures/IMG_0012.jpg ~/Pictures/IMG_0013.jpg
```

Windows では写真の道を `C:\Users\<名前>\Pictures\IMG_0012.jpg` のように書く。

```bash
seed observe --ask grow,soil --say "ask: 果樹は向くか" ~/Pictures/IMG_0012.jpg
```

`--ask` の語は `grow, soil, plants, history, access, sow, next, names`。`--say` は `did:`、`saw:`、`said:`、`note:`、`ask:` の形で何度でも。読む先は `--local`（この PC の claude。あれば既定）、`--server`（claude が無いときの既定）、`--claude-code`（読まずに手順を出す）。CLI の写真の数に上限は無いが、サーバーの道は 6 枚まで。外のサーバーはまだ開いていないので、Claude Code が無い PC では、今は既定のままでは読みが戻らない（`--claude-code` で手順を出し、§6.2 で頼む）。Claude Code がある PC では既定（この PC の claude）でよい。

```bash
seed mark 2026-11-05-142107 soil_surface wrong --reason "北側は見える"
```

同じ key の行がいくつもあるとき（`plants` など）は `--text "行の文"` でどの行かを指す。本人の行は `seed say 2026-11-05-142107 did "今日は見ただけ"`。

### 借りる・買うことができたら — 栽培計画

1. 自分の畑として撮る（「自分の畑」、`kind: own`）。
2. 「話す」で「来年の春の計画を立てたい」のように言う（季節もその言葉で）。Claude（この PC の Claude Code、自分の鍵、サーバーのどれか）が、手引き、観察、`place.md` を読んで、`~/seed/plan.md` の `## Plan` の行を書く。
3. どれも使えない端末では「これは PC の Claude Code でできます」と、鍵か招待コードを入れればここでも頼める事が返る。手で頼む手順は `seed plan --claude-code` が出す。立てた計画は「計画を見せて」で見える。
4. 違う行は「話す」で言葉で言う（Claude が印を付ける）。決めたことは「決めたこと」（`decided`）、したことは「したこと」（`did`）として、「話す」で言うか `seed say plan …` で書く。立て直しても、判定と自分の行は残る。
5. 立ち位置（菌根菌を活かす自然農法から。理由はりん酸肥料の高騰）は出発点で、前提ではない。数字と混植は書かない（手引き 09 章、04 章）。収量や経費の数字は、作者の別の手引き aiai（就農の手続きと自然農法の経営計画）に任せる。

```bash
seed plan --season "2026-27 冬" --decided "南側は草のまま"
```

`seed say plan did "北側を刈った"`、`seed mark plan sow wrong --reason "種が無い"` のように、`plan` を観察の名の代わりに使う。

同じ場所（100 m 以内）をまた撮ると、読みに `change`（前の観察からの変化）が付く。「したこと」を残しておけば、何が効いたかが並んで読める。同じ写真をもう一度読ませると AI の行は置き換わり、判定と自分の言葉は残る。判定の付いていた行の文が変わると、古い行は「前の読み」に移る。

3. 白い穂の草を Claude は「ススキらしい」と読み、作者が「違う」を付けた（理由: ススキではなくてオギ）。土の固さは写真に写らない、と読みの側にも書かれた。
4. 栽培計画 `plan.md` の元になったのは、作者が記録に書いた言葉（元田んぼ、硬盤層、おそらくシルト質埴土、サブソイラにはトラクターが要る）で、Claude はそれを案に並べた。固い層の厚さは分からないので、次に見ることとして計画に残った。

### 農地が無いとき — ここから始める

1. 気になる耕作放棄地を、道から撮る（人の土地に入らない）。
2. 「話す」で「設定を見せて」と送り、「今見ている畑」を「候補地に変える」にしてから撮る（CLI は `seed observe --candidate`）。
3. 筆と所有者を調べるのは、あなた。手引き 13 章に、地番は法務局の地図（公図）で、所有者は登記事項証明書か近所で、とある。分かったことは「言ったこと」「そのほか」に自分の言葉で残す。**所有者の名前や住所は公開しない。** 公開の下書きで Claude が人の名前を「近所の方」のような言い方に直し、載せる前にサーバーの人が読みます（§9）。電話番号・メール・郵便番号の形はアプリが止めます。
4. 持ち主と話せたら、その人にも seed を渡す。公開の「その次」に「貸す」「借りる」「手伝う」の札がある。

### 農地を紹介されたら — 借りる・買うかの材料

1. その農地を候補地として観察する（道、水の口、周りの畑、傾斜が分かるように）。
2. 読みに、道（`access`）、日当たりと傾斜（`sun_slope`）、周り（`surroundings`）、水（`water`）、草（`plants`）が並ぶ。
3. 筆・地形・ハザード・地質・土壌の**資料の行（`data`）**は、「この土地」の画面に出る（照会の部品 `[lookup]` を入れた PC か、招待コードでサーバーで引く。§3、§5 の初め）。この PC の Claude Code で読んだだけでは付かない。
4. これは材料で、借りる・買うの判定は出ない。手続きは手引き 13 章と 00 章。

### 畑の成り立ちの動画 `seed origin`

座標から、公開の地図と空中写真を順に並べた一分ほどの動画を組む。AI は使わない。場面は、標準地図（引いた所から寄る）、色別標高図、地形分類、洪水浸水想定区域、土砂災害警戒区域、土壌図、年代別の空中写真（その場所にある年代だけ）、近くの史跡、あなたの写真。字幕は `place.md` の照会の行（出典付き）だけで、各場面の下に地図の出典が出る。照会の行が無いと字幕は付かず、史跡の場面は省く。

```bash
seed origin
```

- 中心は、座標のある一番新しい観察か、`--lat` と `--lon`。ほかに `--seconds`（一場面、既定 3）、`--fps`（既定 24）、`--size`（既定 1280x720）、`--font`、`--out`（記録のフォルダーの中だけ）。
- 出力は `~/seed/origin/<日>/`（`origin.mp4`、`frames/`、字幕と出典の表 `captions.md`）。タイルは `~/seed/origin/tiles/` に置き、次からは取らない。一回に取るタイルは 200 枚まで。
- mp4 には `pip install -e ".[origin]"`。無ければ `origin.gif`。日本語のフォント（Noto Sans CJK など）が無ければ `--font` で渡す。
- **動画には畑の場所が写る。** `seed publish` は動画を送らない。公開は、下書きの全文を読んで「出す」と言った物だけが送られる。座標と名前は下書きで外れる。地図の利用の条件は `captions.md` の最後（Claude が確認）。タイルのキャッシュは人に渡さない。

### 計画の絵（仮説）`seed grow`

`plan.md` の `## Plan` の行から、畑が季節ごとにどう見えるはずかを、線と色と字の図にする（場面は 6 まで）。上から見た図、横から見た土の断面、見えるはずの物が一枚に並ぶ。**仮説の図で、あなたの写真でも判定でもない。** 時期が来たら同じ所を撮って並べ、合う／違うを付けるための物。

Claude が場面を書き、seed がそれを計画の行と照らして描く。計画の行に無い場面と作物は描かず、省いた理由を `captions.md` に書く。確からしさは元の行より高くならない。先に `seed plan` で計画の行が要る。

```bash
seed grow
```

- 道は二つ。この PC の claude（既定。`--scenes 3` で場面の数を絞る）か、`seed grow --claude-code` で手順を出し、Claude Code に手引き 09 章の「計画の絵（仮説）」に従って `grow/<日>/scenario.json` を書かせ、`seed grow --render grow/<日>/scenario.json` で描く。
- 出力は `~/seed/grow/<今日>/`（`scenario.json`、`01-2026-12.svg` のような図、`captions.md`）。図はブラウザで開ける。
- **公開しない。** `seed publish` は `grow/` を送らない。図に実在の地名が入っていないかは seed には確かめられないので、人に見せる前に読む。

**自分の機械で絵にする（`--draw`）。**（上級者向け。GPU のある機械と画像生成サーバーが要る）場面の図を、あなたが用意した画像生成の機械（stable-diffusion.cpp の sd-server、FLUX.2 klein 4B）でイラストにする。要るのは `[grow]` と、その機械。絵の指示（英語の `prompt`）は Claude がシナリオに書く物で、`prompt` の無い場面は描かない。

```bash
seed grow --draw --server http://<あなたの機械>:11445   # 門（deploy/halo）の口。token は credentials.toml の draw_token
```

- 機械の場所は `--server` > 環境変数 `SEED_DRAW_URL` > `seed.toml` の `[grow]` の `server`。無いか応えなければ止まる（図の SVG は残る）。日は `--day`（既定は `grow/` の一番新しい日）。参照の写真は `--photo <道>`（3 枚まで）、`--size` の既定は 1280x720。
- **送るのは、場面の `prompt`、図の PNG、`--photo` の写真（EXIF を落とした写し）だけ。座標は送らない。** 機械が家の中（192.168.*、10.*、localhost）なら `captions.md` に「写真は家の外に出ていない」と出る。
- 出力: `grow/<日>/raw/`（戻ったまま）と、「計画の絵（仮説）」の印を焼いた `grow/<日>/01-2026-12.png`。`captions.md` に「絵の作り方」と「Claude の照らし」。
- 描いた後、この PC の claude があれば、絵にシナリオに無い物（計画に無い作物、構造物、人、文字）が入っていないかを照らす。無ければ Claude Code で見る手順が出る。**生成の絵は計画に無い物を描く**（11-04 の作者の畑では、穂の出たライムギ、畝の形の筋）。人に見せる前に照らしを読む。
- 機械の支度の例は `scripts/setup-draw-server.sh`（読んでから、その機械で走らせる）。

### 畑を分ける `seed field`

畑が二つ以上ある時は、一つのプロジェクトフォルダーの中に `fields/<畑の名>/` を作って分けます。
畑のフォルダーの中身は、今までの記録のフォルダーと同じです（写真、観察、`place.md`、`plan.md`、公開の控え）。
設定（`seed.toml`）、手引き（`skill/`）、`CLAUDE.md`、本人の画面（`plugins/`）は、プロジェクトフォルダーに一つだけ置き、どの畑でも使います。
`fields/` が無いプロジェクトは、今まで通り、プロジェクトフォルダーそのものが一つの畑です。

- `seed field new 北の畑` で `fields/北の畑/` を作り、今の畑にします。プロジェクトフォルダーにもう記録（観察や写真）があれば、初めての畑を作る時に、その記録をこの畑へ移します（設定、手引き、`CLAUDE.md`、`plugins/` は移しません）。
- `seed field use 北の畑` で今の畑を選びます（`seed.toml` の `field` に書きます）。`seed field use all` でプロジェクト全体にします。
- `seed field list` で畑の並びを見ます（今の物に `*`）。
- どの命令も `--field 北の畑` で、その回だけその畑を使えます。観察を作る、読む、公開するなどの命令は、畑を選んでから使います。

アプリでは、上の端のフォルダーの印を押すと、下に板が出ます。上に「プロジェクト全体」と畑の並び（今の物に印）、細い線の下に別のプロジェクトが並びます。
畑を選ぶと、上の端の名は「プロジェクトの名 / 畑の名 — 話す」になります。
「プロジェクト全体」では、写真は畑ごとの見出しで全部を並べ、話すは畑ごとの見出しでやり取りを並べます。言葉は、この PC の Claude Code にプロジェクトフォルダーで渡します。
写真は畑ごと、月ごと、日ごとに並びます（新しい月、新しい日が上）。話すのやり取りには、月が替わる所に小さく月が出ます。
写真を撮る、選んで送る、公開するは、畑を選んでからです（全体の時に写真のボタンを押すと、畑を選ぶ板が出ます）。

別のフォルダー（別のプロジェクト）は、プロジェクトの一覧（`~/.config/seed/fields.toml`）で切り替えます。
`seed project add 知人の田 ~/知人の田` で一覧に足し、`seed project use 知人の田` で替え、`seed project list` で見ます。前の名の `seed field add` も同じ事をします。
**どのフォルダーを使うか**は、この順で決まります: `--folder` → 今いるフォルダー（`seed.toml` がある時。Claude Code と同じ）→ `--field`（このプロジェクトに無い名なら一覧の名）→ 今のプロジェクト → `SEED_FOLDER` → `~/seed`。
PC のアプリでは、板の「別のフォルダーを開く」で選んだフォルダーが、フォルダーの名で一覧に足されて、今のプロジェクトになります。

## 5b. 土地の仮説を確かめる、覆い％、声（2026-11-11。fieldnotes から）

- **仮説。** `seed hypothesis add "南に水田が並ぶ（出典: 本人）"` で足し、`seed hypothesis list` で見る。`seed check` は、写真を見る前に「正しければ何が見え、違えば何が見えるか」を書き（`hypotheses.md` の `## Expect`）、それから一番新しい観察の写真で確かめる（観察の `## Checks`）。確かめられたら `seed mark hypotheses h1 right`、違ったら `wrong --reason …`。見込みが違えば `seed mark expect h1 wrong`。アプリでは「確かめ」の画面。
- **刈り方。** `seed plan --cut`。伸びた所を作物に戻す最初の一刈り（所、高さ、残す物、刈り方）だけを立て直す。ほかの計画の行は残る。
- **写真の覆い％。** `seed sam`。Meta の SAM 3.1 で、写真の何％を各名詞が覆うか（観察の前書き `coverage`）。名詞は `seed concept list`、違う名詞は `seed concept mark <名詞> wrong --instead <代わり>`。Meta の鍵（`~/.config/seed/credentials.toml` の `meta_key`）が要る。
- **声。** `seed voice <録音>`（Meta の Muse Voice Transcribe で書き取り、Claude が「したこと」「見たこと」と読みの合う／違うに分ける）。書き取った文があれば `seed voice --text "…"`。
- **草の読み。** `seed plants`。優占する草がなぜ優占するかを一度だけ Claude に聞き、`plants/` に置く。次の読みに仮説として渡る。
- **本人の AI から。** `seed mcp`（Claude Desktop や Claude Code の MCP の設定に書く）。家の網に出すなら `seed mcp --http`（口 8552）。
- **fieldnotes の記録を移す。** `seed import fieldnotes <fieldnotes の農場のフォルダー>`。元のフォルダーは変えない。畑ごとに `fields/<名>/` になる。

## 6. 自分の Claude で読む

**自分の Claude の鍵（Anthropic の API の鍵）で。** Claude Code が無い PC とスマートフォンでも、自分の鍵を入れると、写真の読み取りと「話す」の細かい作業（違う所を直す、計画、公開の下書き）がその端末から直にできる。費用はあなたの鍵に掛かる。鍵は [console.anthropic.com](https://console.anthropic.com/) で作る。入れ方: 上の端の歯車を押し、「自分の Claude の鍵（あれば）」の「Anthropic の API の鍵」の欄に貼って「保存」（伏せ字で出る）。「話す」で「設定を見せて」→「自分の Claude の鍵」の「入れる」を押し、下の欄に貼って送ってもよい（「入りました」とだけ返る）。鍵はやり取りにも記録にも残らない。置き場はこの端末の `~/.config/seed/credentials.toml`（600）だけで、送り先は Anthropic の API だけ。外すのは、歯車のフォームの「鍵を外す」か、「設定を見せて」の「鍵を外す」（続けて「本当に外す」）。モデルは `seed.toml` の `claude_model`（既定 `claude-opus-5-5`。安くするなら `claude-sonnet-5-5` か `claude-haiku-5-5`）。Claude は記録のフォルダーの中だけに効く道具を使い、アプリがそれを端末の中で動かす（公開を送る事と、命令を走らせる事はできない）。待つ間も画面は動き、「止める」で止まる。

**サーバー経由で。** 招待コードを入れると（歯車のフォームの「招待コード」か `seed invite CODE`）、写真の読み取りと「話す」がサーバー（作る人の鍵）を通る。一日の回数に上限があり、使い切った時と受け付けを止めている時は、あなたの言葉を書き留めて理由を返す。

どれを使うかは、歯車のフォームの「読む所」で選ぶ（「手元の Claude（Claude Code）で」は、この PC に claude がある時だけ出る）。「設定を見せて」の「読み取りと話す」でも、押すと次の物に変わる。既定は、PC がこの PC の Claude Code → 自分の鍵 → サーバー、スマートフォンが自分の鍵 → サーバー。

### 6.1 この PC の Claude Code に読ませる（自動）

Claude Code が入っていてログインしている PC では、`seed observe` は何も付けなくてもこの PC の `claude -p` で読む。アプリでは、写真を送った時に、設定の「読み取りと話す」が「手元の Claude（Claude Code）で」（PC の既定）ならこの道で読む。API キーは要らない。費用はあなたのサブスクの分。

- 渡す手引きは、`SKILL.md` と、06 畑を読む、02 地質と土、04 生物（栽培計画と `seed grow` では 06 の代わりに 09）。03 気象と時期は渡さない（気象の実績は記録の `weather/` から読む）。
- `SKILL.md` は、あなたの写し `~/seed/skill/` にあればそれ、無ければパッケージの物を一つ選ぶ。章（06 か 09、02、04）は一つずつ、写し → パッケージの順で探す。写しに無い章はパッケージの物で補われるので、11-05 より前の写し（古い章の名）でも章は付く。ただし、あなたが古い名の章に書き足した物は名が合わないので読まれない（写し直し方は §11）。
- 「話す」では、記録のフォルダーの中でなら、言葉でフォルダーを作ったり写真を移したりできます（例: 「島根の写真。フォルダーを作って保管して」）。観察が指している写真は動かしません（外すのは「写真」で）。消すのは Claude はしません。頼むと、自分で打つ命令を返事に書くので、中身を確かめて自分で走らせてください。
- 写真はこの PC から Anthropic に送られ、seed のサーバーは通らない。照会の資料の行（`data`）はこの道では付かない（§5）。
- 写真の数だけ時間がかかる（11-03 の別の観察で、23 枚に約 2 分の実例がある。§5 の実例の 24 枚とは別）。モデルは `--model opus` か `--model sonnet`。別の場所の claude を使うなら環境変数 `SEED_CLAUDE`。
- `keep = research` なら、渡した物と戻った物が `observations/<id>.raw/` に残る。

### 6.2 手で頼む

1. Claude Code で `~/seed/` を開く。
2. `~/seed/skill/SKILL.md`（`seed skill-path` が道を出す）を読ませる。Claude.ai なら、プロジェクトの知識に `~/seed/skill/` の中身を入れる。
3. 「`observations/<日>-<時刻>.md` の写真を読んで、観察を書いて」と頼む（`seed observe --claude-code` が、この手順を道付きで出す。同じ場所の前の観察があれば、それも読ませるように出る）。
4. 書けたら、アプリの「話す」で同じように見える。費用はあなたの Claude の分。seed のサーバーは通らない。

フォルダーには `CLAUDE.md`（`seed init` が書く）があるので、Claude Code をここで開けば（PC の端末でも、スマートフォンから使う時も）、アプリの「話す」と同じ決まりで動きます。

## 7. 公開する

seed.aiseed.dev は開いています。サーバーの Claude の読み取りと話すは準備中で、公開された記録は読めます。

公開は、Claude を使って行う。本人が読んだ文と、送られる文を同じにするためで、アプリは公開を組み立てない。「話す」で「この観察を公開したい」と送ると、Claude（この PC の Claude Code、自分の鍵、サーバーのどれか）が下の 1〜2 をする。自分の鍵とサーバーの時は、Claude は下書きを作るだけで送れない。アプリが下書きの写真と全文と「出す」を出し、あなたが写真と全文を見て「出す」を押すと、その中身のまま送る（見せた後に下書きが変わっていたら送らず、新しい全文を出す）。どれも使えない端末では「これは PC の Claude Code でできます」と返る。

1. Claude に「この観察を公開したい」と頼む。Claude が、行の候補（判定の付いた行が先）、場所の粗さ（都道府県／市町村／大字。座標を付けるなら小数 2 桁、約 1 km まで）、呼び名、札、その次、一言（200 字まで。入口に並ぶ）をあなたと決め、下書きを作る（`seed publish … --local`。`~/seed/public/<id>.md` に書かれ、送られない）。公開は成長の記録で、写真は、同じ場所を日を追って撮った物が日ごとに一枚 `photo` の行で入る（二日以上に渡る場所が無ければ、その日の今日の一枚）。別の写真にしたい時は、Claude にそう言う。
2. 下書きの全文を読む。直したい所は Claude に言う。直したら、Claude はもう一度全文を見せる。
3. 「出す」と言うと（自分の鍵とサーバーの時は「出す」を押すと）、その下書きがそのまま送られる（`seed publish --file ~/seed/public/<id>.md`）。「出す」の前には送らない。写真は長い辺 1280 に縮め、撮った場所などの情報（EXIF）を外して一緒に送る。サーバーも受けた写真を開いて書き直し、位置の情報を残さない。行が指す写真が手元に無い時は送らない。
4. 取り下げ・書き直しは同じ PC（同じ token）から。アプリの「話す」で「公開した物を見せて」と送り、「取り下げる」を二度押す。取り下げると、出した写真もサーバーから消える。
5. HTML、電話番号・メール・郵便番号の形の文があると止まる（「直す所」が出る）。候補地の観察を含むと、所有者のことを書かないよう注意が出る。
6. サーバーは、届いた物をすぐには載せない。サーバーを動かす人が読んで「載せる」と言ってから、公開の頁に出る。アプリには「送りました。サーバーの人が読んでから、載ります。」と出る。載ったかは、「公開した物」の「載ったかを見る」で見る。家の PC（`seed home`）では待ちは無く、すぐ載ります。戻された時は、そこにその人の一言が出る。もう載っている記録を書き直した時は、載せるまで前の版が見える。

```bash
seed publish 2026-11-05-142107 --id my-field --place "徳島県 吉野川市" --word "元田んぼを草ごと読んでいます" --local
seed publish --file ~/seed/public/my-field.md
```

一つ目は、判定の付いた読みの行と、`data`、`record` を全部入れた下書きを作る。`--coord`、`--what`、`--next`、`--name`（既定は `seed.toml` の `name`。空なら止まる）、`--contact`、`--photo`（出す写真の名。何度でも。一日 3 枚、全部で 12 枚まで。付けなければ日ごとに今日の一枚）、`--local`（送らずに `public/` に書くだけ。付けなければ作ってすぐ送る）。二つ目は、在る下書きを中身のまま送る（観察や `--id` などは要らない。形が合わなければ送らずに止まる）。

## 8. 探す・繋がる

seed.aiseed.dev は開いています。サーバーの Claude の読み取りと話すは準備中で、公開された記録は読めます。

1. 「話す」で「ほかの人の畑を見たい」と送ると、公開された記録の一覧が出る（一覧はサーバーから取る）。「開く」で中身が読める。
2. 「この人に一言」を押すと、下の欄が「<相手> への一言」になる。書いて送る。送る名はあなたの公開の id（無ければ呼び名）。相手の記録の繋がりの数が増え、自分の `connections.md` に一行残る。同じ相手へは一日一回。
3. 続きの会話は Discord「AI と一緒に自給農」（ https://discord.gg/Q8pwMH2uTA ）で。seed は伝言を持たない。

## 9. 写真と座標、個人情報

- 座標は記録に必須で、あなたの記録には残る。`~/seed/photos/` の写真は位置情報も含めてあなたの物。
- 外に出る物は道ごとに違う。この PC の Claude（§6.1）: 写真を Anthropic へ。自分の鍵（§6）: 縮めた写真（EXIF 無し）と、Claude が道具で読んだ記録の文（観察の細かい座標は渡さない）を Anthropic へ。サーバーで読む・話す: 縮めた写真（EXIF 無し）と座標、話すのやり取りを seed のサーバーへ（サーバーはやり取りの中身を書き残さない）。今の実装は答えを返したら捨て、残すのは回数の上限のための token のハッシュと日時と使った量。Pl@ntNet（§11a）: 縮めた写真だけ、座標は送らない。`--draw`（§5）: prompt と図と選んだ写真（EXIF 無し）だけ。家の PC（`seed home`。§11b）: 写真は縮めず座標入りのまま、動画と撮った時と所、話すの言葉を、家の網の中の PC へ http で送る（外には出ない。PC の Claude Code が読む時に、写真は PC から Anthropic へ）。
- これは今の実装で、約束の中心ではない。**約束は、公開はあなたが了解した物だけ**ということ。場所の粗さもあなたが選ぶ。
- 公開ファイルに本名、住所、電話番号、メールを書かない。アプリが形で止められるのは電話番号・メール・郵便番号と HTML で、住所や名前には形が無い。
- 記録には、近所の人、土地の持ち主、知り合いを名前で書いてよい。記録はあなたの物で、隠す事は無い。名前を見るのは公開の時。Claude が下書きで名前を「近所の方」のような言い方にしてどれを直したかを言い、あなたが全文を読んで「出す」と言い、サーバーを動かす人が読んでから載せる（§7 の 6）。

## 10. 設定 `~/seed/seed.toml`

```toml
folder = "~/seed"
server_url = "https://seed.aiseed.dev"
name = ""                 # 呼び名。公開の既定
language = "ja"           # 本人の言葉の言語。無ければ OS の言語。画面の文と、AI が書く言葉
place_level = "city"      # prefecture / city / oaza。公開の場所の粗さの既定
field = ""                # 今の畑（fields/ の下のフォルダーの名）。空ならプロジェクト全体（seed field use で変える）
keep = "photos"           # text / photos / research（seed keep で変える）
bulk = ""                 # 写真の元 originals/ を置く別の盤の道（seed keep --bulk で変える）
read = ""                 # local / key / server。Claude を呼ぶ所（読み取りと話す）。空なら在る物を順に（「話す」の設定か、歯車のフォームの「読む所」で変える）
claude_model = ""         # 自分の鍵で呼ぶモデル。空なら claude-opus-5-5（費用はあなたに掛かる）
# token、invite、自分の Claude の鍵（秘密）は seed.toml ではなく ~/.config/seed/credentials.toml（600）にある

[grow]
server = "http://<あなたの機械>:11445"   # seed grow --draw の描く機械（任意。門の口。token は credentials.toml）
```

秘密（`token`、`invite`、halo の門の `draw_token`、自分の Claude の鍵 `anthropic_key`）は `seed.toml` ではなく `~/.config/seed/credentials.toml`（許可 600。環境変数 `SEED_CREDENTIALS` で場所を変えられる）に置かれ、`seed.toml` に古く書かれていた物は次に開いた時にそこへ移る。

知らない鍵と表は消さずに書き戻す。ファイルの中の決まった語（`overall`、`farmer: right`、`## Reading`）は英語のまま。どの国の人のフォルダーも同じ読み手で読めるようにするため。画面では日本語で見える。

コマンドの共通の引数と環境変数: `--folder`（`SEED_FOLDER`）、`--field <畑の名>`（この回だけその畑を使う。§5「畑を分ける」）、`--server-url` はこの回だけのサーバー（`SEED_SERVER_URL`。ファイルには書かない）、`SEED_CLAUDE`（§6.1）、`PLANTNET_API_KEY`（§11a）、`SEED_DRAW_URL`（§5）。

## 11. ビルダーの訓練

観察して、読みに合う／違うを付け、「違う」の理由が溜まったら `~/seed/skill/` の手引きの章を直す（`seed marks` が材料を並べる）。この一周が、自分の場所で AI を使い、確かめ、直す、ビルダーの最初の仕事。記録は素の文字のファイルなので、自分の Claude と小さなスクリプトで並べたり比べたりもできる。手順は手引き 08 章。

### 機能は自分で足す

seed は、使う人が自分で機能を足していくアプリです。畑は一枚ずつ違うので、何を記録するか、何をどう読むか、どう見せるかは、人ごとに違います。足し方は二つです。

- **言葉で足す。** 「話す」で「これからは収穫の量も記録して」「写真はまず植物の名で分けて見せて」と言うと、Claude が `~/seed/skill/` の手引きに書き足し、次からそうします。欄も画面も増えません。記録の種類、読む順、売り方、見せ方は、だいたいこれで足ります。
- **画面を足す。** 自分の畑の画面（収穫の表、気象の絵など）は、記録のフォルダーの `plugins/` に Python のファイルを一つ置くと、アプリの上の端に印が増えます。ファイルには `TITLE`（画面の名）、`ICON`（印）、`build(app)`（画面の中身）の三つを書きます。見本は seed の `src/seed/plugins/` の三つです。同梱は三つあります。「この土地」（`land.py`）、「天気」（`weather.py`）、「手続き」（`procedure.py`）です。天気は、畑の二週間（16 日）の予報と、地温と土の水分（深さごと。地表面は ECMWF）を出します（Open-Meteo。座標は小数 2 桁に丸めて送ります）。手続きは、貸し農園から農地法 3 条の下書きまでの道のりを出します（手引き 13 章、`seed procedure`）。自分の Claude Code に「plugins/ に〜の画面を作って」と頼めます。フォークは要りません。
- **コードで足す。** 端末でしかできない事（撮る、位置、画面の形）は、コードです。GitHub の seed を自分のアカウントにフォークし、自分の PC に取ってきて、自分の Claude Code に「写真を撮る画面に〜を足して」と頼みます。`pip install -e ".[app]"` で、その写しが自分の seed になります。ライセンス（AGPL）は、そうやって自分の物にする事を許しています。

フォークした seed は、その人の物で、その人の Claude が動かします。元の seed の Claude があなたのアプリのコードを書き換える事はありません。

画面やコードで足す時の手順は、seed の `skill-builder/` に手引きとしてまとめてあります。自分の Claude Code に `skill-builder/SKILL.md` を読ませてから「〜を足したい」と話すと、言葉で済むかを先に見て、プラグイン一つか、フォークしたコードかの順に進めます。家の PC を仲間のために動かす人の手引きは `skill-keeper/`、その中で使う道具 kagi の手引きは `skill-kagi/` です。写真や資料の置き場を整える時、別の場所の畑をプロジェクトに迎える時、手引きの写しを新しくする時は、`skill-folder/SKILL.md` を読ませてから頼みます。

### 手引きは本人の物

`seed init`（とアプリ、`seed observe`、`seed plan` の始まり）は、手引きを `~/seed/skill/` に写す。これはあなたの手引きで、直してよい。直した手引きが効くのは、この PC の Claude と自分の鍵で読むとき（§6）。サーバーは共通の手引きを読む。

章は 2026-11-05 に組み替えた: 00 始める前、01 立ち位置、02 地質と土、03 気象と時期（気象庁の資料の入口と、記録の気象の行の読み方）、04 生物（菌根菌・草・混植）、05 鳥獣害、06 畑を読む、07 周りの物（筆・史跡・地名）、08 ビルダーの訓練、09 栽培計画、10 種、11 売る、12 加工、13 手続きと農地。

**11-05 より前に写した手引きは、古い章の名のまま**（`02-畑を読む.md`、`06-手続きと農地.md` など）。`seed init` は、もうある `~/seed/skill/` を上書きしない（「上書きしません」と出る）。古い写しのままでも章は付く（§6.1 を見てください）。自分の直しを効かせるには写し直す。写し直すコマンドは無い。手で次のようにする。

```bash
mv ~/seed/skill ~/seed/skill-old
```

```bash
seed init
```

新しい写しができたら、`skill-old/` で自分が直した所を見て、新しい章に移す（`seed marks` の 06 章は、古い写しのあいだはパッケージの物を使っている）。

数字は aiai（作者の別の手引き）に任せ、seed は書かない。混植は、読んだ資料が `~/seed/skill/sources.md` に入るまで書かない。

資料の候補は五つ（`seed init` が `~/seed/skill/` に写す。写した後にリポジトリの `skill/` に足された物は写しに無いので、リポジトリの方を見る。どれも資料の候補で、手引きの本文に引いていない。根拠にはしない）: `sources-regenerative.md`（リジェネラティブ農業と混植と菌根菌、59 件）、`sources-wildlife.md`（鳥獣害）、`sources-law.md`（法令の本文と解説）、`sources-defense.md`（植物の防御機構の論文 178 件）、`sources-security.md`（サイバー攻撃への守り 59 件）。

## 11a. 草の名を確かめる — Pl@ntNet

はじめて作物を作ると、雑草か作物かが分からない。seed は写真を一枚ずつ Pl@ntNet（植物の識別器）に送り、種の候補を `plants` の行に「Pl@ntNet（写真の名）: 名 0.62、…」の形で足す。Claude の読みとは別の行（モデルの読み）なので、合うか食い違うかが分かる。食い違った草は、畑で近くから見直す所です。

- 名を知りたい草は、花か穂か葉を近くで一枚。歩き撮りの全景では当たらない。
- 鍵: 自分の鍵を [my.plantnet.org](https://my.plantnet.org/) で取り、環境変数 `PLANTNET_API_KEY` に置く。鍵がなく招待コードがあれば、サーバーの鍵で送る（`--server`）。seed.aiseed.dev は開いていますが、サーバーの草の名の照会は準備中です。
- 送るのは縮めた写真だけ。座標（EXIF）は送らない。一つの観察で 10 枚まで。
- アプリ: 「写真」で写真を大きく開き「この草の名前は？」。「話す」の例「この草の名前は？」は、一番新しい観察の今日の一枚を確かめる。見つけた草は「この畑で見つけた草を見せて」で写真と並ぶ。
- CLI: 写真の名を省けば全部。`seed observe --ask names` なら観察のときに送る（`--no-identify` で止める）。

```bash
seed identify 2026-11-05-142107 092817 092733
```

`keep = research` なら、答えが `observations/<id>.raw/plantnet-<写真>.json` に残る。

## 11b. スマートフォンだけの人 — スマートフォンのアプリ

アプリは PC 版とスマートフォン（Android、iPhone）です。ストアには出していないので、PC で作って入れます（Android は README の「スマートフォンで試す」、iPhone は Mac で作ります。[iPhone 版.md](iPhone%20版.md)）。人ごとに記録をサーバーに置く Web 版は作りません。

### スマートフォンでの一周

1. seed を開きます。初めは「話す」の画面に「まず一枚、撮ってみます」と「設定を見せて」の札が出ます。
2. 上の端の歯車を押すと、**設定**のフォームが開きます。家の PC に送るなら「PC と繋ぐ」を使います（下の「スマートフォンから PC へ」）。PC を使わないなら、「自分の Claude の鍵（あれば）」に Anthropic の API の鍵を貼るか（§6。費用はあなたに掛かります）、Discord で受けた招待コードを「招待コード」に入れます（サーバーの道。一日の回数に上限があります）。最後に「保存」を押します。
3. 「話す」の左下のカメラの印（撮る）を押すと、カメラが画面いっぱいに開きます。初めての時は、カメラと位置を使ってよいかを端末が聞くので、許します。
4. 撮ります（下の「カメラの使い方」）。写真は一度に 6 枚までです。
5. ✓（撮った枚数が出ます）を押すと、その写真で観察になります。「← 戻る」を押した時は「撮った写真 n 枚を観察にしますか。」と聞かれるので、「n 枚で観察にする」か「観察にせずに戻る」を選びます。
6. 観察にすると「話す」に戻り、写真が大きく出て「読んでいます…」と出ます。読みが戻ったら、違う所を下の欄に言葉で書いて送ります（§5「畑を観察する」）。家の PC と繋いでいれば、写真は PC に届き、PC の Claude Code が読みます。撮った動画は、カメラを出た時に PC へ送ります。

計画を立てる、公開の下書き、読みをその場で直す、も「話す」から頼めます（鍵か、サーバーか、家の PC）。公開は、全文を読んで「出す」を押した時だけ送られます。鍵も招待コードも無い時に言葉だけを送ると、一番新しい観察にあなたの言葉として残り（AI は呼びません）、次に読み取れた時にそれを先に読みます。記録はスマートフォンの中のあなたのフォルダーに残ります。

### カメラの使い方

スマートフォンの標準のカメラに近い形にしてあります。

- **画面**: 画面いっぱいがカメラです。上の端に「← 戻る」と位置の印（「±5 m」のような誤差。まだなら「位置を待っています…」。押すと位置を取り直します）があります。
- **縦と横**: 縦に持つと、下の帯に倍率の札、「写真」「動画」、その下に左から、最後に撮った物の丸、シャッター、✓ が並びます。横に持つと、同じ物が右の端に縦に並びます（上から ✓、シャッター、丸）。
- **倍率**: 画面を二本の指でつまむ（広げると寄ります）か、倍率の札を押します。札は 0.5×、1×、2×、5×、10× のうち、その機種で使える物だけが出ます。開いた時は 1× です。
- **写真**: 位置が取れるまでシャッターは押せません。撮った所、時刻、向き、誤差を写真に書き込みます。
- **動画**: 「動画」を押すとシャッターが赤くなります。押すと録画が始まり（上に赤く ● と経過の時間が出ます）、もう一度押すと止まります。録画の間は写真と動画を切り替えられません。動画は位置が無くても撮れて、撮った時と所を同じ名の `.json` に書きます。動画は読みには入りません（観察は写真だけです）。
- **見返す、消す、元に戻す**: 左下の丸を押すと、撮った物が大きく出ます（‹ › で前後、「消す」「閉じる」）。「消す」を押すと、下に「消しました」と「元に戻す」が数秒出ます。「元に戻す」で元の順に戻ります（写真がもう 6 枚の時は戻せません）。消した物は、カメラを出た時に本当に消えます。
- **戻る**: 「← 戻る」か、端末の戻る操作で「話す」に戻ります（アプリは閉じません）。録画の途中なら、録画を止めて残してから戻ります。
- **残る所**: Android では、撮った写真と動画がスマートフォンの Pictures/seed（日付ごとのフォルダー）にも残ります。アプリを消しても残り、ギャラリーに出て、PC へ写せます。観察にしなかった写真もここに残ります。iPhone はまだ写真ライブラリーに残しません（部品が要ります）。

### スマートフォンから PC へ（一方通行）

PC のプロジェクトフォルダーを本物の記録にして、スマートフォンで撮った写真と動画をそこへ送れます。PC からスマートフォンへ記録を送る事はしません。仲間のために PC を動かす人も、同じ手順です。

PC で（アプリだけでする時）:

- PC のアプリの上の端の歯車を押し、「スマートフォンから写真を受ける」の「始める」を押します。「動いています」と URL が出ます。6 桁の招待コードは、「招待コードを見せる」を押した時だけ出ます。「アプリを開いたら始める」に印を付けると、次からは自分で始まります。止めるには「止める」を押します。アプリを閉じても止まります。この時は、下の 1〜3 は要りません。

PC で（命令でする時）:

1. seed を入れ（§3）、seed のフォルダーでサーバーの部品も入れます。

   ```bash
   pip install -e ".[app,server]"
   ```

2. プロジェクトフォルダーの中で `seed home` を打ちます（別のフォルダーなら `seed home --folder <道>`）。端末に「サーバーの URL: http://…:8800」と「招待コード: 6 桁」が出ます。招待コードはプロジェクトフォルダーの `home.toml` に一つ作られ、次からも同じ物が出ます（`home.toml` を消すと、次の `seed home` で作り直します）。写真を読むのは、この PC の Claude Code です（§6.1）。
3. 端末は開いたまま、PC は点けたままにします。止めるには、その端末で Ctrl+C を押します。

スマートフォンで:

4. PC と同じ Wi-Fi につなぎ、seed の上の端の歯車を押し、「PC と繋ぐ」の「PC を探す」を押します。「同じ Wi-Fi の PC を探しています…」の後に「PC が見つかりました。招待コードを入れて「保存」を押します。」と出て、「サーバーの URL」が入り、「読む所」が「サーバーで」になります。
5. 「招待コード」の欄に、PC に出ている 6 桁（アプリで始めた時は歯車の「招待コードを見せる」、命令で始めた時は端末）を打ち（伏せ字で、数字の鍵盤が出ます）、「保存」を押します。
6. 撮って観察にすると、写真は縮めずに（座標入りのまま）PC のプロジェクトフォルダーに入ります（畑を分けていれば、PC で今選んでいる畑）。PC の Claude Code が読み、答えがスマートフォンの「話す」に出ます。スマートフォンには読み用の縮めた写しだけが残ります。「話す」の言葉も、PC の Claude Code がそのフォルダーで受けます。
7. 動画は、カメラを出た時に PC へ送ります。送れたら「動画を n 本、PC へ送りました（最後は …）」と出て、PC の `videos/<日>/<時刻>.mp4` に入ります（撮った時と所は同じ名の `.json`）。畑で網が無いなどで送れなかった時は「…スマートフォンに残し、次に繋がった時に送ります」と出て、次にカメラを出た時に古い順に送ります。一本は 2 GB までです。

補足:

- 「PC を探す」は、同じ網の中に UDP の 8801 番で呼びかけ、答えが無ければ同じ網の番地に一つずつ聞きます。見つからない時は、PC の端末に出た URL（`http://<PC の番地>:8800`）を、フォームの「サーバーの URL」に打ちます（§12）。
- 繋がっていると、「話す」で「設定を見せて」と送った札に「PC に送っています: <URL>」と出ます。札の「PC を探す」「サーバーを変える」でも繋ぎ先を変えられます。
- 使えるのは家の網の中だけです（外から使うには、家の網に入る道、VPN などが要ります）。送る道は http（暗号化しない）で、家の網の中だけを通ります。

### スマートフォンから PC の Claude Code と話す

PC のアプリの「設定を見せて」にある「スマートフォンから使う」の「始める」を押すと、その畑のフォルダーで Claude Code のリモートコントロールが立ちます。スマートフォンの Claude アプリの Code に畑の名のセッションが出るので、開けば、その PC の Claude（seed の手引きと `seed` の命令つき）と話せます。要る物は、Pro 以上の Claude のアカウントと、点けたままの PC です。初めて立てる時は、Claude Code が「Remote Control を使ってよいか」と聞くので、アプリの「はい」を押します。そのフォルダーは、一度端末で `claude` を開いて、信頼すると答えておきます。立ったあとに出る URL か QR コードからも開けます。

## 11c. サーバーを動かす人 — 相手ごとの token

seed のサーバーを自分で動かす人のための節（使うだけの人は読まなくてよい）。招待コードの一覧に加えて、相手ごとに token を出せる。

```bash
seed token add "買い手の呼び名" --scope buyer --days 30
```

出た一行が token。**出るのはこの一度だけ**で、台帳（`~/.config/aiseed/tokens.json`。サーバーでは `--file /var/lib/seed/gate/tokens.json`）に残るのはハッシュだけ。その人にだけ渡す。相手は招待コードと同じ所（歯車のフォームの「招待コード」か `seed invite`）に入れる。

- `--scope member`（既定）: 招待した人。読み、公開、一言。
- `--scope buyer`: 買い手。公開の記録に一言を送るだけ。読みも公開もできない。
- `seed token list` で、誰に、範囲、期限、今の状態。`seed token revoke "呼び名"` で取り消す（次の要求から効かない）。

管理は、kagi の机の画面（`kagi app --dir <作業の場所>`）の「人の出入り」から。サーバーの URL と、動かす人の token（`--scope admin`）を「繋ぐ先」に入れると、今の状態、気を付ける事、人に渡す token、公開された記録、操作の記録をそこで見て、出す・取り消す・取り下げるができる（`skill-kagi/SKILL.md`）。動かす人の token を seed のアプリに入れても、ほかの人と同じ様に使えるだけ。

- 「気を付ける事」には、何が起きているかの文の下に、サーバーで打つコマンドが一行ずつ出る。そのまま写して、サーバーの端末で打つ。
- 「受け付けを止める」を押す（二度押し）と、公開、一言、写真の読み取り、話す、草の名を断る（使う人には「今、受け付けを止めています。」と出る）。管理の操作、公開の頁を見る事、本人の取り下げ、土地の照会は通る。「受け付けを再開する」（二度押し）で戻る。サーバーを再起動しても止めたまま。操作の記録が書き換えられた時や、断った要求が多い時に使う。
- 「token を全部取り消す」（二度押し）は、押した本人の token だけを残して全部取り消す。token が漏れたかもしれない時に使い、要る人に出し直す。
- 「載せる前の記録」には、届いた公開の記録が並ぶ。全文と写真を読んで、「載せる」か「戻す」（一言を添える。送った人に届く）。載せるまで、公開の頁にも一覧にも出ない。名前、住所、他の人の事、場違いな物が無いかを読む。読まずに載せる形に戻すのは、サーバーの設定 `SEED_PUBLISH_REVIEW=0`。
- 「公開された記録」には、公開した人、公開した日、寄せられた一言の数と、公開の頁を開くリンクが出る。「寄せられた一言を見る」で中身を見て、一件ずつ消せる（二度押し）。

誰が何をしたか（通した、断った）は、サーバーの記録に一行ずつ残る。token も招待コードも書かれない。確かめは `kagi log verify`、期限は `kagi check tokens`（`skill-kagi/SKILL.md`）。

## 12. 困ったとき

| 出た文 | 何が起きたか、どうするか |
|---|---|
| 「この PC に claude（Claude Code）が見つかりません。」 | 歯車の「準備を見直す」を開き、「入れる」と「ログインする」を押す。または §6.2 |
| 「この PC の Claude Code のログインが切れています。」 | 文の下の「ログインし直す」を押す（ブラウザが開きます）。または、ターミナルで `claude` を起動し、`/login` し直す |
| 「サーバーに届きません（…）。」 | 網に繋がっているかを見る。外のサーバー（seed.aiseed.dev）の読み取りと話すは準備中（§4）なので、この PC の Claude か §6.2 で。家の PC に送っている時は、PC で `seed home` が動いているか、スマートフォンが同じ Wi-Fi にいるかを見る |
| 「招待コードが要ります（Discord で渡します）。」 | `seed invite CODE` か、歯車のフォームの「招待コード」に入れる。家の PC に送る時は、PC の端末に出た 6 桁 |
| 「今日はここまで。」 | サーバーの一日の上限（読み取りは既定で一人 10 回、全体 200 回。話すは一人 60 回、全体 300 回。家の PC の `seed home` は 500 回と 1000 回）。明日か、自分の Claude で |
| 「読めませんでした。写真が暗い・遠い、または Claude が断りました。」 | 近くで、地面と草が分かるように撮り直す |
| 「座標がありません。」 | 写真に位置情報が無い。カメラの設定で位置情報を付けて撮り直す（手で場所を入れる欄は無い） |
| 「HEIC の写真を読むには pillow-heif が要ります」、「flet がありません。」など | `pip install -e ".[app]"`。HEIC がだめならカメラを JPEG（互換性優先）に |
| 「写真 … は、ほかの写真から … m 離れています。」 | 別の場所の写真なら、別の観察に分ける |
| 「plan.md の ## Plan に行がありません。」 | 先に `seed plan`（`seed grow` は計画の行からだけ描く） |
| 「描く server がありません。」 | `--server`、`SEED_DRAW_URL`、`[grow]` の `server` のどれか |
| 「同じ Wi-Fi に PC が見つかりません。…」 | PC の端末で `seed home` が動いているか、スマートフォンが PC と同じ Wi-Fi にいるか（モバイルデータになっていないか）を見ます。ゲスト用の Wi-Fi は、つないだ機械どうしが届かない事があります。PC の防火壁（ファイアウォール）が `seed home` の口（TCP の 8800 番と、探す時の UDP の 8801 番）を止めていても見つからないので、この二つを家の網の中だけ通します。探せない網でも、PC の端末に出た URL を歯車の「サーバーの URL」に打てば繋がります（8800 番が通っていれば） |
| 写真は PC に届くが、動画が届かない | 動画はカメラを出た時（✓ か「← 戻る」で「話す」に戻った時）に送ります。動画を受ける口は 2026-11-07 の夕方に足したので、それより前に入れた seed の `seed home` は動画を受けません。PC で seed を新しくし（`git pull` の後に `pip install -e ".[app,server]"`）、`seed home` を Ctrl+C で止めて、もう一度 `seed home` を打ちます。写真が届いているなら、写真と動画は同じ 8800 番を通るので、PC の防火壁は原因ではありません |
| 「動画 n 本は PC に断られました（大きすぎる等）…」 | 一本 2 GB より大きい動画か、動画を受けない古い `seed home` に送った時です。断られた動画は送り直しません。Android ならスマートフォンの Pictures/seed から PC に写し、PC のアプリの「写真・動画・zip を選ぶ」で入れます（§5） |
| 「位置を待っています…」でシャッターが押せない、「位置が許されていません（端末の設定）。」 | 空の見える所で待ち、上の端の位置の印を押して取り直します。許されていない時は、スマートフォンの設定で seed に位置を許します |
| 「カメラを開けません（端末の設定）。」 | スマートフォンの設定で seed にカメラを許し、「カメラを開く」を押します |
| 「zip を開けませんでした（…）。」 | 壊れた zip か、大きすぎる zip です（中の一つ 4 GB、取り出す全体 16 GB、2,000 個まで）。分けて zip にし直すか、写真と動画をそのまま選びます |
| 「seed home にはサーバーの部品が要ります…」 | seed のフォルダーで `pip install -e ".[server]"` を打ちます（§11b） |
| そのほか | Discord の `#seed` か、GitHub の Issues（ https://github.com/aiseed-dev/seed/issues ） |
