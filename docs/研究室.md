# 研究室 — 本人と Claude で、自然農法の資料と記録を自前で整理する（案、2026-11-03）

作者の「私と Fable で、自然農法の研究室をつくる。GitHub にはすべての資料を載せることはできない。だから、自前でデータを整理しないと
いけない。この PC には内蔵の HDD があるから、それも使って」から。Claude が調べて書いた案。詳しい議論は本人と 11-03 に。

## 1. 一言で

GitHub に載せられない物が三種ある。**他人の著作物**（論文の PDF、本の写し）、**座標の入った記録**（本人の畑）、**重い物**（写真の元、
読みの生の出力、地図のタイル）。だから置き場は三つに分け、何がどこにあるかを一つの決まりで引けるようにする。
知識は GitHub、畑の記録は本人のフォルダー、資料の本体と重い物は別の盤の「研究室」。

## 2. 三つの置き場

| 置き場 | 盤 | 中身 | 公開 |
|---|---|---|---|
| `~/dev/seed`（GitHub） | 速い盤 | **知識。** 手引きの章、資料の一覧と要約（`sources*.md`）、植物ごとの資料 `plants/<学名>/`、索引（書誌だけ）、コード、設計 | する |
| `~/farm/<畑>/` | 速い盤 | **その畑の記録。** 観察、読み、判定、計画、取り込んだ写真、本人の手引きの写し（`seed --folder`） | しない |
| `<研究室>/`（作者は `/mnt/hdd2/lab/`） | 大きい盤 | **資料の本体と重い物。** 図書室（PDF、全文、図）、写真の元、読みの生の出力、地図、気象、統計、控え | しない |

境は二つ。**「この畑で」と書いてあるか**（書いてあれば畑の記録、無ければ知識）。**他人の著作物か、重いか**（どちらかなら研究室）。
畑の記録から研究室へは `seed.toml` の `bulk` で繋ぐ（記録の形 §11）。知識から研究室へは、資料の一覧の番号（A2、W18）と図書室の
`cited_as` で互いに引く。

作者の PC の盤（2026-11-03）: NVMe 1 TB（OS と ~/dev と ~/farm。空き 267 GB）、/mnt/hdd2 HGST 2 TB（CMR。研究室。空き 1.6 TB）、
/mnt/hdd1 WD 2 TB（SMR = 書き込みが続くと遅くなる。別の利用者の物で、控え向き。使うなら持ち主が場所を作る）。
効くのはほぼディスクの空きで、メモリ 64 GB と 24 コアは写真の変換と手元の claude に十分。

## 3. 図書室 `<研究室>/library/` — 資料の整理の決まり

調べた定石（研究データ管理の手引き、CSL-JSON、Zotero の添付の置き方）から、seed の立ち位置（素の文字、本人の物、AI が Read で
読める、このコード無しで読める）に合う形を選んだ。

```
library/
  SCHEMA.md                 一つの資料の書き方
  inbox/                    取ってきたが、まだ整理していない物
  items/<id>/               一つの資料 = 一つのディレクトリー
    item.toml               書誌、出所、権利、読んだ範囲、何について、手引きのどこから引かれているか
    original.pdf            取ってきた物そのまま（手を入れない）
    text.txt                本文の抜き出し（pdftotext）。rg と Claude の Read のため
    figures/                図の切り出しと figures.md（頁、見出し、権利）
    notes.md                この資料について言うこと。Claude の行と本人の行を分けて
  catalog.jsonl, catalog.md 索引。bin/catalog.py build が item.toml から作る。書誌だけなので GitHub に写せる
```

- **id** は `<年>-<筆頭著者の姓（ASCII）>-<一語か二語>`（例 `2022-asaeda-h2o2-riparian`、`2017-ibaraki-museum-sugao-flood`）。
  言語を問わず同じ名になり、人も Claude も読める。DOI は項目に持つ（DOI の無い資料が多いので id にはしない）
- **原本に手を入れない。** 抜き出しと図は別のファイル。ハッシュ（sha256）を item.toml に
- **権利を書く。** `open`（CC BY など。出所を付けて図も文も使える）、`admin`（行政の資料。利用規約を確かめて）、`quote`（著作物。私的な
  写しは図書室だけ、著作権法 30 条。手引きには 32 条の引用の形で、短く、出所付きで）、`unknown`。**GitHub に図を置くのは `open` か、
  規約を確かめた `admin` だけ。** これが「GitHub にはすべてを載せられない」の線
- **読んだ範囲を書く。** `read.claude`（full / abstract / snippet）と `read.person`（none / skim / full）。本人が読むまで、手引きでは
  確からしさ 0.6 まで（06 章の決まりと同じ）
- **そのまま公開か、要約して公開か（作者 2026-11-05。Claude の案、未実装）。** `item.toml` に `publish = "as-is" | "summary"` を一つ持つ。`open` と確かめた `admin` と法令の本文は `as-is`、`quote` と `unknown` は `summary`。`seed publish` と静的サイトは、`summary` の資料の原本と図を外に出さない（手引きには 32 条の形の短い引用と要約だけ）。要約して公開する物でも原本は図書室に保管する（30 条の私的な写し）。
- **逆に引ける。** `cited_as = ["plants/miscanthus-sacchariflorus/sources-world.md W2"]`。手引きの番号から図書室へ、図書室から手引きへ
- **Claude が付けた物は Claude が付けたと分かるように。** `fetched.by`、notes.md の見出し。**消すのは本人だけ**
- **探す**は `rg` で text.txt を、`jq` で catalog.jsonl を。埋め込み（ベクトル）は要らなくなるまで入れない
- **Zotero を使いたくなったら**、catalog.jsonl は CSL-JSON に近いので取り込める。Zotero の「リンク添付のベースディレクトリー」を
  `library/` にすれば、ファイルを動かさずに繋がる。設計は Zotero に依らない

## 5b. アプリ間の認証 — seed の側から（2026-11-05）

作者の言葉（11-05 02:50、fieldnotes の計画担当を通して）: 「アプリや AI エージェント間の連携は重要です。そうなると認証も重要ですよね。

fieldnotes はそれに合わせる。fieldnotes 側の案（fieldnotes の `docs/implementation.md`「WP19: authentication between apps」、11-05 02:16 の
コミット 9e2ac2e）を受けて、seed 側の答えをここに書く。返事でなく文書に残す約束。実装は 11-08 の後（fieldnotes は 11-05 11:00 の提出の後、
0.2.0 から）。期間中の境界（設計書 §2）は動かさない。

**fieldnotes 側の案（五点、要約）。**

1. 農家がクライアントごとに token を発行する（`fieldnotes token add <name>` / `list` / `revoke <name>`）。`~/.config/fieldnotes/tokens.json` に
   名、ハッシュ、scope、作成日。token が一つでもあれば MCP の HTTP（8551）とアプリは全要求に `Authorization: Bearer <token>` を要求し、
   無ければ今のまま LAN 限定で、起動時にそう言う。
2. scope は `read`（記録・site・lookup・timeline）、`mark`（農家の ✓✗。農家の token だけ）、`write`（observe、note、propose、写真の取り込み）、
   `buyer`（read から写真と private の農家メモを除いた物）。買い手の AI は `buyer`、seed は `read`、農家のスマートフォンは `write`+`mark`。
3. 家の外へ出るときは HTTPS。`fieldnotes app --https` が自己署名証明書を書き、指紋を QR でスマートフォンに見せる。農家自身の証明書でもよい。
4. アプリ間で同じ Bearer token の形にし、`~/.config/aiseed/tokens.json` 一つに「どのアプリが誰に何を許したか」を並べる。公開 API
   `fieldnotes.Farm`（0.2.0）はネット越しに読むとき token を受ける。
5. Meta の鍵（`MODEL_API_KEY`）は渡さない。自前のモデル呼び出しが要るクライアントは自分の鍵を持ってくる。

**seed の今の形との違い（まずここを揃える）。** seed の token は向きが逆で、三種類を名前で分ける必要がある。

- seed の `token`（`seed.toml`。初回にアプリが作る乱数）は、**農家が共同のサーバー（deb2）に対して「同じ持ち主」を示す物**。サーバーは
  ハッシュだけ持ち（`.owners.json`）、公開の上書きと取り下げ、一言の `from` に使う（設計書 §7.1、§7.5）。scope は無い。発行するのは農家でなくアプリ。
  → **持ち主の token**。今のまま。
- seed の `invite`（招待コード）は、**共同のサーバーの運営者が人に渡す物**。すべての `/api/*` の門（§7.5）。→ **招待コード**。今のまま。
- fieldnotes の WP19 の token は、**農家が自分の PC で動かすサービス（MCP 8551、アプリ）に客（seed、買い手の AI、スマートフォン）を入れる物**。
  → **客の token**。seed には今これに当たる物が無い（アプリは自分の PC で完結し、サーバーは共同の物）。ただし家の中の halo のサービス
  （Glimmer の llama-server 11434、seed の絵の sd-server 11435。設計書 §16.5。11-04 に ufw を LAN に開けた）は認証無しで、
  seed の側で最初に客の token が要る所はここ。

**seed の答え（Claude の案。決めるのは本人、設計書 §13 の 12）。**

1. **形は WP19 の通り。** 農家が発行、`Authorization: Bearer <token>`、受ける側はハッシュだけ持つ、token が一つでも在れば全要求に要求し、
   無ければ LAN 限定で起動時にそう言う。seed が家の中で動かすサービスにも同じ形を使う（まず halo の sd-server。`seed grow --draw` が
   `[grow]` の token を Bearer で送る。llama-server は `--api-key` を持つと Claude は覚えているが未確認、sd-server は要確認）。
2. **置き場は一つ。** `~/.config/aiseed/tokens.json`（fieldnotes の 4 に乗る）。項目は `name`、`app`（受け付けるアプリ。`fieldnotes`／`seed`／
   `halo-draw` のような語）、`scope`（配列）、`sha256`（全桁）、`created`、`note`（誰に渡したか。本人の言葉）。発行と取り消しのコマンドは
   各アプリが持つ（`fieldnotes token add`、`seed token add`）が、書く先は同じ一つのファイル。権限は 600。seed の記録フォルダー（`~/seed/`）には
   置かない（記録のフォルダーは写しや公開の対象になるから）。理由: 農家が「誰に何を許したか」を一か所で見渡し、一か所で取り消せる。
   アプリごとに別ファイルだと、合流（§5a）の後に二重になる。
3. **（11-06 に取り下げ。下の「11-06 の追記」の 2 に置き換え）客として持つ token は `seed.toml` の各サービスの表に。** 今の `[grow] server = "…"` に `token = "…"` を足す形で、`[fieldnotes]` も
   `url`、`token`、`fingerprint`（自己署名のとき、下の 5 の指紋）の三つ。`seed.toml` はすでに `token` と `invite` を持つので、秘密の置き場を
   増やさない。リポジトリには入れない（今の決まり）。
4. **scope は fieldnotes の四つをそのまま使い、seed は `read` だけ求める。** `mark` は求めない（判定は本人だけ。設計書 §9、§5a の
   「Checks を判定にしない」と同じ線）。`write` も求めない（seed の仮説は農家が `hypothesis` 行にする。§5a）。seed の側のサービスに scope が
   要るときは、同じファイルに seed の語を足す（例: 絵の生成は `draw`）。四つの語は seed の `docs/記録の形.md` にも書き、両方で同じ語にする。
5. **HTTPS は fieldnotes の 3 の通り。** 共同のサーバー（deb2）はすでに Caddy の本物の証明書。農家の PC のサービスが家の外へ出るときは
   自己署名 + 指紋の QR で、seed のアプリは指紋を `seed.toml` に持って照合する（違えば繋がない）。
6. **鍵は渡さない。** fieldnotes の 5 と対称に、seed の `ANTHROPIC_API_KEY`（サーバーの env）と本人の Claude のログインは seed の物で、
   他のアプリには渡さない。seed の持ち主の `token` と `invite` も fieldnotes に渡さない。他のアプリが Claude を呼ぶなら自分の鍵で。
7. **持ち主の token の形は変えない。** ただし 11-08 の後、`/api/publish` と `/api/connect` が form の `token` に加えて
   `Authorization: Bearer` でも受けるようにし、クライアントから見た形を客の token と揃える（意味は変えない）。招待コードもそのまま。

**決めること（本人）:** (a) 置き場を `~/.config/aiseed/tokens.json` 一つにするか、アプリごとか。(b) seed が fieldnotes に求める scope は
`read` だけでよいか。(c) halo のサービス（11434、11435）に token を掛ける順（LAN に開いた今、家の中だけなら急がない）。
(d) `seed token add/list/revoke` を 11-08 の後のどこに入れるか。
