## 1a. 審査基準の全文（作者が 11-05 に貼った物。基本計画 §7 の表はこれで見直す）

**インパクト (30%)**

- 課題が、自分の仕事・暮らし・技術・趣味、または日本の具体的な現場から出発しているか
- テーマ1の場合：その世界に身を置いてきた人だからこそ見えた「足りないもの」を捉えているか
- テーマ2の場合：これまで届いていなかった具体的な人を想定し、その人を阻んでいた壁を取り除いているか
- 誰が、どんな場面で、どれくらい困っているかが具体的に描かれているか
- ハッカソン後も、誰がどんな場面で使い続けるかを具体的に言えるか

**デモ (25%)**

- 「誰の、どんな課題を、どう解決するか」が冒頭で明確か
- 前提知識のない人でも、実際の操作の流れを通じて、使う人にとっての価値が分かるか
- 最後まで見たくなる、引き込まれる動画か

**Claudeの活用 (25%)**

- Claude を創造的に使い、基本的な使い方を超え、Claude の新しい使い方や可能性を見せているか
- Claude Code を開発の中心に据え、それによって何が可能になったかを示せているか
- モデルや機能(Skills、サブエージェント、MCP、フックなど)を目的に応じて選び、使い分けているか。

**深さと実行力 (20%)**

- 最初のアイデアにとどまらず、試行錯誤を重ねて磨き上げたか。その場しのぎではなく、課題にじっくり向き合った跡が見えるか
- 設計と実装がしっかりしていて、丁寧に作り込まれているか
- 困っている人が、安心してそのまま使える形に仕上がっているか

## 2. 概要（下書き。フォームの字数が分かったら切る）

**概要の本文（案 7。11-06 深夜に Fable が書いた。動画の台本の案 7 と同じ言葉。作者「あまり難しいことは言わないほうがいいでしょう」。「できていない事」は、提出の時点の事実に直してから出す）**

**seed — Claude と一緒に種を播く。畑では撮るだけ。あとは Claude と話す。**

作者は徳島の元田んぼで、肥料を入れずに自然農法を試しています。背丈を超える草むらに、通路を刈る所から始めました。自然農法は、やる事が多い仕事です。記録を付ける時間は、なかなか取れません。

畑のアプリは、今まで作りにくい物でした。畑は一枚ずつ違います。土、水、昔の様子、今生えている草。決まった入力欄に入りません。seed も最初は入力欄を並べて作っていました。作者に「全部の画面がこれまでの作り方」と言われて、一晩で作り直しました。

今の seed は、写真を撮って、Claude と話すだけです。

- 写真を送ると、Claude が読みます。その日の一枚を選び、気づいた事を返し、一つ問い返し、次に撮ると良い物を言います。
- 「この土地の成り立ちを教えて」と頼むと、土、地形、水、歴史と、昔の空中写真が古い順に並びます。公開の地図から引く物で、AI は使いません。
- 間違いは、言葉で直します。Claude は草の名を外しました（「ススキらしい」と読み、作者が「オギ」と直した）。
- 写真の整理はアプリでします。細かい文字の作業は、自分の Claude Code に頼みます。
- 記録は素の文字のファイルで、自分の PC に残ります。アプリが無くても読めます。

安全に動かす方は、別のアプリ kagi にしました。こちらは入力欄で、きっちり管理します。誰が入れるか、期限はいつか、鍵は何処に在るか。サーバーの今の形を調べて、直す所と、打つコマンドを出します。

**Claude の使い方。** 畑では、写真を読み、問い返し、言葉で直される相手です。細かい作業は、本人の Claude Code がします。スマートフォンでは、本人の API の鍵か、seed のサーバーを通して Claude を呼びます。手引きは Skill が二つ（畑を読む、サーバーを守る）。作る時は、作者が言葉で決め、Claude（Fable）が計画と確かめをし、別の Claude（Opus）が書きました。

**できていない事（11-06 深夜の事実）。** スマートフォンの実機では、まだ撮っていません。サーバーには、まだ置いていません。作者以外の人が一周した記録はありません。固い層の厚さは、まだ分かりません。本当の確かめは、育てる事です。

**前の案（案 5・テーマ 1。11-06 に Fable が書いた。考え方の説明が多い。使うなら短くする）**

**AI との付き合い方 — 業務システムと自然農法を比べてみた。** 作者は徳島の元田んぼで四年間肥料を入れずに自然農法を試している農家で、その前は会社のシステムを IT 業者に預ける側に居ました。二つの世界に身を置いてきたから見えた事が一つあります。AI との付き合い方は、分野で分かれるのではなく、二つの問いで分かれる。世界が文字で書かれているか。結果を機械が確かめられるか。

業務システム（サーバー、鍵、扉）は両方「はい」です。構成も口も鍵の置き場も全部文字で読めるので、現状さえ分かれば AI がその日のうちに対策を書き、テストと動作で自分で確かめます。この期間に、鍵の管理の決まり（K-01〜15）と、社内の係が「できる事から」踏む七つの歩と、Windows と Samba のファイル共有の会社の例（警察庁の令和 7 年上半期の情勢: ランサムウェアの被害 116 件のうち中小企業 77 件、侵入は VPN とリモートデスクトップの機器からが 8 割以上）を文書にし、在庫表・口の突き合わせ・秘密の在り処の走査・追記だけの記録を持つ道具 kagi を、文書を朝に書き、昼前に動かしました（25 のテスト。鍵の値は一度も読まない）。認証と鍵の管理の道具が一日でできる事が、業務の側の見せ場です。残るのは、何を守るか決め、これでよいと決め、できたかを確かめる一人で、守りの仕事は終わりません。

畑は両方「いいえ」です。この土で今何が起きているかは誰も書いていません。11 月 2 日、背丈を超えるセイタカアワダチソウと白い穂の草に覆われた区画で写真を撮り、「土は固い。棒が入るのは 20 cm ぐらい」と一言残しました。seed はその写真と場所を自分の Claude に渡し、公開の地図（地形、地質、土壌、筆の形、史跡）を出典付きで引き、写真に写る草と地面を一行ずつ確からしさ付きで読む道具です。草の名は外れました（Claude は「ススキらしい」と読み、作者が「オギ」と付けた）。土の固さは写真に写りません。畑で AI にできるのは、人が見て書いた物を読んで並べる事だけで、だから記録を残す事が一番大事になります。今まで自然農法にソフトウェアが使えなかったのは、決まった欄に入れる数字が無かったからで、写真と一言を読める AI がそれを変えました。

同じ AI が、係には仕事をやって人が確かめ、農家には読んで人が見て書く。向きが反対で、人に残る三つの仕事は同じです。動画はこの比較を一枚の表にして見せます。

**作った物（11-02 12:00 JST 以降）。** seed: 手引き（Skill）14 章、アプリ（Flet 1.1。Python だけで PC の窓と Web とスマートフォンに同じコードで出る。作者は Flet を広めたい側で、seed はその実例。Discord が 2026-11-04 に Electron と React Native を捨てて Rust と GPUI で書き直すと確かめた流れと同じ側で、Flutter が GPU で描き Python は中身だけを書く。Discord が Rust でやる事を Python の人がやる道が Flet）、CLI、サーバー、静的な公開ページ、261 のテスト。kagi: 計画書・設計書・手引きと道具（25 のテスト）。文書: 基本計画、設計書、鍵の管理の仕組み、digitaldoor の層 2 の設計書、りん酸と無肥料の現状（出典 60 件余り）。読みの道は三つ（本人の PC の `claude -p`、サーバーの API、Claude Code）で、手引きと行の形は一つ。

**できていない事。** 認証と控えの運用は設計だけ。halo の口の二つに認証が無い。気象の章は骨組みだけ。作者以外の人が一周した記録は無い。協生農法などの圃場で菌根を測った数字は見つからなかった。

**使い続ける人。** 作者自身。seed が取り上げた二つの問題（サーバーの守りと、自然農法）は、普通のユーザーの経験が使えない所にある（作者 11-06）。会社のシステムを業者に預けて使ってきた経験も、肥料と農薬を買って作ってきた経験も、守りと無肥料の畑には当てはまらない。作者自身も守りの専門家ではなく、自然農法は四年目。普通の人には「どう改善すればよいか」の案が出ない所で、経験でなく論理でやるしかない問題（作者 11-06）。経験の代わりに使ったのは、AI に調べさせ（出典付き）、何の事実で決まるかを並べて決め、自分の畑と自分のサーバーでやってみせて記録を残す事。論理と事実で進む問題だから、AI が効く。 効果の大きさは「AI 無しでできた事」との差で決まる。アプリを作る事もデータを分析する事も、今までも人を雇えばできた。守りと無肥料の畑は、普通の人には案が出ず止まっていた所で、そこが 0 から動く。だから AI を使う効果は、こちらの二つの方が大きい（作者 11-06）。主催の説明会の二つのパート（ホワイトボードで Claude Code の使いどころを整理する、Managed Agents でデータを分析してグラフを返す）は、経験を持つ側（Anthropic の CS）が見せる物で、立つ場所が違う。seed は、経験の無い本人が自分のために自分で作った物。畑の記録は年を重ねて初めて意味を持ち、サーバーの守りは終わらない。

seed は、畑の写真と場所を自分の Claude に渡して、畑を読むための手引きとアプリです。作者は徳島の元田んぼで、四年間肥料を入れずに福岡正信の自然農法を試しています。11 月 2 日、背丈を超えるセイタカアワダチソウと白い穂の草に覆われた区画で写真を撮り、「土は固い。棒が入るのは 20 cm ぐらい」と記録に書きました。知りたかったのは、この土で何が育つか、固い層の下はどうなっているか、白い穂はオギかススキか、この土地はどうできたか、です。

**何をするか。** 写真を自分の Claude に渡すと、手引き（Skill）を読んだ Claude が、座標から公開の地図（地形、地質、土壌、筆の形、史跡）を出典付きで引き、写真に写る草と地面を読んで、一行ずつ確からしさを付けて返します。行の形は `- key: text [confidence] → farmer: right | wrong (reason)` の一つで、事実の行（`data`、本人の `record`）と AI の読みの行が分かれています。本人は観察した人として、行ごとに合う／違うを付け、その判定が次の読みの根拠になります。栽培計画 `plan.md` は本人の言葉から案を並べた物で、「こうしなさい」の行は書きません。選んだ行だけを公開し、公開された記録は seed.aiseed.dev で探せて、一言を添えて繋がれます（サーバーは 11-05 時点でまだ開いていません）。記録は素の Markdown で、アプリが無くても読めます。

**seed が持ち込むのは、作者の得意な生物学・気象・地質の読み（出典付き）で、農業のやり方ではありません。** 手引きは 00 始める前、01 立ち位置、02 地質と土、03 気象と時期、04 生物、05 鳥獣害、06 畑を読む、07 周りの物、08 ビルダーの訓練、09 栽培計画、10 種、11 売る、12 加工、13 手続きと農地、の 14 章で、本人が自分の物として写し、直せます。種苗法や農地法の本文 15 件は研究室の図書室にあり、条文は引けますが、解釈と判定は本人が書くまで書きません。

**Claude の使い方。** 読みの道は三つ（本人の PC の `claude -p`、サーバーの API、Claude Code に直接）で、手引きと行の形は一つ。手引きは Skill（`skill/SKILL.md` と章）。読みは構造化出力（JSON schema）で行の形を固定し、判定の行は決まりと機械の両方で落とします。研究室の整理と文献の目録はサブエージェント。開発はすべて Claude Code で、作者が立ち位置と判断を言葉で出し、Claude（Fable）が設計と確かめ、実装は別の Claude（Opus）が書き、決めた日と理由は全部文書（`docs/設計書.md` §13）に残っています。MCP とフックは使っていません。

**何が足りなかったか。** 今まで、システムは IT 業者に委託し、食べる物は便利だからスーパーで買い、農業をするにも肥料も農薬も種子も業者から買って、その人たちの言う通りの方法で栽培してきました。それには理由がありました。AI が無ければ会社で自分たちでアプリケーションを作るのは難しく、肥料は安く、スーパーにはいろいろな物があり、海外から輸入した方が安かった。でも、安全を考えると、輸入に頼っていては、戦争が起これば輸入は止まります。だから自給も考えておく必要があります。中身が読めないので、経験が自分に残りませんでした。seed は、その三つを AI と一緒に自分でやるための物です。作者の畑の記録では、こうなっています。農業: 入れない物（りん酸肥料、家畜ふん堆肥）は出典付きで、硬盤層の扱いは六つの案を並べて作者が決め（決めたのはライ麦とえん麦の混播、クローバーの試験）、根拠は業者の説明ではなく作者が見た物（棒が 20 cm で止まる、オギが一年で元の大きさに戻った）です。システム: 記録は作者の PC の素の文字で、読みは作者の PC の Claude Code で、業者のサーバーも鍵も通っていません。読みは外れましたが（ススキ → オギ）、作者が自分の手引きに草の名を書いた後は直りました。生活: 売る・加工・手続きの記録はまだ空です。

**AI 時代のシステムのあり方（作者の立ち位置）。** 「AI 時代は、既存のようなアプリを作るのは簡単になる。でも、ソフトウェアのシステムを運用し守るのは難しい。だから、ソフトウェア開発者はビルダーにならないと仕事がなくなる」。seed はその一例で、六つの形があります。(1) 記録は人の手元に素の文字で、(2) 事実と AI の読みを分ける、(3) 資料を持つ（一次資料を出所と取得日とハッシュ付きで図書室に。そのまま公開する物と要約して公開する物を分ける）、(4) AI 同士は最小の権限で繋ぐ、(5) 外に出るのは人が了解した物だけ、(6) 控えは切り離し、守るのは人と AI が一緒に、決めるのは人。**動いているのは (1)(2)(5)。(3) は図書室まで。(4)(6) は設計だけです。** 作者の言葉（11-05）: 「これからは、ソフトウェアシステムを開発するよりも守ることが重要。これは、植物と同じですよね。植物は、植物を食べる虫や鳥獣から逃げられませんよね。インターネットに繋がったシステムも同じです」「こういう勉強は、実際にシステム開発のしてみないと身につかないです」「耕作放棄地を畑にして自給するのも同じです。生活を守るためです。何でも外の世界に依存しすぎるのはよくないです。できることは自分でする」。

**できていないこと。** 草の名は外れました（Claude は「ススキらしい」と読み、作者が「オギ」と付けた）。土の固さは写真に写りません。気象の章は骨組みだけで、記録に天気の行はありません。アプリ間の認証と控えの運用は設計だけです。作者以外の人が `pip install` から観察まで一周した記録は（11-05 時点で）ありません。固い層の厚さはまだ分かりません。本当の確かめは、育てることです。

**期間中に作った物。** このリポジトリの中身（コード、手引き、文書、テスト）はすべて 11-02 12:00 JST 以降に書きました。座標からの照会だけは、同じ作者が Meta のハッカソン（10-26〜11-04）向けに作った別のパッケージ fieldnotes-farm を、PyPI の 0.2.0 に固定し、手を入れずに任意の依存として呼んでいます。記録の行の形は仕様（fieldnotes の docs/records.md）で共有し、コードは共有していません。Meta のモデルを使う部分は呼びません。草の名の候補に Pl@ntNet の API を使う予定ですが、11-08 の後です。ライセンスは AGPL-3.0-or-later。
