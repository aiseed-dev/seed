# 02 入口と鍵

## この章で読むこと

誰が機械に入れるか（認証）と、どの鍵で入るか（鍵）。二つは同じ表 `machines.toml` に並べ、同じ突き合わせで
見ます。連載 第 4 章（SSH という玄関）の形です。

## 形

- ssh は鍵でだけ入る。`PasswordAuthentication no`、`KbdInteractiveAuthentication no`、`PermitRootLogin no`
- 入れてよい人は表の `users`、sudo を持ってよい人は `admins`、入れてよい鍵は `keys`
- 鍵ごとに `[[key]]` を一件（id、持つ人、`.pub` の道）。在庫表にも同じ id で一件（期限と回す周期）
- 機械の鍵（ed25519）の指紋を表の `hostkey` に書く

kagi が読むのは `.pub` と指紋だけです。秘密鍵のファイルと、`value`、`private`、`password`、`passphrase` の欄は
読まずに止まります。

## 機械の鍵の指紋を目で比べる

初めて ssh で入る時に尋ねられる指紋は、その機械の物か、間に誰か居るかを分ける所です。

歩 1 指紋を表に書く
- 人: 機械の画面（ssh でなく）で `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`。出た `SHA256:…` を表の `hostkey` に
- 道具: —
- 確かめ: 自分の PC から初めて `ssh <名>` した時に尋ねられた指紋が同じ。違えば yes を押さずに止める

kagi の写し（`collect`）は、尋ねられる形を全部落とします。この PC の ssh がその機械の鍵をまだ覚えていない時
（`known_hosts` に無い時）は入りません。人が先に一度入り、上の通りに比べて yes を押すと覚えます。表の `hostkey` は
別の物で、`check` が写しの指紋と比べます。違えば「直す」に出ます。入れ直したのでなければ、別の機械か、間に誰か居ます。

## 鍵でだけ入る形にする

歩 2 パスワードでは入れなくする
- 人: 先に、別の窓から鍵で入れる事を確かめる。その窓は閉じない。写しを取るアカウントが sudo を持たない時は、
  sudo を持つアカウント（04 の「管理者」の「見るだけ」の行）が鍵で入れるか、入ってから替われるかも、切る前に
  確かめる。そのアカウントがパスワードでしか入れないなら、先に鍵を入れる。切った後は遠くから直せなくなる。`kagi machine fix --host <名>` が出す行を打つ
  （`/etc/ssh/sshd_config.d/10-kagi.conf` に四行、`sudo sshd -t && sudo systemctl reload ssh`）
- 道具: `kagi machine fix` が手の文を出す
- 確かめ: 別の機械から、鍵を使わずに繋いでみる（人か Claude。打つ前に人に一言断る。機械の側の記録に失敗が一行残る）
  ```
  ssh -o PubkeyAuthentication=no -o BatchMode=yes <名> true
  ```
  `Permission denied (publickey)` なら鍵でだけ、`(publickey,password)` ならパスワードの入口が開いている。もう一度
  `collect` と `check` で「パスワードで入れる」が消える

**連載と違えてある所。** 連載は `99-hardening.conf`、kagi は `10-kagi.conf` です。sshd は同じ項目の最初の値を使い、
Debian は `sshd_config.d/*.conf` を名の順で先に読みます。`50-cloud-init.conf`（`PasswordAuthentication yes`）のような
物が在る機械では、`99-` の値は効きません。設定のファイルを読むだけでは、効いている値は分かりません。
効いている値は root で `sudo sshd -T` です（04）。

## 鍵の表と在庫表

`kagi key list`（人か Claude）で、鍵ごとに、持つ人、指紋、入れてよい機械、在庫表の期限が出ます。在庫表に同じ id が無い鍵は
「無い（K-14）」と出ます。公開鍵の指紋だけを見るのは `kagi key fingerprint <ファイル>.pub` です。

## 足す・回す・外す

鍵を作るのは人です。kagi は鍵を作らず、回さず、発行しません。

- **足す。** 人: `ssh-keygen -t ed25519 -a 64`（合言葉を付ける。持ち歩く物なら `-t ed25519-sk` で物の鍵に）。
  `[[key]]` に一件、機械の `keys` に id、在庫表に同じ id。`ssh-copy-id -i <新しい>.pub <機械>`。
  確かめ: `collect` と `check` で「表に無い鍵」が出ない
- **回す。** 人: 新しい鍵を足す → 新しい鍵で入れる事を確かめる → 機械の `authorized_keys` から古い行を消す →
  表から古い id を外す。古い鍵のファイルを消し、在庫表の行に消した日を書く。確かめ: `check` で「表に無い鍵」が出ない
- **外す（人が辞めた、端末を無くした）。** 人: その人の鍵の id を全部の機械の `keys` から、その人を `users` と
  `admins` から外す。道具: `kagi machine check`（`--host` 無しで全部の機械）が、残っている所を「表に無い鍵」
  「表に無いアカウント」として出し、`fix` が一台ずつ手を出す。確かめ: 全部の機械で出ない

どれも終わったら `kagi log add --actor <自分> --action key.add --detail <id>` を一行（回すは `key.rotate`、外すは
`key.remove`）。

## 見つかった知らない鍵

`authorized_keys` に表に無い鍵があれば、誰のどの機械の鍵かを人が確かめます。分かれば `[[key]]` に足し、
手元の `.pub` を `kagi key fingerprint <ファイル>.pub` に掛けて、`check` が出した指紋と比べると、
どの鍵かが分かります。分からなければ `kagi machine fix` の通りにその行を消します（`deploy/deb2/手順.md` の d）。
