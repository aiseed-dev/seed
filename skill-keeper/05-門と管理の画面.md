# 05 門と管理の画面

## この章で読むこと

seed のサーバーに、誰が、何をしに入れるか。招待コードと相手ごとの token、誰が何をしたかの記録、管理の画面。
門は `src/seed/server/gate.py`、画面は kagi の机の画面「人の出入り」（`src/kagi/admin.py`、`src/kagi/app.py`）です（設計書 §5.9、§5.10）。
seed のアプリの中には管理の画面を置きません。

## 招待コードと token

招待コードは平文の一覧（`/etc/seed/invites.toml`）で、入れるか入れないかの二つです。一覧の人は「招待した人」に
なります。token は相手ごとに出し、範囲と期限を付け、取り消せます。

| 範囲 | 誰 | できる事 |
|---|---|---|
| `member` | 招待した人 | 読み、話す、草の名、照会、公開、取り下げ、一言 |
| `buyer` | 買い手 | 公開の記録に一言を送るだけ |
| `admin` | 動かす人 | 管理の口（kagi の「人の出入り」から）。`member` の事も全部 |

台帳（サーバーでは `/var/lib/seed/gate/tokens.json`）に残るのはハッシュだけです。token は出した時に一度だけ
人の端末に出ます。あなたはそれを見ません。期限の無い物は通らず、台帳が無くなれば閉じる側に倒れます。

## 出す・取り消す

歩 1 動かす人の token を出す（最初の一つだけは機械の上で）
- 人（読んで確かめてから）: 機械の端末で `sudo -u seed /opt/seed/.venv/bin/seed token add "<自分の呼び名>" --scope admin --days 365 --file /var/lib/seed/gate/tokens.json`。
  出た一行を、kagi の机の画面「人の出入り」の「繋ぐ先」に、サーバーの URL と一緒に入れる。どこにも書き写さない
- 道具: 台帳にハッシュを一件書く
- 確かめ: 「人の出入り」に今の状態が出る

歩 2 相手に出す
- 人（読んで確かめてから）: 「人の出入り」の「人に渡す token」で、渡す相手の名前、できる事、期限、覚え書きを入れて「出す」。写す釦で写し、
  その人にだけ渡す。機械の上なら `sudo -u seed /opt/seed/.venv/bin/seed token add "<呼び名>" --scope buyer --days 30 --file /var/lib/seed/gate/tokens.json`
- 道具: 台帳に一件。記録に一行
- 確かめ: 一覧に、呼び名、範囲、期限が出る。`seed token list --file …` でも同じ

歩 3 取り消す
- 人（読んで確かめてから）: 画面の一覧から取り消す（二度押し）。機械の上なら `sudo -u seed /opt/seed/.venv/bin/seed token revoke "<呼び名>" --file /var/lib/seed/gate/tokens.json`
- 道具: 取り消した行は消さず、日を書く。次の要求から効かない
- 確かめ: その token での要求が 403

token が会話や画面の写真に出たら、その token を取り消して出し直します。

## 誰が何をしたかの記録

門を通した事も断った事も、サーバーの記録（`/var/lib/seed/audit/audit.log`）に一行ずつ残ります。呼び名、
した事、結果です。token も招待コードも書かれません。形は kagi の記録と同じで、追記だけ、連番、ハッシュの連鎖、署名です。

歩 4 記録と門を外から確かめる
- 人（打つ。確かめは結果で）: `sudo KAGI_LOG_KEY_FILE=/etc/seed/log-key /opt/seed/.venv/bin/kagi log verify --dir /var/lib/seed/audit`
- 道具: `ok N lines` か、落ちた行と理由
- 人か Claude: 招待コード無しで試す（どこからでも打てる）
  ```
  curl -s https://<入口の名>/health; echo
  curl -s -w ' %{http_code}\n' 'https://<入口の名>/api/lookup?lat=0&lon=0'
  ```
- 確かめ: `ok`。`/health` の `audit` が `on`（鍵が無ければ `off`、書けなければ `error`）。`/api/lookup` が 403。
  買い手の token で公開を試すと 403

期限は、人が機械の端末で `sudo -u seed /opt/seed/.venv/bin/kagi check tokens --file /var/lib/seed/gate/tokens.json` で見ます。
台帳の置き場 `gate/` は seed だけが入れる（seed 700。`docs/deb2 の配備.md` 0-1）ので、seed として読みます。
期限切れのまま取り消していない物が「直す」に出ます。机の画面では「鍵」の下に並びます。

## 間違いを重ねた番地を止める

門は、招待コードか token を間違えた回数を、要求の番地ごとに数えます（`src/seed/server/limits.py` の `Tries`、
`src/seed/server/main.py` の `_invite`、`_gate_closed`、`_missed`）。10 分に 10 回間違えた番地は、10 分のあいだ、正しいコードでも
429 で断られます。数えるのは、知らないコード、期限切れ、取り消された物を送った時です。コード無しと、正しいコードで範囲の外の時は
数えません。数はサーバーのメモリにだけ在り、サーバーを立て直すと消えます。

- **門の全部に効きます。** 読み、話す、動画、草の名、照会、公開、取り下げ、一言、`/api/whoami`、管理の口。管理者の token でも、
  止められた番地からは 429 です。kagi の「人の出入り」には「サーバーに断られた（429）: 招待コードを何度も間違えたので、
  あと N 分ほど受け付けない」と出ます（`src/kagi/admin.py` の `Client.call`）
- **記録に一行残ります。** 止め始めた時に「止めた: <番地> が 10 分に 10 回間違えたので 10 分断る」の一行が、サーバーの記録と
  サーバーのログ（`journalctl -u seed`）に出ます。コードと token は書かれません
- **数と長さは環境変数で変わります。** `SEED_GATE_TRIES`（回数、既定 10）、`SEED_GATE_WINDOW`（数える秒、既定 600）、
  `SEED_GATE_BLOCK`（止める秒、既定 600）。置き場は `/etc/seed/env` です
- **間に Cloudflare などを置く時。** 門が見る番地は、Caddy が渡す番地です。Caddy の全体の設定か `(cf)` に Cloudflare の範囲が
  `trusted_proxies` で書いてあれば、本当の相手の番地で数えます。無ければ Cloudflare の番地で数えるので、一人が間違いを重ねると、
  同じ Cloudflare の番地を通る人の全員と、管理の画面が 10 分止まります。確かめ方は `docs/deb2 の配備.md` 0-7 の
  `grep -n 'trusted_proxies\|client_ip_headers\|CF-Connecting-IP' /etc/caddy/Caddyfile`（`deploy/Caddyfile` のコメントも同じ事を書いています）

**もう一つの 429、一日の上限。** 429 は二つあります。上の止めは、間違いを重ねた番地に出る 429 で、スマートフォンには
「招待コードを何度も間違えたので、しばらく受け付けません。少し待ってから、正しいコードで試してください。」と出ます。もう一つは、
一日の回数（`limits.py` の `Limits`）を使い切った 429 で、スマートフォンには「今日はここまで。明日か、「自分の Claude で読む」で。」と出ます
（`src/seed/app/strings.py` の `server_tries`、`server_limit`）。サーバーの返事の中の言葉も別です（`too_many_tries` と `limit`。
`src/seed/client.py` の `_call` が分けます）。

| | 解ける時 | サーバーを立て直すと |
|---|---|---|
| 番地の止め | 止め始めから 10 分（`SEED_GATE_BLOCK`） | 消える |
| 一日の上限 | サーバーの日付が替わる時 | 数が 0 に戻る |

一日の上限の既定は、読み 200 回（token 一つあたり 10、番地一つあたり 20）、話すと動画は合わせて 300 回（相手一つあたり 60）、
費用 20 ドル（`SEED_DAILY_READS`、`SEED_PER_TOKEN_READS`、`SEED_PER_IP_READS`、`SEED_DAILY_TALKS`、`SEED_PER_TOKEN_TALKS`、
`SEED_DAILY_USD`。`src/seed/server/settings.py`）です。どちらの 429 かは、サーバーの記録の「止めた」の行の有る無しと、
スマートフォンの文で分けます。`seed home` の上限は 09 の歩 5 です。

## 管理の画面の五つ

kagi の机の画面（`kagi app --dir <作業の場所>`）の「人の出入り」です。欄と決まりのはっきりした形で、
token の期限は 1〜365 日（管理者は既定 30 日）、変える操作はどれも二度押し、した事は kagi の記録にも一行残ります。

1. **今の状態**: サーバー、受け付け、写真の読み取りができるか、外の鍵（在るか無いかだけ）、操作の記録を書いているか、
   今日の残り、公開の数と寄せられた一言の数、入れる人の数、今日断った要求の回数
2. **気を付ける事**: 何が起きているかの文と、その下にサーバーで打つコマンド。無ければ「ありません」。
   今日断った要求が 20 回以上になると「今日、断った要求が N 回あります。誰かが試しているかもしれません。」の札が出ます
   （`src/kagi/admin.py` の `DENIED_MANY`）。
   札の下に「受け付けを止める」／「受け付けを再開する」（二度押し）
3. **人に渡す token**: 出す、写す、取り消す。「token を全部取り消す」（二度押し。押した本人の分は残す）
4. **公開された記録**: 公開した人、公開した日、寄せられた一言の数、公開の頁へのリンク。寄せられた一言を見て一件ずつ消す、
   記録を取り下げる（どちらも二度押し）
5. **操作の記録（サーバー）**: 操作の記録の終わりの 40 行を人の言葉で（「仲間　Claude と話した　通した」など）

要るのは、サーバーの URL（https だけ。例 `https://seed.example`）と、歩 1 で出した管理者の token です。token は作業の場所の
`seed-admin.json`（600）に平文で置かれ、画面には出ません。このファイルは開きません。在庫表にその一件が無ければ、画面がそう言うので書いてもらいます。
同じ画面の「在庫・口・記録」で、サーバーの Claude と Pl@ntNet の鍵が在るか無いかと在庫表の行が並び、在庫表に無い鍵は「直す」に出ます。

「気を付ける事」に出た文は、まずそのまま読んでもらいます。打つコマンドがその下に一行ずつ出ます。コマンドを打つのは人です
（`sudo test -e /etc/seed/keys/anthropic || …` など。読んで確かめてから）。「操作の記録が書き換えられています」が出たら、先に
「受け付けを止める」を押してもらいます。止めている間、読み、話す、動画（`/api/video`）、草の名、公開、一言は 503 で断られます。公開の頁、本人の取り下げ、土地の照会、
管理の操作、`/health` は通るので、表に出ている物は見えたまま、書き足す口とお金が掛かる口だけが閉じます（`src/seed/server/main.py` の `_paused`）。token が漏れたかもしれない時は「token を全部取り消す」で、
要る人に出し直します。

## 入口の機械に seed を置く時

置く手順そのものは `docs/deb2 の配備.md` §0 です。この節は、その前と後に kagi で見る物です。

**置く前に出る行。** `check` の「直す」のうち、次の三つは、まだ置いていないから出る行です（`deploy/deb2/ports.toml` の
コメントの通り）。直す物ではなく、置く作業の残りです。

- 口 8010 が開いていない
- seed の入口が Caddy の設定に無い
- seed が動いていない

**置く前に直す順。** 04 の「直す順」の四つのままです。ただし外へ出ていく通信を止める防火壁の決まり（03 の歩 2）は、置いて読みが通るのを確かめた後にします。
閉じた後に、もう一度読みを試します。止まったら `sudo journalctl -k --grep UFW` で見ます（03 の歩 2）。

**置いた後に確かめる物。**

- もう一度 `collect` と `check`。上の三つの行が消える
- 机の PC から 8010 に繋がらないまま（04 の歩 5。`127.0.0.1` で聞く）
- 秘密の持ち主と許可（00 の表。`sudo ls -l /etc/seed/ /etc/seed/keys/` で、`env` と `invites.toml` が `-rw-r----- root seed`、`log-key` と `keys/` の中が `-rw------- root root`）と、在庫表に一件ずつ
- `/health` の `audit` が `on`、招待コード無しで 403、`kagi log verify` が ok（歩 4）
- 動かす人の token で、kagi の「人の出入り」に今の状態が出る（歩 1）
- 控えの輪に `/var/lib/seed` が入っている（06）

## まだ無い物

招待コードの一覧を画面から直す所、買い手だけが読める記録、人の層（パスキー）、要求ごとの番地の記録（番地が記録に残るのは、
上の「止めた」の一行だけ）、記録のファイルを回す仕組み。機械の側の事は kagi の机の画面です。
