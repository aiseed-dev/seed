# 05 門と管理の画面

## この章で読むこと

seed のサーバーに、誰が、何をしに入れるか。招待コードと相手ごとの token、誰が何をしたかの記録、管理の画面。
門は `src/seed/server/gate.py`、画面は `src/seed/app/admin.py` です（設計書 §5.9、§5.10）。

## 招待コードと token

招待コードは平文の一覧（`/etc/seed/invites.toml`）で、入れるか入れないかの二つです。一覧の人は「招待した人」に
なります。token は相手ごとに出し、範囲と期限を付け、取り消せます。

| 範囲 | 誰 | できる事 |
|---|---|---|
| `member` | 招待した人 | 読み、草の名、照会、公開、取り下げ、一言、Web 版 |
| `buyer` | 買い手 | 公開の記録に一言を送るだけ |
| `admin` | 動かす人 | 管理の画面。`member` の事も全部 |

台帳（サーバーでは `/var/lib/seed/gate/tokens.json`）に残るのはハッシュだけです。token は出した時に一度だけ
人の端末に出ます。あなたはそれを見ません。期限の無い物は通らず、台帳が無くなれば閉じる側に倒れます。

## 出す・取り消す

歩 1 動かす人の token を出す（最初の一つだけは機械の上で）
- 人（読んで確かめてから）: 機械の端末で `sudo -u dev /opt/seed/.venv/bin/seed token add "<自分の呼び名>" --scope admin --days 365 --file /var/lib/seed/gate/tokens.json`。
  出た一行を、自分のアプリの招待コードの欄に入れる。どこにも書き写さない
- 道具: 台帳にハッシュを一件書く
- 確かめ: アプリの下の並びに「管理」が出る

歩 2 相手に出す
- 人（読んで確かめてから）: 管理の画面の「人に渡す token」で、呼び名、できる事、期限、覚え書きを入れて「出す」。写す釦で写し、
  その人にだけ渡す。機械の上なら `seed token add "<呼び名>" --scope buyer --days 30 --file …`
- 道具: 台帳に一件。記録に一行
- 確かめ: 一覧に、呼び名、範囲、期限が出る。`seed token list --file …` でも同じ

歩 3 取り消す
- 人（読んで確かめてから）: 画面の一覧から取り消す（二度押し）。機械の上なら `seed token revoke "<呼び名>" --file …`
- 道具: 取り消した行は消さず、日を書く。次の要求から効かない
- 確かめ: その token での要求が 403

token が会話や画面の写真に出たら、その token を取り消して出し直します。

## 誰が何をしたかの記録

門を通した事も断った事も、サーバーの記録（`/var/lib/seed/audit/audit.log`）に一行ずつ残ります。呼び名、
した事、結果です。token も招待コードも書かれません。形は kagi の記録と同じで、追記だけ、連番、ハッシュの連鎖、署名です。

歩 4 記録と門を外から確かめる
- 人（打つ。確かめは結果で）: `sudo KAGI_LOG_KEY_FILE=/etc/seed/log-key /opt/seed/.venv/bin/kagi log verify --dir /var/lib/seed/audit`
- 道具: `ok N lines` か、落ちた行と理由
- 人か Claude: 招待コード無しで試す（どこからでも打てる）
  ```
  curl -s https://<入口の名>/health; echo
  curl -s -w ' %{http_code}\n' 'https://<入口の名>/api/lookup?lat=0&lon=0'
  ```
- 確かめ: `ok`。`/health` の `audit` が `on`（鍵が無ければ `off`、書けなければ `error`）。`/api/lookup` が 403。
  買い手の token で公開を試すと 403

期限は `kagi check tokens --file /var/lib/seed/gate/tokens.json` で見ます。期限切れのまま取り消していない物が
「直す」に出ます。机の画面では「鍵」の下に並びます。

## 管理の画面の五つ

PC 版、Web 版、電話で同じ物です。`admin` の人にだけ出ます。見たのは PC 版とブラウザまでで、iPhone の実機では
通していません（`docs/iPhone 版.md`）。

1. **今の状態**: サーバー、読みができるか、記録を書いているか、今日の残り、公開の数、入れる人の数
2. **気を付ける事**: 起きている事と、する事を一行で。無ければ「ありません」
3. **人に渡す token**: 出す、写す、取り消す
4. **公開された記録**: 一覧から取り下げる（二度押し）
5. **誰が何をしたか**: 記録の終わりの 40 行を人の言葉で

「気を付ける事」に出た一行は、まずそのまま読んでもらいます。する事がその一行に書いてあります。
読みができない時は、どのファイルのどの行に鍵を入れるかが出ます。鍵を入れるのは人です（`sudoedit /etc/seed/env`）。

## 入口の機械に seed を置く時

置く手順そのものは `docs/deb2 の配備.md` §0 です。この節は、その前と後に kagi で見る物です。

**置く前に出る行。** `check` の「直す」のうち、次の三つは、まだ置いていないから出る行です（`deploy/deb2/ports.toml` の
コメントの通り）。直す物ではなく、置く作業の残りです。

- 口 8010 と 8560 が開いていない
- seed の入口が Caddy の設定に無い
- seed と seed-app が動いていない

**置く前に直す順。** 04 の「直す順」の四つのままです。ただし出る向きの防火壁は、置いて読みが通るのを確かめた後にします。
閉じた後に、もう一度読みを試します。止まったら `sudo journalctl -k --grep UFW` で見ます（03 の歩 2）。

**置いた後に確かめる物。**

- もう一度 `collect` と `check`。上の三つの行が消える
- 机の PC から 8010 と 8560 に繋がらないまま（04 の歩 5。どちらも `127.0.0.1` で聞く）
- 秘密の持ち主と許可（00 の表。`ls -l /etc/seed/` が `-rw-r----- root dev`）と、在庫表に一件ずつ
- `/health` の `audit` が `on`、招待コード無しで 403、`kagi log verify` が ok（歩 4）
- 動かす人の token で、アプリに「管理」が出る（歩 1）
- 控えの輪に `/var/lib/seed` が入っている（06）

## まだ無い物

招待コードの一覧を画面から直す所、買い手だけが読める記録、人の層（パスキー）、要求の番地の記録、記録の
ファイルを回す仕組み。機械の側の事は kagi の机の画面です。
