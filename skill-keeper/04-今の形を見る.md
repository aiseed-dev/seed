# 04 今の形を見る

## この章で読むこと

機械の今の形を写し、表と突き合わせ、直す手を出す。kagi は機械を変えません。直す手を打つのは人です。

作った時の確かめ（テスト、置いた直後の確かめ）では見つからず、動かしている機械を後から見て初めて出る物があります。
作者の機械では四つ出ました。出る向きの防火壁、ssh のパスワードの入口、表に無い鍵、ルーターの管理の口です。
この章と 08 は、動かしている間の確かめです。

命令は作業の場所で打ちます。別の場所から打つ時だけ `kagi --dir <作業の場所> …` です。

## 三つの命令

| 命令 | する事 |
|---|---|
| `kagi machine collect --host <名>` | 人の ssh と人の鍵で入り、読むだけの決まった文を走らせ、写しを `facts/<名>-<日時>.txt`（600）に置く。記録に `machine.collect` を一行（署名の鍵があれば。無ければ 00 の歩 3） |
| `kagi machine check [--host <名>] [--facts <ファイル>]` | 写しを、機械の表・口の表・在庫表と突き合わせ、「直す」と「見るだけ」を出す。`--host` が無ければ全部の機械 |
| `kagi machine fix --host <名>` | 直す手を sh の文で出す。走らせない |

走らせる文そのものは `kagi machine script` で読めます。初めての機械では、`collect` の前に人に見せます。二度目からは要りません。`collect` は、パスワードを
尋ねる機械と、この PC の ssh がその機械の鍵をまだ覚えていない機械（`known_hosts` に無い機械）には入りません。
表の `hostkey` は別の物で、`check` が写しの指紋と比べます（02）。この PC 自身は `--local` か、表の `local = true` です。

歩 1 一台の差を出す
- 人か Claude: `kagi machine collect --host <名>` → `kagi machine check --host <名>`
- 道具: 「直す」と「見るだけ」の表
- 確かめ: 表が出る。出なければ、出た一行（入れない理由）をそのまま読む

歩 2 一行ずつ直す
- 人: `kagi machine fix --host <名>` の文を、一行ずつ読んで機械の端末で打つ。ssh の形を変える行は、先に別の窓で
  鍵で入れる事を確かめてから（02）。写しを取るアカウントが sudo を持たない時、sudo の行は sudo を持つアカウントで
  入って打つ。誰が持つかは、`check` の「見るだけ」の「管理者」の行（`sudo を持つ人 N: …`）に必ず一行出る。
  ssh の形を変える行の前には、そのアカウントが鍵で入れるか、入ってから替われるかを確かめる。パスワードでしか
  入れないなら、先に鍵を入れる（02 の歩 2）
- 道具: 手の文（出すのは Claude が打ってよい）。止まったサービスには `systemctl status …`（理由を見る）と `restart`
- 確かめ: もう一度 `collect` と `check`。「直す物は無い」まで

`fix` の文を、読まずに丸ごと走らせません。あなたが手の意味を一行ずつ添えます。`check` と `fix` は、直す物が
あると終了コード 1 で終わります。失敗ではありません。

## 直す順

直す物が多い時は、この順で出します。

1. 入れる人と鍵（02）。誰が入れるかが先です
2. 届いている口（03 の「機械の中だけに縛る、門を置く」、この章の歩 5）。次に、何に届くか
3. 更新（03）。機械を変えるので、鍵と口が分かってから
4. 出る向きの防火壁（03）。閉じると更新と名前解決が止まるので、最後

## root でない写しで見えない物

root でない写しでは、実際に効いている sshd の値（`sshd -T`）、他の人の `authorized_keys`、他の人が動かしている口の
プロセスの名、パスワードの状態、sudoers が見えません。`check` はその事を「見るだけ」の行で必ず言います。その行が
ある間は「ssh は鍵でだけ」と書きません。「設定のファイルではそう書いてある。効いている値は見ていない」と書きます。

歩 3 root の写しを一度取る
- 人: `kagi machine script > k.sh` → `scp k.sh <名>:` → `ssh -t <名> 'sudo sh k.sh > facts.txt'` → `scp <名>:facts.txt <名>-root.txt`。
  写しを取るアカウントが sudo を持たなければ、sudo を持つアカウントで
- 道具: `kagi machine check --host <名> --facts <名>-root.txt`
- 確かめ: 「root でない写し」の「見るだけ」が消える。`<名>-root.txt` は作業の場所（repo の外）に置く

ssh で入れない機械も同じで、文を持って行って走らせ、出力をファイルで渡します。

## 表に無いサービス

`check` が言うのは、表の `services` と `user_services` に書いたサービスだけです。今動いている物の全部は、写しの
`## kagi services` と `## kagi user-services` の節にあります。表に無い口の持ち主を探す時は、ここを読みます。

## 防火壁の規則

歩 4 ufw の規則を読む
- 人: 機械の端末で `sudo ufw status verbose`。出力を貼るかどうかは人が選ぶ（番地が入る）
- 道具: 写しが取るのは、動いているかと既定の向き（入る・出る）だけ。規則の中身は取らない
- 確かめ: 規則の一行ずつが、口の表の理由（「LAN だけ」など）と合う。合わない行を書き出す

## 聞いている事と、届く事は別

写しの `ss -ltnp` が言うのは、その機械が何を聞いているかです。別の機械から届くかは、防火壁とルーターで
決まり、写しからは分かりません。

歩 5 届くかを測る
- 人か Claude: 机の PC から、その口に繋いでみる
  - Web の口: `curl -s -o /dev/null -w '%{http_code}\n' -m 5 http://<名>:<口>/`
  - ほかの口: `timeout 3 bash -c '</dev/tcp/<名>/<口>' && echo 繋がった || echo 繋がらない`
  - 名前ごとの入口（443）: `curl -s -o /dev/null -w '%{http_code}\n' -m 5 https://<入口の名>/`
  - `~/.ssh/config` にだけ名がある機械は、`curl` と `/dev/tcp` では名が引けない。番地は `ssh -G <名> | grep '^hostname '` で出る
- 道具: —
- 確かめ: どの機械から、どの口に、いつ、何が返ったかを書く

読み方。返事が返れば（200 でも 4xx でも）「届いた」です。token や合言葉を付けずに返事が返れば「認証無しで届いた」です。
入口の機械から測る分は、その機械に入れる人が同じ命令をそこで打ちます。打てなければ「測っていない」と書きます。
前に中継（Cloudflare など）が居る入口は、443 の結果は中継を通った物です。中継を通らずに届くかは、外の網の機械からしか
測れません。測っていなければ、そう書きます。

外から IPv6 で届くかは、外の網の機械からしか測れません。作者の家では、公開の機械から届いた口は二つでした。
データの機械の認証の無い口と、ルーターの管理の口です（`docs/kagi 配線図.md` §1）。ルーターは写しを取れない機械です。

## 入口の表

公開の機械は、`[[door]]` に入口ごとに `site`、`who`（誰が入れるか）、`auth`（`public` 誰でも、`app` 裏のアプリが
確かめる、`gate` 前の Caddy が確かめる、`lan` 網で絞る）を書きます。kagi は Caddy の設定の形だけを写します
（値は取らない）。写しの `## kagi caddy` の節で、名の無い `site` の行は全体の設定、`site (名)` の段は使い回す部品で、
どちらも入口ではありません。出るのは、表に無い入口、`gate` なのに確かめる行が無い入口、`lan` なのに `remote_ip` が無い入口、
表にあって設定に無い入口です。

`app` の入口でアプリが本当に確かめているかは、kagi は見ません。外から、招待コード無しで試します（05 の歩 4）。
Caddy 以外（nginx など）は、まだ読めません。
