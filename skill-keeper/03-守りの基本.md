# 03 守りの基本

## この章で読むこと

防火壁、自動の更新、fail2ban、要らないサービス、新しいソフトや外のサービスを入れる時。連載 第 5 章（守りの基本）の形で、`firstboot.sh` も
`kagi machine fix` も同じ規則を同じ順で書きます。

## 防火壁

形は、入りも出も既定は拒否です。ssh を先に通してから有効にします。順を逆にすると、その場で入れなくなります。

歩 1 防火壁を入れる（動いていない機械）
- 人（読んで確かめてから）: `kagi machine fix` が出す行を、上から一つずつ読んで打つ
  ```
  ss -Htn state established | awk '{n=split($3,l,":"); m=split($4,r,":"); if (l[n]+0>=32768) print r[m]}' | sort -n | uniq -c | sort -rn
  sudo apt install -y ufw
  sudo ufw default deny incoming && sudo ufw default deny outgoing
  sudo ufw limit 22/tcp
  sudo ufw allow out 53 && sudo ufw allow out 123/udp && sudo ufw allow out 80,443/tcp
  sudo systemd-run --unit=ufw-modosu --on-active=10min /usr/sbin/ufw default allow outgoing
  sudo ufw enable
  sudo systemctl stop ufw-modosu.timer
  ```
  一行目は、この機械が今、外のどの口へ通信しているかを数えます（sudo は要らない）。出た口のうち要る物は、
  `sudo ufw allow out 53 ...` の行に足します（ssh と git の push は 22: `sudo ufw allow out 22/tcp`）。
  `systemd-run` の行は、10 分後に自動で外向き許可に戻すタイマーです。許可し忘れで何かが止まっても、待てば戻ります。
  問題が無ければ最後の行で取り消します（取り消さないと 10 分後に許可に戻る）。
  ssh を家の網だけにするなら、`sudo ufw limit 22/tcp` を `sudo ufw allow from 192.0.2.0/24 to any port 22 proto tcp` に
- 道具: `kagi machine check` の「防火壁」の行
- 確かめ: 別の窓から ssh で入れる。`sudo ufw status verbose` に既定の拒否が二つ。`check` の「防火壁」が消える

歩 2 出る向きを閉じる（入る向きだけ閉じている機械）
- 人（読んで確かめてから）: `kagi machine fix` が出す行を、上から一つずつ読んで打つ
  ```
  ss -Htn state established | awk '{n=split($3,l,":"); m=split($4,r,":"); if (l[n]+0>=32768) print r[m]}' | sort -n | uniq -c | sort -rn
  sudo ufw allow out 53 && sudo ufw allow out 123/udp && sudo ufw allow out 80,443/tcp
  sudo systemd-run --unit=ufw-modosu --on-active=10min /usr/sbin/ufw default allow outgoing
  sudo ufw default deny outgoing
  sudo apt update
  sudo systemctl stop ufw-modosu.timer
  ```
  一行目で、この機械が今、外のどの口へ通信しているかを数えます。出た口のうち要る物は二行目に足します（ssh と
  git の push は 22: `sudo ufw allow out 22/tcp`）。家の網の機械へ出るなら `sudo ufw allow out to <LAN>` も先に。
  三行目は 10 分後に自動で外向き許可に戻すタイマーで、許可し忘れで何かが止まっても、待てば戻ります。
  `sudo apt update` が通り、問題が無ければ最後の行で取り消します（取り消さないと 10 分後に許可に戻る）
- 道具: `check` が「出る向きを既定で通している」を出す
- 確かめ: `sudo apt update` が通る。止まった通信は `sudo journalctl -k --grep 'UFW BLOCK'` に出る

閉じる理由は、この道具が出す事実で書きます。`check` が「出る向きを既定で通している」と出した機械は、乗っ取られた
時に外へ何でも送れます。閉じた後に止まった通信は `sudo journalctl -k --grep UFW` で見えます（連載 第 5 章）。
作者の三台は、三台とも出る向きを既定で通していました（kagi 設計書 §3.4b）。

## 機械の中だけに縛る、門を置く

口が全部の番地（`0.0.0.0`、`::`、`*`）で聞いていて、口の表は機械の中だけ（`127.0.0.1`）の時。手は二つです。

- (a) そのサービスの設定で、待ち受けを `127.0.0.1` に縛る
- (b) 外から使うなら、前に門（token を確かめる口）を置く

見本は `deploy/halo/手順.md` と `deploy/halo/Caddyfile` です。要点は五つです。

1. 元のサービスは `127.0.0.1` に縛り、Caddy が別の口（元の口に 10 を足した番号）で聞く
2. `Authorization: Bearer <token>` が口ごとの token と一致した時だけ通し、違えば 401。token が空なら誰も通さない
3. token は口ごとに一つ。値は Caddyfile にも repo にも無く、root 600 のファイルから systemd が渡す。作るのは人
4. 記録から `Authorization` を消し、Caddy の管理の口は開けない（`admin off`）
5. 置いたら `sudo caddy validate` が通るまで先へ進まない。この見本は validate をまだ走らせていない

歩 3 一つの口を縛る
- 人（読んで確かめてから）: (a) か (b) の手を、見本の順で打つ
- 道具: `check` の「口」の「外向きで表と違う」の行。`fix` は (a) と (b) を一行の覚え書きで出す
- 確かめ: 機械の中で `ss -ltn` に `127.0.0.1:<口>` だけ。机の PC から元の口に繋いで「繋がらない」（04 の歩 5）。
  (b) なら、token 無しで門の口に繋いで 401

## 自動の更新

歩 4 更新を当て、自動にする
- 人（打つ。確かめは結果で）: `sudo apt update && sudo apt full-upgrade`、`sudo apt install -y unattended-upgrades`、
  `/etc/apt/apt.conf.d/20auto-upgrades` に二行（`Update-Package-Lists "1"`、`Unattended-Upgrade "1"`。手の文は `fix` が出す）
- 道具: `check` の「更新」の行（更新の数、一覧が 7 日以内か、unattended-upgrades が動くか、再起動が要るか）
- 確かめ: 「更新」の行が消える。再起動が要ると出たら、止めてよい時を選ぶ

## fail2ban

補助の番犬です。主役は鍵でだけ入る形（02）です。`firstboot.sh` は `/etc/fail2ban/jail.local` を、無い時だけ
`bantime = 10m`、`findtime = 10m`、`maxretry = 5`、`[sshd]` の `enabled = true` で書きます。
写しが見るのは動いているかだけで、入っているかは分かりません。`check` は、動いていない時に「fail2ban が動いていない」を
「見るだけ」で出します。

## 時計

期限は時計で決まります（K-11）。`timedatectl set-ntp true`。`check` は合っていなければ「直す」で出します。

## 要らないサービス

動いている物が少ないほど、攻められる面が小さくなります。机の形で入れた機械には、画面のログイン、印刷、
近くの機械を探す物、Bluetooth、電話の網の物が動いている事があります（入口の機械の写しで見た例。
`deploy/deb2/手順.md` の h）。

歩 5 要らないサービスを止める
- 人か Claude: 写しの `## kagi services` の節を読み、役に要らない物を書き出す
- 人（打つ。確かめは結果で）: 書き出した物を一つずつ止める（止め方は連載 第 5 章）。口の表からその口の行を消す
- 道具: `check` が、口の表に無い口と、表にあって開いていない口を出す。kagi は止める手を出さない
- 確かめ: `check` の口の差が無い。役のサービス（表の `services`）は「動いている」に入ったまま

どれが要らないかは、その機械の役（00）で分かります。役に書いていない物から聞きます。

## 新しいソフトや外のサービスを入れる時

八つの「新しいソフトや外のサービスを入れる」に当たります。入れると、口、動くサービス、外へ出る通信、置く秘密が増える事が
あり、それは入れる手の文を読んだだけでは見えません。だから入れる前と後に写しを取り、差で見ます。

歩 6 入れる前に言う
- 人か Claude: 何を、どこから（Debian の apt か、外から取る物か）、何のために入れるかを一行ずつ。分かっていれば、増える口と
  サービス、外へ出る通信の相手、置く秘密（外のサービスの鍵など）、外へ渡すデータも
- 人か Claude: `kagi machine collect --host <名>` → `kagi machine check --host <名>`。今の差を、入れる前の形として残す
- 確かめ: 人が、何が増えるかを読んで「入れる」と言う

歩 7 入れて、表を合わせる
- 人（読んで確かめてから）: 入れる手を打つ
- 人か Claude: もう一度 `collect` と `check`
- 道具: 増えた口とサービスが「表に無い」で出る
- 人か Claude（00 の「表を誰が書くか」）: 要る物は、口の表と `services` に理由を付けて足す。秘密が増えたら在庫表に一件（値は書かない）。
  要らない口は、歩 3 で機械の中だけに縛る
- 確かめ: `check` の差が、歩 6 で残した形に戻る。出る向きを閉じた機械で止まった通信は `sudo journalctl -k --grep 'UFW BLOCK'` に出る。
  要る相手は歩 2 の `allow out` の行に足す。`kagi log add --actor <自分> --action software.add --detail <名>`

外の AI やサービスに渡すデータの範囲を広げる時も、同じ二歩です。歩 6 で、今送っている物と、広げた後に送る物を並べて人に見せます。
今の seed が外に送る物は二つです。

- 読み: 縮めた写真（EXIF 無し）と座標と本人の言葉を seed のサーバーへ。サーバーが Claude に渡す
  （`docs/設計書.md` の `/api/read`、`docs/利用マニュアル.md` §9）。家の PC の `seed home` へは、縮めない元の写真（座標入り）を
  家の網の中で送る（09）
- 草の名: 縮めた写真だけを Pl@ntNet へ。座標は送らない（`docs/利用マニュアル.md` §11a）
