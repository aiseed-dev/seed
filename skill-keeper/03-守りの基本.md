# 03 守りの基本

## この章で読むこと

防火壁、自動の更新、fail2ban、要らないサービス。連載 第 5 章（守りの基本）の形で、`firstboot.sh` も
`kagi machine fix` も同じ規則を同じ順で書きます。

## 防火壁

形は、入りも出も既定は拒否です。ssh を先に通してから有効にします。順を逆にすると、その場で入れなくなります。

歩 1 防火壁を入れる（動いていない機械）
- 人: `kagi machine fix` が出す行を、上から一つずつ打つ
  ```
  sudo apt install -y ufw
  sudo ufw default deny incoming && sudo ufw default deny outgoing
  sudo ufw limit 22/tcp
  sudo ufw allow out 53 && sudo ufw allow out 123/udp && sudo ufw allow out 80,443/tcp
  sudo ufw enable
  ```
  ssh を家の網だけにするなら、三行目を `sudo ufw allow from 192.0.2.0/24 to any port 22 proto tcp` に
- 道具: `kagi machine check` の「防火壁」の行
- 確かめ: 別の窓から ssh で入れる。`sudo ufw status verbose` に既定の拒否が二つ。`check` の「防火壁」が消える

歩 2 出る向きを閉じる（入る向きだけ閉じている機械）
- 人: 要る出口（53、123/udp、80・443/tcp）を通してから `sudo ufw default deny outgoing`。家の網の機械へ出るなら
  `sudo ufw allow out to <LAN>` も先に
- 道具: `check` が「出る向きを既定で通している」を出す
- 確かめ: `sudo apt update` が通る。止まった通信は `sudo journalctl -k --grep UFW` に出る

閉じる理由は、この道具が出す事実で書きます。`check` が「出る向きを既定で通している」と出した機械は、乗っ取られた
時に外へ何でも送れます。閉じた後に止まった通信は `sudo journalctl -k --grep UFW` で見えます（連載 第 5 章）。
作者の三台は、三台とも出る向きを既定で通していました（kagi 設計書 §3.4b）。

## 機械の中だけに縛る、門を置く

口が全部の番地（`0.0.0.0`、`::`、`*`）で聞いていて、口の表は機械の中だけ（`127.0.0.1`）の時。手は二つです。

- (a) そのサービスの設定で、待ち受けを `127.0.0.1` に縛る
- (b) 外から使うなら、前に門（token を確かめる口）を置く

見本は `deploy/halo/手順.md` と `deploy/halo/Caddyfile` です。要点は五つです。

1. 元のサービスは `127.0.0.1` に縛り、Caddy が別の口（元の口に 10 を足した番号）で聞く
2. `Authorization: Bearer <token>` が口ごとの token と一致した時だけ通し、違えば 401。token が空なら誰も通さない
3. token は口ごとに一つ。値は Caddyfile にも repo にも無く、root 600 のファイルから systemd が渡す。作るのは人
4. 記録から `Authorization` を消し、Caddy の管理の口は開けない（`admin off`）
5. 置いたら `sudo caddy validate` が通るまで先へ進まない。この見本は validate をまだ走らせていない

歩 3 一つの口を縛る
- 人: (a) か (b) の手を、見本の順で打つ
- 道具: `check` の「口」の「外向きで表と違う」の行。`fix` は (a) と (b) を一行の覚え書きで出す
- 確かめ: 機械の中で `ss -ltn` に `127.0.0.1:<口>` だけ。机の PC から元の口に繋いで「繋がらない」（04 の歩 5）。
  (b) なら、token 無しで門の口に繋いで 401

## 自動の更新

歩 4 更新を当て、自動にする
- 人: `sudo apt update && sudo apt full-upgrade`、`sudo apt install -y unattended-upgrades`、
  `/etc/apt/apt.conf.d/20auto-upgrades` に二行（`Update-Package-Lists "1"`、`Unattended-Upgrade "1"`。手の文は `fix` が出す）
- 道具: `check` の「更新」の行（更新の数、一覧が 7 日以内か、unattended-upgrades が動くか、再起動が要るか）
- 確かめ: 「更新」の行が消える。再起動が要ると出たら、止めてよい時を選ぶ

## fail2ban

補助の番犬です。主役は鍵でだけ入る形（02）です。`firstboot.sh` は `/etc/fail2ban/jail.local` を、無い時だけ
`bantime = 10m`、`findtime = 10m`、`maxretry = 5`、`[sshd]` の `enabled = true` で書きます。
写しが見るのは動いているかだけで、入っているかは分かりません。`check` は、動いていない時に「fail2ban が動いていない」を
「見るだけ」で出します。

## 時計

期限は時計で決まります（K-11）。`timedatectl set-ntp true`。`check` は合っていなければ「直す」で出します。

## 要らないサービス

動いている物が少ないほど、攻められる面が小さくなります。机の形で入れた機械には、画面のログイン、印刷、
近くの機械を探す物、Bluetooth、電話の網の物が動いている事があります（入口の機械の写しで見た例。
`deploy/deb2/手順.md` の h）。

歩 5 要らないサービスを止める
- 人か Claude: 写しの `## kagi services` の節を読み、役に要らない物を書き出す
- 人: 書き出した物を一つずつ止める（止め方は連載 第 5 章）。口の表からその口の行を消す
- 道具: `check` が、口の表に無い口と、表にあって開いていない口を出す。kagi は止める手を出さない
- 確かめ: `check` の口の差が無い。役のサービス（表の `services`）は「動いている」に入ったまま

どれが要らないかは、その機械の役（00）で分かります。役に書いていない物から聞きます。
