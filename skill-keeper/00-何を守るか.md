# 00 何を守るか

## この章で読むこと

機械の役と、役ごとに置く物。最初にする事は、機械の表 `machines.toml` を書く事です。表に書けば、入れる時の
答えの文、今の形と表の差、直す手の文は kagi が書きます。人に残るのは、表を書く、画面でパスワードを打つ、
盤を選ぶ、機械の鍵の指紋を目で比べる、直す手を読んで打つ、の五つです（kagi 設計書 §3.4）。

## 最初の一歩

歩 1 机の PC を表に書いて、写しを取る
- 人: `kagi init --dir ~/kagi-data` を打ち、`cd ~/kagi-data`。以後の命令はここで打つ
- 人か Claude: できた `machines.toml` に、今使っている PC を一件（`host`、`role`、`users`、`admins`、`keys`、
  `local = true`）。Claude が書く時は下の「表を誰が書くか」の通り
- 人か Claude: `kagi machine collect --host <名> --local` → `kagi machine check --host <名>`
- 道具: 写しを `facts/` に置き、「直す」と「見るだけ」を出す
- 確かめ: 表が出る。「直す」の数を紙に書く。それが今日の出発点

作業の場所は repo の外に置きます。表と写しには、番地、指紋、アカウントの名が入るからです。

## 作業の場所に在る物

| 物 | 中身 |
|---|---|
| `machines.toml` | 機械の表、鍵の表、入口の表 |
| `ports.toml` | 口の表 |
| `inventory.toml` | 在庫表（値は無い） |
| `audit.log` | 追記だけの記録 |
| `facts/` | 写し（600） |
| `install/` | 入れる時の三つのファイル（01） |
| `weekly-<日>.md` | 週の定例の一枚（08） |
| 人が置いた覚え書き | 番地の対応など。人が読んでよいと言ってから読む |

## 表を誰が書くか

表（`machines.toml`、`ports.toml`、`inventory.toml`）は秘密を持ちません。Claude は足す行を文で出し、人が
「それでよい」と言ったら Claude が書いてよい物です。書いた時は、表の頭のコメントに、誰がいつ下書きしたかを書きます
（例 `# 2026-11-06 Claude が下書き、dev が読んだ`）。

## 機械の持ち方

持ち方が変わっても、する事の順は同じです（表を書く、写しを取る、差を読む、直す）。変わるのは、表に書く機械の数と、
読む章です（`docs/基本計画.md` §5）。

| 形 | 役の乗り方 | この形で守れない物 | 読む章の順 |
|---|---|---|---|
| スマートフォンだけ | 机も入口も無い。スマートフォンのアプリだけ（読みは自分の鍵か、人の入口のサーバー。`docs/利用マニュアル.md` §11b） | 記録の置き場が人のサーバーになる。その人が止めると止まる | —（動かす機械が無い） |
| PC 一台 | 机だけ。入口を持たない | 外から届く口が無いので、守る物は PC そのもの（盤、控え、更新） | 00 → 04 → 03 → 06 → 08。スマートフォンから写真と動画を送るなら 09 も |
| PC と、借りた機械 | 机は家、入口は借りた機械 | 入口の機械の盤は貸す側の物。雛形の設定が先に効く事がある（02 の設定のファイルの名） | 00 → 02 → 04 → 03 → 05 → 06 → 08（機械は貸す側が入れるので 01 は無い） |
| PC と、家の一台 | 入口とデータが同じ機械 | 入口が破られると、同じ機械のデータに届く。機械の防火壁では分けられない | 00 → 01 → 02 → 04 → 03 → 05 → 06 → 08 |
| PC と、家の二台 | 入口とデータを分ける | 同じ網に居る間は、番地を名乗る手が残る（07） | 00 → 01 → 02 → 04 → 03 → 05 → 06 → 07 → 08 |
| 上に、もう一台 | 個人情報を分ける。盤を暗号化（01 の `encrypt = true`） | 再起動のたびに、人が合言葉を打つ | 上と同じ順。もう一台は 01 から |

もう動いている機械がある時は、01 を飛ばして 04 の写しから入ります。どの形でも 00 の歩 1（机の PC を表に書く）が先です。
試してあるのは、PC 一台と、家の二台の形です（SKILL.md の「確かめていない事」）。

スマートフォンだけと PC 一台は、使う側です。記録を人と共有するには、仲間のうち誰か（ビルダー）が入口を動かします。
この手引きは、その動かす一人のための物です。

## 機械の表

| 役 | 置く物 | 置かない物 | 表に足す欄 | kagi が見る物 |
|---|---|---|---|---|
| 入口 | 逆 proxy（Caddy）、seed のサーバー、公開の頁、token の台帳 | 重いデータ、他の機械に入る鍵 | `[[door]]`、`services` | 入口ごとに誰が何で守られて入るか、口 |
| データ | 記録、写真、データベース | 外からの入口 | `data`、`services`、`timers` | 置き場の大きさ、盤の残り、控えの timer |
| 個人情報 | 人の口座と、人ごとの記録 | 外からの入口 | `encrypt = true` | 盤の暗号化 |
| 机 | kagi と作業の場所、机の画面（`kagi app`）、ssh の鍵 | 網に出す画面と口（`seed home` を立てる間は、家の網に口が一つ出る。09） | `local = true` | この PC 自身の写し |

ほかに、網の外の根の置き場（紙か金庫の USB。管理者の鍵）と、控えの盤（LUKS）があります
（`docs/鍵の管理の仕組み.md` §3）。小さく始めるなら、入口と本体の二台と、根の置き場（紙）と、控えの盤一つです。

役を一つの機械に一つにすると、機械ごとに見る物が決まります。入口は入口の表、データは置き場の残り、
個人情報は暗号化と入口が無い事です。

## 入口の機械に置く秘密

seed の配備（`docs/deb2 の配備.md` 0-1、0-3）で、入口の機械に置く秘密は次の通りです。どれも在庫表 `inventory.toml` に
一件ずつ書きます。書くのは名、置き場、持つ人、役、期限、なくした時、漏れた時で、値は書きません。seed のサーバーは、ログインしない
専用の利用者 `seed` で動きます。

| 秘密 | 置き場 | 持ち主と許可 |
|---|---|---|
| Claude の鍵、Pl@ntNet の鍵 | `/etc/seed/keys/anthropic`、`/etc/seed/keys/plantnet` | root:root 600（`keys/` は root 700）。systemd の `LoadCredential=` が seed のサービスにだけ渡す |
| 招待コードの一覧 | `/etc/seed/invites.toml` | root:seed 640 |
| 記録の署名の鍵 | `/etc/seed/log-key` | root:root 600。`umask 077` で作る。無いと `seed.service` が起きない |
| 相手ごとの token の台帳（ハッシュだけ） | `/var/lib/seed/gate/tokens.json` | 置き場 `gate/` は seed 700。サーバーが書く |

`/etc/seed/env` は秘密でない設定（root:seed 640）で、鍵の行はありません。家の PC の `seed home` の招待コード
（`<プロジェクト>/home.toml`）も、在庫表に一件書きます（09 の歩 4）。

見本は `deploy/deb2/inventory.example.toml` です。置いていない物の行は、置いた日に写します。

歩 2 在庫表を埋める
- 人: 今ある秘密を全部挙げる。探す所は機械の `/etc` と home、ルーターの管理の画面、ブラウザの保存、スクリプトの中。
  `kagi scan` は、机の PC で、作業の場所と手元に写してある設定のファイルに掛ける。入口の機械の `/etc` は、
  その機械で sudo を持つ人が打つ
- 人か Claude: `kagi check inventory`
- 道具: `scan` は `path:line  種類` だけを出す（値は出さない）。`check inventory` は期限切れ、30 日以内に切れる物、
  欄の抜けを出す
- 確かめ: 走査で出た場所が全部、在庫表にある。`kagi key list` の在庫表の欄に「無い」が出ない。`kagi machine check` に
  「在庫表に無い」が出ない。`kagi check inventory` は在庫表が 0 件でも「抜けも期限切れも無い」と言うので、それだけでは
  確かめにならない（鍵の表に鍵があれば、その事を一行言う）

歩 3 記録の署名の鍵を置く
`collect` が「記録には足していない（署名の鍵が無い）」と言ったら、この歩です（`docs/kagi 手引き.md` §3）。
- 人: 自分の端末で三行。`head -c 32 /dev/urandom > ~/.config/kagi/log-key`、`chmod 600 ~/.config/kagi/log-key`、
  `export KAGI_LOG_KEY_FILE=~/.config/kagi/log-key`。鍵を作るのは人で、Claude は中身を読まない
- 人か Claude: 在庫表に一件（置き場 `pc:~/.config/kagi/log-key`、役「kagi の記録の署名」。値は書かない）
- 確かめ: `kagi log verify` が `ok` を出す

## 作った時の確かめと、動かしている間の確かめ

確かめは二つに分かれます。作った時の確かめは、その時に変えた物が思った形になったかを見ます。動かしている間の確かめは、
誰も変えていないつもりの物が、変わっていないかを見ます。作者の機械では、出る向きの防火壁、ssh のパスワードの入口、
表に無い鍵、ルーターの管理の口の四つが、作った時の確かめでは見つからず、動かしている機械を後から見て初めて出ました（04）。
だから、作った時の確かめが全部通っても、動かしている間の確かめを始めます。

| | いつ | 何で見るか | 章 |
|---|---|---|---|
| 作った時 | 機械を入れた直後 | 十二歩の確かめの欄、`collect` と `check` で「直す物は無い」 | 01 |
| 作った時 | 鍵と ssh の形を変えた直後 | 別の窓で鍵で入れる、`Permission denied (publickey)` | 02 |
| 作った時 | 防火壁を入れた直後、口を縛った直後 | 別の窓から ssh、`ufw status verbose`、机の PC から繋いで「繋がらない」 | 03 |
| 作った時 | seed を入口の機械に置いた直後 | 「置いた後に確かめる物」 | 05 |
| 作った時 | `seed home` を立てた時 | 家の網の機械から `/health`、ルーターの転送の一覧 | 09 |
| 作った時 | 控えから立て直した直後 | `collect` と `check`、`/health`、`kagi log verify` | 06 |
| 動かしている間 | 週に一度 | `kagi weekly`、前の写しから増えた直す物 | 08 |
| 動かしている間 | 月に一度 | `kagi check inventory`、`kagi check tokens` | 08 |
| 動かしている間 | 気になった時、表を変えた後 | `collect` と `check`、別の機械から届くかを測る | 04、07 |
| 動かしている間 | 記録を見る時 | `kagi log verify`、`/health` の `audit` | 05 |
| 動かしている間 | 年に一度以上 | 控えから一つ戻してみる | 06 |

## 理由の書き方

役を分ける理由は、その人の写しと測った事から書きます。作者の家では、公開の機械から、データの機械の認証の
無い口に届いていました（`docs/kagi 配線図.md` §1）。手で開けた規則が広すぎた例です。こういう一行が
見つかるまでは、分ける理由を一般論で足しません。
