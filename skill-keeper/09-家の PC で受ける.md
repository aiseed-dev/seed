# 09 家の PC で受ける（seed home）

## この章で読むこと

スマートフォンで撮った写真と動画を、家の網の中で PC のプロジェクトフォルダーへ送る形（`seed home`。
`docs/設計書.md` §5.13）を動かす人が見る物です。向きはスマートフォンから PC への一つで、PC のプロジェクトフォルダーが
本物の記録です。入口の機械（05）と違い、口は家の網の中にだけ出します。使う人の側の手順は
`docs/利用マニュアル.md` §11b です。

## 何が動くか

コード（`src/seed/cli.py` の `cmd_home`、`src/seed/server/home.py`、`src/seed/server/main.py`、`src/seed/discover.py`）を
読んで書いた物です（2026-11-07 の main）。

| 物 | 中身 |
|---|---|
| 立て方 | PC の端末で `seed home`。今のプロジェクト（`seed project use` で選んだ物）を家にして、seed のサーバーを前で動かす。Ctrl+C か端末を閉じると止まる。systemd のサービスにはならない。サーバーの部品（`pip install "seed-farm[server]"`）が要る |
| 待つ口 | 8800/tcp（`--port` で変わる）。既定の番地は `0.0.0.0`（IPv4 の、PC の全部の網の口。VPN の口も入る）。`http://` で、TLS は無い |
| PC を探す口 | 8801/udp。`--host` が `0.0.0.0` か `::` の時だけ開く。スマートフォンが網に `seed?` を送り、PC が `seed-home <URL>` を返す。返事が無ければ、スマートフォンは同じ /24 の番地に一つずつ送る。返すのは URL だけで、招待コードは返さない |
| 門 | 招待コード一つ（呼び名 `home`）。`<プロジェクト>/home.toml`（600）に在る。無ければ作り、在ればそのまま使う。6 桁の数で、期限は無い。立てるたびに端末に出る |
| 渡す設定 | `SEED_HOME`、`SEED_INVITES`（`home.toml`）、`SEED_PUBLIC_DIR`、手引きがあれば `SEED_SKILL_DIR`。token の台帳（`SEED_TOKENS`）と記録（`SEED_AUDIT`）は渡さない。端末に無ければ、門は招待コード一つで、誰が何をしたかの記録は書かない（`/health` の `audit` が `off`） |
| 受ける物 | `/api/read`: 写真（縮めない元のまま、座標入り。一枚 12 MB、合計 60 MB まで）。`/api/video`: MP4（一本 2 GB まで。招待コードと撮った時と所は要求の頭の行 `X-Seed-Invite`、`X-Seed-Where` で受け、URL に載せない）。`/api/talk`: 言葉。写真を受けるのは `/api/read` で、`/api/photo` という口は無い |
| 読む物 | PC の Claude Code（`claude`）。無ければ、`seed home` を打った端末の `ANTHROPIC_API_KEY` |
| 一日の上限 | 読みと話すは、それぞれ一日 1000 回、招待コード一つあたり 500 回（端末に環境変数があればそれ。`src/seed/cli.py` の `HOME_LIMITS`） |

`/api/talk` の言葉は、PC に Claude Code が在れば、その畑のフォルダーで Claude Code に渡ります。使える道具は、読む・書く・直す・
探す（Read、Write、Edit、Glob、Grep）、seed の決まった命令、`mkdir`、`mv`、`ls` です（`src/seed/local.py` の `talk_command`）。
招待コードを持つ人は、PC のプロジェクトフォルダーに写真と動画を置けて、Claude Code にそのフォルダーを書き換えさせられる人です。

## 置き場

| 物 | どこ |
|---|---|
| 写真と観察 | 送られた畑の名（`field`）の畑。無ければ `seed.toml` の今の畑、それも無ければプロジェクトの根。`seed observe` と同じ道 |
| 動画 | `<畑>/videos/<日>/<時刻>.mp4` と、同じ名の `.json`（撮った時と所。座標が入る）。同じ名は上書きせず `-2`、`-3` を付ける。同じ名で同じ大きさなら送り直しとみなし、在る物を返す |
| 一時のファイル | 畑の中の `.home-*`（終われば消える）、`.video-*.part`（落ちた時の残り。一日経った物は次の動画の時に消える） |
| 公開を試した物 | `<プロジェクト>/public-home` |
| 招待コード | `<プロジェクト>/home.toml`（600） |

プロジェクトフォルダーの外には書きません（`home.py`）。プロジェクトフォルダーには、座標の入った写真と、座標の入った動画の
`.json` が溜まります。フォルダーを人に渡す、git に入れる、外の控えに出す時は、その事を先に人に言います。控え（06）には
プロジェクトフォルダーを入れます。スマートフォンの側の記録は送った物の写しで、本物は PC の側だけだからです（設計書 §5.13）。

## 守ること

**`seed home` は人が自分の端末で打ちます。** 立てると招待コードが端末に出るので、Claude が打つと会話に出ます。`home.toml` も
開きません。端末の画面を撮った写真と動画にも、招待コードが写ります。

**口は家の網の中だけに出します。** 招待コードは 6 桁の数（百万通り）です。間違えたコードを 10 分に 10 回送った番地は、
10 分のあいだ正しいコードでも断られ、`seed home` の端末に「止めた」の一行が出ます（`src/seed/server/limits.py` の `Tries`）。
番地を替えれば試し続けられ、記録も既定では書かないので、試された事が分かるのは端末のその行だけです。だから口を、ルーターの外にも、
VPN の相手にも出さず、防火壁で相手を家の網に絞ります。

**机の PC に口が一つ増えます。** 00 の表で、机は網に出す口を置かない役です。`seed home` を立てている間は、家の網に口が一つ
出ます。使う時だけ立てると、口が出ている時間が短くなります。

## 歩

歩 1 防火壁で家の網だけに開ける
- 人か Claude: PC の写しを取り、防火壁が動いているかを見る（`kagi machine collect --host <PC> --local` → `kagi machine check --host <PC>`。04）。
  動いていなければ 03 の歩 1 が先
- 人（読んで確かめてから）: 家の網の番地（見本 `192.0.2.0/24`）からだけ通す。八つの「外への口を開ける」に当たります
  ```
  sudo ufw allow from 192.0.2.0/24 to any port 8800 proto tcp
  sudo ufw allow from 192.0.2.0/24 to any port 8801 proto udp
  ```
- 人: ルーターの管理の画面で、8800 と 8801 を外から転送していない事を見る
- 道具: `check` の「防火壁」の行
- 確かめ: `sudo ufw status verbose` に二行があり、相手が家の網だけ。ルーターの転送の一覧に 8800 と 8801 が無い

`--host ::` にすると IPv6 でも待ちます。家の IPv6 の番地に外から届くかは、外の網の機械からしか測れません（07）。既定の
`0.0.0.0` のままなら、IPv6 では待ちません。

歩 2 立てて、届くかを測る
- 人: PC の端末で `seed home`。出た URL を見る。招待コードは画面で読み、どこにも書き写さない
- 人か Claude: PC の中で `ss -ltn | grep 8800` と `ss -lun | grep 8801`。家の網の別の機械から
  `curl -s -m 5 http://<PC の番地>:8800/health; echo`（04 の歩 5）。PC 自身から繋いでも防火壁を通らないので、確かめになりません
- 道具: kagi の写しが読む口は TCP だけ（`ss -ltnp`、`src/kagi/ports.py`）で、8801/udp は写しにも突き合わせにも出ない
- 確かめ: 家の網の機械から `/health` に `"home":true` が返る。スマートフォンの「PC を探す」で PC が見つかる。家の網の外から
  届かない事は、ルーターの転送の一覧を見た事と、外の網から繋いでみた事を分けて書く

歩 3 口の表に書く
- 人か Claude（00 の「表を誰が書くか」）: PC の口の表に一件
  ```
  [[port]]
  host = "<PC>"
  port = 8800
  proto = "tcp"
  service = "seed home"
  bind = "0.0.0.0"
  reason = "家の網だけ（ufw で相手を絞る）。立てている間だけ"
  ```
- 道具: 立てている間の `check` は 8800 の差を出さない。止めている間は「表にあって開いていない」と出る。止めているからで、直す物ではない
- 確かめ: 立てている間の `check` に 8800 の差が無い

歩 4 招待コードを人に渡す
- 人: 渡す前に、相手に言う。招待コードを持つ人は、PC のプロジェクトフォルダーに写真と動画を置けて、Claude Code に言葉を渡せる。
  招待コードは一つで、皆が同じ呼び名 `home` になるので、記録を書いても誰が送ったかは分かれない
- 人: スマートフォンの seed で、話すの画面の「設定を見せて」→「PC を探す」を押し、6 桁を打つ（`seed home` が端末に出す案内の通り）
- 人か Claude: 在庫表に一件（置き場 `pc:<プロジェクト>/home.toml`、持つ人、渡した先、なくした時と漏れた時は「歩 6 で作り直す」。
  値は書かない）。招待コードには期限の仕組みが無いので、`expires` には作り直す日を書く
- 確かめ: スマートフォンの設定の札に「PC に送っている: <URL>」の一行。一枚撮ると、PC の畑に写真と観察が一つ増える

歩 5 送られた物を見る
- 人か Claude: `ls <畑>/videos/<日>/` と、畑の観察の並び。`.json` の座標は会話に写さない
- 確かめ: 録った本数と `.mp4` の数が合う。`.video-*.part` が一日を越えて残っていない

送れなかった動画はスマートフォンに残り、録画を止めた時とカメラを開いた時に、古い順に送り直されます（設計書 §5.13）。
止めていた間に録った物も、次に繋がった時に届きます。

歩 6 止める、招待コードを新しくする、seed を新しくする
- 止める。人: `seed home` を打った端末で Ctrl+C。05 の「受け付けを止める」は token の台帳の隣の印を使う仕組みで、台帳を渡さない
  `seed home` では使えない。確かめ: 家の網の機械から `/health` に繋がらない。`ss -ltn | grep 8800` が何も出さない
- 招待コードを新しくする（漏れた、渡した人を外す）。人（読んで確かめてから）: 止める → `<プロジェクト>/home.toml` を消す
  （中身は開かない）→ `seed home`。新しい 6 桁が端末に出る。スマートフォンごとに打ち直す。八つの「鍵の作り直し」に当たります。
  確かめ: 古い招待コードのスマートフォンからは送れない。在庫表の日を書き直し、`kagi log add --actor <自分> --action invite.rotate --detail "seed home"`
- seed を新しくする。人（打つ。確かめは結果で）: 止める → 入れた時と同じ形で新しくする → `seed home`。招待コードは `home.toml` に
  在るので変わらない。確かめ: `/health` の `version` が新しい版
- 使わなくなった時。人（打つ。確かめは結果で）: 歩 1 の二行を `sudo ufw delete allow from 192.0.2.0/24 to any port 8800 proto tcp` の形で消す。
  口の表から 8800 の行を外す。確かめ: `sudo ufw status verbose` に二行が無い

## 家の外から送りたい時

形は二つです（設計書 §5.13）。入口の機械に seed を置く（05）か、家の網に入る道（VPN など）を作るかです。どちらも、
`seed home` の口をルーターで外に出す形ではありません。VPN で入る形では、防火壁の相手に VPN の網が加わり、その網に居る機械が
皆、6 桁を試せる相手になります。VPN の機器そのものが入口になった数字は 07 の「箱を足すと増える物」にあります。
