# seed のサーバーを kagi で見る、直す

seed を置く機械の形（ssh の認証、入っている鍵、口、入口、更新）を、kagi で表と突き合わせる手順です。歩は `skill-keeper/04-今の形を見る.md` と `skill-kagi/04-機械を見る.md` にあります。ここには、seed のサーバーに合わせた表の見本だけを置きます。

- 口の表の見本: `ports.example.toml`（22、443、8010）
- 機械の表の見本: `machines.example.toml`
- 在庫表の見本: `inventory.example.toml`

作者の機械（deb2）の本物の表と、11-06 に写しを取って見つけた事は公開しません。ほかに載っているサイトの口と、機械の今の弱い所が入るためです（作者 11-08「公開できる部分は ~/dev/seed に、公開できない部分は ~/seed において」）。

歩（どの機械でも同じ。ほかの文書が「手順の d」のように指す記号）:

- **a.** 表を書いて写しを取る（`kagi machine collect`、`kagi machine check`）
- **a2.** 入口の表に、入口ごとに誰が入れるかと何で守るかを書く（`[[door]]`）
- **b.** 在庫表に、この機械に在る秘密を一件ずつ書く（値は書かない）
- **c.** ssh を鍵でだけ入る形にする（先に、別の窓から鍵で入れる事を確かめる）
- **d.** 入っている鍵を表と比べる（`kagi key list`）。表に無い鍵は、誰の物か分かるまで `kagi machine fix` の通りに外す
- **e.** 更新を当てる
- **f.** seed を置く（`docs/deb2 の配備.md`）
- **g.** root の写しで全部を見る（dev の写しでは、効いている sshd の値、他の人の `authorized_keys`、sudo の形が見えない）
- **h.** 見るだけの物（表に無い口、全部の番地に向いた口）は、外から届くかを防火壁の形で確かめる
- **i.** 相手ごとの token と、誰が何をしたかの記録を確かめる（`kagi check tokens`、`kagi log verify`）
