# deb2 を kagi で見る、直す（手順）

書いた日: 2026-11-06（Fable。作者「deb2 用も作って」）。halo の `deploy/halo/` と同じ置き方。deb2 は seed の入口のサーバーで、Cloudflare の後ろ。dev は sudo を持たないので、直す手を打つのは作者。seed を置く作業そのものは `docs/deb2 の配備.md`。ここは、その前と後に機械の形を確かめる所。

11-06 に dev の鍵で入って読んだ今の形（root でない写し）: seed はまだ入っていない（`/etc/seed`、`/opt/seed`、`/var/lib/seed` が無い。`seed.service` と `seed-app.service` も無い）。防火壁（ufw）は動いている。開いている口は 22・443・2222 と、機械の中だけの 2019・3000・8090・8420・8550・631。机の PC の形で入っていて、gdm・cups・avahi・bluetooth・ModemManager が動いている。

置く物（この repo の `deploy/deb2/`）:

| ファイル | 使い方 |
|---|---|
| `ports.toml` | 配備が済んだ後の口の表。作者の作業の場所の `ports.toml` に足す |
| `inventory.example.toml` | seed の秘密の在庫の見本。作者の `inventory.toml` に写して日付を書く |
| `machines.example.toml` | 機械の表の見本。作者の `machines.toml` に写して直す |

## a. 表を書いて、写しを取る

`machines.toml` に deb2（`machines.example.toml`）、`ports.toml` にこの場所の `ports.toml` の中身。そして:

```bash
kagi machine collect --host deb2
```

```bash
kagi machine check --host deb2
```

画面なら `kagi app` の「機械」で deb2 を選び「写しを取る」。

確かめ: 表が出る。配備の前は、次の六つが「直す」に出るのが正しい: 8010 と 8560 が開いていない、seed.aiseed.dev と seed-app.aiseed.dev が Caddy の設定に無い、seed と seed-app が動いていない。

## a2. 入口の表（誰が入れるか）

deb2 は公開の機械。外から来る入口は Caddy のサイトで、11-06 の写しでは office、aiai、git、auth、analytics の五つ（seed の二つは配備の後）。どれも Caddy は通すだけで、確かめているのは裏のアプリ（Forgejo、PocketBase）か、誰でも見てよい物。

`machines.toml` の `[[door]]` に、入口ごとに、誰が入れるか（`who`）と何で守るか（`auth`）を書く。特定の人だけの入口は `app`（アプリが確かめる。seed は招待コード）か `gate`（Caddy が確かめる）。書いていない入口は「表に無い入口」、`gate` と書いたのに Caddy に確かめる行が無い入口は「門が無い」と出る。

kagi が見るのは Caddy の設定の形まで。`app` の入口でアプリが本当に確かめているかは、外から招待コード無しで試して見る（`docs/deb2 の配備.md` の 0-8）。

確かめ: 「表に無い入口」が無い。

## b. 在庫表

`inventory.example.toml` の五件のうち、もう置いた物だけを `inventory.toml` に写し、`made` と `expires` を書く。置いていない物は、置いた日に写す（`docs/deb2 の配備.md` の 0-3 で鍵と招待コードを置く時）。

確かめ: `kagi check inventory` が抜けを出さない。`kagi key list` で `dev-debpc` の在庫表の欄に期限が出る。

## c. ssh を鍵でだけ入る形にする

11-06 の写しでは、設定のファイルに `PasswordAuthentication` が書かれていない（既定は yes）。root でない写しなので、実際に効いている値はまず作者が見る:

```bash
sudo sshd -T | grep -Ei '^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin|allowusers) '
```

`passwordauthentication yes` なら直す。**先に、別の窓から鍵で入れる事を確かめる**（自分のアカウントでも。入れなくなるのを防ぐ）。手は `kagi machine fix --host deb2` が出す三行:

```bash
printf '%s\n' 'PasswordAuthentication no' 'KbdInteractiveAuthentication no' 'PermitRootLogin no' 'PubkeyAuthentication yes' | sudo tee /etc/ssh/sshd_config.d/10-kagi.conf >/dev/null
```

```bash
sudo sshd -t && sudo systemctl reload ssh
```

確かめ: 別の機械から `ssh -o PubkeyAuthentication=no deb2` が `Permission denied (publickey)`。`collect` と `check` で「パスワードで入れる」が消える。

## d. 入っている鍵

11-06 の写しで、dev の `authorized_keys` に、机の PC の dev の鍵のほかにもう一本入っている（halo にも同じ指紋）。誰のどの機械の鍵かを作者が確かめる。自分の物なら `machines.toml` の `[[key]]` に足して `keys` に id を書く。分からなければ、`kagi machine fix` の通りにその行を消す。

確かめ: 「表に無い鍵」が消える。

## e. 更新

```bash
sudo apt update && sudo apt full-upgrade
```

```bash
sudo apt install -y unattended-upgrades
```

```bash
printf '%s\n' 'APT::Periodic::Update-Package-Lists "1";' 'APT::Periodic::Unattended-Upgrade "1";' | sudo tee /etc/apt/apt.conf.d/20auto-upgrades >/dev/null
```

確かめ: `check` の「更新」の行が消える。再起動が要ると出たら、時を選んで。

## f. seed を置く

`docs/deb2 の配備.md` の 0-1 から。済んだら `collect` と `check`。

確かめ: 8010 と 8560 が開き（どちらも 127.0.0.1）、seed の二つの入口が Caddy の設定に在り、seed と seed-app が「動いている」に入る。外向きで出たら `seed.service` と `seed-app.service` の `--host` を見る。

## g. root の写しで全部を見る

dev の写しでは、実際に効いている sshd の値、他の人の `authorized_keys`、パスワードの状態、sudoers が見えない。作者が一度、root で写しを取って渡す:

```bash
kagi machine script > k.sh
```

```bash
scp k.sh deb2: && ssh -t deb2 'sudo sh k.sh > facts.txt' && scp deb2:facts.txt deb2-root.txt
```

```bash
kagi machine check --host deb2 --facts deb2-root.txt
```

`deb2-root.txt` にはアカウントの名と口が入るので、作業の場所（repo の外）に置く。

## i. 相手ごとの token と、誰が何をしたかの記録

売る相手が増えたら、招待コード一つでは足りない。相手ごとに token を出し、範囲と期限を付け、取り消せるようにする（置き方は `docs/deb2 の配備.md` の 0-3 の末尾）。

- `member`（招待した人）: 読み、公開、一言、Web 版。`buyer`（買い手）: 公開の記録に一言を送るだけ。
- 台帳に残るのはハッシュだけ。token は出した時に一度だけ出る。
- 記録（`/var/lib/seed/audit/audit.log`）には、呼び名、した事、通したか断ったか。token も招待コードも書かれない。

確かめ: `https://seed.aiseed.dev/health` の `audit` が `on`。買い手の token で公開を試すと 403。`kagi log verify` が ok。`kagi check tokens --file /var/lib/seed/gate/tokens.json` で期限切れが出ない。

## h. 見るだけの物

- 机の PC の形で入っているサービス（gdm、cups、avahi、bluetooth、ModemManager）。外から届く口は開けていない。連載 第 5 章は、要らないサービスを止める形（動いている物が少ないほど、攻められる面が小さい）。止めたら `ports.toml` の 631 の行を消す。
- 盤は暗号化されていない。
- 2222（forgejo の ssh）は全部の番地に向いている。外から届くかは ufw で決まる（`sudo ufw status verbose`）。

## 終わったら

```bash
kagi log add --actor <自分> --action machine.check --detail deb2
```
