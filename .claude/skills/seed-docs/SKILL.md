# 文書を書く時の決まり

## 読む人で文を分ける

| 読む人 | 物 | 書き方 |
|---|---|---|
| 来た人、使う人 | `README.md`、`docs/利用マニュアル.md`、アプリの文（`src/seed/app/strings.py`）、サイトの文（`src/seed/server/pages.py`）、動画の字幕 | です・ますで、短く、やわらかく。何をすると何が起きるか、画面に何が出るかで言う |
| 作る人、次の回の Claude | `docs/設計書.md`、`docs/記録の形.md`、`docs/基本計画.md`、kagi の文書、`docs/引き継ぎ.md` | そのファイルの今の文体（短い言い切り）。仕組みの名や決まりの文はここに置く |

- 設計書の固い決まりの文を、来た人向けの文に写さない。体言止めの並び、「〜しない」「〜が要る」の並び、括弧の中の用語は、来た人に何を言うかから書き直す。
- 作者の指示の言葉や決めた経緯（「〜はやめた」「昼の決めを戻した」）は、来た人向けの文に書かない。経緯は設計書の変更の記録（§9）に書く。
- 作る側の文書を変えたら、その文書の末尾の「変更の記録」に日付付きで一行。作者の頼みから来た物は「作者 11-07「…」」の短い引用の形でよい。

## どの文にも

- 日本語。そのファイルの今の文体に合わせる。
- 自分で作った縮めた言い方（「出る向きの手」のような）を使わない。それだけ読んで何の事か分かる普通の言葉で書く。
- 「決めるのは作者／本人」「対話で決める」「判定は人」のような、判断を返すだけの一文を書かない。その形の理由を書く。seed を説明する文では、人は畑で見た事を話し、Claude は読んで問い返し、話した事が記録になり、答えは季節が返す、の形で書く。
- 断り書き（「モデルの値で実測ではない」「本人未読」「未確認です」の類）を書かない。出典を URL と日付で、計算の仕方（何を送り、どの値を、どう丸めたか）を書く。確かめた／確かめていない の列の表が元からある文書は、その表で書く。
- 端末の意味の「電話」は「スマートフォン」。「電話番号」の意味は残す。
- 作者の言葉を長く引き写さない。理解した事を自分の言葉で書く。
- 余計を足さない。頼まれていない節、欄、一覧を増やさない。
- Claude を良く見せない。外れた所は隠さず、直す前に書く。
- 鍵、token、招待コードの値、本物の座標、家の網の番地、機器のシリアル番号、個人の連絡先を書かない。

## 手引き（`skill/`）

`skill/` は使う人の Claude が読む畑の手引きで、パッケージに入って配られる。

- 判定の行（「〜すべき」「〜しなさい」）を書かない。やり方を教えない。
- 知らない知識を作って埋めない。
- `<!-- 本人が書く: ... -->` の所は埋めない。使う人が自分の畑の事を書く所。

## 確かめ方

```bash
grep -n "決めるのは\|判定は\|本人未読\|未確認\|実測ではない\|電話" <直したファイル>
```

出た行を一つずつ見る。「電話番号」の意味の「電話」と、記録の形の仕様の「本人の判定（right/wrong）」のような仕組みの名は残す。
